### 抓 DOSBox-X 畫面的三個坑

- **截圖快捷鍵預設是 host key ＋ F5，而 host key 在非 Windows 上是 F12**，
  不是 `Ctrl+F5`。按 `Ctrl+F5` 不會有任何錯誤訊息，`captures` 目錄就是空的。
  繞過去的方法是不用它：`import -window` 直接抓視窗。
- **容器裡沒有視窗管理員，焦點要自己設**（`xdotool windowfocus --sync`）。
  沒設的話按鍵送不進去，而開場動畫照樣在動——看起來像遊戲卡住而不像沒收到鍵。
- **視窗的 640×408 就是畫面本體，一列都不要裁。** 這裡原本寫著
  「上下各一條黑邊，畫面本體在左上角 640×350」，而那句話自己就矛盾——
  上下都有黑邊的話不會從左上角裁。當初的實驗確實看到「`+0+29` 那種
  上下對半的裁法只有四成相符」，而正確的解讀是**任何裁法都會錯開**，
  不是「所以左上角 350 是對的」。原版寫進 CRTC 的 `[12] = 97h` ＝ 408 列
  （`docs/spec/006`）。

  > 一個實驗排除掉一個選項，不等於證明剩下的那個。裁法有無限多種，
  > 「不裁」也是其中一種——而它從來沒被試過。

## 同一串按鍵，兩個實作走同一條路

`tools/dosboxx-record.sh` 拿一個按鍵腳本驅動 DOSBox-X，一邊用
`ffmpeg -f x11grab` 連續錄影，一邊在每一步之後存一張 640×408 的 PNG
（檔名帶著那一步送了什麼鍵）。`internal/parity` 的
`TestZZDosgolemMatchesDosbox` 送同一串鍵給 dosgolem，逐步比畫面。

錄製器固定擷取與影片相同的 Xvfb 左上角 640×408 畫布，不直接擷取
DOSBox-X 視窗：裝置選擇的文字模式視窗是 720×400，進入圖形模式後才是
640×408。每張 PNG 寫出後會立即檢查尺寸，任何一張不符就讓錄製失敗。

**這一支問的不是「remake 對不對」，是「執行器夠不夠」**：同一支原版、
同一串按鍵，兩個獨立實作走到的畫面該一樣。不一樣的地方就是 dosgolem
還沒做到的東西——而那種缺口單獨跑 dosgolem 時**看不出來**，
畫面照樣有東西、程式照樣往前走。

99.92–100.00%，而 23–26 是 27–55%。**兩輪對不上的區間不一樣，
而且都會自己收斂回來**——差異來自兩邊的時鐘，不是 dosgolem 少了功能。

對不上的兩類：

- **防拷密碼那一張**：題目的地支是抽的。dosgolem 抽到「未」，
  DOSBox 抽到「巳」（另一輪是「寅」），連帶右邊兩張人像也不同。
  地圖那半邊逐點相同，差的一萬點全在右邊那一格。
  這一關不擋東西（`internal/parity/password_answer.go`：`1111`／`0000`／
  `4029` 三個答案跑出來的記憶體逐位元組相同），所以答錯不影響後面。
- **一個 dosgolem 抽到、DOSBox 沒抽到的宣戰事件**（袁紹對劉備）。
  同一份按鍵腳本，只把鍵與鍵之間的間隔從 0 改成六百萬道指令，
  這個事件就出現了——原版從計時器取亂數，兩個實作的時鐘不同，
  抽到的東西就不同。

剩下的差異都是**會動的小東西**：主選單右下角那格飾框的動畫
（`x 592..599`）、以及提示列尾巴那個閃爍的游標（`x 576..583`）。
兩個實作不會停在同一格，那不是誰做錯了。

### 對齊：時間對不了，要用程式行為

**兩邊的時鐘差二十倍。** DOSBox 是 `cycles=fixed 60000`，每秒六千萬道
指令；dosgolem 是每個 IRQ0 之間 165,000 道，每秒約三百萬道。
把腳本裡的秒數換算成指令預算**對不齊任何東西**，而且失敗的樣子很像成功：
每一格畫面都靜止，數字只是低。實測照秒數走到第十步時，dosgolem 停在
「建安二年」的密碼畫面，原版在「中平六年」的主畫面。

現在的做法是**問原版自己走到哪了**：主選單會載 `MENU0A`／`MENU0B`／
`MENU1`／`MENU2`／`MENU3` 五張圖，最後一張進來就表示選單要畫了
（實測在第 281,782,097 道指令）。攔載圖常式 `36C9:02B0` 就能知道。

兩個試過但不成立的路標：

- **`int 09h` 的向量**。`docs/re/02` §2 寫著主選單自己裝 IRQ1 處理常式，
  但實際換掉向量的是載入器：第 366M 道指令就換完又還原
  （`0080 → 0B01 → 0080`），那時畫面還停在「程式載入中　請稍待」。
  照它對齊會拿載入畫面去比主選單。
- **跑固定的大預算**。主選單閒置久了會**掉回開場循環**——跑滿
  1.11G 道指令之後畫面退回三英那張，看起來像開場沒走完。

### 五個坑

- **逐格 `import` 抓圖會把時間軸弄假。** 一格 `import` ＋ `convert`
  要 0.4 秒，腳本裡寫「等 60 秒」實際等了 144 秒，後面每一步的時序
  全部對不上。改成 `ffmpeg -f x11grab` 連續錄，關鍵時刻才另外存一張。
- **開場的續行讀的是字元，不是掃描碼。** 拿 `PressScan` 送 Enter，
  三英那張定格永遠不動——而**畫面上有東西、程式也照樣在跑**，
  看起來不像卡住。`bootToMain` 一直是用 `o.Press("\r")`。
- **那個 Enter 要送在它真的在等的時候。** 早送會被前面的畫面吃掉：
  送在第 60M 道指令上，之後跑滿 1G 道指令主選單都不會出來。
  做法是「清乾淨、送一個、跑一段、沒到就再來」，不去記量出來的指令數。
- **同一步裡兩個鍵之間要留空隙。** 錄製腳本每個鍵隔 0.15 秒，
  DOSBox 那一側等於九百萬道指令；連著送的話，畫動畫的那幾步會把第二個
  鍵吃掉——實測宣戰那一段 dosgolem 從此少一個 Enter，落後原版兩張對白，
  而畫面照樣靜止、照樣往前走。
- **兩條輸入路徑要分開餵**（`docs/re/02` §3）：裝置三題、開場續行、
  主選單與年代讀**字元**；「請問有幾人玩」開始的提示才讀**掃描碼**；
  防拷密碼那一關不吃掃描碼。每一步之前先 `Drain()`——沒清乾淨的字元
  副本會把下一個提示堵死，而那看起來像「按了沒反應」。

### 判準只能落在「畫面靜止」的那幾步

錄製時每一步存兩張、隔一秒；兩張一樣才算靜止。**不能要求逐位元組
相同**——提示列尾巴那個游標一直在閃，照那個標準判每一步都是「動畫中」，
判準整個空掉。容差取 400 點。

⚠ **數字要配 Enter，而且一次只送一個。** 「有幾人玩」那一格連送兩個
`1` 會變成 11 個玩家，之後每一步都在問「第 N 位,請選擇」——
畫面一直在動，看起來像卡在選君主。

⚠ **`Y` 之後還有就任對白**，每個現役將一句。只留一個 Return 的話，
後面那個 `2` 會被對白吃掉，整串出兵指令往後偏一步，全部在選單裡空轉。

⚠ **整編每分完一位會問「分配完畢(Y/N)」**（`docs/re/05` §7）：`N` 再分一位、
`Y` 收工，攻方接著問攜帶多少金、多少米，再確認一次。在那一格送 Return
等於答 `N`，畫面會繞回「分配那一位將軍」而且五個隊歸零——看起來像整編
被取消了。

第三列按鈕下緣 356、小飾框下緣 361，**三個都完整落在畫面的 408 列裡**
（先前記著「超出 350 被裁掉」，那是畫布設成 350 造成的，

文字（`assets.MenuText*`）：

- 按鈕上一行字從按鈕左緣 ＋24 起排，先是編號的半形「數字 ＋ 句點」，
  **每個全形字前面空一個半形格**——所以中文的字距是 24 不是 16。
  照 16 排，五個字只佔 80 像素，擠在 200 寬的按鈕左半邊。
- 文字格上緣是按鈕上緣 ＋9，格高 16。
- 左側直牌上「主選擇單」四個字是**橫向拉成兩倍寬**畫的（16×16 的字模
  畫成 32×16），格左緣 x=80、第一格上緣 y=242、行距 24。

remake 這一側的閘門是 `internal/ui` 的 `TestMenuItemLayoutMatchesTheOriginal`

`CURA5` 小飾框畫格）。

### remake 差異

| 差異 | 為什麼 |
|---|---|
| 字模不同 | remake 自建字庫，不內嵌任何原版字模（`CLAUDE.md` §3.3）|
| 選到的那一項畫白色 | 原版沒有選取記號（六項同一個黃，靠按數字鍵選）；remake 支援上下鍵移動，沒有記號看不出停在哪一項 |
| 載入進度、音樂欣賞疊清單時直牌仍寫「主選擇單」 | 原版會換成那一層的名字（實測按下「載入舊進度」之後變成「載入進度」）；選擇年代已照原版換字（`docs/spec/005` §6.4），這兩層還是 remake 的清單 |
| 最上面兩個角落 | 原版 (0,0) 與 (639,0) 是黑的（兩個實作一致），remake 那兩點畫底色 |
