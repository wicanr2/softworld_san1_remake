# 03：畫面的對拍

## 主選單：兩個實作逐點相同（2026-09-09）

`workplace/shots/open/` 那幾張基準畫面是 dosgolem 畫的，而主選單五張圖塊
的位置是從那幾張比對出來的。**同一個實作既當被驗的對象又當標準答案，
驗不出東西**（`CLAUDE.md` §4）——所以另外拿 DOSBox-X 跑一次原版。

| | 產生方式 |
|---|---|
| dosgolem | `internal/parity` 的 `TestZZOriginalOpeningScreens`（`-tags oracle`），`workplace/shots/open/open-06.png` |
| DOSBox-X | `tools/dosboxx.sh`，`workplace/shots/dosboxx/menu.png` |

DOSBox-X 2026.06.02、`machine=svga_s3`、`core=normal`、`cputype=386`、
**`cycles=fixed 60000`**（`cycles=auto` 是可重現性的敵人，兩份 bundle 附的
`dosbox.conf` 都是 auto，不要直接拿來用）。裝置三題送 `1`／`2`／`2`，
之後一路按 Enter 續行開場。

結果：**640×350 裡 223,916 點逐點相同**，剩下的 84 點全部落在
`x 592..599, y 329..343`——右下角小飾框 `MENU3` 裡的一格，
那裡原版放了一段動畫，同一台原版連拍兩張就會不同。

閘門是 `internal/assets` 的 `TestDosgolemMenuMatchesDosboxX`，
兩張圖都在時才跑（都在 gitignore 的 `workplace/` 底下）。

### 抓 DOSBox-X 畫面的三個坑

- **截圖快捷鍵預設是 host key ＋ F5，而 host key 在非 Windows 上是 F12**，
  不是 `Ctrl+F5`。按 `Ctrl+F5` 不會有任何錯誤訊息，`captures` 目錄就是空的。
  繞過去的方法是不用它：`import -window` 直接抓視窗。
- **容器裡沒有視窗管理員，焦點要自己設**（`xdotool windowfocus --sync`）。
  沒設的話按鍵送不進去，而開場動畫照樣在動——看起來像遊戲卡住而不像沒收到鍵。
- **視窗是 640×408，上下各一條黑邊，畫面本體在左上角**。
  `+0+29` 那種「上下對半」的裁法會整張錯開，比出來只有四成相符，
  看起來像兩個實作真的不一樣。

## 同一串按鍵，兩個實作走同一條路

`tools/dosboxx-record.sh` 拿一個按鍵腳本驅動 DOSBox-X，一邊用
`ffmpeg -f x11grab` 連續錄影，一邊在每一步之後存一張 640×350 的 PNG
（檔名帶著那一步送了什麼鍵）。`internal/parity` 的
`TestZZDosgolemMatchesDosbox` 送同一串鍵給 dosgolem，逐步比畫面。

**這一支問的不是「remake 對不對」，是「執行器夠不夠」**：同一支原版、
同一串按鍵，兩個獨立實作走到的畫面該一樣。不一樣的地方就是 dosgolem
還沒做到的東西——而那種缺口單獨跑 dosgolem 時**看不出來**，
畫面照樣有東西、程式照樣往前走。

### 結果（2026-09-09，`workplace/rec9`，38 步）

腳本走完開局 → 選主君 → 出兵宣戰 → 主攻軍團整編（三位將軍分配完畢）。
前六張是文字模式與計時動畫，不列入判準；其餘 32 張逐點比：

| 步 | 畫面 | 相同 |
|---|---|---|
| 7 | 主選單 | 99.96%（差 87 點）|
| 8 | 選擇年代 | 100.00%（差 4 點）|
| 9–11 | 有幾人玩／選君主／難度 | 99.97–100.00% |
| 12–13 | 防拷密碼 | 95.4%（見下）|
| 14–23 | 就任 → 軍事 → 發動戰役 | 19–70%（見下）|
| 24–26 | 宣戰對白 | 99.67–99.70% |
| 27–33 | 軍團整編（分配三位將軍）| 99.63–100.00% |
| 34–38 | 整編完畢之後 | 99.98–100.00% |

合計：32 張列入判準，**20 張在 99.6% 以上，其中 4 張逐點相同**。

同一輪順便量了語音（`docs/re/09`）：訊息常式 `0x3273e` 進去 2 次、
`speak` 進去 320 次、埠 `0x61` 的喇叭位元切換 53,120 次。
**開場自己就會講話**——那 320 次裡絕大多數在主選單之前。

另一輪獨立的紀錄（`workplace/rec8`，33 步）在 14–23 那一段是
99.92–100.00%，而 23–26 是 27–55%。**兩輪對不上的區間不一樣，
而且都會自己收斂回來**——差異來自兩邊的時鐘，不是 dosgolem 少了功能。

對不上的兩類：

- **防拷密碼那一張**：題目的地支是抽的。dosgolem 抽到「未」，
  DOSBox 抽到「巳」（另一輪是「寅」），連帶右邊兩張人像也不同。
  地圖那半邊逐點相同，差的一萬點全在右邊那一格。
  這一關不擋東西（`internal/parity/password_answer.go`：`1111`／`0000`／
  `4029` 三個答案跑出來的記憶體逐位元組相同），所以答錯不影響後面。
- **一個 dosgolem 抽到、DOSBox 沒抽到的宣戰事件**（袁紹對劉備）。
  同一份按鍵腳本，只把鍵與鍵之間的間隔從 0 改成六百萬道指令，
  這個事件就出現了——原版從計時器取亂數，兩個實作的時鐘不同，
  抽到的東西就不同。

剩下的差異都是**會動的小東西**：主選單右下角那格飾框的動畫
（`x 592..599`）、以及提示列尾巴那個閃爍的游標（`x 576..583`）。
兩個實作不會停在同一格，那不是誰做錯了。

### 對齊：時間對不了，要用程式行為

**兩邊的時鐘差二十倍。** DOSBox 是 `cycles=fixed 60000`，每秒六千萬道
指令；dosgolem 是每個 IRQ0 之間 165,000 道，每秒約三百萬道。
把腳本裡的秒數換算成指令預算**對不齊任何東西**，而且失敗的樣子很像成功：
每一格畫面都靜止，數字只是低。實測照秒數走到第十步時，dosgolem 停在
「建安二年」的密碼畫面，原版在「中平六年」的主畫面。

現在的做法是**問原版自己走到哪了**：主選單會載 `MENU0A`／`MENU0B`／
`MENU1`／`MENU2`／`MENU3` 五張圖，最後一張進來就表示選單要畫了
（實測在第 281,782,097 道指令）。攔載圖常式 `36C9:02B0` 就能知道。

兩個試過但不成立的路標：

- **`int 09h` 的向量**。`docs/re/02` §2 寫著主選單自己裝 IRQ1 處理常式，
  但實際換掉向量的是載入器：第 366M 道指令就換完又還原
  （`0080 → 0B01 → 0080`），那時畫面還停在「程式載入中　請稍待」。
  照它對齊會拿載入畫面去比主選單。
- **跑固定的大預算**。主選單閒置久了會**掉回開場循環**——跑滿
  1.11G 道指令之後畫面退回三英那張，看起來像開場沒走完。

### 五個坑

- **逐格 `import` 抓圖會把時間軸弄假。** 一格 `import` ＋ `convert`
  要 0.4 秒，腳本裡寫「等 60 秒」實際等了 144 秒，後面每一步的時序
  全部對不上。改成 `ffmpeg -f x11grab` 連續錄，關鍵時刻才另外存一張。
- **開場的續行讀的是字元，不是掃描碼。** 拿 `PressScan` 送 Enter，
  三英那張定格永遠不動——而**畫面上有東西、程式也照樣在跑**，
  看起來不像卡住。`bootToMain` 一直是用 `o.Press("\r")`。
- **那個 Enter 要送在它真的在等的時候。** 早送會被前面的畫面吃掉：
  送在第 60M 道指令上，之後跑滿 1G 道指令主選單都不會出來。
  做法是「清乾淨、送一個、跑一段、沒到就再來」，不去記量出來的指令數。
- **同一步裡兩個鍵之間要留空隙。** 錄製腳本每個鍵隔 0.15 秒，
  DOSBox 那一側等於九百萬道指令；連著送的話，畫動畫的那幾步會把第二個
  鍵吃掉——實測宣戰那一段 dosgolem 從此少一個 Enter，落後原版兩張對白，
  而畫面照樣靜止、照樣往前走。
- **兩條輸入路徑要分開餵**（`docs/re/02` §3）：裝置三題、開場續行、
  主選單與年代讀**字元**；「請問有幾人玩」開始的提示才讀**掃描碼**；
  防拷密碼那一關不吃掃描碼。每一步之前先 `Drain()`——沒清乾淨的字元
  副本會把下一個提示堵死，而那看起來像「按了沒反應」。

### 判準只能落在「畫面靜止」的那幾步

錄製時每一步存兩張、隔一秒；兩張一樣才算靜止。**不能要求逐位元組
相同**——提示列尾巴那個游標一直在閃，照那個標準判每一步都是「動畫中」，
判準整個空掉。容差取 400 點。

### 開局到出兵的按鍵序列

```
1 2 2          裝置三題（音樂／繪圖／磁碟）
Return ×4      開場動畫續行
1              主選單：開始新遊戲
1              選擇年代：中平六年
1 Return       有幾人玩：1
1 Return       第 1 位：劉備
5 Return       難度
1234 Return    防拷密碼（任意四位數都通得過）
Y              請您一定要確定(Y/N)
Return ×5      就任對白（每個現役將一句）
2 Return       主畫面：軍事
2 Return       軍事：發動戰役
8 Return       從那一郡出兵：齊郡
7 Return       攻打那一郡
Return ×3      宣戰對白
1 Return       分配那一位將軍：1 劉備
1 Return       分到 1 中軍
2 Return       2 關羽 → 2 先鋒
2 Return
3 Return       3 張飛 → 3 左軍
3 Return
```

⚠ **數字要配 Enter，而且一次只送一個。** 「有幾人玩」那一格連送兩個
`1` 會變成 11 個玩家，之後每一步都在問「第 N 位,請選擇」——
畫面一直在動，看起來像卡在選君主。

⚠ **`Y` 之後還有就任對白**，每個現役將一句。只留一個 Return 的話，
後面那個 `2` 會被對白吃掉，整串出兵指令往後偏一步，全部在選單裡空轉。

**還沒解出來的**：整編完畢之後怎麼進戰場。送 Return 或 `Y` 都會**重來一次
主攻軍的整編**（五個隊歸零）。說明書說順序是主攻軍 → 助攻軍 → 主守軍 →
助守軍（`docs/reference/01-manual-20-mechanics` 第 166 行），離開整編要什麼
鍵得從反組譯查。

## 主選單的版面

位置全部拿原版的畫面比對出來（主選單跑在開機鏈的第二層 `DATA0.GRP`，
主程式的碼段 dump 涵蓋不到，`docs/re/02` §1）：

| 圖 | 位置 | 大小 | 相符 |
|---|---|---|---|
| `MENU0A.IMG` | (40, 27) | 280×180 | 100% |
| `MENU0B.IMG` | (320, 27) | 288×180 | 100% |
| `MENU1.IMG` | (56, 215) | 96×151 | 95.3%（字寫在上面）|
| `MENU2.IMG` | x ∈ {152, 376}、y ∈ {215, 267, 320} | 200×46 | 93–97%（字寫在上面）|
| `MENU3.IMG` | (576, 320) | 40×41 | 91%（裡面那格會動）|

**三列的間距是 52、53 不是兩個 52**：第三列在 `y=320`。直牌與第三列按鈕
的下緣都超出 350 被裁掉。

文字（`assets.MenuText*`）：

- 按鈕上一行字從按鈕左緣 ＋24 起排，先是編號的半形「數字 ＋ 句點」，
  **每個全形字前面空一個半形格**——所以中文的字距是 24 不是 16。
  照 16 排，五個字只佔 80 像素，擠在 200 寬的按鈕左半邊。
- 文字格上緣是按鈕上緣 ＋9，格高 16。
- 左側直牌上「主選擇單」四個字是**橫向拉成兩倍寬**畫的（16×16 的字模
  畫成 32×16），格左緣 x=80、第一格上緣 y=242、行距 24。

remake 這一側的閘門是 `internal/ui` 的 `TestMenuItemLayoutMatchesTheOriginal`
（每個字落在原版的哪一格）、`TestMenuLabelIsDoubleWidth`、
`TestTitleScreenMatchesTheOriginal`（扣掉字與動畫那一格之後 **208,050 點
逐點相同**）。

### remake 差異

| 差異 | 為什麼 |
|---|---|
| 字模不同 | remake 自建字庫，不內嵌任何原版字模（`CLAUDE.md` §3.3）|
| 選到的那一項畫白色 | 原版沒有選取記號（六項同一個黃，靠按數字鍵選）；remake 支援上下鍵移動，沒有記號看不出停在哪一項 |
| 小飾框裡不畫動畫 | 那段動畫是什麼還沒解出來 |
| 疊清單時直牌仍寫「主選擇單」 | 原版會換成那一層的名字（實測按下「載入舊進度」之後變成「載入進度」）；remake 的清單標題是多語系的，直排放不下英日 |
| 最上面兩個角落 | 原版 (0,0) 與 (639,0) 是黑的（兩個實作一致），remake 那兩點畫底色 |
