# 010：畫面轉場

狀態：`READY`

範圍：四選一的拉幕 `0x32e40`，以及兩條進它的路：場景圖特效 `0x32dfa`
（48 個呼叫端）與尋訪的直接呼叫（`0x1bbb9`）。其他動畫的清單在
`docs/re/10` §5。

證據等級：呼叫端、圖號、落點 `L0`（執行期碼段
`workplace/dump/code-00b000.bin`，SHA-256 `4d914205…38d7e5a5`；資料段
`dgroup-0427e0.bin`，SHA-256 `e8e8156d…ab68f018`）；拉幕的幾何與逐步畫面 `L1`；
玩家命令那一擲的位置 `L1`（§8）。版本：48 個呼叫端的位址是 `[base]`；
§8 的抽樣序列兩版都量過（`[both]`）。

## 1. 兩條路（`L0`）

```
0x32dfa(x, y)                        ; 場景圖特效
  es:[0x2e78](1)                     ; 之後畫在第二頁
  0x36c9:0x426(x, y)                 ; 把剛載進來的圖畫在 (x, y)
  0x32e40(x, y)                      ; 拉幕：第二頁的那一塊搬到第一頁
  es:[0x2e78](0)
```

每一種計謀有兩處叫判定 `0x2dd66`：前一處是軍師預測（勸諫那一段），後一處
才是真正的判定。所以離間與策反沒得手就不擲，遠交與驅虎不論成敗都擲。

呼叫端的形狀一律是：面板清藍（`0x1058:0x27e8`）→ `0x36c9:0x2b0` 載
`SCG##.IMG`（名字在 DS）→ `0x32dfa(x, y)`。落點只有三種：主畫面右側面板
(432,80)、計略的 (432,120)、主戰場第三塊面板 (448,268)。戰場上有幾處把
座標放在 `si`／`di` 傳，往前追都是 `mov $0x1c0`／`mov $0x10c` 的常數。

尋訪是另一條（`0x1b912`）：`es:[0x2e78](1)` → 第二頁的面板清藍 → 找到人
才在第二頁 (488,88) 畫那一位的肖像 → `es:[0x2e78](0)` → 第一頁的面板清藍
→ `0x32e40(432, 80)`。所以找到人時肖像是**被拉進來的**；沒找到時拉進來
的是一塊藍，畫面看不出變化，`RND(4)` 照擲。

## 2. 四個分支（`L0`）

```
RND(4) → 四選一
  0、1 → i = 3; i < 0x60; i += 4    （24 步，逐列）
  2、3 → i = 0; i < 0xaf; i += 8    （22 步，逐行）
每一步：lcall es:[0x3efc] 搬一塊 → speak(0, 10)
```

迴圈界限 `0x5f` ＝ 95、`0xaf` ＝ 175：從 (x, y) 起 **176 寬、96 高**，正好是
場景圖的尺寸。**橫向的粒度是 8**（EGA 一個位元組八個像素），所以第 1 步
就蓋了 8 行。

## 3. 效果：新畫面整塊滑進來（`L1`）

**不是「逐條露出新畫面」。** 第 n 步把新畫面靠**對邊**的那一塊
（高／寬 i+1）貼到這一邊；i 每一步變大，最後一步兩邊重合、新畫面歸位。

| 方向 | 寫進去 | 從新畫面的哪裡取 |
|---|---|---|
| 0 由上往下 | `y0 .. y0+i` | `y1-i .. y1`（下緣）|
| 1 由下往上 | `y1-i .. y1` | `y0 .. y0+i`（上緣）|
| 2 由左往右 | `x0 .. x0+i+7` | 右緣同寬的一塊 |
| 3 由右往左 | `x1-i-7 .. x1` | 左緣同寬的一塊 |

**判準是「與前一步差異的範圍」**：量到的是**整個已蓋區**——分支 0
第 5 步是 `y80–99`，逐條露出的話那只會是新增的 `y96–99`。四個分支
每一步的範圍（落點 (432,80)）：

| 步 | 分支 0 | 分支 1 | 分支 2 | 分支 3 |
|---|---|---|---|---|
| 1 | y80–83 | y172–175 | x432–439 | x600–607 |
| 5 | y80–99 | y156–175 | x432–471 | x568–607 |
| 9 | y80–115 | y140–175 | x432–503 | x536–607 |
| 最後 | y80–175 | y80–175 | x432–607 | x432–607 |

走完之後那一塊與最後一步的畫面差 **0 個像素**（四個分支都是）；塊外一個
像素都沒動（§7 的場景圖對拍，三種落點都量過）。

⚠ **`es:[0x3efc]` 那支搬運常式本身沒有反組譯**。上表是從**行為**量出來
的（畫面逐步比對），不是從碼讀出來的；它足以重現效果，但答不出
「它有沒有用遮罩」這類問題。

## 4. 聲音

**每一步一聲音效**（`speak(0, 10)`，`docs/spec/008` §4）。24 步或 22 步，
所以一次轉場是 24／22 聲。

## 5. remake 這一側

### R1 `ui.Wipe`

`Kind` 就是 `RND(4)` 的結果（0–3），`Rect` 是拉幕的那一塊，
`From`／`To` 是舊畫面與新畫面。`Advance` 走一步，`Steps` 是總步數。
`ui.NewSceneWipe(canvas, 圖, kind, x, y)` 造「把一張 176×96 的圖拉進 (x, y)」
的那一段：`To` 只在那一塊放著圖。尋訪那一塊由 `ui.SearchPanel` 合成
（藍底，找到人時肖像在 (488,88)），走同一條路。

`Reveal(n)` 與 `Source(dst)` 分開成兩個函式是為了測得到：**動畫在畫面上
對不對測試看不到**（`CLAUDE.md` §7 第 13 條），但「第幾步動到哪一塊、
從哪裡取」量得出來，而那正好是 §3 的兩張表。

### R2 抽樣留在規則層，畫面排進對白佇列

規則層在原版擲 `RND(4)` 的那一刻擲，把結果連同圖號排成佇列裡的一格：
主畫面是 `game.Bubble{Scene, Style}`（尋訪是 `FaceOnly` 加 `WipeIn`），
戰場是 `battle.Speech{Scene, Style}`。與訊息框同一個佇列，所以先後與原版
的對白交錯一致，也不必另外的哨兵值。它不進存檔：原版的進度檔也沒有這一格
（`docs/re/08`）。

### R3 轉場要在繪圖那一層起頭（**remake 的坑**）

輪到拉幕那一格的那一幀，畫布上還是**上一幀畫的舊畫面**。等到下一次
`Update` 才去拿，畫布早就被重畫成新的，兩張圖一樣，轉場等於沒跑。所以
`cmd/san1` 在 `Draw` 開頭起頭：先照**沒有那一格**的樣子畫一次當底，再從
那張底拉進來；`scenePlayed` 記住拉過的那一格，拉完才收鍵。

### R4 一幀一步（**remake 差異**）

原版那一段是阻塞的；remake 一幀走一步（24 步 ≈ 0.4 秒），期間不收輸入。
速度沒有對齊原版——原版一步的長度由 CPU 速度決定，與語音同一個問題
（`docs/spec/008` R8）。

### R5 沒有原版素材就不轉場

退回文字版面時訊息面板不在同一個位置。**寧可不轉場，也不要在錯的地方
拉幕**；那一擲照擲。

### R6 主畫面命令只在玩家親自下令時播

§1.1 的主畫面命令那幾支只在玩家下令的路上；電腦諸侯走分派器，自治的郡
也走分派器（`0x17550`），兩者都不播不擲。remake 的 `commandScene` 因此看
`playerCommand` 與 `AutonomousFor` 兩道。事件那幾張（玉璽、老死、出頭、
四種災害）不看是誰，示範模式也擲；進貢那一張只給玩家操縱的勢力。

## 8. 玩家命令那一擲的位置（`L1`、`[both]`）

`TestPlayerCommandsMatchTheOriginal`／`TestPlayerCommandsPlus` 在每道命令期間
攔原版的 `rand()` 計次、攔 `RND(n)` 記 n，remake 用 `TraceRolls` 記同一段，
兩邊的次數與 n 序列逐項比。**不比結束時的亂數狀態**：原版在等鍵與延遲時
會重設種子（命令結束時的狀態是 `0x0000b970` 這類高位為 0 的值，不同命令
還會落在同一個值），那個比法連沒有場景圖的命令都對不上。

| 命令 | 兩版的序列 |
|---|---|
| 開墾、治水、訓練、徵兵、購買武器、買米、賣米 | `[5 4]`：勸諫、拉幕 |
| 賞賜（三種盤面）| `[5 4 8]`：勸諫、拉幕、道謝的字色 |
| 賑民（兩種盤面，沒有場景圖，負對照）| `[5]` |
| 築關 | 加強版 `[5 4]`；原版那個盤面兩邊都拒絕 |

休息不判：那一道一下完就轉移控制權，取樣點之前原版已經把其他勢力的郡
跑過一輪。沒進這張表的（調動、運送、調整兵力、登用、挖角、撤職、指定、
賜物、出兵）只有 §1.1 的 `L0`。
