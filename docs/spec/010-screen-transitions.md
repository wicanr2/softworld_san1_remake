# 010：畫面轉場

狀態：`READY`

範圍：計謀得手之後那一段四選一的拉幕（`0x32e40`）。其他動畫的清單在
`docs/re/10` §5。

證據等級：`L0`（迴圈界限、參數、每步一次音效）＋ `L1`
（`internal/parity` 的 `TestZZTransitionFrames`：四個分支逐步量畫面）。
版本：`[base]`。加強版沒驗過，不外推。

## 1. 區域（`L0`）

唯一的呼叫端是 `0x1bbb9`：

```
push 0x50            ; y ＝ 80
push 0x1b0           ; x ＝ 432
lcall 3273:0710      ; ＝ 0x32e40
```

配上迴圈界限（`0x5f` ＝ 95、`0xaf` ＝ 175）：
**x 432..607（寬 176）、y 80..175（高 96）** ——畫面右側的訊息面板。

## 2. 四個分支（`L0`）

```
RND(4) → 四選一
  0、1 → i = 3; i < 0x60; i += 4    （24 步，逐列）
  2、3 → i = 0; i < 0xaf; i += 8    （22 步，逐行）
每一步：lcall es:[0x3efc] 搬一塊 → speak(0, 10)
```

**橫向的粒度是 8**（EGA 一個位元組八個像素），所以第 1 步就蓋了 8 行。

## 3. 效果：新畫面整塊滑進來（`L1`）

**不是「逐條露出新畫面」。** 第 n 步把新畫面靠**對邊**的那一塊
（高／寬 i+1）貼到這一邊；i 每一步變大，最後一步兩邊重合、新畫面歸位。

| 方向 | 寫進去 | 從新畫面的哪裡取 |
|---|---|---|
| 0 由上往下 | `y0 .. y0+i` | `y1-i .. y1`（下緣）|
| 1 由下往上 | `y1-i .. y1` | `y0 .. y0+i`（上緣）|
| 2 由左往右 | `x0 .. x0+i+7` | 右緣同寬的一塊 |
| 3 由右往左 | `x1-i-7 .. x1` | 左緣同寬的一塊 |

**判準是「與前一步差異的範圍」**：量到的是**整個已蓋區**——分支 0
第 5 步是 `y80–99`，逐條露出的話那只會是新增的 `y96–99`。四個分支
每一步的範圍：

| 步 | 分支 0 | 分支 1 | 分支 2 | 分支 3 |
|---|---|---|---|---|
| 1 | y80–83 | y172–175 | x432–439 | x600–607 |
| 5 | y80–99 | y156–175 | x432–471 | x568–607 |
| 9 | y80–115 | y140–175 | x432–503 | x536–607 |
| 最後 | y80–175 | y80–175 | x432–607 | x432–607 |

走完之後那一塊與最後一步的畫面差 **0 個像素**（四個分支都是）。

⚠ **`es:[0x3efc]` 那支搬運常式本身沒有反組譯**。上表是從**行為**量出來
的（畫面逐步比對），不是從碼讀出來的；它足以重現效果，但答不出
「它有沒有用遮罩」這類問題。

## 4. 聲音

**每一步一聲音效**（`speak(0, 10)`，`docs/spec/008` §4）。24 步或 22 步，
所以一次轉場是 24／22 聲。

## 5. remake 這一側

### R1 `ui.Wipe`

`Kind` 就是 `RND(4)` 的結果（0–3），`Rect` 是 `ui.WipeRect`，
`From`／`To` 是舊畫面與新畫面。`Advance` 走一步，`Steps` 是總步數。

`Reveal(n)` 與 `Source(dst)` 分開成兩個函式是為了測得到：**動畫在畫面上
對不對測試看不到**（`CLAUDE.md` §7 第 13 條），但「第幾步動到哪一塊、
從哪裡取」量得出來，而那正好是 §3 的兩張表。

### R2 抽樣留在規則層

`internal/game` 的 `PendingWipe` 收 `RND(4)` 的結果，UI 用 `TakeWipe`
取走並清掉。**哨兵是 `NoWipe = -1` 不是 0**——0 是一個真的方向
（由上往下），拿零值當「沒有」的話每一次新局都會多播一次轉場
（`CLAUDE.md` §7 第 11 條）。

它不進存檔：原版的進度檔也沒有這一格（`docs/re/08`）。

### R3 轉場要在繪圖那一層起頭（**remake 的坑**）

規則層設好 `PendingWipe` 的那一幀，畫布上還是**上一幀畫的舊畫面**。
等到下一次 `Update` 才去拿，畫布早就被重畫成新的，兩張圖一樣，
轉場等於沒跑。所以 `cmd/san1` 在 `Draw` 開頭起頭，`Update` 只負責推進。

### R4 一幀一步（**remake 差異**）

原版那一段是阻塞的；remake 一幀走一步（24 步 ≈ 0.4 秒），期間不收輸入。
速度沒有對齊原版——原版一步的長度由 CPU 速度決定，與語音同一個問題
（`docs/spec/008` R8）。

### R5 沒有原版素材就不轉場

退回文字版面時訊息面板不在同一個位置。**寧可不轉場，也不要在錯的地方
拉幕。**

## 6. 驗收

| 項 | 怎麼驗 |
|---|---|
| 步數與每一步的範圍 | `internal/ui` 的 `TestWipeStepCountsMatchTheOriginal`、`TestWipeTouchedAreaGrowsFromTheEdge` |
| 搬的是對邊那一塊、走完就是新畫面 | `TestWipeSlidesTheNewPictureIn` |
| 原版那一側的數字 | `internal/parity` 的 `TestZZTransitionFrames`（`L1`）|
| 接進遊戲 | `cmd/san1` 實跑；**沒有無頭判準**，記為 remake 自驗 |

## 7. 還沒解的

| 缺口 | 現況 |
|---|---|
| `es:[0x3efc]` 的語意 | 沒有反組譯；效果由行為量測決定（§3 的 ⚠）|
| 什麼時候還會轉場 | 只驗過「計謀得手」一條；失敗會不會也轉場沒有樣本（`docs/mechanics/70-ai` §2.13.7）|
| 一步的長度 | 原版由 CPU 速度決定，remake 用一幀（R4）|
