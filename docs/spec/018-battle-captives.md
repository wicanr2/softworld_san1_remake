# 018：戰場上的被擒處置與中途紮寨

狀態：`READY`

範圍：交戰、計謀、單挑把將領打光之後的處置常式 `0x259fe`，四種處置
`0x25f6a`／`0x260dc`／`0x262b8`／`0x25b94`，釋放的去處 `0x265ac`，以及
招降或投敵的人進了空部隊時的紮寨 `0x2731a`。

證據等級：`L0`（執行期碼段 `workplace/dump/code-00b000.bin`，SHA-256
`4d914205…38d7e5a5`；字串在 `dgroup-0427e0.bin`）。對拍在 §6。版本：`[base]`。
加強版的對應位址在 `docs/re/05` §12.5 的對照表（`0x259fe` → `0x23306`），
逐行沒有比過，不外推。

## 1. 入口（`0x259fe(捕獲方軍力, 人物)`）

```
0x2514c 重算部隊
印「%s主公 / 我們抓到%s / 請主公裁決 / 1.斬首 2.囚禁 / 3.釋放 4.招降 / :」（DS:0x7d2c）
捕獲方諸侯 offset 0 == 2（電腦）：
    choice = RND(10) < 2 ? 1 : 2                  ; 0x25a93
    招降判定 0x25e50 > 0 → choice = 4
    人物 offset 17 == 0（君主）→ choice = 1
否則（玩家）：
    讀鍵（0x1058:0xe24）直到 '1'..'4'           ; 其他鍵不理，不重印
choice 1 → 0x25f6a 斬首   2 → 0x260dc 囚禁   3 → 0x262b8 釋放   4 → 0x25b94 招降
回傳 −1 → 回到最上面：重算、重印、重新決定（電腦會重擲 RND(10)）
否則 0x2514c 重算、0x2020:0x2a94 重畫捕獲方
```

## 2. 四種處置（`L0`）

下面的「戰場郡」是工作區 `es:[0x1bf8]`；「在野數」是州郡 offset 23、
「現役數」是 offset 22。對白一律是訊息常式 `0x3273e`，第三塊面板、
肖像在左、說話者是被擒的人，進去擲 `RND(8)`。

| 處置 | 拒絕（回 −1，不擲骰）| 骰序 | 人物與州郡 | 訊息 |
|---|---|---|---|---|
| 斬首 `0x25f6a` | 無 | 對白 454 `RND(8)` | 身分 12（死）、所屬與所在 `0xFF`；身分 1（軍師）先清舊主的軍師欄；**君主**另設繼承的三格（`es:0x20f0` 勢力、`es:0x24d6` 人物、`es:0x31b8` 所在郡、`es:0xc4 ← 1`）| `DS:0x7d81`「%s在 %s之戰中 被斬首身亡」|
| 囚禁 `0x260dc` | 君主；戰場郡在野數 ≥ 50 | 對白 453 `RND(8)`、場景圖 `SCG08` `RND(4)` | 身分 10、所屬 `0xFF`、所在 ＝ 戰場郡；戰場郡在野數 +1；軍師先清軍師欄 | `DS:0x7da4`「%s在 %s之戰中 被擒囚禁」|
| 釋放 `0x262b8` | 戰場郡在野數 ≥ 50 | 去處 `RND(n)`（§3，n ＝ 0 不擲）、對白 455 `RND(8)`、場景圖 `SCG26` `RND(4)` | 見下 | 見下 |
| 招降 `0x25b94` | 招降判定 ≤ 0：先印對白 452「不從」`RND(8)` 再回 −1 | 判定裡的 `RND(3)`（君主與 ≥ 50 將領時不擲）、對白 451 `RND(8)`、場景圖 `SCG04` `RND(4)` | `0x25cd2` 加入捕獲方（`docs/re/05` §12.3）| 無 |

釋放之後：

| 條件 | 結果 | 訊息 |
|---|---|---|
| 有去處 d（§3）| 所在 ← d、**所屬不變**；d 的現役數 0 就把 d 的主事者（offset 32）設成他；d 的現役數 +1；`0x1538:0x411e(d)`（＝ `0x1949e` 重整守將清單，君主在就接主事者，`docs/spec/016`）| 君主 `DS:0x7dc5`「君主%s 逃到%s」、其他 `DS:0x7dd3`「將軍%s 逃到%s」|
| 沒有去處、君主 | 身分 8、所屬 `0xFF`、所在 ＝ 戰場郡、戰場郡在野數 +1；繼承的三格、`es:0xc4 ← 2` | `DS:0x7de1`「%s在 %s被釋放.」|
| 沒有去處、其他 | 軍師先清軍師欄；身分 8、所屬 `0xFF`、所在 ＝ 戰場郡、戰場郡在野數 +1 | `DS:0x7de1` |

## 3. 釋放的去處（`0x265ac(勢力)`）

```
清單 ＝ 郡 1..42 裡 所屬 == 勢力 且 現役數 < 50 且 不是戰場郡
清單空 → 清單 ＝ 郡 1..42 裡 所屬 == 0xFF 且 不是戰場郡
清單不空 → 去處 ＝ 清單[RND(清單長)]，否則 −1
```

## 4. 中途紮寨（`0x2731a(軍力, 隊伍)`）

`0x25cd2` 把人放進**原本空著**的部隊時叫它：把整張戰場上可紮的格子標出來，
印開戰前紮寨同一個提示（`DS:0x7e88`「(%2d%s)%s之%s請%s將軍紮寨」），
軍力的諸侯 offset 0 是 1（玩家）就走游標挑格（`0x2020:0x1a7c`，挑到為止），
否則 `0x2020:0x293a(−1, −1)` 由電腦挑。之後部隊的欄、列寫進部隊記錄。

## 5. remake

### R1 回呼

`battle.Battle` 兩個欄位給玩家那一方用；nil 就維持舊行為：

- `PlayerCaptive func(captor Side, x *Leader) Fate`：玩家捕獲時回 `Executed`／
  `Jailed`／`Released`／`Defected` 之一。規則層照 §1–§2 執行，回 −1 的情況
  （拒絕、不從）**再問一次**。nil 時玩家捕獲的人留 `FateNone`（不是玩家指揮
  的戰役走這條，§7）。
- `PlayerCamp func(u *Unit) Hex`：玩家那一方的空部隊收到第一位將領時問紮在
  哪；回傳的格子要能紮（`CampArea`），不能紮就再問。nil 時照舊由
  `spotNear` 擺並標 `Unplaced`。

### R2 戰場郡的兩個數與釋放的去處

`battle` 不知道州郡表，所以另給一個介面 `CaptiveHost`（`game.State.CaptiveHost(戰場郡)`
造，開戰時掛上）：`IdleRoom() bool`（戰場郡在野數 < 50，含這一場已經囚禁／
釋放進去的人，`AddIdle` 記）與 `ReleaseTo(人物, roll) int`（§3，用戰場的擲骰；
清單比的是人物的勢力，在野者 `0xFF` 也照比）。沒有 host 時兩者分別是「有空位」
與「沒有去處」。

### R3 搬回人物表

`game.applyFate`（收尾的 `settle` 與對拍用的 `ApplyCaptiveFate` 共用）照
§2 寫人物：囚禁是身分 10、所屬 `0xFF`、所在戰場郡；釋放有去處時只改所在、
去處沒有現役就設他主事，再 `RefreshGarrison(去處)`（＝ `0x1949e`，君主回去
就接主事者）；沒有去處是身分 8。囚禁與釋放不動忠誠與兵。現役數與在野數
由人物表推導，不另外存。**君主的繼承**照原有的戰後流程（`retireBy`）處理，
不另外複製 `es:0xc4` 那一套。玩家當場處置的人照樣列進 `BattleResult.Captives`
（帶 `Fate`、被擒當下是不是君主與勢力），勝方接收寶物看這一份。

### R4 UI：協程

戰術層是同步的；`cmd/san1` 把每一次會推進戰術層的呼叫（`Runner.Next`、
玩家的每一道命令）包在 `iter.Pull` 的協程裡。回呼把問題 yield 出去，UI 畫
「請主公裁決」四選一或紮寨游標，收到答案再 resume。協程與 UI 一次只有一方
在跑，戰場資料不會同時被讀寫。

### R5 remake 差異（登記）

- 電腦那一方的中途紮寨用 `spotNear`，不是 `0x2020:0x293a`（§7）。
- 繼承的三格不複製（R3）。
- **沒有介面時玩家那一方的捕獲照電腦的判斷式處置**（Issue #100）。
  原版**不管那一場由誰指揮**，玩家那一方抓到人都當場出四選一
  （`0x259fe`）；remake 在示範模式、月度對拍、批次跑，以及「守城」開關
  關著的那一條沒有人可以答，先前直接留 `FateNone`——**被抓了卻什麼都
  沒發生，原版沒有這個狀態**，而且三張表會不一樣。現在走 `Computer`
  那一套（`RND(10)` → 斬首／囚禁、招降判定、君主一律斬首）。
  ⚠ 這會**多擲一次 `RND(10)`**，所以是差異不是還原。
  動之前量過：六張逐日對拍盤面（`TestZZUnitAIDayParity`）與三十六個月的
  無畫面局（`TestNoInterfaceCapturesHappen`）**一次都沒走到**這一條，
  既有對拍的骰序不受影響；計數器的正對照是
  `TestNoInterfaceCaptiveCounterFires`——**沒有正對照的 0 不算數據**。
