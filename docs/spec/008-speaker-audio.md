# 008：PC 喇叭的音效與語音

狀態：`READY`

範圍：原版用 PC 喇叭播的**一位元取樣**——四個緩衝槽、載入器、兩個開關、
一句話三段，以及 remake 這一側怎麼把它變成聲音。配樂（OPL2／AdLib）
是另一條路，在 `docs/spec/009`。

證據等級：`L0`（`AA.EXE` 反組譯，線性位址）＋ `L1`
（`internal/parity/speech_oracle_test.go` 三支對拍）。
版本：`[base]`。加強版沒驗過，不外推。

RE 在 `docs/re/09`；素材清單在 `docs/formats/04`。

## 1. 波形格式（`L0`＋`L1`）

**一位元 PCM，最高位先送，八個位元一個位元組。** 每個取樣只有兩個值，
直接寫進埠 `0x61` 的 bit0 與 bit1。沒有表頭、沒有取樣率欄位、沒有壓縮——
檔案長度乘以 8 就是取樣數。

`L1` 兩層都釘住了：

- `TestSpeechClipsAreTheAssetBytes`：播放入口拿到的遠指標指向的位元組，
  與容器裡的素材**雜湊相同**。
- `TestSpeechBitStreamMatchesTheClip`：喇叭實際切換的序列換算回位元跑，
  與素材的位元**165／165 全部對上**（100.0%）。

> 先前「自相關約 0.55，判為壓縮過」是只量了統計特徵。統計特徵不是語意
> （`CLAUDE.md` §7 第 16 條）。

## 2. 四個緩衝槽

載入器 `loadClip(char far *name, int slot)`（線性 `0x5a76`）：

| 檢查 | 訊息字串（`L0`）|
|---|---|
| `slot` 不在 0–3 | `Invalid SND`（`DS:0x5402`）|
| `slot == 0` 且長度 > 1000 | `Real#0>1000`（`DS:0x540e`）|
| 長度 > `0x1068`（4200）| `Real#1-3>4200`（`DS:0x541a`）|

讀進去之後：資料的遠指標寫 `es:[0x878 + slot*4]`（段取自 `DS:0xa55e`），
長度寫 `es:[0x3c8c + slot*2]`（段取自 `DS:0xa560`）。

| 槽 | 誰 | 來源 | 何時載 |
|---|---|---|---|
| 0 | **音效** | `S000.SND`（`DATA1`，128 bytes）| 開機一次（線性 `0x117df`）|
| 1–3 | **語音** | `R%03d.OKR`（`DATA2`／`DATA3`）| 每則訊息現載（線性 `0x32b4b`／`0x32b77`／`0x32ba3`）|

上限對得上素材：全部 465 段 `.OKR` 最長 4,061 < 4,200；`S000.SND`
是 128 < 1,000。

> `S000.SND` 的 128 個位元組反組譯起來是一段完整的 ISR
> （取樣某個埠的 bit4、湊八個位元存一個位元組、`out 0x20` 之後 `iret`）
> ——看得出是作者的數位化工具留下來的。**遊戲把它當波形播**，
> 這一點由 `L1` 釘住，不必解釋它為什麼長這樣。

## 3. 兩個開關

| 開關 | 工作段位移 | 存檔位移（`docs/re/08`）| 值 |
|---|---|---|---|
| 音效狀態 | `0x31aa` | `0xBA` | 0 ＝ 開啟、1 ＝ 關閉 |
| 語音狀態 | `0x3148` | `0xBE` | 同上 |

- `speak(索引, 速度)`（線性 `0x5b80`）自己的門是**音效狀態**：關掉音效，
  四個槽一個都播不出來。
- 訊息常式那三段的門是**語音狀態**。

所以**語音要兩個都開**——說明書 p.26 的「若關閉音效，語音將無法使用」
就是這個結構。

⚠ 兩道門讀的是**不同的段變數**（`speak` 用 `DS:0xa562`，訊息常式用
`DS:0xaa82`）。攔錯段不會報錯，只會看起來像「原版沒有這道門」。

## 4. 音效是動畫的節拍聲（`L0`）

`speak(0, 10)` 的呼叫端不是「某件事發生了」，而是**動畫每畫一格一次**
（`docs/re/10` §1）：

| 在哪 | 每次幾聲 |
|---|---|
| 畫面轉場的四種拉幕（`0x32eb5` 等）| 24 或 22 |
| 防拷密碼盤問畫面的兩圈（`0x409a`／`0x4112`）| 160 ＋ 160 |

所以 remake 要把音效接在**動畫的步進**上，不是接在事件上。
轉場做出來了（`docs/spec/010` 已經 `READY`），音效就接在它的每一步；
防拷不實作，那 320 聲 remake 不會有。

## 5. 一句話三段

訊息常式（線性 `0x3273e`，111 個呼叫端）在畫完訊息之後，依序
`speak(1, 速度)`、`speak(2, 速度)`、`speak(3, 速度)`——**一句話由三個槽
接起來**。檔名索引先夾到 `≤ 499`。

**哪一則訊息配哪三個索引還沒解**（`worklist.json` 的 `speech-message-map`）。

## 6. 播放時機與取樣率

模組有兩個公開入口，**遊戲只走 `05C4:01AB`**（線性 `0x5deb`，
`L1`：320 次呼叫全部走它，8253 通道 0 的分頻值從頭到尾沒被動過）。
那一支用**軟體延遲迴圈**，而且**播完才回**：

```
mov cx,分頻值 ; loop $ ; 送一個位元 ; 沒播完就再來一次
```

兩個後果：

1. **原版在一段聲音播完之前整個停住。**
2. **取樣率跟 CPU 速度成正比**，不是固定值。說明書要玩家按機器設
   「語音速度」（`16 MHz 約 100`）就是這個緣故。

`L1` 量到的：音效那一段每個位元約 36 道指令（11,690,000 ÷ 320 ÷ 1,024），
其中延遲迴圈 13 圈。

## 7. remake 這一側

### R1 解碼（`internal/speaker`）

`Clip` 是一段一位元取樣。`Render(rate)` 把它變成 16 位元 PCM：

1. 每個位元 → 兩個位準之一。
2. 依 `來源取樣率 ÷ 輸出取樣率` 線性重取樣。
3. 過一階低通（預設 4 kHz）——真實喇叭的紙盆本來就是低通，
   不過濾的話一位元訊號在 48 kHz 上是刺耳的方波。

低通與位準是 **remake 差異**，不影響位元序列本身。

### R2 槽

`Bank` 有四格，`Load(slot, data)` 照 §2 的上限檢查（超過就回錯誤，
不靜靜截斷）。槽 0 開機從 `DATA1／S000.SND` 載一次。

### R3 開關

- 音效關 → 四個槽全部不出聲（對齊 `speak` 的門）。
- 語音關 → 槽 1–3 不出聲，槽 0 照常。

### R4 一句話三段

`Say(a, b, c)` 把三段接成一個佇列，依序播，中間不留空隙。

### R5 不阻塞（**remake 差異**）

原版播完才回；remake 非同步播，畫面不等它。理由：現代視窗系統下
凍住畫面幾百毫秒是當掉的樣子，而這一項不影響任何遊戲規則。
**記在這裡，不在程式碼裡默默改。**

### R6 第一個位元組（**remake 差異**）

原版**播不出素材的第一個位元組**（`docs/re/09` §5.1：準備動作寫錯變數，
播出去的第一個位元組是上一段留下來的殘留值）。remake 從第 0 個位元組
播到底。

理由：那個殘留值是越界讀來的，remake 沒有對應的記憶體可以重現；
而差別是音效的 128 分之 1、語音的數千分之一。**記在這裡，
不在程式碼裡默默改。**

### R7 觸發點

| 觸發點 | 出處 |
|---|---|
| 畫面轉場的每一步（24 或 22 聲）| **照原版**（`docs/spec/010` §4）|
| 切換「音效狀態」時播一聲 | **remake 自己的**：按下去什麼都不會變的選項，與「這個功能還沒做」在畫面上長得一模一樣（`cmd/san1` 的音樂開關是同一個理由）|

防拷密碼那 320 聲 remake 不會有——不實作防拷。

### R8 取樣率（`L3`，可調）

原版的取樣率由機器決定（§5），remake 要一個固定值。模型：

```
每個位元的週期數 ≈ loopCost × 分頻值 + fixed
取樣率 = CPUHz ÷ 每個位元的週期數
```

基準機器取 16 MHz 的 80286（`loopCost = 8`、`fixed = 45`），與說明書的
「16 MHz 約 100」同一台。**這是估的**：真值取決於等待狀態與 BIOS。
遊戲選項的「語音速度」直接餵進分頻值，所以玩家仍然調得動。

**開放項**：語音那三段的速度參數（訊息常式的 `[bp-4]`）還沒量到——
要先讓原版吐一則帶語音的訊息。在那之前語音用與音效相同的模型，
分頻值取 130（≈ 說明書的 100 乘上音效那一段量到的 1.3 倍）。

## 8. 驗收

| 項 | 怎麼驗 |
|---|---|
| 播出去的是素材本身 | `TestSpeechClipsAreTheAssetBytes`（`L1`，已過）|
| 位元序列（含 §R6 的首位元組）| `TestSpeechBitStreamMatchesTheClip`（`L1`）|
| 上限與槽 | `internal/speaker` 單測，不需要原版素材 |
| 開關 | `internal/speaker` 單測：兩個開關的四種組合 |
| 接進遊戲 | `cmd/san1` 實跑；**沒有無頭判準**，記為 remake 自驗 |
