# 007：電腦諸侯的移防

狀態：`READY`

範圍：電腦諸侯「出兵」四選一裡走**移防**那兩支（占領無主的鄰郡、
搬進自己的鄰郡）之後，盤面實際被改成什麼樣。進攻那一支走的是戰役
（`0x188ea`），不在這一份裡。

證據等級 `L0`（`AA.EXE` 反組譯，線性位址）＋ `L1`（月度對拍）。
版本：`[base]`。加強版沒驗過，不外推。

## 1. 呼叫鏈

```
郡的分派表第 18 張（0xec1b：出兵）
  → 0xb666／0xb696／0xb6c6（三個難度等級，碼相同）
      → 0xb2b4  規劃用的編隊（洗牌 → 從尾端拿人）
      → 0xb47a  三道閘門 → RND(4) 挑類別 → RND(n) 挑目標郡
      → 0xb520／0xb568  兩支移防（無主／己方），各自
            → 0xb706  出發：重編隊、算比例錢糧、夾上限
                  → 0x1938a  搬人搬錢糧          ← 這一份
```

`0xb706` 的呼叫端只有 `0xb560` 與 `0xb5ba` 兩處，都是移防，所以這一份
描述的行為與進攻無關。

`0x1938a` 本身是**兩條路徑共用的**：

| 呼叫端 | 誰 | 編碼 |
|---|---|---|
| `0xb9f3` | 電腦諸侯的移防 | `lcall 1538:400a` |
| `0x18fbc` | 玩家的「調動軍隊」（`0x18bc8`，`docs/re/03` §1.5）| `push cs; call` 近呼叫 |

⚠ **掃呼叫端要用線性位址掃，不要只掃 `lcall` 的位元組樣式。** 同一個
目標在同一個段裡是 `push %cs; call rel16`，位元組完全不同；只掃
`9a 0a 40 38 15` 會漏掉玩家那一條，得出「只有一個呼叫端」的錯結論
（`CLAUDE.md` §7 第 20 條的同一類）。

## 2. `0x1938a`：搬運本身

```
1938a: push %bp; mov %sp,%bp
       ; 參數：0x6(bp) 來源郡、0x8(bp) 目標郡、0xa(bp) 金、0xc(bp) 米
19395: movw $0x0,-0x2(%bp)                    ; i = 0
1939c:   mov %ax,%bx; shl %bx                 ; 名單索引 × 2
193a4:   mov $0x1e,%ax                        ; 30 ＝ 人物記錄大小
193a7:   imulw %es:0x58c(%bx)                 ; × 名單[i]
193b2:   mov 0x8(%bp),%al
193b5:   mov %al,%es:0x2223(%bx)              ; 人物 offset 19（所在郡）← 目標郡
193ba:   incw -0x2(%bp)
193bd: cmp -0x2(%bp),%es:0xc; jg 0x1939c      ; **整份出征名單**

193da: sub %ax,%es:0x492(%bx)  ; 來源郡的金 −= 金   （州郡 offset 18）
193df: jns +7 ; else movw $0x0                ; 下限 0
193f3: sub %ax,%es:0x494(%bx)  ; 來源郡的米 −= 米   （offset 20）
193f8: jns +7 ; else movw $0x0                ; 下限 0
1940c: add %ax,%es:0x492(%bx)  ; 目標郡的金 += 金
19411: jns +7 ; else movw $0x7530             ; 溢位（16 位元變負）→ 30000
19425: add %ax,%es:0x494(%bx)  ; 目標郡的米 += 米
1942a: jns +7 ; else movw $0x7530
```

之後兩郡各自重整守將清單（`0x1949e`），目標郡原本無主就顯示「占領」，
來源郡被搬空就顯示訊息。**這條路徑上沒有交戰呼叫。**

## 3. 三條規則

| # | 規則 | 出處 |
|---|---|---|
| R1 | **整份出征名單都搬**：名單裡每一位的人物 offset 19 都寫成目標郡 | `0x1939c`–`0x193c9` |
| R2 | 來源郡的金米相減後**夾下限 0**；目標郡相加後若在 16 位元下變負，**設成 30000** | `0x193df`／`0x193f8`／`0x19411`／`0x1942a` |
| R3 | **電腦這一條沒有「主事者要有人接手」的閘門**。整郡搬空是允許的——郡的歸屬在下一個郡回合由 `0x1e394` 從人物表重算，來源郡就此變成無主 | `0xb706`／`0x1938a` 全文無此判斷；`docs/mechanics/70-ai` §「搬進去之後」 |

R1 與 R2 在 `0x1938a` 裡，**兩個呼叫端都適用**；R3 是呼叫端的政策，
電腦那一條與玩家那一條都適用：玩家的「調動軍隊」（`0x18bc8`）同樣沒有接手閘門，
差別只在呼叫端的多選清單與金米上限（`docs/mechanics/40` §1.1）。

所以 remake 這一邊的分法是：搬運本身一份（`relocateSupplies`），
政策兩份（`Move` 給玩家、`Relocate` 給電腦）。

## 4. remake 這一側要改什麼

`internal/ai/ai.go` 的 `sortie()` 原本回 `game.MoveOrder{General: force[0]}`
——只搬一位，違反 R1；`internal/game/commands.go` 的 `Move()` 沒有 R2 的
兩個夾值，而 `ErrNoGovernor` 會擋下 R3 允許的「整郡搬空」。

做法：`relocateSupplies` 收下 R1＋R2（兩條路徑共用），`Relocate` 是電腦
那一條的政策外殼，`Move` 維持玩家的閘門但改走同一個搬運。

驗收：`TestZZMonthParity` 裡郡 6 的主事者（州郡 offset 32）與人物表的
「所在」欄回到與原版相同。
