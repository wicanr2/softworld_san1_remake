# 02：原版從開機走到遊戲設定

`L1`（可重現的執行）。素材是 `org_game/三國演義`（base），執行器是
`dosgolem-san` 分支 `san1-msc-oracle`。

## 1. 開機鏈

三層，每一層都是完整的 MSC 程式（自己縮 PSP 區塊、自己起 far heap、
自己跑啟動碼）：

```
AA.EXE (354,960)
  └ 自解壓後把一段 stub 搬到 9FE4:0000，從那裡發出 int 21h AH=4Bh AL=03
      └ DaTa0.gRp (42,488)   載到 0110:0000，重定位加數 0110
          （檔名大小寫混雜是 overlay 載入器的寫法，不是筆誤）
          └ DaTa5.gRp (145,378)  同樣載到 0110:0000，蓋掉上一層
```

`DATA5.GRP` **是主程式不是資料容器**。`10.BAT`／`20.BAT` 做的是
`DEL DATA5.GRP` ＋ `COPY 10.GRP DATA5.GRP`，而 `10.GRP` 與出貨的
`DATA5.GRP` 逐位元組相同。

## 2. 走到遊戲設定要的東西

按時間順序：

| 什麼 | 為什麼 |
|---|---|
| 三個裝置選項的按鍵 `1`／`2`／`2` | `int 21h AH=08`，只收 `1` 或 `2` |
| 字元路徑 `Enter` | 夕陽故事畫面的續行；由 `int16-AH00-stdin` 讀走 |
| BIOS `Return` | 標題清鍵後的新鍵續行；runtime caller `0AD0:0104` |
| MCB 鏈同步 | 原版沿鏈釋放記憶體、沿鏈算可用量（`dosgolem/docs/spec/012`）|
| handle 號碼重用 | 號碼爬到 20 之後 MSC 的低階 I/O 表放不下（`spec/013`）|
| 硬體鍵盤 IRQ1 ＋ 埠 `0x60` | 主選單自己裝 IRQ1 處理常式，不從 BIOS 讀鍵（`spec/014`）|
| EGA 圖形控制器 | 少了 latch，畫面是有規律的直線雜訊（`spec/011` §4）|

## 3. 已作廢的指令數配方

```sh
DOSGOLEM_ORIG=~/cht/softworld_san/org_game tools/go.sh run ./cmd/probe \
  -exe "/orig/三國演義/AA.EXE" -root "/orig/三國演義" \
  -steps 3000000000 -keys '122' \
  -keys-at '250000000:\r,900000000:1,1500000000:1' \
  -dump-ega '640x408=out.png'
```

上列只保留為舊研究的可追溯記錄，**不得再用於回歸或正式對拍**。現行入口
是 `internal/parity/boot_behavior_oracle_test.go` 與
`docs/spec/015-behavior-triggered-oracle-boot.md`。

⚠ **那幾個指令數是量出來的不是算出來的**，而且會隨執行器的改動而變。
按鍵早送一步就會被前一個畫面吃掉，晚送則是多跑幾億道指令而已——
所以寧可晚不要早。要當回歸測試用的話，觸發條件該換成程式行為
（例如某個畫面畫完），不是指令數。

另一個坑：字元佇列的頭被一個程式不要的鍵卡住時，**後面的鍵全部進不去**
（`int 16h AH=01` 只看不取）。多餘的鍵不是無害的。

## 3.1 進到遊戲的完整順序

配方走到君主選擇之後還有三個提示，而**它們讀掃描碼不讀字元佇列**：

| 步驟 | 送什麼 | 之後的畫面 |
|---|---|---|
| 請問有幾人玩(0-16) | `0` ＋ Enter | 「電腦自動示範模式」|
| （確認）| 任一鍵 | 「請設定難度(1-10)」|
| 請設定難度(1-10) | `5` ＋ Enter | **全畫面重繪，遊戲開始** |
| 請輸入密碼(-寅-) | ？ | **卡在這裡**（§3.3）|

⚠ **兩條輸入路徑要分開用。** 裝置三題走 `int 21h` 讀 handle 0；
主選單與上面這三個提示自己裝 IRQ1 讀埠 0x60。一律用「兩條一起餵」的
話，主選單沒取走的字元副本會留在佇列裡，把後面 `int 21h` 的讀取堵死
——按了沒反應，而那不是錯誤。

`oracle` 這一側的對應是 `Type`（字元）／`PressScan`（掃描碼）／
`Drain`（清掉殘留）。

## 3.2 判準用畫面不用盤面

選君主、設難度都不會動到三張表。拿盤面當「輸入被收下了沒」的判準，
每一種送法都會報「沒反應」——而那是**量錯了**，不是每一種都不對。

畫面要用 `IndexedEGA(640, 408)` 解平面（`docs/spec/006`），而且**色盤用 EGA 的十六色**：
`Palette()` 是 VGA 的 DAC，在這個模式下全黑，存出來的圖整張黑，
看起來像畫面沒東西而不像色盤取錯。

按鍵之間要留沉澱時間：上一個畫面剛動不代表下一個提示畫完了。

## 3.3 載入舊進度路徑的行為觸發勘誤

**舊結論（已推翻）**：本節先前記成「載入舊進度直接進主畫面，不問
密碼；第一道帶 ＊ 的命令之後才問」。該結論來自用固定指令預算送鍵：
`bootToMain` 在真正主命令停點之後仍盲跑約二十億道指令並消耗後續輸入，
因此把兩個時間點錯接成因果。

**新證據**（`L1`、`[base]`）：`docs/spec/015` 的行為探針在每個原版輸入
callsite 停下。載入第 1 格後，先出現畫面文字「請輸入密碼」與範圍
0..9999 的數字輸入（caller `03EB:02C2`），接著是 Y/N 確認
（caller `03EB:02DE`）、玩家選擇（caller `1538:2EB8`），最後才是主命令
（caller `1538:236B`）。在第一個主命令執行「內政 → 休息 → Y」後，原版
直接到下一次 `1538:236B`，沒有第二次密碼輸入。

| 路 | 主選單 | 結果 |
|---|---|---|
| 開新遊戲 | `1` | 走到 `請輸入密碼(-寅-)` 就過不去 |
| **載入舊進度** | `2` | 存檔槽 → 畫面所示密碼／確認 → 玩家選擇 → 主畫面 |

新遊戲那條會問防拷密碼。密碼表在說明書 044／045 兩面，**採防影印彩色
網點印刷，四位數密碼在掃描中完全無法判讀**
（`docs/reference/01-manual-00-index`），所以那條走不了。

兩份 bundle 的 `DATA2` 裡都帶著存檔槽（`BASEMAS.SV1`–`SV6` 等）；
載入路徑的精確輸入狀態機如下。

### 載入舊進度的完整順序

```
122          裝置三題（int 21h）
\r           夕陽故事續行（字元路徑）
Return       標題清鍵後續行（BIOS 佇列）
2            主選單「載入舊進度」
1            存檔槽
1  \r        畫面所示密碼輸入
Y            確認
1  \r        玩家選擇
→ 遊戲主畫面：十個命令、「新莊主主公,請對(41)南海下您的命令:」
```

⚠ **那幾個鍵之間要等畫面動過再送下一個**，不要照指令數排（§3.2）。

### 密碼關時間點的舊解釋已作廢

舊探針確實擷取到兩張人物圖、一個地支、四個 `?` 與
`請輸入密碼(-寅-)`，但「它在第一道帶 ＊ 的命令之後才出現」已被上述
行為時間軸推翻。畫面本身與「輸入可通過」的實驗仍有效；失效的是固定
預算對它所作的時間歸因。

| 送什麼 | 結果 |
|---|---|
| 載入第 1 格後到 `03EB:02C2` | 密碼畫面已出現 |
| `1`＋Enter → `03EB:02DE` → `Y` | 進玩家選擇，再進第一個主命令 |
| 第一個主命令 `4` 內政 → `4` 休息 → `Y` | 直接進下一次主命令 |

掃描碼等待點由 runtime `1058:0E57` 的 bytes 與行為共同確認；正式 helper
只在該點送鍵。先前「掃描碼沒有反應、必須兩條一起餵」的觀測混入了錯誤
時間點與殘留字元佇列，不再作正式輸入契約。

### 這一關不擋東西：任何四位數都過得去

| 輸入 | 結果 |
|---|---|
| `1111` ＋ `Enter` ＋ `Y` | 畫面差 51,785 像素，**月份走到九月** |
| `0000` ＋ `Enter` ＋ `Y` | 同上，51,785 像素 |
| `4029` ＋ `Enter` ＋ `Y` | 同上，51,785 像素 |

三個輸入的結果一致，所以**「輸入之後畫面換掉」量不出「答對了」**。
說明書 p.44–45 的密碼表採防影印彩色網點、掃描中判讀不出來，
`AA.EXE` 裡也沒有以 packed BCD 或 16 位元小端連續存放的 1728 組表——
但對拍不需要那張表：隨便四位數就進得去。

**答錯也沒有延後的代價。** 從同一個快照用 `0000` 與 `4029` 各跑一段，
`0xA0000` 以下只差 4 個位元組，而且**全部是輸入本身**：

| 位址 | 長度 | 內容 |
|---|---|---|
| `0x000434`、`0x0417f4` | 各 2 | 輸入的數字，16 位元（`0x0fbd` ＝ 4029）|

先前的 60-byte 結論混入錯誤開機停點下的離螢幕字形緩衝差異；2026-09-13
以 `bootToPassword` 的行為停點重跑後已由上述 4-byte 收據取代。

**答案沒有被存到第三個地方**，所以沒有可以拿來延後懲罰的狀態。
這一條由 `internal/parity` 的 `TestPasswordAnswerDoesNotMatter` 釘住。

整局也驗過：用 `4029` 與 `0000` 各連走十六個月，每個月倒一份三張表，
**十八份逐位元組相同**。所以「沒有延後代價」不是從記憶體推的，是量的。

### 走存檔那條時盤面搜不到

三張表的內容是存檔的不是劇本檔的，所以拿劇本檔的位元組去搜會落空。
**那不代表沒載入**——位址是固定的 `0x399b0`（`docs/formats/03` §7），
退回去用它。

## 3.4 主畫面的輸入：鍵收得到，一個數字要跟著 Enter 才算數

進到主畫面之後停在 `新莊主主公,請對(41)南海下您的命令:`。
**鍵一路都到得了**，記憶體差分把整條路徑攤開來：按下 `9` 之後多動的
位址裡有三組看得懂的：

| 位址 | 值 | 那是什麼 |
|---|---|---|
| `0x000004` | `0x0a` | 掃描碼。遊戲自己的 IRQ1 常式存的（`docs/spec/014` 的 `mov es:[0004],al`）|
| `0x00b09c`／`0x00b09d` | `0x39`／`0x0a` | **字元 `'9'` 與它的掃描碼**——已經翻譯成 ASCII |
| `0x04e414`／`0x04e41e` | `0x39` | 同一個字元的其他副本 |

配套的數字：`KeyWaits` 0（沒有人讀 DOS／BIOS 那條）、還沒實作的服務無、
`IRQ1ToProgram` 18 → 20、佇列 2 → 0（被取走了）、**滑鼠被輪詢 0 次**
（主畫面不看滑鼠）。

所以「按了沒反應」不是輸入的問題，是**輸入還沒送出去**。說明書 p.5／p.17
講得很清楚：

- 十類指令用數字鍵 `0`–`9` 選，**先鍵入數字再按 `Enter`**
- 不輸入數字直接按 `Enter` ＝ 結束該郡的指令
- 換頁用空白鍵

裸送一個數字只會讓它停在輸入欄裡等 `Enter`。量到的（扣掉游標雜訊之後）：

| 送什麼 | 畫面差 | 意思 |
|---|---|---|
| 什麼都不送 | **0** | 雜訊扣乾淨了，這個判準可以用 |
| `Enter` | 0 | 主提示上單獨一個 `Enter` 沒有作用 |
| `9` ＋ `Enter` | **1912** | 「其他」子選單打開了 |

主提示要的是**一個數字加 `Enter`**。手冊 p.5 的「不輸入數字直接按
`Enter` 結束該指令」講的是子提示，不是這一層。

要把一個郡的指令用掉又不動盤面，最便宜的是 `4` 內政 → `4` 休息
（「不做任何事」，而且帶 ＊「使用後即轉移控制權」，手冊 p.42）。

### 判準：畫面差要先扣掉游標閃爍

主畫面上回顯一個字大約動兩百多個像素，**與游標閃爍同一個量級**。
拿「畫面差幾個像素」當「按了有沒有反應」的判準時，門檻訂在雜訊之上
就會把回顯一起濾掉——每一種送法都會被判成沒反應，而那是量錯了。

執行器是決定性的，所以雜訊可以扣乾淨：從同一個快照跑同樣的指令數，
游標的相位一模一樣。做法是先跑幾輪什麼都不按、把會自己變的像素標成
遮罩，之後只數遮罩外面的差異；對照組扣完應該剛好是零。

⚠ 這一條與「送鍵的方式」無關。三個數字（佇列被取走、`IRQ1ToProgram`
增加、記憶體裡出現翻譯後的字元）都正常之後，繼續換送法是在問一個已經
回答過的問題。

## 5. 打開的檔案

到君主選擇為止共 18 次開檔（handle 會重用，所以數字不是同時開著的數量）：

```
DATA0.GRP
DATA1.IDX  DATA1.NAM  DATA1.GRP ×2
DATA5.GRP
DATA1.IDX  DATA1.NAM              ← 主程式重開一次
DATA2.IDX  DATA2.NAM
DATA3.IDX  DATA3.NAM
DATA1.GRP ×2  DATA2.GRP ×2  DATA3.GRP ×2
```

三組容器的開法都是 `fopen(name,"rb")` → `fclose` → `fopen(name,"r+b")`，
第二次要的是**讀寫**。主程式的資料段有一張檔名表，第二組帶 `B:` 前綴
（`B:DATA3.GRP`），那是雙磁碟機安裝的路徑。
