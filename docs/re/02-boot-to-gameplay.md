# 02：原版從開機走到遊戲設定

`L1`（可重現的執行）。素材是 `org_game/三國演義`（base），執行器是
`dosgolem-san` 分支 `san1-msc-oracle`。

## 1. 開機鏈

三層，每一層都是完整的 MSC 程式（自己縮 PSP 區塊、自己起 far heap、
自己跑啟動碼）：

```
AA.EXE (354,960)
  └ 自解壓後把一段 stub 搬到 9FE4:0000，從那裡發出 int 21h AH=4Bh AL=03
      └ DaTa0.gRp (42,488)   載到 0110:0000，重定位加數 0110
          （檔名大小寫混雜是 overlay 載入器的寫法，不是筆誤）
          └ DaTa5.gRp (145,378)  同樣載到 0110:0000，蓋掉上一層
```

`DATA5.GRP` **是主程式不是資料容器**。`10.BAT`／`20.BAT` 做的是
`DEL DATA5.GRP` ＋ `COPY 10.GRP DATA5.GRP`，而 `10.GRP` 與出貨的
`DATA5.GRP` 逐位元組相同。

## 2. 走到遊戲設定要的東西

按時間順序：

| 什麼 | 為什麼 |
|---|---|
| 三個裝置選項的按鍵 `1`／`2`／`2` | `int 21h AH=08`，只收 `1` 或 `2` |
| 一個 `Enter` | 開場動畫的續行 |
| MCB 鏈同步 | 原版沿鏈釋放記憶體、沿鏈算可用量（`dosgolem/docs/spec/012`）|
| handle 號碼重用 | 號碼爬到 20 之後 MSC 的低階 I/O 表放不下（`spec/013`）|
| 硬體鍵盤 IRQ1 ＋ 埠 `0x60` | 主選單自己裝 IRQ1 處理常式，不從 BIOS 讀鍵（`spec/014`）|
| EGA 圖形控制器 | 少了 latch，畫面是有規律的直線雜訊（`spec/011` §4）|

## 3. 目前的操作配方

```sh
DOSGOLEM_ORIG=~/cht/softworld_san/org_game tools/go.sh run ./cmd/probe \
  -exe "/orig/三國演義/AA.EXE" -root "/orig/三國演義" \
  -steps 3000000000 -keys '122' \
  -keys-at '250000000:\r,900000000:1,1500000000:1' \
  -dump-ega '640x350=out.png'
```

⚠ **那幾個指令數是量出來的不是算出來的**，而且會隨執行器的改動而變。
按鍵早送一步就會被前一個畫面吃掉，晚送則是多跑幾億道指令而已——
所以寧可晚不要早。要當回歸測試用的話，觸發條件該換成程式行為
（例如某個畫面畫完），不是指令數。

另一個坑：字元佇列的頭被一個程式不要的鍵卡住時，**後面的鍵全部進不去**
（`int 16h AH=01` 只看不取）。多餘的鍵不是無害的。

## 3.1 進到遊戲的完整順序

配方走到君主選擇之後還有三個提示，而**它們讀掃描碼不讀字元佇列**：

| 步驟 | 送什麼 | 之後的畫面 |
|---|---|---|
| 請問有幾人玩(0-16) | `0` ＋ Enter | 「電腦自動示範模式」|
| （確認）| 任一鍵 | 「請設定難度(1-10)」|
| 請設定難度(1-10) | `5` ＋ Enter | **全畫面重繪，遊戲開始** |
| 請輸入密碼(-寅-) | ？ | **卡在這裡**（§3.3）|

⚠ **兩條輸入路徑要分開用。** 裝置三題走 `int 21h` 讀 handle 0；
主選單與上面這三個提示自己裝 IRQ1 讀埠 0x60。一律用「兩條一起餵」的
話，主選單沒取走的字元副本會留在佇列裡，把後面 `int 21h` 的讀取堵死
——按了沒反應，而那不是錯誤。

`oracle` 這一側的對應是 `Type`（字元）／`PressScan`（掃描碼）／
`Drain`（清掉殘留）。

## 3.2 判準用畫面不用盤面

選君主、設難度都不會動到三張表。拿盤面當「輸入被收下了沒」的判準，
每一種送法都會報「沒反應」——而那是**量錯了**，不是每一種都不對。

畫面要用 `IndexedEGA(640, 350)` 解平面，而且**色盤用 EGA 的十六色**：
`Palette()` 是 VGA 的 DAC，在這個模式下全黑，存出來的圖整張黑，
看起來像畫面沒東西而不像色盤取錯。

按鍵之間要留沉澱時間：上一個畫面剛動不代表下一個提示畫完了。

## 3.3 兩條進遊戲的路，只有一條走得通

| 路 | 主選單 | 結果 |
|---|---|---|
| 開新遊戲 | `1` | 走到 `請輸入密碼(-寅-)` 就過不去 |
| **載入舊進度** | `2` | **直接進主畫面，不問密碼** |

新遊戲那條會問防拷密碼。密碼表在說明書 044／045 兩面，**採防影印彩色
網點印刷，四位數密碼在掃描中完全無法判讀**
（`docs/reference/01-manual-00-index`），所以那條走不了。

載入舊進度那條不問。兩份 bundle 的 `DATA2` 裡都帶著存檔槽
（`BASEMAS.SV1`–`SV6` 等），從那裡進去就是遊戲主畫面。

### 載入舊進度的完整順序

```
122          裝置三題（int 21h）
\r           開場續行
2            主選單「載入舊進度」
1            劇本／存檔槽
1  \r        選存檔
\r
5  \r        難度
\r  \r       續行
→ 遊戲主畫面：十個命令、「新莊主主公,請對(41)南海下您的命令:」
```

⚠ **那幾個鍵之間要等畫面動過再送下一個**，不要照指令數排（§3.2）。

### 走存檔那條時盤面搜不到

三張表的內容是存檔的不是劇本檔的，所以拿劇本檔的位元組去搜會落空。
**那不代表沒載入**——位址是固定的 `0x399b0`（`docs/formats/03` §7），
退回去用它。

## 3.4 主畫面的輸入路徑還沒解

進到主畫面之後停在 `新莊主主公,請對(41)南海下您的命令:`，
而**六種送法都送不進去**（同一個快照展開，每一種跑四億道指令）：

| 送法 | 畫面差 | 盤面差 |
|---|---|---|
| 什麼都不送（對照組）| 224 | 0 |
| 清空後 `PressScan("9")` | 271 | 0 |
| `Type("9")` | 224 | 0 |
| 清空後 `Type("9")` | 244 | 0 |
| `Press("9")` | 316 | 0 |

**對照組就有 224 個像素在動**——那是游標閃爍。全部落在同一個量級裡，
所以不是「哪一種比較好」，是**沒有一種被收下**。

前面幾個提示（幾人玩、難度）走掃描碼，主畫面顯然不是同一條路。
繼續換鍵試沒有意義，下一步是**反組譯主畫面的輸入常式**——
`AA.EXE` 的 `.i64` 已經建好（`workplace/ida/`），主迴圈在
`docs/re/03` §6。

## 5. 打開的檔案

到君主選擇為止共 18 次開檔（handle 會重用，所以數字不是同時開著的數量）：

```
DATA0.GRP
DATA1.IDX  DATA1.NAM  DATA1.GRP ×2
DATA5.GRP
DATA1.IDX  DATA1.NAM              ← 主程式重開一次
DATA2.IDX  DATA2.NAM
DATA3.IDX  DATA3.NAM
DATA1.GRP ×2  DATA2.GRP ×2  DATA3.GRP ×2
```

三組容器的開法都是 `fopen(name,"rb")` → `fclose` → `fopen(name,"r+b")`，
第二次要的是**讀寫**。主程式的資料段有一張檔名表，第二組帶 `B:` 前綴
（`B:DATA3.GRP`），那是雙磁碟機安裝的路徑。
