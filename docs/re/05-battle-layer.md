# 戰術層的程式碼與資料（`AA.EXE`）

推論等級與版本標在每一節。位址是**執行期線性位址**，取自開機之後
`0x00b000`–`0x050000` 的碼段 dump；資料段（DGROUP）在 `0x0427e0`，
所以 `DS:xxxx` 的線性位址是 `0x0427e0 + xxxx`。

兩份 dump 由 `internal/parity` 的 `TestZZDumpCode` 與
`TestZZDumpBattleCode` 產生，寫到 `SAN1_DUMP` 指的目錄。

本章使用的原版 `AA.EXE` SHA-256 是
`474780e5be697b3b4899da5e0dbadd2f327e0bbe7e56306ac3b732a15fc124ca`；
碼段 dump 是
`4d9142055ce3b86fa87c9517b1de163f577b19f13ab20d145fa6772838d7e5a5`，
DGROUP dump 是
`e8e8156d7821020ab2d63c64ae3f2bb746396d070f5c542ea556c375ab68f018`。
§12 的函式邊界與控制流以 IDA Pro 9.4（容器映像
`ida-pro-9.4-idapython:locked-v1`）重解；位址仍採本章開頭定義的執行期
線性位址，不與 IDA 載入位址或檔案位移混寫。

⚠ **objdump 印的近呼叫目標在跨 `0x10000` 時會繞回**：那是 16 位元
位移的正確語意，但 objdump 是對整個檔案線性算的，所以
`0x2fc55: e8 80 05` 印成 `call 0x201d8`，實際目標是 `0x301d8`。
看到不合理的目標就自己加一次 `0x10000`。

## 1. 入口與盤面（`L0`、`[base]`）

戰鬥是一支普通的遠呼叫，**不是 overlay**：

```
2020:0000 ＝ 線性 0x20200
battle(攻方郡, 攻方援郡, 守方郡, 守方援郡)
```

玩家的「發動戰役」在 `0x18bb9` 呼叫它，兩個援軍格填 `0xFFFF`
（`docs/re/03` §1.5）。四個參數是**兩郡對兩郡**：進去第一件事就是掃
1..42，把不在這四格裡的郡交給 `es:[0x20ea]` 處理掉（`0x2021e`）。

主戰場是 `0x2053c`。它開頭做三件事：

```
20588: es:[0x1bf8] ← 守方郡                ; 戰場設在守方
20593: for 列 = 0..9, 欄 = 0..11:
         es:[0x163a + 列×12 + 欄] ← 州郡[守方郡].[0x4b7 + 列×12 + 欄]
205fd: 0x20770(攻方郡,   2)                ; 四個軍團依序編成
2060b: 0x20770(攻方援郡, 3)
20618: 0x20770(守方郡,   0)
20626: 0x20770(守方援郡, 1)
```

`0x4b7` 減掉州郡表的基底 `0x480` 是 **55**，所以那 120 個位元組就是
州郡記錄 offset 55–174（`docs/spec/003` §3.3）。陣營碼 0、1 是守方，
2、3 是攻方。

## 2. 戰場地圖（`L0`、`[base]`）

### 2.1 版面

12 欄 × 10 列，索引 `列 × 12 + 欄`。畫格的座標在 `0x22742`：

```
x ＝ 48 × 欄 + 56
y ＝ 32 × 列 + 36        ; 奇數欄再 +16
```

**奇數欄往下移半格**，也就是六角格的 odd-q 排法。走訪鄰格用
`DS:0x7c6a`（dx）與 `DS:0x7c82`（dy）兩張表，索引
`(欄的奇偶 × 6 ＋ 方向) × 2`（`0x24c11`）：

| 方向鍵 | 4 | 5 | 6 | 1 | 2 | 3 |
|---|---|---|---|---|---|---|
| dx | −1 | 0 | +1 | −1 | 0 | +1 |
| dy（偶數欄）| −1 | −1 | −1 | 0 | +1 | 0 |
| dy（奇數欄）| 0 | −1 | 0 | +1 | +1 | +1 |

畫面上的鍵盤配置就是 `4 5 6` 在上、`1 2 3` 在下（`DS:0x7f9e`）。

劇本 001 的 42 個郡只有兩種形狀：**12 欄 × 7 列**（21 個郡，最後一列
只有偶數欄）與 **8 欄 × 10 列**（21 個）。兩種都塞得進 640×408。

### 2.2 一格是兩個半位元組

```
低四位 = 地形     高四位 = 標記     0xFF = 圖外
```

畫的時候低四位當底圖的圖塊編號直接畫（`0x2277b`，大於 10 就不畫），
高四位小於 10 的再疊一層：拿它去索引州郡記錄 `0x4ad`（＝ offset 45，
相鄰表），把那個鄰郡的名字印在格子上（`0x227b8`）。

| 高四位 | 意思 |
|---|---|
| 0–9 | 通往相鄰表第 n 格那個郡的通道 |
| 10 | 城池 |
| 11–14 | 四個軍團的起點，對應 `0x20770` 的陣營碼 0–3 |
| 15 | 沒有標記 |

**一個通道是一片格子不是一格**：遼東通往鄰郡的通道佔五格。
標記 10–14 則是每張圖各一格，42 個郡都成立。

### 2.3 地形碼

| 碼 | 地形 | 移動力（`DS:0x7c42`）| 攻（`DS:0x85c2`）| 守（`DS:0x85e2`）|
|---|---|---|---|---|
| 1 | 大山 | 999（過不去）| 0 | 0 |
| 2 | 山丘 | 3 | 20 | 22 |
| 3 | 淺水 | 4 | 8 | 9 |
| 4 | 深水 | 6 | 6 | 8 |
| 5 | 城池 | 3 | 27 | 40 |
| 6 | 關寨 | 3 | 25 | 30 |
| 7 | 平原 | 2 | 20 | 17 |
| 8 | 樹林 | 3 | 16 | 22 |
| 9 | 沙漠 | 2 | 15 | 16 |

移動力那一欄與**說明書 p.29 的表逐格相同**，兩份互為佐證。
對照是這樣定下來的：

- 碼 1 在 `0x24895` 被單獨挑出來當成走不進去（與圖外同值），
  而說明書只有大山「無法穿越」。
- 碼 5 在每一張圖上剛好出現一次，位置就是標記 10 那一格 → 城池。
- 剩下七個碼的移動力互不相同或成對，把手冊那張表套上去只有一種排法
  對得起來（2/2 ＝ 平原沙漠，3/3/3 ＝ 山丘樹林城寨，4 ＝ 淺水，6 ＝ 深水）。
- 平原與沙漠都是 2，用出現次數分：碼 7 有 777 格遍佈 42 個郡，
  碼 9 只有 10 格而且**全部在武威**——河西走廊的郡。
- 山丘與樹林都是 3，用攻守表分：碼 8 的攻 16 低於平原、守 22 高於平原，
  正是「相當不錯的防禦掩護」；碼 2 兩邊都不低於平原。

**第三條證據是原版自己畫出來的顏色。** 把原版驅動進廬陵的戰場、
照解出來的座標取每一格中心 32×22 像素的顏色（扣掉配色用的黑），
主色的分佈是：

| 碼 | 地形 | 主色 |
|---|---|---|
| 1 | 大山 | 亮紅 32%、褐 24%、暗紅 20%、**白 11%**（雪頂）|
| 2 | 山丘 | 亮紅 43%、暗灰 30%、黃 9%（**沒有白**）|
| 3 | 淺水 | 亮藍 60%、青 39% |
| 4 | 深水 | 暗藍 60%、青 39% |
| 7 | 平原 | 綠 44%、亮綠 36%、黃 10% |
| 8 | 樹林 | 暗灰 30%、黃 17%、**綠 15% ＋ 亮綠 14%**（樹冠）|

大山有雪頂而山丘沒有、樹林有樹冠而山丘沒有、深水比淺水暗——
三對都分得開，而且與前兩條證據指向同一個排法。

`DS:0x80d4` 是另一張依地形索引的布林表。執行期讀出來是
`[0 0 1 1 1 0 0 1 1 1]`（地形碼 0–9，`L1`、`TestArcheryTargetScan`）——
`1 大山`、`5 城池`、`6 關寨`是 0，其餘是 1，也就是**開闊地與構造物的
分界**。

用途是**戰術層的目標篩選**（`L0`）。兩個使用處 `0x28a5d` 與 `0x2999a`
是同一個形狀：先看那一格的佔位不是 `0xFFFF`、佔位除以 20 與自己不同
陣營，**再拿地形碼查這張表，是 0 就跳過**。所以站在大山、城池或關寨
上的部隊不會被那兩支選成目標。

攻守那兩張表在 `0x2df44`／`0x2df8d` 分別用**攻方所在格**與**守方所在格**
取值，參與每一位將領的戰力值（§3.1）。

### 2.4 走一格要花多少

取 `DS:0x7c42` 那一格的值，直接跟部隊剩下的移動力比
（`0x27e71`，部隊記錄 offset 36），**中間沒有任何按兵種的調整**。
說明書 p.30 的「移動力來源是訓練度和兵種能否適應地形」講的是
移動力本身（§3.2）與兵種在戰力上的加成（§3.1），不是每一格的花費。

### 2.5 部隊標記怎麼畫（`0x21b40`，`L0`、`[base]`）

`0x21b40` 是「重畫一支部隊」，兩個參數：軍力（0–3）與隊伍（0–4）。
二十四個呼叫端全走它。

```
BX ＝ (軍力×10 + 隊伍) × 42        ; 部隊記錄
if es:[0x3502+BX] == 0xFFFF        ; 沒有這支部隊
    重畫該格地形（0x23a6:0x0c2e），回 0xFFFF
x  ＝ 48 × es:[0x3518+BX] + 56     ; 欄
y  ＝ 32 × es:[0x351a+BX] + 36     ; 列；奇數欄再 +16
畫 20 + 軍力×6 + 隊伍 號圖，位置 (x+8, y)
兵力牌：sprintf("%5d", es:[0x3520+BX]) 畫在 (x+8, y+15)，
        字色 DS:[0x796a + 軍力×2] ＝ 10、11、12、13
```

旗幟在載入端（`0x11636`）就是同一個式子：`WFLAG%s%c.IMG`，`%s` 取
`DS:0x5da2` 的四筆組名 `D0`／`D1`／`A0`／`A1`，`%c` 是 `'0'+n`
（n 走 0–5），載進槽號 `20 + 組×6 + n`。

**`D` 是守、`A` 是攻，四組的順序就是行動順序**（主守、助守、主攻、
助攻）。判準在紮完寨的基準畫面上：四面綠旗（`D0`）的兵力牌合計 7900，
等於面板上「周瑜軍　主守軍　四軍 4將　兵 7900」；另一個標記 3000 等於
「陳就軍　主攻軍　一軍 1將」，用的是 `A0`。

每組六張，0–4 的旗面上印**帥、先、左、右、後**（字模逐像素讀出來），
即中軍、先鋒、左軍、右軍、後軍——與紮營順序相同（說明書 p.28）。
第六張（n ＝ 5）是 16×15 的城門圖示，**載進去但原版不畫**（`L0`＋`L1`，
Issue #32）：

- 主程式裡算 `20 ＋ 軍力×6 ＋ 隊伍` 的只有 `0x21c06`（這一支），畫圖常式
  `0x36c9:0x426`（線性 `0x370b6`）的其餘 57 個呼叫端槽號都是常數或別的
  式子（天候圖示 `0x2196f` 是 `0xed ＋ 天候`）。
- 隊伍永遠是 0–4：整編、日循環（`0x23c1c` 的順序表 5 格）、重算
  `0x2514c`（`0x252fb` `cmp $5`）與招降加入 `0x25cd2`（`0x25d8c` `cmp $5`）
  的迴圈全到 5 為止，佔位圖 `es:0x2532` 存的也是這些記錄的編號，二十六個
  呼叫端拿到的隊伍不是迴圈變數就是這些值。
- 實跑正對照（`TestZZCityGateIconNeverDrawn`）：盤面丁打一場含對戰子畫面，
  載圖常式攔到 `WFLAGD05`／`D15`／`A05`／`A15` 分別進槽 25／31／37／43，
  畫圖常式攔到的槽有 20–24、32、36（旗）與子畫面的 48–55，四個城門槽
  0 次。

remake 不畫它，`VERIFICATION-MATRIX.md` §2.5 記為「原版不畫」。

**選到的部隊會閃**：呼叫端把反白旗標打開、畫一次、關掉、再畫一次
（`0x275b9`–`0x275ec`；旗標由 `es:[0x2e78]` 的間接呼叫切換，
參數 1 開、0 關）。反白 ＝ **每一格顏色取補數**（`^15`）：基準畫面停在
亮的那一格，陳就的中軍與 `WFLAGA00` 取補數後 360 格逐格相同。

## 3. 戰力與移動力（`L0`、`[base]`）

`0x2deb0(攻方軍團, 攻方部隊, 守方軍團, 守方部隊)` 是**對戰的前置**：
它對雙方每一位將領各算兩個值，再把畫面交給 `2020:1616`。

### 3.1 一位將領的戰力值

```
0x2e13a 攻方 / 0x2e01a 守方（兩段對稱）
  fild  人物.offset 10（戰力）
  fmul  7.0                       ; DS:0xa9fc
  fiadd 3 × 人物.offset 25（武裝度）
  fimul 兵種適性[人物.offset 21][地形] + 地形值
  fmul  0.001                     ; DS:0xaa04
  lcall 05c4:4d60                 ; 轉成整數
  → es:[將領槽 × 2 + 0x55c]（攻方）／`0x548`（守方）
```

也就是

```
戰力值 ＝ (戰力 × 7 + 3 × 武裝度) × (兵種適性 + 地形值) ÷ 1000
```

地形值攻方取 `DS:0x85c2`、守方取 `DS:0x85e2`，兩邊各用**自己所在
那一格**的地形。**兵種適性表在 `DS:0x8602`**，七個兵種各 16 格：

| 兵種 | 山丘 | 淺水 | 深水 | 城池 | 關寨 | 平原 | 樹林 | 沙漠 |
|---|---|---|---|---|---|---|---|---|
| 陸 | | | | | | 5 | 5 | |
| 山 | 10 | | | | | | | |
| 水 | | 10 | 10 | | | | | |
| 山陸 | 10 | | | | | 5 | 5 | |
| 水陸 | | 10 | 10 | | | 5 | 5 | |
| 山水 | 10 | 10 | 10 | | | | | |
| 強力 | 12 | 13 | 15 | 8 | 8 | 6 | 6 | 5 |

正好是說明書 p.18 那句話的數字版：「山、陸、水各代表在山丘、平地
或水域有優良戰力」，而「強力軍是萬能兵種……也更能發揮地形特性」
——強力軍每一種地形都有，水上還高過水軍。大山誰都沒有加成。

### 3.2 兩個「移動力」

**對戰子畫面裡單一將領的值**，同一支常式接著算（`0x2e07a`）：

```
min(15, (訓練度 − 武裝度 + 100) ÷ 10 + 1)
```

上限 15 寫死在 `0x2e08f`。範圍 1–15。

**部隊在 12×10 的戰場上一天能走多遠**是另一支（`0x27114`–`0x271dc`），
寫進部隊記錄 offset 34。它走十個將領槽，空的（`0xFFFF`）跳過：

```
每一位：值 ＝ ftol((訓練度 × 0.75 + 武裝度 ÷ 4) × 兵力 × 0.01 + 0.5)
        分母累加兵力
Σ兵力 ≤ 0 → offset 34 ＝ 2                          ; 0x271f9
否則        offset 34 ＝ ftol(Σ值 ÷ Σ兵力 × 10 + 0.5) + 2
接著        offset 36 ← offset 34                    ; 0x27200
```

四個常數是資料段裡的 double：`DS:0xa8fc` ＝ 0.75、`DS:0xa8d2` ＝ 0.01、
`DS:0xa8ec` ＝ 0.5、`DS:0xa904` ＝ 10.0。**武裝度在這條裡是加分**
（`0x2716c` 是 `fiadds`，係數 ¼），與說明書 p.30「全副武裝將稍減移動力」
相反——以碼為準。訓練與武裝都拉滿也只到 12，所以沒有上限，只有下限 2。

⚠ **兩個累計器都是 16 位元**（`add %ax,-0x2(%bp)`／`-0x6(%bp)`），
分母又走 `fidivs`（整數除數）：十位將領的兵加起來超過 32767 會繞回去。

量到的三組（`TestBattleUnitsMatchTheOriginal`）：訓 97／武裝 97 的部隊
是 12、訓 50／武裝 50 是 7、訓 80／武裝 80 是 10，逐支相同。

**每一支回合結束時回填，不是重設**（`0x24ee1`–`0x24f0d`，在回合常式
`0x24cf6` 的尾巴，§12.3）：

```
ax ← offset 34（上限）
cmp offset 36, ax；jge 跳過        ; 剩下的 >= 上限就不動它
offset 36 ← ax                     ; 否則補到上限
```

也就是 `offset 36 ← max(offset 36, 上限)`。紮完寨量到上限 12、剩下 14
（休息 +2），連走七天還是 14——**多出來的不會被砍掉**。

**上限整場只算一次**：日循環跑了七天，`0x24ee1` 每天每支各一次
（五支就是 ×5），而算上限的 `0x27114` 一次都沒再跑。傷亡讓兵力變少
不會讓部隊變慢。

**休息是 +2 夾在 15**（`0x27c00`，命令 0 的處理常式）：

```
addw $2, es:[bx+0x3526]            ; 剩下的移動力 += 2
cmpw $0xf, es:[bx+0x3526]；jle 跳過
movw $0xf, es:[bx+0x3526]          ; 夾在 15
```

說明書 p.29、p.30 只給了那個 2，**上限 15 是碼裡才有的**。

所以連休七天的部隊會停在 15，即使它的上限只有 7：
量到的五支是 14→15、9→11→13→15、10→12→14→15，逐日相同
（`TestBattleUnitsMatchTheOriginal`，七天五支五十個欄位全中）。
`0x24ee1` 的回填在這個情境下永遠不動手——它是**下限**不是上限。

### 3.3 記錄的欄位

**軍團記錄 22 bytes**，四個，基底 `es:[0x175e]`（工作區的段）：

| 位移 | 欄位 |
|---|---|
| 0 | 統帥的人物槽號 |
| 6 | 隨軍的金 |
| 8 | 隨軍的米 |
| 10 | 部隊數 |
| 12 | 將領人數 |
| 14 | **兵士（百）＝ 該軍團五支部隊的兵士數合計 ÷ 100** |
| 16 | 勢力 |
| 18 | 出兵的郡 |
| 20 | 陣營碼（0、1 守方；2、3 攻方）|

10／12／14 三個一起算（`0x252e1`–`0x2533f`）：走完五支部隊，
兵士數用 32 位元累加再 `÷ 100`（`5c4:37cc` 是 MSC 的長除法）。

未解：2、4。

**部隊記錄 42 bytes**，每個軍團 5 個（陣列跨距 10），基底 `es:[0x3502]`：

| 位移 | 欄位 |
|---|---|
| 0–19 | 十個將領的人物槽號，`0xFFFF` ＝ 空 |
| 22 | 欄（x）|
| 24 | 列（y）|
| 26 | 中陷阱之後不能動的天數（§4.3）|
| 28 | 將領人數 |
| 30 | 兵士數 |
| 32 | 綜合能力：整編寫 Σ(謀略×2÷5 ＋ 戰力×3÷5) ÷ 將領人數；之後每天輪到之前重算成兵數加權的武裝／訓練／戰力（§12.3）|
| 34 | 一天的移動力上限（§3.2，整場只算一次）|
| 36 | 這一天剩下的移動力；每支回合結束時回填成 `max(剩下的, 上限)`（§12.3）|
| 38 | 謀略最高那一位的人物槽號 |
| 40 | 每天減一（`0x26fa4`），誰讀它未解 |

offset 20 是弓箭剩餘次數（§4.2b）。格子索引是 `列 × 12 + 欄`（`0x2df20`、`0x27e91`）。

⚠ **offset 38 在整編那一支（`0x2099c`）被寫成謀略的「值」而不是槽號**，
另外兩個寫入端（`0x252dc`、`0x254e3`）寫的才是槽號，而兩個讀取端
（玩家 `0x28c28`、電腦 `0x297e6`）都當槽號用。整編剛結束時倒記憶體
量到的是值（周瑜 97、關羽 83、劉備 87、陳就 21），戰鬥開始之後會被
覆蓋成槽號。**對規則沒有影響**：兩條路最後問的都是「隊伍裡謀略最高
那一位的謀略」。

### 3.4 體能在對戰裡會消耗

`0x2deb0` 開場時把雙方每一位將領的體能（人物 offset 8）抄進工作陣列
`es:[0x2f80]`（守方）與 `es:[0x2f94]`（攻方），對戰結束時再寫回去
（`0x2e520`–`0x2e589`，兩邊各十格）。人物槽號的對照表在
`es:[0x1bc8]`／`es:[0x1bdc]`。

休息加回來（`0x2eafc`：戰力 ÷ 20 ＋ 1，不超過抄下的值）；`0x2ea5b`
拿體能跟 10 比，低於就不問人、自動休息。走一格扣 1、攻擊扣 5、被攻擊
扣 3（§10.2）。

### 3.5 一次交戰的傷亡（`0x30560`，`L0`）

雙方**同時**算，各自套到對方身上：

```
0x3059f: es:fild 人物[甲].offset 22（兵士數）
0x305a9: fimul  es:[bx+0x548]        ; 戰力值
0x305ae: fmul   0.01                 ; DS:0xaa3c
         → 甲的殺傷
（乙同一套，0x305f9–0x3060c）

0x30618: 乙剩下的兵 ＝ 乙的兵士數 − 甲的殺傷
0x306bb: 甲剩下的兵 ＝ 甲的兵士數 − 乙的殺傷
         結果 < 0 或 > 5000 → 歸 0
0x30716: 兵歸 0 → 印 DS:0x87b5「我們抓到%s」
```

也就是

```
殺傷 ＝ 兵士數 × 戰力值 ÷ 100
```

**不看對方的防禦力**——地形對守方的保護走的是守方自己那一份戰力值
（§3.1 用守方所在格的 `DS:0x85e2`），交手是對稱的，不是攻減防。
一位將領最多 5000 兵；兵打光的將領被俘（`1.斬首 2.囚禁 3.釋放 4.招降`）。

`es:[bx+0x548]` 的索引是 `(10 × 陣營 + 將領槽) × 2`，**陣營在這裡只有
兩格**：`es:0x3ef0`／`es:0x34fa` 是 `0 ＝ 守方、1 ＝ 攻方` 的兩格陣列
（`0x2dee9`–`0x2df04` 寫進去，`0x30567`／`0x3057a` 讀出來）。所以

```
守方第 n 位將領 → 0x548 + 2n
攻方第 n 位將領 → 0x548 + 20 + 2n ＝ 0x55c + 2n
```

正好接上 §3.1 那兩個寫入端——`0x548` 與 `0x55c` 本來就是同一個
二十個字的陣列。

### 3.6 交戰結算 `0x2a224`（`L0`，殘差未收斂）

主戰場的快戰、死戰、誘敵與圍攻走的是這一支；「對戰」（命令 `2`、
選項 7）進的是對戰子畫面（§10），子畫面裡的攻擊走 §3.5 的 `0x30560`。

參數（far call，`o.Arg(0..4)`）：甲軍力、甲隊伍、乙軍力、乙隊伍、模式。

```
0x2a3d4  甲的欄／列 ← 部隊記錄 offset 22／24
0x2a3fe  乙的欄／列 ← 同上
0x2a423  甲那格的地圖位元組 es:[0x163a + 甲列×12 + 甲欄]，取低四位
0x2a42e  filds  DS:0x8162[地形碼]      ; 攻值表
0x2a43a  fimuls 甲.部隊記錄 offset 30  ; 兵士數

0x2a47d  filds  DS:0x8182[地形碼]      ; 守值表
0x2a487  fimuls 乙的兵士數
0x2a48d  fimuls 乙的綜合能力
0x2a492  fmull  DS:0xa98e ＝ 1e-04     ; **這一邊不乘倍率**
0x2a498  ftol → 乙的殺傷

0x2a4a0  甲的兵士數 ≤ 0 → 比例取 DS:0xa996 ＝ 0.0
0x2a4d5  否則 filds 甲的兵士數；fidivrs 乙的殺傷
         → 甲的比例 ＝ 乙的殺傷 ÷ 甲的兵士數    ; 存 [bp-0xa]
0x2a4fe  乙那一邊同一套                          ; 存 [bp-0x32]

0x2a558  將領人數 ← 甲的部隊記錄 offset 28
0x2a578  **從第 9 格往第 0 格走**
0x2a59d    槽號 ← es:[(甲軍力×10+甲隊伍)×21 + 格]×2 + 0x3502
0x2a5a5    0xFFFF → 跳過
```

也就是


**傷亡是比例不是絕對值**，與火攻水淹（§4.2）同一個形狀。

三張表（都用地形碼索引）：

| 地形碼 | 2 山丘 | 3 淺水 | 4 深水 | 5 城池 | 6 關寨 | 7 平原 | 8 樹林 | 9 沙漠 |
|---|---|---|---|---|---|---|---|---|
| 攻 `DS:0x8162` | 30 | 15 | 10 | 40 | 30 | 25 | 20 | 20 |
| 守 `DS:0x8182` | 30 | 20 | 10 | 50 | 40 | 20 | 25 | 20 |

倍率 `DS:0x81a2` ＝ `[80, 100, 150, 200, 250, 300, 350, 400]`，
與 §4.2b 用的是同一張。

**量到的三次交戰**（`TestZZBattleDaySweep`，玩家走到守軍旁邊按 `2`）：

| 次 | 甲 | 乙 | 模式 | 甲的殺傷 | 乙的殺傷 | 乙的兵 | 甲的兵 |
|---|---|---|---|---|---|---|---|
| 1 | 2-0（樹林、3000、78）| 0-2（樹林、1500、66）| 8→1 | 468 | 247 | 1500→1031（算 1032）| 3000→2752（算 2753）|
| 2 | 0-1（山丘、1500、84）| 2-0（樹林、2752、78）| 2 | 567 | 536 | 2752→2184（算 2185）| 1500→962（算 964）|
| 3 | 0-2（樹林、1031、65）| 2-0（樹林、2184、78）| 2 | 201 | 425 | — | — |

**殘差是兩件事，都收斂了。**

第一件是那道 `dec`：先前把新兵直接當成 `ftol(兵 × (1 − 比例))`，
量到的四項裡三項少 1。

第二件是 **x87 的 80 位元尾數**。`1500 × (1 − 585/1500)` 數學上是 915；
用 `float64`（53 位元尾數）算會捨進成剛好 `915.0`——915 附近的間距是
1.1e-13，而誤差只有 2e-14，不到半格——`ftol` 得 915；用 64 位元尾數算
是 `914.99999999999998`，`ftol` 得 914。量到的原版是後者。
remake 這一層因此改用 `math/big` 指定 64 位元尾數。

`fidivrs` 算完的比例會 `fstpl` 存成 **double**，所以比例本身是
`float64`——那一步的捨入是原版就有的，不要一路用 80 位元帶下去。

**「每支部隊有兩位將領、各截一次尾」這個假說量過，不成立**：
五支部隊的將領人數全是 1。

`TestBattleUnitsMatchTheOriginal` 現在把兩次交戰的雙方兵力都比進去，
56 個欄位全中。

`battle.exchange` 照這一支寫。§3.1 的逐將領 `LeaderPower`
（`DS:0x85c2`／`DS:0x85e2`）是**對戰子畫面**（`0x30560`）用的，
與這裡是兩套東西：主戰場的交戰看的是**部隊的**綜合能力與另外兩張
地形表。remake 那一份留著給弓箭與自動作戰的估算用。

### 3.7 糧草（`0x25040`–`0x250c7`，`L0`）

每天走一次，兩件事分開：

```
0x25040  勝方已定 → 直接回
0x2504e  四個軍團各查一次：
0x25067    米（offset 8）> 0 → 跳過
0x25073    否則 call 0x25576(軍團編號)     ; 逃亡
0x2508a  天數 % 3 != 0 → 回
0x2509c  四個軍團各扣一次：
0x250ad    米 −= 軍團記錄 offset 14（兵士（百））
0x250b9    扣成負的歸 0
```

**三天扣一次不是每天**，而且**守方也扣**——迴圈四個軍團都走
（`0x2509c`：`cmpw $0x4`）。三十天下來只扣十次，所以實際耗用是
兵士（百）× 10，而出兵畫面印的「30日須耗用%d米」是兵士（百）× 30
——**原版報的是三倍**。

**逃亡是除不是減**（`0x25576`）：印「沒米了」（`DS:0x7d11`），
然後這個軍團五支部隊、每支十個將領槽，每一位

```
人物.兵士數 ÷= RND(2) + 2        ; 0x255ce–0x255f2
```

——剩一半或三分之一，**一次就少掉五成到六成七**。說明書 p.28 的
「士兵將會陸續逃亡」一點都不含蓄。

## 4. 計謀（`L0`、`[base]`）

**先問方向再問哪一計。** 命令 `6` 之後 `0x28af5` 讀一個鍵，
Enter 取消、不在 `'1'`–`'6'` 之間重問；`鍵 − '1'` 是**方向索引**，
`0x28d7a` 拿它查兩張各 12 格的位移表——`(欄 % 2) × 6 + 方向`——

| 方向鍵 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| 欄位移 `DS:0x7c6a` | −1 | 0 | 1 | −1 | 0 | 1 |
| 列位移 `DS:0x7c82`（偶數欄）| 0 | 1 | 0 | −1 | −1 | −1 |
| 列位移（奇數欄）| 1 | 1 | 1 | 0 | −1 | 0 |

——算出目標格。**那一格沒有敵人就直接回 `0xFFFF` 取消**，所以
**計謀只能對相鄰的六格用，沒有「隔空指定一格」這回事**。

過了位置那道門才出選單 `1.火攻 2.水渰 3.陷阱 4.誘敵 5.燒糧 6.圍攻`
（`DS:0x8113`）。三道門依序：

```
28bef: 費用表 DS:0x7f62[計謀] > 軍團的金（軍團記錄 offset 6）→ 不行
28c3e: 人物[部隊記錄 offset 38].謀略 < 門檻表 DS:0x7f6e[計謀] → 不行
28c67: 2a22:1cc8(..., 目標軍力, 目標隊伍, 計謀−1)＝ −1 → 不行（天候與位置，§4.0）
28c95: 2a22:0998(...) 執行
```

| 計謀 | 費用（`DS:0x7f62`）| 智力門檻（`DS:0x7f6e`）|
|---|---|---|
| 1 火攻 | 600 | 80 |
| 2 水渰 | 500 | 75 |
| 3 陷阱 | 100 | 60 |
| 4 誘敵 | 400 | 60 |
| 5 燒糧 | 300 | 70 |
| 6 圍攻 | 200 | 65 |

**與說明書 p.32–34 的表逐格相同**，兩份互為佐證。電腦諸侯用同一組
（`0x297e6` 讀同樣的兩張表），所以玩家與電腦的門檻一致。

### 4.0 天候與位置那道門（`2a22:1cc8` ＝ `0x2bee8`，`L0`、`[base]`）

`0x28c67` 呼叫的第三道門。它自己只是分派器：`0xe(bp)` 是**計謀編號減一**，
`cmp $5 / ja` 之後 `jmp *cs:0x1d56(bx)` 跳六個 thunk，每個 thunk 把
`0x6`–`0xc` 四個參數原封轉給對應的檢查常式。回 `0` ＝ 可以，
`0xFFFF` ＝ 不行。

四個參數裡真正被讀的是後兩個：`0xa(bp)` 是**目標的軍力**、
`0xc(bp)` 是**隊伍**，六支都用同一條算式取部隊記錄
`(軍力 × 10 + 隊伍) × 42`，再讀 offset 22（欄）與 24（列）。

| 計謀 | 檢查常式 | 條件 |
|---|---|---|
| 1 火攻 | `0x2bf86` | `天候 == 2`（刮風）|
| 2 水渰 | `0x2bfa2` | `天候 == 1`（下雨）**而且**目標的六個鄰格裡有一格地形碼 `3`（淺水）|
| 3 陷阱 | `0x2c066` | 目標格的地形碼**不在 3–6**（淺水、深水、城池、關寨）|
| 4 誘敵 | `0x2c0c8` | 無條件（`sub ax,ax; lret`）|
| 5 燒糧 | `0x2c0d2` | 目標格的地形碼**不是 3 也不是 4**，**而且**天候不是 `1`（下雨）|
| 6 圍攻 | `0x2c140` | 目標的六個鄰格裡，我方的部隊要**兩支以上**（含施法者，`cmpw $1; jle` 回 −1）|

**天候在 `es:[0x17bc]`**（段取自 `ds:[0xa9d6]`）：`1` ＝ 下雨、`2` ＝ 刮風。
火攻與燒糧各只看它一次，水淹看它一次再加地形，其餘三支不看。

**水淹的「岸邊」比說明書窄。** p.33 寫「目標必須在水上或岸邊」，
碼裡掃的是**目標的六個鄰格**、而且 `cmp al,3 / jne` **只認淺水**——
深水（碼 4）不算，目標自己站在水上也不算。

**圍攻數的是佔位圖。** `es:[0x2532]`（段取自 `ds:[0xa9ca]`）是
10×12 的 word 陣列，索引 `(列 × 12 + 欄) × 2`，`0xFFFF` ＝ 空格，
否則是佔著那一格的部隊。判「是不是同一邊」用的是 `佔位值 ÷ 20`
對上 `目標的軍力 ÷ 2`——兩邊都化到「守方（軍力 0、1）」與
「攻方（軍力 2、3）」，不等就記一筆。所以數到的是**目標周圍我方的
部隊數**，施法者自己也在其中，門檻是大於 1。

六支引用的段變數：部隊記錄 `ds:[0xa984]`、戰場地圖 `ds:[0xa99e]`、
方向位移表 `ds:[0xa9c6]`（列）與 `ds:[0xa9c8]`（欄）、天候 `ds:[0xa9d6]`、
佔位圖 `ds:[0xa9ca]`。**這些變數裝的是同一個段**——一次實跑裡
`[0xa872]`、`[0xa984]`、`[0xa99e]`、`[0xa9d6]` 讀出來都是 `0x3e64`
（`L1`，`TestStratagemsRunLive`），偏移量也與 §2.2、§3.3 解出來的版面
相符（`0x163a` 地圖、`0x3502` 部隊記錄），是同一塊工作區。

**天候逐日重擲**（`L1`）：同一場戰役第 1 天量到 `1`（下雨）、
第 3 天量到 `0`。所以「這一場能不能用火攻」不是開場就定下來的，
判準要在下計謀的那一天讀。

### 4.1 成功判定（`2a22:0998` ＝ `0x2abb8`）

**說明書完全沒提這一關**——它只寫了智力門檻與費用，過了那兩關看起來
就一定成功。實際上還要賭一次（`0x2abf4`–`0x2ac4d`）：

```
RND(上限表 DS:0x81e0[計謀]) + 目標領隊的謀略 < 施法者領隊的謀略 → 成功
```

| 計謀 | 亂數上限 |
|---|---|
| 1 火攻 | 10 |
| 2 水渰 | 8 |
| 3 陷阱 | 2 |
| 4 誘敵 | 2 |
| 5 燒糧 | 4 |
| 6 圍攻 | 6 |

上限愈大愈難：火攻要贏過對方 10 點以內的亂數，陷阱與誘敵只要 2 點。
**謀略不高過對方就一次都不會成功**（亂數最小是 0）。費用在判定與效果
之後才扣（`0x2ada2`），成敗都扣；移動力不動（§12.3）。

### 4.2 火攻與水淹的殺傷（`0x2adec`／`0x2b15a`）

```
基數 = 表[地形碼 & 0x0D]                ; 火攻 DS:0x8200、水淹 DS:0x8224
比率 = (基數 + RND(10)) × 0.01
施法者領隊的謀略 ≥ 98 → 比率 × 1.6      ; DS:0xa9b6
比率 > 0.9 → 0.9                        ; DS:0xa9be，上限
逐將領：新兵 = 兵 × (1 − 比率)
        新兵 ≤ 0 → 從部隊除名；RND(100) > 20 就燒死
```

**索引是 `& 0x0D` 而表只有八格**：那個遮罩把第 1 個位元抹掉，
所以山丘 2→0、大山 1 與淺水 3→1、深水 4 與關寨 6→4、
城池 5 與平原 7→5、樹林 8→8、沙漠 9→9。8 與 9 已經超出表尾，
讀到的是後面那串檔名字串當成數字（一萬多）。**玩起來看不出來**：
比率被 0.9 夾住，所以樹林與沙漠一律吃滿九成——正是說明書寫的
「樹林殺傷力最強」。

| 地形 | 索引 | 火攻 | 水淹 |
|---|---|---|---|
| 山丘 | 0 | 25 | 20 |
| 大山、淺水 | 1 | 15 | 2 |
| 深水、關寨 | 4 | 20 | 30 |
| 城池、平原 | 5 | 55 | 35 |
| 樹林 | 8 | 表外 → 90 | 表外 → 90 |
| 沙漠 | 9 | 表外 → 90 | 表外 → 90 |

說明書把城池的火攻列在「損失普通」，但碼裡它與平原同一格（55）；
沙漠列在「傷害較大」，碼裡是滿的 90。**以碼為準。**

成功之後依計謀分派：

| 計謀 | 常式 | 效果 |
|---|---|---|
| 火攻 | `0x2adec` | §4.2 |
| 水渰 | `0x2b15a` | §4.2 |
| 陷阱 | `0x2b4ca` | §4.3 |
| 誘敵 | `0x2b6aa` | §4.4 |
| 燒糧 | `0x2b892` | §4.3 |
| 圍攻 | `0x2bb00` | §4.5 |

**每一支都會看領隊的謀略有沒有到 98**（`0x62`），到了就加碼。

### 4.2b 共同的交戰結算（`0x2a224`，`L0`）

火攻與水淹之外的兩招（誘敵、圍攻）不自己算傷亡，交給這一支：

```
0x2a224(攻方軍力, 攻方部隊, 守方軍力, 守方部隊, 模式)
  0x2a2c9  模式 < 0 或 > 7 → 模式 = 1
  0x2a444  si = 模式 × 2；傷害乘上 DS:0x81a2[模式]
  0x2ab90  decw es:[0x3516 + 攻方部隊×42]      ; 部隊 offset 20，某種次數
```

`DS:0x81a2` 是八格的倍率表（百分比）：

| 模式 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| 倍率 | 80 | 100 | 150 | 200 | 250 | 300 | 350 | 400 |

**攻守是參數順序決定的**：圍攻推的第一對是鄰格的部隊、第二對是目標
（`0x2bddf`），所以第一對是出手的一方。收尾時對兩邊各查一次
「將領人數 ≤ 0 → 把那一格畫回地形」（`0x2a732`／`0x2a790`），
所以**兩邊都可能在一次結算裡消失**（`L2`）。

部隊 offset 20 是**弓箭剩餘次數**。兩道 `> 0` 的閘門分別守著弓箭選單
（`0x288a7`，選單本身把它印出來：`DS:0x80ae`「弓箭攻擊 次數:%d」）與
**目標列舉**（`0x29884`）；`0x272eb` 設初值，這裡遞減。所以誘敵與圍攻
消耗的是**出手那一方的箭**。

目標列舉（`0x29896`–`0x299f5`）六個方向各走一輪，每一輪**照同一個方向
連走兩步**，第一步之後重算奇偶列（`欄 % 2` 決定用方向表的哪一組），
落點出界就跳過，候選存進 `es:[0x1ece + i×2]`／`es:[0x16f6 + i×2]`
（初值 `0xFFFF`）。一個候選都沒有就回 `0xFFFF`。

**「相間一格」因此是「同方向連走兩步」**，不是「距離 2」——折線走到的
格子不在候選裡。這一條原本標 `L2`（`docs/mechanics/40` §5），現在是 `L0`。

初值的算式（`0x2723e`–`0x272f4`，`L0`）：

```
逐一走過十個將領槽（槽號 0xFFFF 跳過）：
  S += round(武裝度 × 兵士數 × 0.01)      ; 武裝度 = 人物 offset 25
  N += 兵士數                              ; 人物 offset 22（u16）
N > 0：次數 = round(S ÷ N × 100) ÷ 20
N ≤ 0：次數 = 0
```

也就是**兵數加權**的平均武裝度 ÷ 20。常數在 `DS:0xa8d2` ＝ 0.01、
`DS:0xa8ec` ＝ 0.5（四捨五入）、`DS:0xa8f4` ＝ 100.0。
手冊 p.32 的算例看起來像算術平均，那是因為算例沒提兵數。

### 4.3 陷阱與燒糧

```
陷阱（0x2b648）：部隊記錄 offset 26 ← RND(5) + 1
                 領隊謀略 ≥ 98 再加 RND(5) + 2      ; 所以 1–5 或 3–11
燒糧（0x2ba6b）：領隊謀略 ≥ 98 → 留下 1 ÷ (RND(2) + 4)      ; 20–25%
                 否則          → 留下 1 − 1 ÷ (RND(3) + 2)  ; 50–75%
                 軍團記錄的金（offset 6）與米（offset 8）各乘一次
```

offset 26 是每天遞減的倒數（`0x24e71` 比 0、`0x24e8a` 遞減）。

⚠ **說明書 p.33 寫「中陷阱九日內無法活動」，碼裡不是**：一般是 1–5 日，
謀略 98 起跳才可能到 11 日。以碼為準。


### 4.4 誘敵（`0x2b6aa`，`L0`）

播完動畫（施法者的謀略最高者頭像、目標被「引」過來的二十步移動）之後：

```
0x2b863  施法者的謀略 ≥ 0x62（98）→ 模式 9，否則 8
0x2b877  push 模式
         push 施法者部隊, push 施法者軍力     ; → 守方
         push 目標部隊,   push 目標軍力       ; → 攻方
0x2b885  call 0x2a224
```

**攻守是對調的**：先推的目標落在第一對參數，也就是出手的那一方。
所以誘敵是**把敵人引過來打你**，不是說明書 p.33 寫的「來犯敵軍攻擊力
暫時下降」——碼裡沒有任何「暫時」的狀態欄位。

而且模式 8 與 9 都在 0..7 之外，被 `0x2a2c9` 夾成 1（倍率 100）。
**「施法者謀略 ≥ 98 就加碼」在原版完全沒有作用**，那是原版的 bug。

### 4.5 圍攻（`0x2bb00`，`L0`）

```
0x2bc90  [bp-0x12] = 目標的欄 % 2         ; odd-q 的奇偶列
0x2bc95  [bp-0xe] = 0                      ; 倍率格，先算出來
第一輪（0x2bc9e–0x2bd0e）六個方向：
  出界 → 跳過
  es:[0x2532 + (12列+欄)×2] == 0xFFFF → 空格，跳過
  那一格的部隊 ÷ 20 == 目標軍力 ÷ 2       → 同陣營，跳過
  否則 [bp-0xe]++                          ; 0x2bd04
0x2bd10  施法者（[bp+6]、[bp+8]）的謀略最高者（部隊 offset 38）
         謀略 >= 0x62（98） → [bp-0xe]++    ; 0x2bd41
第二輪（0x2bd49）六個方向各一輪：
  欄 += DS:0x7c6a[(奇偶×6 + 方向)×2]
  列 += DS:0x7c82[同上]
  出界（欄 < 0、欄 ≥ 12、列 < 0、列 ≥ 10）→ 跳過
  es:[0x2532 + (12列+欄)×2] == 0xFFFF     → 空格，跳過
  那一格的部隊 ÷ 20 == 目標軍力 ÷ 2       → 同陣營，跳過
  目標的將領人數（offset 28）≤ 0          → 跳過
  否則 0x2a224(那一格的部隊, 目標, [bp-0xe])
```

**倍率格不是常數。** `0x2bdf8` 推的第五個參數是 `[bp-0xe]`——
**圍著目標的敵方部隊有幾支就加幾**，施法者的領隊謀略到 98 再加一。
所以「圍攻」名副其實：圍的人愈多，每一支打得愈重（倍率表 `DS:0x81a2`
是 80／100／150／200／250／300／350／400）。施法者自己一定貼著目標，
所以最小是 1（＝ 100），圍滿六格又有神算是 7（＝ 400）。

實跑量到過一次（`L1`，`TestSiegeWithTwoUnits`）：兩支我方部隊貼著同一支
守軍、施法者的領隊謀略 99，`0x2a224` 收到兩次呼叫，攻方分別是那兩支
自己的編號，模式都是 **3**（2 支 ＋ 謀略加碼 1）。

**判準是「與目標不同陣營」，不是「不是施法者」**——貼著目標的施法者
自己也會打一次。每一輪都重查目標的將領人數，打光就不再打。

## 5. 軍團的編成（`L0`、`[base]`）

`0x20770(郡, 陣營碼)` 把一個軍團清乾淨：軍團記錄整份重設、五個部隊
記錄的將領欄清成 `0xFFFF`、offset 28 與 30 歸零。郡編號不在 1..42
就回 `0xFFFF`（沒有這個軍團），所以援軍格填 `0xFFFF` 的軍團整個跳過。

一場最多 **4 個軍團 × 5 支部隊**，與整編畫面的「將%s分到那一軍(1-5)」
（`DS:0x7a60`）對得起來。部隊陣列的跨距是 10 不是 5——每個軍團留了
十格，只用前五格。欄位見 §3.3。

### 5.1 電腦的整編（`0x23630`，`L0`＋`L1`、`[both]`；加強版 `0x21138`）

`0x20770` 對電腦控制的郡走這一支。**出征的名單在這裡才決定**——出兵那
一張表（`0xb5c2`／加強版 `0xb4e0`）只挑目標、比兵力門檻，然後直接進
戰役入口（`0x20200`／`0x1e252`），沒有第二次編隊（`0xb706` 只在移防那兩
條路上）。加強版的入口在整編之前先讓兩邊的主事者各說一句話（`0x1e317`／
`0x1e34f`），對白框的字色各 `RND(8)`（`0x2f912`）——兩擲不影響規則，
少了它整個月的骰序從這裡岔開。

主攻軍（陣營碼 2）：

```
call 行動者(郡)                          ; 0xec86／加強版 0xe7bc：重建清單、按行動者鍵重排、
                                         ;   重算留守目標，收尾把 Σ兵力÷100 寫回兵士（0xf072／0xebd5）
                                         ;   加強版在這裡再抽一次策略值 RND(((難度−1)%10)×2+3)（0xe7e2）
keep ＝ 留守目標 × 100                    ; es:[0x2e62]／0x2e6a；0x236a9
洗牌：for i in 0..n−1: swap(清單[i], 清單[RND(n)])                ; 0x238a1／0x2135c
從尾端往前：累計兵力 < keep 就把那一位留在家裡                     ; 0x238f8
    位置 0 永遠出征；加強版多一條：一個都沒留而 keep <= 0 時
    再把最後一位留下（0x213f3）
帶走的金 ＝ 郡的金 ÷ 郡的兵士(百) × 出征兵力 × 0.01（米同；x87 算完才截尾）; 0x239bb
    郡的兵士(百) <= 0 時整郡的金米全帶走                             ; 0x23a02
名單按「戰力 ＋ 謀略 ÷ 2，君主再加 1000」交換排序（0xf262）           ; 0x23738
    加強版的除數是 5（0xedb4）
五支部隊依序填：每支 (n−1)÷5 位，前 n − 5×那個數 支多一位           ; 0x23789
出征的每一位所在郡 ← 0，然後 0x1d638(郡)                            ; 0x23296
```

⚠ 帶走的金米讀的是**行動者剛寫回的兵士**，不是出兵那張表看到的：調整
兵力重建清單時寫的是攤平之前的總數，而攤平用的是入口那一份陳舊的 Σ上限
（`docs/mechanics/70` §2.5b），總數會變。加強版月度對拍量到郡 15 從
175 變 195，帶走的金米按 195 算。

主守軍（陣營碼 0）：整個郡的守將（模式 2 的清單，不比對勢力），原版先排
行動者的序（`0x23656`），加強版沒排（`0x21158`）；兩版接著都走同一道整編
排序與分隊，然後所在郡 ← 0、`0x1d638(郡)`——**守方的郡在開打期間是無主
、沒有主事者的**（§7.1）。

援軍（陣營碼 1／3）：留守目標原版是「清單第一位的兵力」（同勢力）或
「keep ÷ (RND(2)＋2)」（不同勢力）；加強版一律清單第一位的兵力。

remake：`game.ComputerAttack`／`formAttackers`／`BattleShare`／
`sortForFormation`，`battle.formUp` 的電腦分支。

## 7. 怎麼把原版驅動進戰鬥

`internal/parity` 的 `TestZZBattleKeySweep` 與 `TestZZDumpBattleCode`：
開機一次（兩分半）、`stageABattle` 直接寫記憶體擺盤面、存快照，
之後每個候選按鍵序列還原重試（十秒）。打得起來的最短序列是

```
2 ⏎ 2 ⏎ <出兵郡> ⏎ <目標郡> ⏎        ; 軍事 → 發動戰役 → 從哪 → 打誰
⏎ 1 ⏎ 1 ⏎ N 2 ⏎ 1 ⏎ Y                ; 守方（兩位將）整編
⏎ 1 ⏎ 1 ⏎ Y <金> ⏎ <米> ⏎ Y          ; 攻方（一位將）整編
```

**整編**（`0x20a30`）每個軍團一輪，援軍格是 `0xFFFF` 的直接跳過。
玩家發動的戰役量到第一輪是**主攻軍**（`L1`，窗口讀到 `SCG06.IMG` 與
`主攻軍`；`TestZZPlayerSortieDriven`）：

```
進行%s團整編 → 請按任一鍵（1058:0e24）
0x21457      → 分配那一位將軍(1-n) ⏎
0x21509      → 將%s分到那一軍(1-5) ⏎         ; 然後回頭再問一次將軍
0x21493      → 分配完畢(Y/N) → Y 收工
陣營碼 0（主守軍）→ 錢糧直接取郡的全部，不問，jmp 0x20c5e（0x20ac3）
其餘         → 攜帶多少金 ⏎ → 攜帶多少米 ⏎ → 確認(Y/N)
0x20c6d/75   → 郡的金、米各扣掉隨軍的量
0x20c89/8e   → 寫進軍團記錄 offset 6／8
0x20c9a      → **走完這個軍團的五支部隊，每一位將領的人物記錄
                offset 19（所在郡）寫 0**（0x20ce0）
```

⚠ **「分配完畢(Y/N)」只在「分配那一位將軍」被取消時才問**
（`0x21475: cmpw $0xffff,-0xe(%bp); jne 0x214a6`），而取消 ＝
**空欄位按 Enter**（`33d8:115e` 回 `0xFFFF`）。已經分配過的人再選一次會被
退回重問（`0x214af: cmpw $0, es:0x3494(%bx)`），所以一直送同一個號碼是
**無限迴圈**，量到過上千次而軍團只有一位將領。收尾的走法是：
選一位 → 分到某軍 → **再問將軍時送空的 Enter** → `Y`。

**主守軍那條也會扣錢糧、也會清所在郡**：`0x20ac3` 判陣營碼 0 之後把
`-0x4/-0x2(%bp)` 直接填成郡的金與米，然後 `jmp 0x20c5e` 進同一段
（`0x20ae5`）。所以四個軍團的將領都會離開原本的郡——主守軍本來就在戰場
那個郡，打完再寫回去等於沒動。

打到這裡畫面就是主戰場，提示是
`(%2d%s)%s之%s請%s將軍紮寨` ＋ `數字鍵選方向`。

四個軍團帶的錢糧存在工作區 `0x1764` 起（`0x22f41` 印它，格式字串
`金%6d`／`米%6d` 在 `DS:0x7bc0`／`DS:0x7bc6`）。⚠ **這兩個字串一度被
記成州郡記錄的 offset 84／86**——那兩格其實在戰場地圖裡
（`docs/spec/003` §3.0）。

**每一個提示都要 Enter，選單也一樣**——欄寬由上限決定，一位數的選單
欄寬是 1，滿了之後多打的數字被直接丟掉（`docs/re/03` §1.5 的按鍵表）。

### 7.0 紮寨與日循環

打到主戰場之後還有兩段：

- **紮寨**：提示是 `數字鍵選方向 / 4 5 6 / 1 2 3 / 0:紮寨`
  （`DS:0x7f9e`）。**1–6 移游標，`0` 才是紮下去**，一支一支問。
- **每天的命令**：`0x27a40` 印選單 `DS:0x7f22`
  （`1.移動 2.對戰 3.快戰 4.死戰 5.弓箭 6.策略 7.查看 8.退兵 0.休息`），
  `0x27a63` 用 `1058:0e24` 讀**一個 ASCII**，`0x27aba` 做
  `sub $0x30; cmp $8; ja` 再跳 `cs:0x13a` 的九格表——**不是數字欄位，
  不要送 Enter**。下完之後接的是 **Y/N 確認**（`0x1538c`：讀一個鍵，
  `0x153a2` 寫 `'Y'`、`0x153aa` 寫 `'N'`）。

**移動**（命令 `1`）進去之後 1–6 一律當方向（`0x27d41` 的
`cmp $0x31 / cmp $0x36`），**只有 Enter 離得開**（`0x27d63` 的
`cmpw $0xd`）——按 `2` 不會跳去對戰，會被當成「往下走一格」。
離開移動模式就等於這一支的回合結束。

**對戰**（命令 `2`）讀一個方向鍵（`0x28e6a`：1–6，Enter 取消），那一格
站著敵軍就進對戰子畫面 `0x2deb0`（§10），回來把移動力歸零。

每個命令的後續提示各有自己的讀鍵點：移動 `0x27d3e`、對戰 `0x28eb9`、
快戰 `0x27f91`、死戰 `0x28681`、弓箭 `0x2891f`、查看 `0x281c6`。

所以「玩家的部隊休息一天」就是兩個鍵：`0` 再 `Y`。天數
（工作區的 `0x2100`）跟著 +1，每天走一次 `0x21816`（戰場迴圈）、
每支部隊一次 `0x24ee1`（回填移動力）、`0x24f8c`（統帥條件）二十一次、
`0x250d4`（三十天）一次。

⚠ **送 Enter 答 Y/N 會讓天數一直停在 1**，而畫面看起來就只是
「還在問同一個人」——與「鍵沒送進去」一模一樣。判準要看
`0x27a68` 回來的 AX（我們送的鍵原版收到什麼）與天數，不是畫面。

⚠ **紮寨的最後一個 `0` 就是第 1 天的命令（休息）。** 紮寨提示與命令
提示的 `0` 是同一個鍵，一支一支問完之後多出來的那一個直接落到命令上，
所以要接一個 `Y` 把那一天的 Y/N 答掉，天數才推得到 2。少了這一步，
玩家那支在第 1 天已經沒有命令可下，後面送的 `1`（移動）、`6`（計謀）
會被別支或下一天的提示吃掉——**部隊留在原地，而按鍵一路被收下去，
看起來像方向錯或按鍵表不對**。

由此得到一條通用判準：**送完鍵之後要斷言的是盤面本身**（座標變了沒、
目標格上站著誰），不是「有沒有讀到鍵」。讀鍵計數只證明某一個提示收了
一個字元，證明不了那是我們想要的那個提示。計謀尤其明顯——方向那一格
沒有敵人時原版直接取消、也不扣錢，六種計謀「全部沒扣錢」與「六種的
條件剛好都不合」印出來一模一樣。

⚠ **`OnCall` 的位址必須是確定的指令邊界。** 拿 dump 視窗的起點
（例如 `0x27a40`）當攔截點不會報錯，只會**一次都不觸發**，看起來就像
「那段碼沒被走到」。安全的取法是**攔某個呼叫回來的位址**——
`0x27a68` 是 `lcall 1058:0e24` 的下一道指令，那個邊界是確定的。

判準是 `0x18bb9`（呼叫戰鬥）或 `0x2053c`（進主戰場）被執行到，
不是畫面看起來對。

## 7.1 電腦對電腦不進戰術層（`L0`＋`L1`、`[base]`）

`0x20200` 佈完場（清 10×12 的佔位地圖、寫天數 ← 1、畫出兵通告）之後，
在 `0x20471` 分兩條路：

```
[bp-4] = 0
四個郡各判一次：諸侯[該郡的所屬] offset 0 == 1（玩家控制）→ [bp-4] = 0xFFFF
                                                    ; 0x203c4／0x203ea／0x2041c／0x2044e
es:[0x2174] == 0 → [bp-4] = 0xFFFF                  ; 0x2045f
lcall 0x3eb:0x31a
[bp-4] == 0 → lcall 0x1e90:0x8（＝ 0x1E908）        ; 沒有玩家：自動結算
否則       → call 0x2053c                           ; 有玩家：戰術層
```

⚠ **郡編號 <= 1 或 >= 0x2b 的那一格跳過判定**（`0x203f7`／`0x20429`），
所以 `0xFFFF`（沒有援軍）不會被誤判成玩家。

實測背書：三個月裡電腦進攻 5 次，`0x20200` 與 `0x20253`（天數 ← 1）各
5 次，而 `0x24f8c`（每天判一次的統帥條件）與 `0x250d4`（三十天期滿）
**一次都沒跑**（`internal/parity/battleover_oracle_test.go` 的入口計數）。

**所以 §8 與 §8.1 只在玩家在場的戰役裡生效。** 電腦對電腦走 `0x1E908`。

### `0x1E908` 讀到的部分（`L0`）

```
四個軍力各設一次：lcall 0x2020:0x570（＝ 0x20770），參數 (郡, 軍力編號)
    主攻 2 ← [bp+6]、助攻 3 ← [bp+8]、助守 1 ← [bp+0xc]、主守 0 ← [bp+0xa]
天數（es:[0x2100]）← 1；勝方（es:[0x20dc]）← 0xFFFF
四個 double 累計器清成 0.0（DS:0xa7e4）：es:[0x78]、es:[0xbc]、es:[0x9ce]、es:[0x1608]
四個軍力各跑一次（部隊數在軍力記錄 offset 10：es:[0x1768/0x177e/0x1794/0x17aa]）：
    逐支部隊（42 byte 一筆）
        累計器 A += 部隊[+32] × 0.01        ; DS:0xa808 ＝ 0.01
        累計器 B += 部隊[+30]
攻方 A（es:[0x78]）  ÷= 軍力2部隊數 ＋ 軍力3部隊數
守方 A（es:[0xbc]）  ÷= 軍力0部隊數 ＋ 軍力1部隊數
es:[0x570] ← 攻方 B（es:[0x9ce]）  ＋ 0.0001        ; DS:0xa812
es:[0x870] ← 守方 B（es:[0x1608]） ＋ 0.0001
call 0x1ecfc(主攻郡, 主守郡)
es:[0xa] ← 2；接著看 es:[0x20dc] 是不是 2 決定後續
```

所以四個量是：**兩邊的「部隊 +32 欄的平均值 × 0.01」與「部隊 +30 欄的
總和」**。加 `0.0001` 這個 epsilon 只有一個用途——那兩個和後面要當除數，
兩邊都沒兵時不能除以零。

`0x1ecfc(主攻郡, 主守郡)` **就是這一仗**。它開頭算戰役動畫在大地圖上的
位置（取兩郡 `MapX`／`MapY` 的較大者，`(|較大者 − 0x20| >> 3 ＋ 10) << 3`），
接著跑**日迴圈**：每天呼叫 `0x1f538`（`0x1f4ba`）、回來就 `天數++`
（`0x1f4c1`）。`0x1E908` 的呼叫順序因此是

```
0x1ec0a  call 0x1ecfc   ; 打這一仗（日迴圈）
0x1ec14  es:[0xa] ← 2；勝方 == 2（攻軍勝）時改成 0   ; ＝ **敗方**的軍團編號
0x1ec33  call 0x1f6fe   ; 打完的收尾：存活比例、傷亡、郡的善後
0x1ec37  call 0x1fb26   ; 戰後安置
0x1ec3e  照 es:[0x20dc] 印「攻軍獲勝」／「守軍獲勝」
```

### 戰後安置（`0x1fb26`，`L0`＋`L1`、`[both]`；加強版 `0x1dc1c`）

`0x1f6fe` 把四個軍團每一位的所在郡清成 0、勝方兩個軍團的人放回戰場郡
（`0x1fab8`）、戰場郡重整（`0x1949e` 再 `0x1d638`）之後，由這一支決定敗方
的人去哪裡：

```
候選表 es:[0x2102]／長度 es:[0x17c4] 清空
for i = 0..9：                                    ; 州郡 offset 45–54 的十格相鄰表
    鄰郡 = 州郡[戰場郡].offset(45 + i)
    鄰郡 == 0xFF → 跳過
    鄰郡的所屬（offset 30）== 敗方主軍的勢力 或 == 0xFF（無主）→ 收進候選表
逐軍團（敗方主軍、敗方援軍）、逐部隊、逐槽 0..9 的每一位：
    挑 = RND(候選數)                              ; 0x1fc32；候選數 0 時 RND 不抽
    候選數 <= 0                        → 進名單
    r = RND(200)                                  ; 0x1fc5d
    謀略 ＋ 戰力 ÷ 2 >= r              → 進名單   ; 0x1fc8a
    候選[挑] 的現役將（offset 22）>= 50 → 進名單   ; 0x1fc9d
    否則：所在郡 ← 候選[挑]，該郡現役將 ＋1      ; 逃掉了
名單裡的每一位：
    所在郡 ← 戰場郡                               ; 0x1fd4f
    旗標 = 0
    身分 == 0（君主）                          → 旗標 = 1   ; 0x1fd54
    州郡[戰場郡].在野將（offset 23）>= 50      → 旗標 = 1   ; 0x1fd73
    0x1ff7c(勝方的勢力, 戰場郡, 人物槽) > 0    → 旗標 = 2   ; 0x1fdaa
```

**候選表是敗軍的退路**：戰場旁邊敗方主軍勢力還握著的郡，加上無主的郡。
謀略高、戰力強的人逃不掉（判式方向是 `>=` 進名單），逃得掉的人也要看
目的地有沒有位子。**沒逃掉的才進名單**，名單裡的人一律先落在戰場郡。

### 戰後收降（`0x1ff7c(勝方的勢力, 郡, 人物槽)`，`L0`）

```
人物身分 == 0（君主）             → 回 0        ; 0x1ff93 君主不被收編
州郡[郡].現役將（offset 22） >= 50 → 回 0        ; 0x1ffb4 郡裡的在職將滿了

抵抗 = max(人物 offset 9 謀略, offset 10 戰力)                    ; 0x1ffc8–0x1ffdd
牽絆（offset 14）!= 自己 且 牽絆對象的勢力 == 自己的勢力 →
    抵抗 += 60 − RND(30)                                          ; 0x20014（31–60）
諸侯[勝方].人望（offset 8） >= 抵抗 ÷ 2 → 回 人望（收編成功）      ; 0x20034
否則 → 回 0
```

**牽絆那一項只在對象還在同一個勢力時加**——舊主那邊還有牽掛的人就不容易
收編，與登用、挖角同一個路子。`÷ 2` 是整數除法。

⚠ 兩處的 50 是**不同欄位**：`0x1fd73`（安置的迴圈裡）看的是在野將
（offset 23），`0x1ffb4` 看的是現役將（offset 22）。

remake 這一邊是 `game.WarRecruitResistance` 與 `game.WarRecruited`。

### 名單的三條路（`0x1fdb0`–`0x1fe12`，`L0`＋`L1`）

| 旗標 | 什麼時候 | 做什麼 |
|---|---|---|
| 0 | 收不下來，而且不是君主、戰場郡的在野將沒滿 | `0x200f4`：**失去勢力**——身分 ← 10、勢力 ← 0xFF、所在郡 ← 戰場郡、州郡[戰場郡].在野將 ＋1、他若是軍師則舊主的軍師槽 ← 0xFFFF；忠誠不動 |
| 1 | 君主，或戰場郡的在野將已滿 50 | `0x20050`：**下野**——身分 ← 12、勢力 ← 0xFF、所在郡 ← 0xFF；君主的話另記一筆事件（`es:[0xc4]`／`0x20f0`／`0x24d6`），收尾由 `0x26c08` 處理 |
| 2 | 收得下來 | `0x1feba(勝方勢力, 勝方軍團編號, 人物槽)`：再判一次 `0x1ff7c`（有牽絆的人**第二次** `RND(30)`），過了才改欄位；沒過落到 `0x1fe04` 走 `0x20050(1, 人物槽)`，與旗標 1 同一支 |

**沒有「什麼都不做」這一條。** 收不下來的人一律離開敗方：要嘛變成戰場郡
的在野（身分 10，勝方下一回合的登用表就看得到他），要嘛下野。

### 收編實際改什麼（`0x1feba`，`L0`）

```
ax = 0x1ff7c(勝方勢力, 郡, 人物槽)     ; 再確認一次
ax <= 0 → 回 0xFFFF（沒收成）
忠誠  ← min(100, ax)                   ; ax 就是勝方的人望   0x1fee6／0x1ff27
原身分 == 1（軍師）→ 諸侯[他舊勢力].offset 6（軍師槽） ← 0xFFFF   ; 0x1ff11
勢力  ← 軍團[勝方].offset 16           ; 0x1ff41
身分  ← 3（一般武將）                   ; 0x1ff46
所在郡 ← 戰場郡                         ; 0x1ff58
```

**收編一律降成一般武將**——原本是軍師或太守的人過來之後從頭做起，
而且舊主的軍師位子就這麼空出來了。忠誠直接等於新主的人望（夾在 100），
所以人望高的諸侯收來的降將一開始就死心塌地。

名單跑完之後（`0x1fe16`–`0x1fe94`）只做重整：先對戰場郡叫一次
`0x1949e`，再掃一次十格相鄰表，對候選表那些鄰郡（敗方的或無主的）各叫
一次。

### 君主落到旗標 1 之後（`0x26c08(勝方)`，`L0`）

`0x1E908` 收尾看到事件旗標就叫 `0x26c08(勝方)`：先走 `0x14968` 的繼承
（與君主老死同一支，`docs/re/06` §3），然後**勝方分走敗方的寶物**：

```
k = RND(4)；敗方諸侯 offset (15 + k) ＋= 2          ; 0x26c31
四件（offset 15–18：兵書、寶刀、美女、駿馬）各自：
    半 = 敗方件數 ÷ 2
    拿走 = 半 ＋ RND(半)                          ; 0x26c67；半 == 0 時不抽
    勝方 ← min(100, 勝方 ＋ 拿走)；敗方 −= 拿走
```

玉璽（offset 14）不在這一支裡。remake：`game.spoilsFromFallenLord`。

### 混編的郡是這樣來的

敗方留在戰場郡的人分兩種：收編的（勝方的人）與失去勢力的（身分 10、
勢力 0xFF、在野將 ＋1）。**勝方的郡裡不會留下掛著敗方勢力的人**——先前
量到的「28 個郡站著外勢力的武將」另有來源：指定太守可以指到別家的人
（`0xd74d` 讓郡易主）、逃散的人落到無主的郡、以及重算歸屬（`0x1e394`）
之前的空窗。這也是原版的名單過濾器一律不比對勢力的原因。

### 兩支重整常式（`0x1949e`／`0x1d638`，`L0`＋`L1`、`[both]`；加強版 `0x17fc8`／`0x1ba90`）

戰役前後叫的都是這兩支，語意要分清楚：

`0x1949e(郡)`——**重整守將清單**：

```
建清單（模式 2 ＝ 在郡、身分 0–3，不比對勢力），按「魅力 ＋ 加權表[身分]」交換排序（0xf520）
現役將（offset 22）← 清單長度
清單空 → 所屬 ← 0xFF、主事者 ← 0xFFFF、兵士 ← 0，回
所屬（offset 30）← 清單第一位的勢力
主事者：第一位是君主 → 他
        否則存的主事者還在郡裡 → 不動
        否則 → 0x1d638(郡) 的結果
主事者身分 3 → 2；清單裡其他身分 2 的 → 3
兵士（offset 16）← Σ 兵力 ÷ 100
```

`0x1d638(郡)`——**主事者補位**：

```
建清單（模式 2）——建表常式（0xfc1e／加強版 0xf67c）收尾一律按行動者鍵
    （謀略 ＋ 戰力 ＋ 加權表[身分]，0xf170／0xecd0）交換排序
清單空 → 主事者 ← 0xFFFF、所屬 ← 0xFF
存的主事者還在郡裡 → 不動
否則 → 主事者 ← 清單第一位（玩家控制的勢力在這裡改問玩家）；身分 3 → 2
現役將 ← 清單長度；兵士 ← Σ 兵力 ÷ 100
```

**補位挑的是行動者鍵最大的人，不是槽號最小的。** 身分的加權（太守 1200、
一般 800）會讓剛在別的郡當上太守的人領先：加強版月度對拍量到郡 37 的
114 先在指定太守被升成太守，帶兵打下郡 30 之後以 63＋64＋1200 對 11 的
77＋64＋800 接下新郡（`internal/parity/plusmonth_oracle_test.go`）。

主守軍整編時也叫 `0x1d638`（守軍的所在郡已經清成 0），所以**戰場郡在
開打期間是無主、沒有主事者的**（`L1`：加強版量到 `0x1ba90(30)` 建出空表）。
打完之後戰場郡的重整從這個狀態重建，存的主事者是 0xFFFF，於是必走補位。

### 電腦對電腦的每日結算（`0x1f538`，`L0`）

勝負寫在這一支（全碼段只有十一處寫 `es:[0x20dc]`，這一支佔三處）：

這一支由日迴圈在**每天收尾時**呼叫（唯一的呼叫點 `0x1f4ba`，回來的下一道
指令就是 `天數++`，`0x1f4c1`）。

四個工作量（都在 `0x1E908` 備好，`§5` 的部隊欄位）：

| 量 | 位址 | 內容 |
|---|---|---|
| 攻方戰力 | `es:[0x9ce]` | Σ 部隊 offset 30（兵士數），軍團 2、3 |
| 守方戰力 | `es:[0x1608]` | 同上，軍團 0、1 |
| 攻方品質 | `es:[0x78]` | Σ(部隊 offset 32 綜合能力 × 0.01) ÷ 部隊數 |
| 守方品質 | `es:[0xbc]` | 同上 |

**兩個戰力在戰鬥中會被改寫**（`0x1f683`／`0x1f691` 用 `movsw` 整塊複製，
不是 `fstpl`），`es:[0x570]`／`es:[0x870]` 留著開場值各加 `0.0001`，
`0x1f6fe` 拿 `現在 ÷ 開場` 算剩餘比例——epsilon 是為了兩邊都沒兵時除得下去。

```
天數 es:[0x2100] % 3 == 0：                            ; 0x1f545–0x1f55d
    攻方隨軍的米 es:[0x1792] ← trunc(米 − 攻方戰力 × 0.01)
    攻方的米 <= 0 → es:[0x20dc] = 0（守軍獲勝），回      ; 0x1f592
    守方隨軍的米 es:[0x1766] ← trunc(米 − 守方戰力 × 0.01)
    守方的米 <= 0 → es:[0x20dc] = 2（攻軍獲勝），回      ; 0x1f5c9

天數 <= RND(11) + 20 → 跳過這一段                       ; 0x1f5d8–0x1f5f2
否則（門檻小於天數；兩個新值都用舊值算，同時更新）：
    新守方戰力 = max(0, 守方戰力 − 攻方戰力 × 攻方品質)   ; 0x1f5f5
    新攻方戰力 = max(0, 攻方戰力 − 守方戰力 × 守方品質)   ; 0x1f63c

守方戰力 <= 0 → es:[0x20dc] = 2（攻軍獲勝）              ; 0x1f6b7 → 0x1f5c5
攻方戰力 <= 0 → es:[0x20dc] = 0（守軍獲勝）              ; 0x1f6d8 → 0x1f58c
天數 >= 30    → es:[0x20dc] = 0（守軍獲勝）              ; 0x1f6f1
```

比較方向由 IDA Pro 9.4 保留的原始指令釘住：`0x1f5eb cmp ax,es:[0x2100]`
比較 `RND(11)+20` 與天數，`0x1f5f0 jl 0x1f5f5` 只有在門檻較小時進入
傷亡段；否則 `0x1f5f2 jmp 0x1f69f` 跳過。語意為**已證實**，證據是上述
原始位址、控制流與碼段 dump SHA-256，不靠改名。

`es:[0x1766]` ＝ 軍團 0 的 offset 8、`es:[0x1792]` ＝ 軍團 2 的 offset 8，
照 §3.3 的欄位表那是**隨軍的米**——所以每三天那一段是**糧草消耗**：
各自按自己的規模吃糧（戰力的 1 %），**糧盡的一方就敗**。各扣各的、與
對手強弱無關，這樣就不是筆誤而是合理的。

### 傷亡怎麼寫回去（`0x1f6fe` 頭段 ＋ `0x1f9fe`，`L0`）

打完之後一次寫回，不是逐日扣：

```
存活比例(守) = es:[0x1608]（結束時的守方戰力） ÷ es:[0x870]（開場 ＋ 0.0001）
存活比例(攻) = es:[0x9ce]                     ÷ es:[0x570]
    ; 0x1f711–0x1f743，四個軍力各存一份 double（守 0/1 同值、攻 2/3 同值）

三層迴圈：軍力 0..3 × 部隊 0..部隊數−1 × 將領 0..9
    槽 = es:[0x3502 + ((軍力 × 10 + 部隊) × 21 + 將領) × 2]
    槽 == 0xFFFF → 跳過
    人物 offset 22（兵力） ← trunc(兵力 × 存活比例[軍力])   ; 0x1fa20
    人物 offset 19（所在郡） ← 0                            ; 0x1fa25
```

**四個軍力都乘，贏的那一方也折損**；同一方的所有部隊共用一個比例。
所在郡先清成 0，再由後面的安置決定誰進哪個郡。

### 打完之後郡的善後（`0x1f6fe` 後段，`L0`＋`L1`）

傷亡寫回之後還動了戰場郡的六個欄位（`L1`：加強版月度對拍逐格相同）：

```
州郡 offset 18（金）← Σ 四個軍團的隨軍金                          ; 0x1f82f
州郡 offset 20（米）← trunc(clamp(Σ 四個軍團的隨軍米, 0, 30000))   ; 0x1f86f 的 DS:0xa836 ＝ 30000.0
民眾忠誠（offset 26）← max(0, 民眾忠誠 − RND(10) − 1)             ; 0x1f8b2
地力（offset 27）    ← max(0, 地力 − RND(10) − 1)
水利（offset 28）    ← min(100, 水利 ＋ RND(7) ＋ 2)              ; 0x1f95e
物價（offset 29）    ← min(70, 物價 ＋ RND(18) ＋ 2)              ; 0x1f9a3
```

**隨軍的錢糧不管誰贏都收進戰場郡**——攻方打輸等於把補給送給守方。
米是打完之後的數：每三天那一段的消耗直接寫在軍團記錄上（`0x1f545`／
`0x1f5a9`），所以收進去的是吃剩的。

三件事跟玩家那條（§8）不一樣：

- **勝負有兩條路**：糧盡，或戰力被削到零。
- **不看統帥在不在**（§8.1 的 `0x24f8c` 在這條路上不跑）。
- **三十天期滿直接判守軍獲勝**，不查城池那一格。

累計迴圈的上界取的是**軍團 offset 10 ＝ 部隊數**。這一格與 offset 12 的
標法原本是反的，量過了（`internal/parity/battleover_oracle_test.go`，
19 次取樣）：上界與 offset 12 成對出現 (1,1)、(2,2)、(5,7)、(5,10)——
**一個軍團最多五支部隊**（§5），所以 7 與 10 不可能是部隊數。

## 8. 三十天的勝負判定（`0x250d4`，`L0`、`[base]`）

```
es:0x20dc != 0xFFFF → 已經有結果，回 0xFFFF
es:0x2100（天數）< 30 → 回 0xFFFF          ; 第 1 天開始（0x20253），每天遞增（0x23c42）
否則：
  es:0x20dc = 0                            ; 預設主守軍
  bx = 城池的格子 = 12 × es:0x586（列） + es:0x584（欄）
  佔位地圖 es:[bx + 0x2532] != 0xFFFF → es:0x20dc = 那一格的部隊 ÷ 10
```

**看的是「此刻誰站在城池那一格」**，不是「攻方有沒有進去過」——
進去又走掉就不算。城池空著的結果是 0，也就是主守軍。
`es:[0x2532 + (12列+欄)×2]` 是「哪一格站著誰」的地圖，圍攻掃鄰格
用的也是它。

`es:0x20dc` 是**勝方的軍力編號**，四種軍力在工作區裡的順序是
主守軍 0、助守軍 1、主攻軍 2、助攻軍 3——軍力記錄在
`es:[0x175e + 22×軍力]`，第 0 個欄位是統帥。

**玩家親征時這兩支才跑**（`L1`，`TestBattleFinishesWithPlayer`）：把玩家
驅動進主戰場、守軍的兵壓到 120、貼上去每天對戰，六輪打完分出勝負，
期間統帥條件 `0x24f8c` 跑了 **105 次**、三十天判定 `0x250d4` 跑了 **5 次**。
電腦對電腦那條路兩支都是 0 次（§7.1），所以「日循環要玩家在場」這一條
兩邊都有證據。

勝方欄位 `es:[0x20dc]` 在那一場被寫四次（位元組層），寫入端是
`0x23a6:0x0101`（填 `0xFF`）與 `0x23a6:0x1520`（寫勝方，線性 `0x24f80`，
就在統帥條件那一支裡）。

⚠ **盤面要在判定發生的那一刻取。** 戰役結束之後軍團與部隊記錄會被拆掉，
事後再讀是一整排 `0xFFFF`——量到過一次，比對因此拿垃圾去算，還算出
「兩邊統帥都不在」的假結論。

### 8.1 統帥條件（`0x24f8c`，`L0`、`[base]`）

三十天之前就能分勝負的那一條：

```
es:0x20dc != 0xFFFF → 已經有結果，直接回
攻方（軍力 2、3）：
  統帥 != 0xFFFF 且 統帥 == es:[0x3502 + 420×軍力]  → 還在，跳過
  兩個都對不上 → es:0x20dc = 0                      ; 主守軍勝
守方（軍力 0、1）：
  同樣的比對
  兩個都對不上 → es:0x20dc = 2                      ; 主攻軍勝
```

`es:[0x3502 + 420×軍力]` 是該軍力**第一支部隊的第一位將領槽號**
（部隊記錄 42 byte，一方十支，所以一方 420 byte）。統帥死了、被俘了、
所屬部隊撤退或全滅了，這個比對都會對不上。

**兩段的順序有意義**：守方那一段在後面，會蓋掉前面寫的值，
所以兩邊統帥都不在時判攻方勝。

### 8.2 加強版多的兩條（`L0`、`[plus]`）

加強版在同一段多了兩處寫 `es:0x20dc` 的地方（原版 6 處、加強版 8 處），
兩處都對得上加強版 README：

```
0x2296b  cmpw $0xb, %es:0x310a     ; 難度 ≥ 11
0x22971  jge  0x229b8              ; → 跳過「守方統帥全滅 → 攻方勝」整段
```

難度存在 `es:0x310a`（原版是 `es:0x30fe`；加強版的工作區純量整批往後
移了幾個位元組，天數 `0x2100`→`0x2102`、佔位地圖 `0x2532`→`0x2536`）。
這就是 README 第 5 條的「難度 11～20 時防守方若主帥軍被消滅並不算敗」。

另一處是加強版獨有的函式（原版沒有對應的碼）：

```
0x229ba  先呼叫 0x22b22 重算各軍力的總兵數
0x229da  軍力 0（主守）與 1（助守）的 +14 都是 0 → es:0x20dc = 2
0x229f5  軍力 2（主攻）與 3（助攻）的 +14 都是 0 → es:0x20dc = 0
```

**不看難度**，所以打光守方的統帥在難度 11–20 不算贏，打光守方的兵
還是算。軍力記錄的 offset 14 因此是**總兵數**。這是 README 第 6 條的
「總兵數為 0 者敗」。

第三處難度閘門在 `0x26758`（移動那一支的開頭）：難度 ≥ 11 且對方帥隊
第 0 槽那一位的身分（人物 offset 17）不是 0 時，行軍的**起點**從「本軍
帥隊的座標」（`0x26782` 讀 `unit[本軍][0]` 的 offset 22／24）換成城池座標
（`es:0x584`／`es:0x586`）。那是同一條規則的另一面——打死非君主的主帥既然
不算贏，就得去搶城。起點之後還有一段守不守得住的判斷，整支見 §12.5。

⚠ 加強版是**用 80186 以上的指令集編的**（`c1 e3 02` 的 `shl bx,imm`、
`c9` 的 `leave`），原版是 8086。所以兩版的碼段不能逐位元組比：
同一段邏輯的位元組本來就不同。

## 9. 一騎討（`L0`、`[base]`）

對戰畫面的第二個動作是單挑（`0x2fc2e` 的分派表）：

```
0x301d8  印 DS:0x8798「武將單挑」，讀一個鍵
         0x0d → 取消（回 0xFFFF）
         '1'..'6' → 0x3024e(軍團, 將領, 方向−1)
0x3024e  照方向走一格（同一組 dx／dy 表，對戰的子地圖也是 12 欄 × 10 列，
         地形在 es:[0x23c2 + (12列+欄)×2]、佔位在 es:[0x3b9c + …]）
         那一格空的、或站的是自己人（部隊 ÷ 10 相同）→ 回 0xFFFF
         否則 0x30a1e(我方陣營, 我方將領, 對方陣營, 對方將領)
         回來之後把行動力 es:[0x3c9c + …] 歸零
0x30a1e  叫陣：印挑戰者的名字，對方決定應不應戰
```

### 9.1 接不接受（`0x30c5b`–`0x30d5b`，`L0`）

`[bp-0x2e]` 的初值是 `0xFFFF`，**那是「拒絕」**——玩家控制的一方
原版直接問 `DS:0x87df`「接受嗎(Y/N)」，按 `Y` 就把它清成 0，
所以 **0 ＝ 接受**。電腦控制的一方（諸侯記錄 offset 0 ＝ 2）走三道：

```
RND(10) + 被挑戰者的戰力 − 5 > 挑戰者的戰力            → 接受
被挑戰者的兵 ÷ 2 > 挑戰者的兵，且
        RND(20) + 被挑戰者的戰力 > 挑戰者的戰力        → 接受
被挑戰者的兵 ÷ 5 > 挑戰者的兵                          → 接受
```

**強者才應戰，兵力懸殊時更願意應戰。** 戰力相同時十次接受四次；
被挑戰者弱五點以上、兵力又相當的話一律拒絕——所以「猛將帶寡兵」
去叫陣靠的是後兩條（對方兵力兩倍、五倍）。

接受之後若被挑戰者的戰力 ≥ `RND(5) + 90`，多印一句對白（`0x30d66`）
——那只是台詞，不影響勝負。

### 9.2 拒絕的後果（`0x30de6`–`0x30ef5`，`L0`）

**掉兵的一律是拒絕的那一方（被挑戰者）**：`si` 在 `0x30e31` 設成
`30 × [bp-0x3c]`，三條分支要嘛沿用要嘛重新指回同一個人。

```
被挑戰者的謀略 > RND(10) + 80  → cx = RND(10) − 被挑戰者戰力 ÷ 10 + 50
否則 RND(5) + 被挑戰者戰力 < 挑戰者戰力
                               → cx = 25 − RND(被挑戰者戰力 ÷ 20)
否則                           → cx = 10 − RND(被挑戰者戰力 ÷ 20)
損失 = 被挑戰者的兵士數 ÷ cx；大於 0 就印 DS:0x87ed
```

**`cx` 越小掉得越多**，所以三條的輕重是：謀士拒絕約 2 %、
明顯打不過而拒絕約 4–5 %、**旗鼓相當卻拒絕約一成**——那是怯戰，
軍心散得最快。`[bp-0x2c]` 是挑戰者、`[bp-0x3c]` 是被挑戰者，
由 `0x30e0d` 取 `[bp+0xa]`（對方的軍團）當說話者的顏色定出來。

### 9.3 勝負（`0x30faa`–`0x31212`，`L0`）

**體能（人物 offset 8）就是血條。**

```
回合數 ＝ RND((甲戰力 + 乙戰力) ÷ 2) + 甲戰力 ÷ 7 + 乙戰力 ÷ 7   ; 0x310b6
每回合雙方各算一次：
  分數 ＝ RND(5) + (我方戰力 − 對方戰力) − RND(5) − RND(6) − 4    ; 0x31170
  分數 < 0 → 0
  對方的體能 −= 分數，下限 0                                      ; 0x31212
畫面上的體能條長度 ＝ 體能 ÷ 2，上限 46（0x2e）
```

**期望值是「戰力差 − 6.5」**：`RND(5) − RND(5)` 的平均是 0、`RND(6)`
的平均是 2.5，所以戰力沒有高過對方七點左右就一點都傷不了——
正是說明書寫的「依其戰力強弱分高下，與率領軍力大小無關」。
戰力相同的兩個人打到回合用完也分不出勝負。

每二十回合印一句對白（`0x310e6` 那個 `回合 ÷ 2` 是不是 10 的倍數的
檢查，`RND(3)` 挑一句），從 §10 的對白表裡取。

### 9.4 落敗的處置（`0x31815`–`0x3209b`，`L0`）

迴圈在每一輪開頭查三件事（`0x31815`）：任一方的體能 ≤ 0、或回合數用完，
就跳出。跳出之後：

```
0x318b7  兩邊的體能都 > 0 → 印 SCG29.IMG，平手，什麼都不發生
0x31a48  甲的體能 ≤ 0 → 甲敗；否則乙敗
敗者：
  0x31ab8  es:[0x3502 + (部隊×21 + 將領序號)×2] = 0xFFFF   ; 從部隊裡除名
  0x31b04  RND(7)
           != 0（6/7）→ SCG28.IMG，敗者的槽號寫進勝方的俘虜欄
                        es:[0x1732 + (軍力×10 + 將領)×2]    ; 被擒
           == 0（1/7）→ SCG27.IMG ＋ DS:0x8859「死在%s的刀下」
                        呼叫 2a22:1bf2 的陣亡處理             ; 戰死
```

**被擒 6/7、戰死 1/7**，不是各半。說明書 p.30 只說「可能被擒，或死於
刀下」，沒給比例。

   每一格的低四位是地形碼，**高四位小於 10 的是守方那一槽的起點**；寬圖
   只有 0–6 列（第 6 列奇數欄是圖外），窄圖只有 0–7 欄。remake 把這 1920
   個位元組收成 `skirmishTemplates`，`TestSkirmishTemplatesMatchTheExe`
   逐位元組核對。
3. **攻方的起點寫死在碼裡**（`0x2e228`–`0x2e30d`）——寬圖十槽的欄列
   `(0,3) (1,3) (0,4) (1,2) (1,4) (0,5) (0,2) (1,1) (0,1) (2,3)`，窄圖
   `(3,9) (2,9) (4,9) (3,8) (1,9) (5,9) (1,8) (5,8) (2,8) (4,8)`。
4. 佔位圖照兩方二十槽寫一遍，空槽寫在 `(11,9)`（`0x2e419`，兩種版型都
   是圖外）。

城池與關寨的版型多了地形碼 10–14（城內、牆）：移動力消耗表 `DS:0x7c42`
是 16 格的（`999 999 3 4 6 3 3 2 3 2 2 2 2 999 999 999`；1–9 與說明書
p.29 相同，10–12 是 2，0 與 13–15 是 999），戰力值的地形表在 10 以上
都是 0。尋路把碼 1、13、14 與圖外當成走不過（`0x2f665`–`0x2f6ad`）。

### 10.2 每一時刻（`0x2e498`–`0x2e516`、`0x2e68a`、`0x2e952`）

```
時刻 ← 6
迴圈：
  守方槽 0..9、再攻方槽 0..9：
    0x2e68a() 說結束了 → 跳過（守方或攻方的第 0 槽是 FFFF，或時刻 > 18）
    槽裡有人 → 0x2e952(陣營, 槽)
  時刻 += 1；0x2e68a() 說結束了 → 收尾（§10.7）
```

一位將領的一步 `0x2e952`：

```
剩餘行動力 > 15 → 夾成 15                                  ; 0x2e9b1
體能 < 10 → 自動休息（印 DS:0x86f2）                          ; 0x2ea5b
否則 諸侯記錄 offset 0 == 2（電腦）→ 0x2eb8a，否則 玩家選單 0x2fb14
剩餘行動力 < 移動力 → 補成移動力                             ; 0x2eb6d
```

**休息**（三處同一條：`0x2ec01` 電腦、`0x2eaa2` 自動、`0x2fcf0` 玩家答 Y）：
體能 ＋= 戰力 ÷ 20 ＋ 1，不超過進來時的值；剩餘行動力 ＋= 2。所以休息
會把剩餘行動力累到 15 以上，下一步開頭再夾回 15——實跑量到 11 → 13 →
15 → 17 → 17（§10.8）。

**體能**（`0x323f4(陣營, 槽, n)`，扣到 0 為止）：走一格扣 1（`0x2f4f5`）、
攻擊扣 5、被攻擊扣 3（`0x3040f`／`0x30420`）。

### 10.3 電腦的判斷式與六處骰（`0x2eb8a`–`0x2f28b`）

```
完成旗標 es:0x31c0 ← −1；目標槽 ← −1
RND(30)@0x2ebe5：難度 × 4 ＋ 10 < 骰 → 休息，回                    ; ①
槽 ≠ 0（不是帥）：
  帥的六個鄰格沒有敵人 → 尋路到帥的格，照路走到走不動；走過就回
攻擊搜尋（0x2edb8）：六個方向依序看鄰格
  站著敵人 → 有鄰敵；目標 ← 那一位（**方向順序最後的**）；
             那一位是槽 0 → 敵帥相鄰；兵最多的另記「最強」與其方向
RND(3)@0x2eeee：我方兵 < 最強的兵 ÷ (骰 + 1) → 想逃                 ; ②
  想逃：路徑圖清成 −1；RND(3)@0x2ef90                              ; ③
        方向 ← (骰 ＋ 最強的方向 ＋ 2) mod 6；那一格在圖內且空著就標 0
        走一步（0x2f28e）走得成 → 回；走不成往下
攻擊分支（0x2f067）：
  敵帥相鄰 → 目標 ← 槽 0
  有鄰敵 且 目標是槽 0 → 交手
  否則 RND(16)@0x2f086 == 0 → 交手                                  ; ④
       否則 尋路到敵帥的格，照路走到走不動；走過就回，沒走過 → 交手
交手（0x2f122）：目標 −1 → 休息
  RND(20)@0x2f1b7：我方戰力 > 對方戰力 ＋ 骰 → 單挑 0x30a1e（§9）      ; ⑤
  對方兵 ≤ 我方兵 → 攻擊 0x30364（§10.5）
  對方兵 ÷ 3 > 我方兵 → RND(10)@0x2f265：我方戰力 ＋ 骰 − 5 > 對方戰力 ; ⑥
                        → 單挑，否則休息
  否則休息
```

「沒有鄰敵」時最強的兵是 −1，`−1 ÷ (骰 + 1)` 是 −1 或 0，永遠逃不成
——所以 ② 每一步都擲，③ 只在真的想逃時擲。難度 5 時 ① 的門是 30，
`RND(30)` 最大 29，每一步都行動。

### 10.4 尋路與走一步（`0x2f5d8`、`0x2f28e`）

**尋路** `0x2f5d8(起欄, 起列, 終欄, 終列, 陣營)`：

1. 距離圖 `es:0x2e7c` 全填 9999；圖外、地形碼 1／13／14、**自己這一方**
   站著的格填 −999（敵方站著的格算得過）。
2. 起點填 1；`k` 從 1 起，每一輪把所有距離 ＝ `k` 的格的鄰格（距離 > `k`
   的）填成 `k + 1`，直到沒有格可填（`0x2f71c`–`0x2f7af`）。
3. 路徑圖 `es:0x300c` 全填 −1；終點的距離是 9999 或 −999 → 回 −1，什麼都
   不標。否則終點標 0，從終點往回、`k` 從終點距離減一起，每一步挑
   「距離剛好 ＝ `k`、移動力消耗最低」的鄰格（相同取方向順序在前的，
   `0x2fa8a` 的 `<`），標 0，直到找不到（`0x2f922`–`0x2fb13`）。起點
   （距離 1）也會被標到。

**走一步** `0x2f28e(陣營, 槽, 欄, 列)`：

1. 自己站的格從路徑圖抹成 −1。
2. 六個鄰格裡挑**方向順序最後**一個「路徑圖是 0 而且空著」的；沒有 → −1。
3. 消耗 ＝ `DS:0x7c42[目的格地形碼]`，大於剩餘行動力 → −1。
4. `0x2f3b3`–`0x2f4e5`：對目的格的六個鄰格各看一次「有人就擲
   `RND(20)`@0x2f42b，那一位的兵 > 我方兵 ＋ 骰 → −1」。**但查佔位時用的
   是目的格自己的欄列**（`0x2f408`／`0x2f415`），目的格在第 2 步已經確定
   是空的，所以這一擲從來不會發生、也從來擋不住人（實跑十次走一步零擲）。
5. 扣 1 體能、扣行動力、改佔位與欄列，完成旗標 ← 0，回 0。

### 10.5 攻擊與俘虜（`0x30364(陣營, 槽, 敵陣營, 敵槽)`）

```
對白 0x3273e（RND(8)）；攻方扣 5 體能、守方扣 3；二十幀動畫（不擲）
甲殺傷 ＝ ftol(甲兵 × 甲戰力值 × 0.01)、乙同（§3.5）
甲新兵 ＝ 甲兵 − 乙殺傷；乙新兵 ＝ 乙兵 − 甲殺傷；**< 0 或 > 5000 → 0**
甲新兵 ≤ 0 → 印「我們抓到%s」、等鍵（0x1058:0xe80，會 srand）
             俘虜表[乙陣營 × 10 ＋ 甲槽] ← 甲；甲的部隊槽 ← FFFF；佔位清掉
否則 乙新兵 ≤ 0 → 對稱地抓乙
```

雙方**同時**結算（先算完兩邊的殺傷才扣），攻方被抓就不再看守方。
「> 5000 也歸 0」是這一層的前提——帶八千兵的將領被打一下就被抓，所以
對拍的盤面把將領的兵壓在五千以內。

## 11.5 那幾個函式指標指到哪（`L0` ＋ `L1`、`[base]`）

戰場工作區裡有四個透過指標呼叫的常式，靜態掃不到目標。**指標的值執行期
讀得到**（`TestBattleFunctionPointers`）：四個的段全是 `0x0110`，也就是
§4.0 那張遠指標表指到的同一個**繪圖程式庫碼段**（線性 `0x1100`）。
把碼段 dump 補到 `0x400` 之後，四支都反組譯得出來：

| 指標 | 目標（線性）| 是什麼 |
|---|---|---|
| `es:[0x2e78]` | `0x1166` | 反白開關：參數 `and 1` 寫進 `DGROUP:0x46`（§2.5 已解，這裡當正對照）|
| `es:[0x20ea]` | `0x3239` | **繪製清單的執行器**：參數當索引查 `DGROUP:0x1095` 的指標表取一張清單，逐筆讀三個 word 當參數呼叫 `0x2f0c`，讀到 `0xFFFF` 結束 |
| `es:[0x2e5e]` | `0x2b40` | **畫面頁複製**：對 `0x3ce` 寫 `0x0105`（EGA 圖形控制器的 Graphics Mode ← 寫入模式 1，latch 複製），再把 VRAM 從 `A000` 搬到 `A800` |
| `es:[0x314a]` | `0x2eeb` | **選顯示頁**：`al = 參數 and 1`，`int 10h` `AH=05h` |

後兩支合起來就是**雙緩衝**：畫在一頁、複製、翻頁。remake 用 Ebiten 的
畫面緩衝，這一層**沒有東西要移植**——不是還沒讀，是不需要。

### 12.1 九支的判斷式（`L0` ＋ `L1`、`[base]`；Issue #22，2026-09-15）

上面是「哪一支做什麼」，這一節是「什麼條件選哪一支」。碼在
`workplace/dump/code-00b000.bin`（執行期碼段，`0x29014`–`0x2a224`），浮點
段照 `docs/re/03` §1.4 的對照把 `INT 34h`–`3Dh` 換回 ESC 位元組讀。
remake 的 `internal/battle/autobase.go` 逐條照做；對拍
`TestZZUnitAIDayParity`（四張盤面 133 次決策，選項、目標、落點逐次相同）。

**共用的資料**（段值全是 `ds:[0xa92e]`…`ds:[0xa97e]` 那一批，實測都是
戰場工作區 `0x3e64`）：部隊記錄 `0x3502`＋42×(軍力×10＋隊伍)，六方向位移
表 `DS:0x7c6a`（欄）／`DS:0x7c82`（列），偶欄用前六格、奇欄用後六格
（與 remake 的 `Dirs()` 同序）；佔位圖 `0x2532`（列×12＋欄，`0xFFFF` 空，
否則 軍力×10＋隊伍）；地形圖 `0x163a`（低四位地形碼）；「敵我」的判準
一律是 `佔位 ÷ 20 != 軍力 ÷ 2`。

**選項 1 評估前置**（`0x29e78`）：

```
S ＝ 100 × (軍力 0 的 +14 ＋ 軍力 1 的 +14) ＋ 1        ; 守方兵士（百）
A ＝ 100 × (軍力 2 的 +14 ＋ 軍力 3 的 +14) ＋ 1        ; 攻方
es:0x1bf0 ＝ 攻方 ? S÷A : A÷S                           ; 敵方總兵力 ÷ 我方
es:0x1610 ＝ 1.0
es:0x31a8 ＝ es:0x1604 ＝ 0xFFFF                        ; 目標軍力／隊伍
es:0xa6   ＝ 0xFFFF；城池格（es:0x584／0x586）站著我方 → 0；
            軍力的 0 號隊伍（帥）旁邊有敵人 → 0xFFFF；軍力是奇數（助軍）→ 0xFFFF
本隊六個鄰格裡的敵軍照方向收進清單 → 沒有就回 −1
pick ＝ RND(清單長度)；清單裡有隊伍 0（帥隊）就改挑它（後面的蓋前面的）
目標 ＝ 清單[pick]；es:0x1610 ＝ (目標兵士＋1) ÷ (本隊兵士＋1)
```

`es:0xa6 == 0` 的意思是「主軍、守著城池、主帥沒被貼身」，後面三支拿它
切換保守／積極。

**選項 2 退兵**（`0x29138`）：鄰格有敵軍才算；M ＝ 鄰格敵軍裡兵士最多的；
`本隊兵士 ≤ M ÷ (4 ＋ RND(2))` 才繼續（`0x292e2` 的 `cmp`＋`jle`，**有號**
比較）；`RND(8) ＋ 3 ≤ es:0x1bf0` 才繼續（`0x29307` 的 `fcom`＋`jbe`）；
最後退兵常式 `0x23dd4(軍力, 隊伍, 0)` 回 −1 就不成立。那一支列的是
戰場所在郡（`es:0x1bf8`）的鄰郡裡**無主或本勢力**的、本隊將領數＋該郡
現役武將數 ≤ 50 的、而且不是**對方助軍出兵郡**（軍力記錄 offset 18，
守方看軍力 3、攻方看軍力 1）的郡；一個都沒有就印 `DS:0x7ca4`「無郡可逃」。

**選項 3 移動**（`0x29344`）：`es:0xa6 == 0` 時多一道門——城池格上我方
部隊的兵士÷100 大於城池六個鄰格敵軍兵士÷100 的和（`0x296aa`）就不動。
然後三段：

```
0x24842(軍力)   距離圖 es:0x2e7c：大山（地形碼 1）／圖外（0xFF）／我方部隊
                佔的格 ← −999（0xfc19），其餘 ← 9999（0x270f）
0x29425         城池格無條件 ← 9999
0x24918(欄,列)  從本隊那一格 BFS：本隊 ＝ 1，每一輪把「值 > 目前層」的鄰格
                寫成層＋1，直到沒有格子被寫
0x24b1a(城池)   目標的值是 9999 或 −999 → 回 −1（沒有路）；否則從目標倒
                著走：每一步在六個鄰格裡挑「值剛好等於目前層 − 1」的、
                地形移動花費（DS:0x7c42）最小的那一格（先到先贏），
                寫進路徑圖 es:0x300c（0 ＝ 在路上）
0x294ae         走一步：本格的路徑圖 ← −1；六個鄰格裡「路徑圖 0 而且
                佔位空」的**最後一格**；地形花費 > 剩下的移動力（offset 36）
                就停；否則扣移動力、改欄列、改佔位圖、es:0x31c0 ← 0
                重複到走不動為止
```

**行軍目標永遠是城池**：`es:0x584`／`0x586` 只在開戰時掃一次地形碼 5
（`0x23afe`–`0x23b54`），之後沒有別的寫入端（整段碼掃 `mov es:0x584,…`
只有這一處）。加強版的 `0x26758` 才會在難度 ≥ 11 時換目標（§8.2）。

**選項 4 弓箭**（`0x2985c`，門 `RND(2)==0`）：offset 20 的箭數 > 0；六個
方向各**同方向連走兩步**（第一步之後照新的欄奇偶重取位移），落點在圖內
且有部隊、**中間那格**的地形碼查 `DS:0x80d4` 是 1（大山／城池／關寨是 0）、
落點是敵軍 → 候選存進 `es:[0x1ece＋方向×2]`（照方向存，不是壓縮存）；
`pick ＝ RND(候選數)`，帥隊優先，`pick` 指到空槽就 `(pick＋1) mod 6` 往後找；
射箭常式 `0x2a80a(軍力, 隊伍, 目標軍力, 目標隊伍, 1, 第一步的欄, 列)`；
本隊移動力 ← 0。

**選項 5 策略**（`0x29784`，門 `RND(3)!=0`）：`k ＝ RND(6)`（火攻、水淹、
陷阱、誘敵、燒糧、圍攻）；軍力記錄的金（offset 6）≥ `DS:0x7f62[k]`
（600／500／100／400／300／200）；`人物[部隊 offset 38].謀略 ≥ DS:0x7f6e[k]`
（80／75／60／60／70／65）；`0x2bee8`（天候與位置，§4.0）不是 −1；然後
`0x2abb8` 判定（成敗都先扣金）。

**選項 6 死戰**（`0x29c56`，門 `RND(4)==0`）：`es:0x1610 ≤ DS:0xa964 ＝ 0.23`
（`0x29c6d` 的 `fcom`＋`jbe`）；本隊站在城池或關寨（地形碼 5／6）時目標
隊伍要是 0（帥隊）；`模式 ＝ 難度 ÷ 5`，反覆 `0x2a224(…, 模式)` 直到
一方將領數（offset 28）為 0；本隊移動力 ← 0；本隊還有將領就把欄列改成
目標的（佔進去），重畫。

**選項 7 對戰**（`0x29b82`，門 `RND(16)==0`）：`RND(100) ＋ 本隊兵士÷2 ≥
目標兵士`（有號）；`es:0xa6 == 0` 時另要 `es:0x1bf0 < DS:0xa95a ＝ 0.4`
（`0x29c13`）；然後 `0x2deb0(軍力, 隊伍, 目標軍力, 目標隊伍)` 進對戰子畫面。

**選項 8 快戰**（`0x29ade`，無門）：`es:0xa6 == 0` 時要 `es:0x1bf0 < 0.4`
（`0x29b00`），否則無條件；`模式 ＝ 難度 ÷ 5 ＋ 1`，`0x2a224` 一次。

**選項 9 休息**（`0x29e2e`）：offset 36 ＋2，上限 15（`0x29e5f`）。

**骰的順序就是上面的順序**：選項 1 的 `RND(清單長度)`（有鄰敵才擲）、
選項 2 的 `RND(2)`（有鄰敵才擲）與 `RND(8)`（過第一道門才擲）、選項 4 的
門、選項 5 的門與 `RND(6)`、選項 6 的門、選項 7 的門與 `RND(100)`。移動
那一支有一道 `RND(0)`（`0x29384`）——回 0 而且不動種子。

⚠ **部隊兵士數是有號 16 位元**：兩位將領各兩萬七的部隊（53,984）在
`cmp`＋`jle` 眼裡是負的，選項 2 的「被壓倒」門會過（盤面丙量到的）。
remake 的 `s16` 照做。**軍力記錄的「兵士（百）」也跟著它**：重算那一支

32 位元累加（`0x252e9`–`0x252ed`）再除以 100（`0x25336`），所以負的部隊
把整個軍力的總數拉小，選項 1 的總兵力比跟著偏大（加強版盤面丙量到：
remake 用全寬相加算出 0.04、原版是 0.51，那一天的移動判斷就分家）。
remake 的 `armyHundreds` 逐支 `s16` 再加。兩版同一支碼。

### 12.3 回合常式與日循環（`0x24cf6`／`0x23bbb`，`L0`、`[base]`）

日循環（`0x23bbb`–`0x23c5a`）：

```
天數 ← 1（es:0x2100）；天候 ← RND(3)（0x23b78）        ; 0 晴 1 雨 2 風
每天：
  軍力 0..3（主守、助守、主攻、助攻）：
    隊伍照 DS:0x7c9a 的順序（先鋒、左、右、中、後）：
      0x26fc6(軍力, 隊伍)   重算綜合能力（offset 32）
      0x24cf6(軍力, 隊伍)   這支的回合
      0x24f20、0x24f8c      統帥條件
  0x25030 糧草、0x250d4 三十天、天數 +1
  0x26f48：RND(10) > 5 才重擲天候 RND(3)；四個軍力五支部隊的 offset 40 各減一
```

一支部隊的回合（`0x24cf6`）：

```
0x24d03  0x2514c 重算
0x24e71  offset 26（陷阱倒數）> 0：印「不能動」、減一、跳到回填
0x24eb0  諸侯記錄 offset 0 == 2（電腦）→ 決策鏈 0x29014；否則玩家命令迴圈 0x2799e
0x24edb  0x27604 投敵判定（下段）
0x24ee1  offset 36 < offset 34 → offset 36 ← offset 34      ; 回填移動力
```

**回填是每一支自己的回合結束時做，不是一天結束時**——所以「休息多加的 2
留得住」（§7.0 量到的上限 12、剩下 14）是因為回填取 `max(剩下的, 上限)`。
電腦的快戰（`0x29ade`）、計謀（`0x29784`）、對戰（`0x29b82`）**不碰 offset
36**，只有弓箭（`0x29aca`）與死戰（`0x29dc7`）歸零；玩家那一邊快戰
（`0x280e1`）、死戰（`0x28822`）、弓箭（`0x28ac0`）、對戰（`0x29009`）歸零，
計謀不歸零。

**綜合能力每天重算**（`0x26fc6`，每支輪到之前；招降讓空部隊重新有人時也
叫一次 `0x25e1a`）：

```
逐將領：v ＝ ftol((武裝 × 5 ÷ 20 ＋ 訓練 × 0.05 ＋ 戰力 × 14 ÷ 20) × 兵 × 0.01 ＋ 0.5)
        S ＋= v；N ＋= 兵
N > 0：offset 32 ＝ ftol(S ÷ N × 100 ＋ 0.5)；否則 0
```

兩個 `÷ 20` 是 `idiv`；常數 `DS:0xa8e4` ＝ 0.05、`DS:0xa8d2` ＝ 0.01、
`DS:0xa8ec` ＝ 0.5、`DS:0xa8f4` ＝ 100.0。**謀略不在裡面**——§3.3 那條
`Σ(謀略×2÷5＋戰力×3÷5)÷將領人數` 是整編寫進去的初值，第一天輪到之前
用的還是它（守方先動，所以守方第一天的交戰讀到的攻方值是整編的那一個）。
盤面甲實跑逐條相同（`L1`）。

**投敵判定**（`0x27604`，每支回合結束時，玩家的部隊也判）：從第 9 槽往
第 0 槽，統帥（軍力記錄 offset 0）跳過：

```
RND(5) != 0 → 下一位                                  ; 0x276a3
對方主軍勢力的人望 ÷ 2 > 這一位的忠誠 才往下           ; 0x276e7–0x276f5，忠誠 cbw（在野 0xFF ＝ −1）
對方主軍的將領數（軍力 offset 12）≥ 50 → 下一位         ; 0x276fe
對白（0x27768）→ 這一格 ← 0xFFFF → 0x25cd2 加入對方主軍，忠誠 ＝ min(100, 100 − 原忠誠)
```

「對方主軍」是守方兩軍看主攻軍（軍力 2）、攻方兩軍看主守軍（軍力 0）
（`0x27642`：`((軍力 ≫ 1) ^ 1) ≪ 1`）。人帶著兵走（`0x25cd2` 把人物的兵
加進那支部隊的 offset 30）。盤面甲量到（`L1`）：第 7 天守方兩位（忠誠
0xFF）先後投奔玩家，第 8 天守方只剩三支有決策。

**加入部隊**（`0x25cd2(軍力, ?, 人物, 忠誠)`，招降與投敵共用）：忠誠夾 100
寫進人物 offset 16；身分是軍師（1）的把舊主的軍師欄清成 `0xFFFF`；身分 ← 3、
勢力 ← 捕獲方、所在郡 ← 戰場那一郡；五支部隊由前往後看，**最後一支**將領
數不到 10 的收下他（槽位 ＝ 將領數，將領數 +1，兵加進 offset 30）；那一支
本來是空的就重新初始化（`0x2731a`、`0x26fc6`、`0x270f8`、`0x27226`——後三支
之外還沒讀）。

**退兵的去處**（`0x23fb5`–`0x24030`）：對白之後，電腦的部隊——主守軍
（軍力 0）以外的軍力，出兵郡（軍力記錄 offset 18）的現役武將 ＋ 本隊將領
數 ≤ 50 就直接回出兵郡，不擲；主守軍或裝不下就 `RND(鄰郡數)`
（`es:0x17c4`，`0x2401b`）從 `es:0x2102` 的清單挑一郡。玩家出清單問人。

**天候**：開場 `RND(3)`（`0x23b78`），之後每天 `RND(10) > 5` 才重擲。所以
「火攻要刮風」一場裡大約每兩天換一次牌。

### 12.4 被擒處置（`0x259fe`，`L0`、`[base]`）

交戰結算收尾走兩張俘虜表（`0x2a7a3`／`0x2a7d2`）：**先出手方打光的將領
（由承受方處置）、再承受方的（由出手方處置）**，各照槽位 0 → 9。表在扣兵
時填（`0x2a5e9`／`0x2a6bf`），扣兵本身從第 9 槽往第 0 槽。**承受方的第 0
槽在出手方打光時留下**（`0x2a684`–`0x2a68e`：出手方的將領數在迴圈裡逐一
遞減，歸零之後承受方第 0 槽兵扣到 0 也不除名）——兩支不會在同一次結算
裡一起消失，留下的那一位兵是 0、下一次結算再被俘。

`0x259fe(捕獲方軍力, 人物)`：印「我們抓到 %s」，然後

```
捕獲方諸侯記錄 offset 0 == 2（電腦）：
  RND(10) < 2 → 斬首，否則囚禁                       ; 0x25a93
  0x25e50 招降判定 > 0 → 招降
  人物 offset 17 == 0（君主）→ 斬首
否則（玩家）：讀鍵 1–4
斬首 0x25f6a：對白
囚禁 0x260dc：對白、特效
釋放 0x262b8：對白、特效（電腦不會選）
招降 0x25b94：再判定一次 0x25e50，≤ 0 → 對白「不從」、回 −1 → 從頭再來
              > 0 → 對白、特效、0x25cd2 加入
```

招降判定 `0x25e50(捕獲方勢力, 捕獲方軍力, 人物)`：

```
君主 → 0
捕獲方軍力的將領數（offset 12）≥ 50 → 0
門檻 ＝ max(戰力, 謀略)；牽絆對象（offset 14）不是自己而且與自己同勢力 → ＋1000
門檻 ÷= RND(3) + 1                                     ; 0x25edf
捕獲方的人望 < 門檻 → 0
回 clamp(ftol((100 − 忠誠 ÷ 2) × 人望 × 0.01), 0, 100)   ; 招降後的忠誠
```

實跑只走到「君主被擒 → `RND(10)` → 斬首 → 對白」（`10@25a98 8@32d52`，
盤面甲乙丙戊各一次）；其餘分支是 `L0`。remake：`battle.capture`／
`surrenderChance`／`enlist`，玩家捕獲的不在戰場上處置（留給戰略層問，
registered remake 差異）。

## 出兵怎麼把錢糧與部隊搬走（2026-09-10，`L0`）

電腦的出兵在郡回合裡由分派表第 18 張（`0xec1b`）發動，執行的常式入口是
**`0x1938a`**（線性位址），四個參數：來源郡、目標郡、金、米。

```
1938a: push %bp; mov %sp,%bp
       迴圈：名單裡每一位將領
193a4:   mov   $0x1e,%ax               ; 30 ＝ 人物記錄大小
193a7:   imulw %es:0x58c(%bx)          ; × 名單裡的槽號
193b5:   mov   %al,%es:0x2223(%bx)     ; 0x2223−0x2210 ＝ 19 ＝ 所在郡 ← 目標郡
       之後：
193da:   sub   %ax,%es:0x492(%bx)      ; 來源郡的金 −= 金（0x492−0x480 ＝ 18）
193df:   jns → 否則 movw $0x0          ; **不能變負，夾 0**
193f3:   sub   %ax,%es:0x494(%bx)      ; 來源郡的米 −= 米（offset 20）
1940c:   add   %ax,%es:0x492(%bx)      ; 目標郡的金 += 金
```

實測（`TestZZSortieSupplyTiming`，攔函式入口讀參數）：

    郡 6 → 4   金 8000   米 3045   呼叫端 0x0B9F8   接在「分派表：出兵」之後
    郡 2 → 1   金 4292   米  630   呼叫端 0x0B9F8

月流程的時間軸（結算 → 第一個郡）證實它**在郡自己的回合裡**，不在開月階段：

    1 月底結算 → 2 重算所屬 → 3 開月 → 4 月份推進 → 5 四季分派器
    → 6 冬季事件 → 7‥22 進貢×16 → 23 郡回合入口 → 24 重算所屬
    → 25 分派表：出兵 → 26 ★搬運(郡 6 → 4) → 27 郡的分派器 → …

### `[HARD]` 三個把這一條追歪的坑

1. **`o.ToIDA()` 回的是 IDA 位址，不是映像位移**，兩者差 `0xEF00`
   （寫入者 IP `1538:405F` 的線性位址是 `0x193DF`，`ToIDA` 給 `0x282DF`）。
   拿 IDA 位址去 `objdump --adjust-vma=0xb000` 會讀到**完全不相干的碼**，
   而那段碼一樣讀得通——第一版就這樣把「搬運金米」誤讀成「部隊記錄的
   迴圈」，還據此寫下「原版在月底結算之後才搬」的錯結論。
   **攔截點與反組譯一律用線性位址。**
   露餡的是攔截次數：那個函式入口攔起來 **0 次**——真的是它的話不可能。

2. **`o.Arg(n)` 讀的是 `[SS:SP + 4 + n*2]`，假設剛進入函式**（bp 還沒 push）。
   攔在函式中間時 SP 早就變了，讀到的是垃圾（實測「郡 1864 → 2859」）。
   這個錯自己會露餡，因為郡號超出 0–42。

3. **`0x174f3` 不是「郡回合開始」**。`month_parity_test.go` 的 `startLog`
   在那裡記金米並標成「回合開始時」，而時間軸顯示它排在**出兵搬運之後**
   ——記到的是搬走之後的值。拿它跟 remake 的「`ActPrefecture` 之前」對照
   等於比兩個不同時刻，會憑空生出一個 8000 金的假差異。
