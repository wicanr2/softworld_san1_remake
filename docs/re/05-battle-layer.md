# 戰術層的程式碼與資料（`AA.EXE`）

推論等級與版本標在每一節。位址是**執行期線性位址**，取自開機之後
`0x00b000`–`0x050000` 的碼段 dump；資料段（DGROUP）在 `0x0427e0`，
所以 `DS:xxxx` 的線性位址是 `0x0427e0 + xxxx`。

兩份 dump 由 `internal/parity` 的 `TestZZDumpCode` 與
`TestZZDumpBattleCode` 產生，寫到 `SAN1_DUMP` 指的目錄。

## 1. 入口與盤面（`L0`、`[base]`）

戰鬥是一支普通的遠呼叫，**不是 overlay**：

```
2020:0000 ＝ 線性 0x20200
battle(攻方郡, 攻方援郡, 守方郡, 守方援郡)
```

玩家的「發動戰役」在 `0x18bb9` 呼叫它，兩個援軍格填 `0xFFFF`
（`docs/re/03` §1.5）。四個參數是**兩郡對兩郡**：進去第一件事就是掃
1..42，把不在這四格裡的郡交給 `es:[0x20ea]` 處理掉（`0x2021e`）。

主戰場是 `0x2053c`。它開頭做三件事：

```
20588: es:[0x1bf8] ← 守方郡                ; 戰場設在守方
20593: for 列 = 0..9, 欄 = 0..11:
         es:[0x163a + 列×12 + 欄] ← 州郡[守方郡].[0x4b7 + 列×12 + 欄]
205fd: 0x20770(攻方郡,   2)                ; 四個軍團依序編成
2060b: 0x20770(攻方援郡, 3)
20618: 0x20770(守方郡,   0)
20626: 0x20770(守方援郡, 1)
```

`0x4b7` 減掉州郡表的基底 `0x480` 是 **55**，所以那 120 個位元組就是
州郡記錄 offset 55–174（`docs/spec/003` §3.3）。陣營碼 0、1 是守方，
2、3 是攻方。

## 2. 戰場地圖（`L0`、`[base]`）

### 2.1 版面

12 欄 × 10 列，索引 `列 × 12 + 欄`。畫格的座標在 `0x22742`：

```
x ＝ 48 × 欄 + 56
y ＝ 32 × 列 + 36        ; 奇數欄再 +16
```

**奇數欄往下移半格**，也就是六角格的 odd-q 排法。走訪鄰格用
`DS:0x7c6a`（dx）與 `DS:0x7c82`（dy）兩張表，索引
`(欄的奇偶 × 6 ＋ 方向) × 2`（`0x24c11`）：

| 方向鍵 | 4 | 5 | 6 | 1 | 2 | 3 |
|---|---|---|---|---|---|---|
| dx | −1 | 0 | +1 | −1 | 0 | +1 |
| dy（偶數欄）| −1 | −1 | −1 | 0 | +1 | 0 |
| dy（奇數欄）| 0 | −1 | 0 | +1 | +1 | +1 |

畫面上的鍵盤配置就是 `4 5 6` 在上、`1 2 3` 在下（`DS:0x7f9e`）。

劇本 001 的 42 個郡只有兩種形狀：**12 欄 × 7 列**（21 個郡，最後一列
只有偶數欄）與 **8 欄 × 10 列**（21 個）。兩種都塞得進 640×350。

### 2.2 一格是兩個半位元組

```
低四位 = 地形     高四位 = 標記     0xFF = 圖外
```

畫的時候低四位當底圖的圖塊編號直接畫（`0x2277b`，大於 10 就不畫），
高四位小於 10 的再疊一層：拿它去索引州郡記錄 `0x4ad`（＝ offset 45，
相鄰表），把那個鄰郡的名字印在格子上（`0x227b8`）。

| 高四位 | 意思 |
|---|---|
| 0–9 | 通往相鄰表第 n 格那個郡的通道 |
| 10 | 城池 |
| 11–14 | 四個軍團的起點，對應 `0x20770` 的陣營碼 0–3 |
| 15 | 沒有標記 |

**一個通道是一片格子不是一格**：遼東通往鄰郡的通道佔五格。
標記 10–14 則是每張圖各一格，42 個郡都成立。

### 2.3 地形碼

| 碼 | 地形 | 移動力（`DS:0x7c42`）| 攻（`DS:0x85c2`）| 守（`DS:0x85e2`）|
|---|---|---|---|---|
| 1 | 大山 | 999（過不去）| 0 | 0 |
| 2 | 山丘 | 3 | 20 | 22 |
| 3 | 淺水 | 4 | 8 | 9 |
| 4 | 深水 | 6 | 6 | 8 |
| 5 | 城池 | 3 | 27 | 40 |
| 6 | 關寨 | 3 | 25 | 30 |
| 7 | 平原 | 2 | 20 | 17 |
| 8 | 樹林 | 3 | 16 | 22 |
| 9 | 沙漠 | 2 | 15 | 16 |

移動力那一欄與**說明書 p.29 的表逐格相同**，兩份互為佐證。
對照是這樣定下來的：

- 碼 1 在 `0x24895` 被單獨挑出來當成走不進去（與圖外同值），
  而說明書只有大山「無法穿越」。
- 碼 5 在每一張圖上剛好出現一次，位置就是標記 10 那一格 → 城池。
- 剩下七個碼的移動力互不相同或成對，把手冊那張表套上去只有一種排法
  對得起來（2/2 ＝ 平原沙漠，3/3/3 ＝ 山丘樹林城寨，4 ＝ 淺水，6 ＝ 深水）。
- 平原與沙漠都是 2，用出現次數分：碼 7 有 777 格遍佈 42 個郡，
  碼 9 只有 10 格而且**全部在武威**——河西走廊的郡。
- 山丘與樹林都是 3，用攻守表分：碼 8 的攻 16 低於平原、守 22 高於平原，
  正是「相當不錯的防禦掩護」；碼 2 兩邊都不低於平原。

**第三條證據是原版自己畫出來的顏色。** 把原版驅動進廬陵的戰場、
照解出來的座標取每一格中心 32×22 像素的顏色（扣掉配色用的黑），
主色的分佈是：

| 碼 | 地形 | 主色 |
|---|---|---|
| 1 | 大山 | 亮紅 32%、褐 24%、暗紅 20%、**白 11%**（雪頂）|
| 2 | 山丘 | 亮紅 43%、暗灰 30%、黃 9%（**沒有白**）|
| 3 | 淺水 | 亮藍 60%、青 39% |
| 4 | 深水 | 暗藍 60%、青 39% |
| 7 | 平原 | 綠 44%、亮綠 36%、黃 10% |
| 8 | 樹林 | 暗灰 30%、黃 17%、**綠 15% ＋ 亮綠 14%**（樹冠）|

大山有雪頂而山丘沒有、樹林有樹冠而山丘沒有、深水比淺水暗——
三對都分得開，而且與前兩條證據指向同一個排法。

`DS:0x80d4` 是另一張依地形索引的布林表，`1 大山`、`5 城池`、`6 關寨`
是 0，其餘是 1——開闊地與構造物的分界，用在 `0x28a5d` 與 `0x2999a`
兩處的閘門（用途未解，`L3`）。

攻守那兩張表在 `0x2df44`／`0x2df8d` 分別用**攻方所在格**與**守方所在格**
取值，參與每一位將領的戰力值（§3.1）。

### 2.4 走一格要花多少

取 `DS:0x7c42` 那一格的值，直接跟部隊剩下的移動力比
（`0x27e71`，部隊記錄 offset 36），**中間沒有任何按兵種的調整**。
說明書 p.30 的「移動力來源是訓練度和兵種能否適應地形」講的是
移動力本身（§3.2）與兵種在戰力上的加成（§3.1），不是每一格的花費。

## 3. 戰力與移動力（`L0`、`[base]`）

`0x2deb0(攻方軍團, 攻方部隊, 守方軍團, 守方部隊)` 是**對戰的前置**：
它對雙方每一位將領各算兩個值，再把畫面交給 `2020:1616`。

### 3.1 一位將領的戰力值

```
0x2e13a 攻方 / 0x2e01a 守方（兩段對稱）
  fild  人物.offset 10（戰力）
  fmul  7.0                       ; DS:0xa9fc
  fiadd 3 × 人物.offset 25（武裝度）
  fimul 兵種適性[人物.offset 21][地形] + 地形值
  fmul  0.001                     ; DS:0xaa04
  lcall 05c4:4d60                 ; 轉成整數
  → es:[將領槽 × 2 + 0x55c]（攻方）／`0x548`（守方）
```

也就是

```
戰力值 ＝ (戰力 × 7 + 3 × 武裝度) × (兵種適性 + 地形值) ÷ 1000
```

地形值攻方取 `DS:0x85c2`、守方取 `DS:0x85e2`，兩邊各用**自己所在
那一格**的地形。**兵種適性表在 `DS:0x8602`**，七個兵種各 16 格：

| 兵種 | 山丘 | 淺水 | 深水 | 城池 | 關寨 | 平原 | 樹林 | 沙漠 |
|---|---|---|---|---|---|---|---|---|
| 陸 | | | | | | 5 | 5 | |
| 山 | 10 | | | | | | | |
| 水 | | 10 | 10 | | | | | |
| 山陸 | 10 | | | | | 5 | 5 | |
| 水陸 | | 10 | 10 | | | 5 | 5 | |
| 山水 | 10 | 10 | 10 | | | | | |
| 強力 | 12 | 13 | 15 | 8 | 8 | 6 | 6 | 5 |

正好是說明書 p.18 那句話的數字版：「山、陸、水各代表在山丘、平地
或水域有優良戰力」，而「強力軍是萬能兵種……也更能發揮地形特性」
——強力軍每一種地形都有，水上還高過水軍。大山誰都沒有加成。

### 3.2 移動力

同一支常式接著算（`0x2e07a`）：

```
移動力 ＝ min(15, (訓練度 − 武裝度 + 100) ÷ 10 + 1)
```

上限 15 寫死在 `0x2e08f`。訓練度愈高愈遠、武裝度愈高愈近，
與說明書 p.29–30 的兩句話同向。範圍 1–15；訓練 0、武裝 100 的部隊
移動力是 1，而最便宜的地形要 2——**原版就是讓這種部隊動不了**。

### 3.3 部隊記錄的欄位

| 位移 | 欄位 |
|---|---|
| 0–19 | 十個將領的人物槽號，`0xFFFF` ＝ 空 |
| 22 | 欄（x）|
| 24 | 列（y）|
| 36 | 這一天剩下的移動力 |

格子索引是 `列 × 12 + 欄`（`0x2df20`、`0x27e91`）。

## 4. 軍團與部隊（`L0`、`[base]`）

`0x20770(郡, 陣營碼)` 編成一個軍團：

```
軍團記錄 22 bytes，四個，基底 es:[0x175e]
部隊記錄 42 bytes，每個軍團 5 個，基底 es:[0x3502]
  offset 0–19：十個武將編號，清成 0xFFFF
  offset 28、30：清成 0
郡編號不在 1..42 → 回 0xFFFF（沒有這個軍團）
```

一場最多 **4 個軍團 × 5 支部隊**，與整編畫面的「將%s分到那一軍(1-5)」
（`DS:0x7a60`）對得起來。

## 5. 介面字串（`L0`、`[base]`）

戰術層的字串都在 DGROUP，位移是**執行期的 DS 位移**（與
`docs/re/04` 的檔案位移不是同一組數字）。主要幾條：

| DS 位移 | 內容 |
|---|---|
| `0x797d` | `進行%s團整編` |
| `0x798b`／`0x79af` | `攜帶多少金`／`攜帶多少米` |
| `0x79a0` | `30日須耗用%d米` |
| `0x7a3a`／`0x7a60` | `分配那一位將軍(1-%d):`／`將%s分到那一軍(1-5):` |
| `0x7f02` | `%s主公請下%s(%2d)%s的命令(0-8):` |
| `0x7f22`–`0x7f4c` | `1.移動 2.對戰 3.快戰 4.死戰 5.弓箭 6.策略 7.查看 8.退兵 0.休息` |
| `0x8113`／`0x8128` | `1.火攻 2.水渰 3.陷阱 4.誘敵 5.燒糧 6.圍攻` |
| `0x7fef` | `查看敵軍須10金!` |
| `0x7d49`／`0x7d57` | `1.斬首 2.囚禁 3.釋放 4.招降` |
| `0x7cad`／`0x7ca4` | `%s逃向那一郡`／`無郡可逃` |

## 6. 怎麼把原版驅動進戰鬥

`internal/parity` 的 `TestZZBattleKeySweep` 與 `TestZZDumpBattleCode`：
開機一次（兩分半）、`stageABattle` 直接寫記憶體擺盤面、存快照，
之後每個候選按鍵序列還原重試（十秒）。打得起來的最短序列是

```
2 ⏎ 2 ⏎ <出兵郡> ⏎ <目標郡> ⏎        ; 軍事 → 發動戰役 → 從哪 → 打誰
⏎ 1 ⏎ 1 ⏎ N 2 ⏎ 1 ⏎ Y                ; 守方（兩位將）整編
⏎ 1 ⏎ 1 ⏎ Y <金> ⏎ <米> ⏎ Y          ; 攻方（一位將）整編
```

**整編**（`0x20a30`）每個軍團一輪，順序是主守 → 助守 → 主攻 → 助攻，
援軍格是 `0xFFFF` 的直接跳過：

```
進行%s團整編 → 請按任一鍵（1058:0e24）
0x20d26      → 分配那一位將軍(1-n) ⏎ → 將%s分到那一軍(1-5) ⏎
               → 分配完畢(Y/N)：N 再分一位，Y 收工
陣營碼 0（主守軍）→ 錢糧直接取郡的全部，不問（0x20ac3）
其餘         → 攜帶多少金 ⏎ → 攜帶多少米 ⏎ → 確認(Y/N)
```

打到這裡畫面就是主戰場，提示是
`(%2d%s)%s之%s請%s將軍紮寨` ＋ `數字鍵選方向`。

**每一個提示都要 Enter，選單也一樣**——欄寬由上限決定，一位數的選單
欄寬是 1，滿了之後多打的數字被直接丟掉（`docs/re/03` §1.5 的按鍵表）。

判準是 `0x18bb9`（呼叫戰鬥）或 `0x2053c`（進主戰場）被執行到，
不是畫面看起來對。

### 3.4 一次交戰的傷亡（`0x30560`，`L0`）

雙方**同時**算，各自套到對方身上：

```
0x3059f: es:fild 人物[甲].offset 22（兵士數）
0x305a9: fimul  es:[bx+0x548]        ; 戰力值
0x305ae: fmul   0.01                 ; DS:0xaa3c
         → 甲的殺傷
（乙同一套，0x305f9–0x3060c）

0x30618: 乙剩下的兵 ＝ 乙的兵士數 − 甲的殺傷
0x306bb: 甲剩下的兵 ＝ 甲的兵士數 − 乙的殺傷
         結果 < 0 或 > 5000 → 歸 0
0x30716: 兵歸 0 → 印 DS:0x87b5「我們抓到%s」
```

也就是

```
殺傷 ＝ 兵士數 × 戰力值 ÷ 100
```

**不看對方的防禦力**——地形對守方的保護走的是守方自己那一份戰力值
（§3.1 用守方所在格的 `DS:0x85e2`），交手是對稱的，不是攻減防。
一位將領最多 5000 兵；兵打光的將領被俘（`1.斬首 2.囚禁 3.釋放 4.招降`）。

`es:[bx+0x548]` 的索引是 `(10 × 陣營 + 將領槽) × 2`，**陣營在這裡只有
兩格**：`es:0x3ef0`／`es:0x34fa` 是 `0 ＝ 守方、1 ＝ 攻方` 的兩格陣列
（`0x2dee9`–`0x2df04` 寫進去，`0x30567`／`0x3057a` 讀出來）。所以

```
守方第 n 位將領 → 0x548 + 2n
攻方第 n 位將領 → 0x548 + 20 + 2n ＝ 0x55c + 2n
```

正好接上 §3.1 那兩個寫入端——`0x548` 與 `0x55c` 本來就是同一個
二十個字的陣列。

## 7. 還沒解

  透過函式指標呼叫的常式。
