# 主程式（`DATA5.GRP`）的程式碼地圖

已經辨識出來的常式。位址有兩種寫法：

- **映像位移**：把 `DATA5.GRP` 載到 `0110:0000` 之後，從 `0110:0000` 起算的
  位元組位移。這是**穩定的**，跟執行期段值無關。
- **執行期 `段:位移`**：那一次跑到的值，只用來對照軌跡。

取得方式在 `docs/re/01`：用 dosgolem 把解壓後的映像 dump 出來，
再用 `objdump -b binary -m i8086` 逐段對讀。

## 1. 三張表是一個結構

主程式把劇本的三張表原封不動連續載進記憶體，用同一個 `ES` 加固定位移取用：

| 表 | 結構位移 | 大小 |
|---|---|---|
| `BASEMAS` | `0x0000` | 1,152 |
| `BASESTA` | `0x0480` | 7,568 |
| `BASEGEN` | `0x2210` | 10,500 |

所以 `mov al, es:[si+0x2219]` 這種指令直接就是「人物記錄的第 9 個 byte」。
掃描全映像的 `es:[si+disp]` 就得到程式碰過哪些欄位——欄位版面因此可以
**從程式碼推出來，不必猜**（`docs/spec/003`）。

## 1.1 誰寫哪一個欄位（`L1`、`[base]`）

執行期量的：讓執行器在寫入落進三張表的範圍時記下當時的 `CS:IP`，
跑一個月再按位址分組（`internal/parity` 的 `TestZZWhoWritesTheTables`）。

**靜態交叉參考做不到這件事**——三張表全部以結構基底加位移存取
（`mov es:[si+0x2228], al`），掃不出來。

位址是**這一次執行的線性位址**。⚠ **還沒對到任何一份 dump 的映像位移**：
`workplace/ida/OVL.BIN`（從 `0110:0000` 取的 77,280 byte）裡連一次
`28 22` 都沒有出現——那是人物表訓練度欄的位移（結構 `0x2210` ＋ 24），
所以含這些程式碼的那一層不在那份 dump 裡。要對得上得從**同一次執行**
把載入後的映像取出來。

只動一項。

## 1.3 「訓練兵士」整支讀出來了（`L0`、`[base]`）

共用常式在線性 `0xbd70`。碼段取法在 §1.2；`objdump -b binary -m i8086
--adjust-vma=0xb000`。

```
bd70:  push bp; mov bp,sp
bd73:  mov ax,4; lcall 05c4:051c        ; MSC 的區域變數配置
bd7b:  mov word [bp-4], 0               ; i = 0
bd82:  mov ax,0x1e                      ; 30 ＝ 人物記錄大小
       mov es,[0xa5a4]; mov bx,[bp-4]; shl bx
       imul word es:[bx+0x58c]          ; 表[i] × 30 → 人物記錄位移
       mov bx,ax; mov es,[0xa5a6]
bd99:  mov al, es:[bx+0x2228]           ; 訓練度
       cbw; mov cx,ax
bda1:  mov al, es:[bx+0x2219]           ; 智
       mov dx,cx                        ; DX ← 訓練度
       mov cl,3; cbw; idiv cl; cbw      ; AX ＝ 智/3
       mov cx,ax
bdb0:  mov al, es:[bx+0x221a]           ; 武
       mov bl,2; cbw; idiv bl; cbw      ; AX ＝ 武/2
bdbb:  add ax,cx                        ; 智/3 ＋ 武/2
       mov cx,dx                        ; CX ← 訓練度
bdc0:  idiv word [bp+6]                 ; 除以呼叫端給的常數
bdc3:  add cx,ax
bdc8:  cmp word [bp-2],100; jle; mov 100 ; 上限 100
bded:  mov es:[bx+0x2228], al           ; 寫回
bdf2:  inc word [bp-4]                  ; i++
```

迴圈的條件在 `0xbdf5`–`0xbe2f`：

```
bdfc:  cmp es:[0xc], ax               ; i 超過清單長度就結束
be19:  cmp word es:[bx+0x2226], 0     ; 兵士數是不是零
be1f:  je  → mov word [bp-2], 0       ; 是 → 訓練度歸零
be21:  否則 → 回去算增量
```

所以整支常式是

```
對清單裡的每一位（長度在清單前面的 [0xc]）：
    兵士數 == 0 → 訓練度 = 0
    否則        → 訓練度 = min(100, 訓練度 + (智/3 + 武/2) / 參數)
```

**「沒有兵就歸零」說明書沒寫。** 一支被打光的部隊在補到兵之前一直是
零訓練，影響的是戰力不只是顯示。

**逐項截斷**：智與武各自先整數除，再相加，再除。`(智 + 1.5×武)/9`
在多數輸入下同值，但 `智=武=11` 分得出來（2 對 3）。

### 那個參數是 3 或 4

兩個 thunk 各推一個常數再呼叫共用常式：

| thunk | 推的值 | 一個月呼叫幾次 |
|---|---|---|
| `0xbe94` | 3 | 28 |
| `0xbe80` | 4 | 4 |

兩者的呼叫端是**同一個位址 `0x00e97f`**——那是指令分派器的間接呼叫點
（§6 的「每輪十六個函式指標」）。**分岔的條件還沒解。**
`internal/game` 取 3（`game.TrainGain`）。

⚠ `MemWrite.IP` 指的是**指令的下一個位元組**，不是起點。
`0xbdf2` 這個「寫訓練度的位址」實際上是 `26 88 87 28 22` 這道指令的
結尾；指令從 `0xbded` 開始。查碼的時候要往回退。

## 1.5 回合的骨架與郡的歸屬（`L0`、`[base]`）

### 每個郡的回合入口 `0x17471`

```
call 0x1949e(郡)                 ; 重整這個郡的守將清單
郡的所屬 == 0xFF → 回 −1          ; 無主的郡跳過
call 0x1e394()                    ; **重算全部 43 個郡的所屬**
lcall 33d8:1636 ＋ sprintf        ; 顯示郡名
諸侯 offset 0 == 2（電腦控制）→ call 0x17504(郡)   ; 十八張分派表
```

`0x17504` 正是 §1.4 那個分派器的唯一呼叫端，所以這一支就是回合的骨架。

### 郡的歸屬是導出值 `0x1e394`

```
1e3a8: for 郡 = 0..42:  movb es:[bx+0x49e], 0xff    ; 全部設成無主
1e3c4: for 人 = 0..349:
1e3d0:   cmpb es:[bx+0x2222], 0xff ; je 跳過         ; 在野的不算
1e3f0:   mov  es:[鄰郡記錄+0x49e], cl                ; 郡 ← 他的勢力
```

**掃描順序決定歸屬**：同一個郡裡有兩方的人時，**人物槽號較大的那位
說了算**。這就是電腦諸侯「出兵」之後郡易主的機制——搬進去的部隊
不打仗（`docs/mechanics/70-ai` §2.13.6）。

remake 這一邊是 `game.RecomputeOwners`，換月時跑；
`TestOwnersAreDerivedFromTheGeneralTable` 拿劇本存的所屬與從人物表
算出來的逐格比對，42 個郡全對。

### 玩家的「發動戰役」流程（`L0`、`[base]`）

`0x17471` 的主命令提示（數字輸入的呼叫端 `0x176eb`）→ 類別 2 進到
**軍事子選單 `0x18856`**：

```
18866: 顯示子選單字串（DS:0x6b98）
1887b: lcall 33d8:115e(1, 3)      ; 讀 1..3
188d4: 1 → 0x18bc8 調動軍隊       ; 這一支裡面呼叫 0x1938a 搬部隊
       2 → 0x188ea **發動戰役**
       3 → 0x18fee 運送錢糧
```

**發動戰役 `0x188ea`**：

```
1891f: cmpb es:[太守記錄+0x2221], 0    ; **主事者的身分要是 0（君主）**
       不是 → 189ac：出兵郡直接取目前的郡，跳過選擇
1892a: 建清單：42 格全填 0xFFFF
1894d: 與本郡同屬的郡填 0              ; 只有自己的郡可選
18992: 選郡（0x1d4ec，提示 DS:0x6bc3「從那一郡移出」）
       回 0xFFFF → 整個取消
189c5: 再建一份清單：42 格全填 0xFFFF
189e8: 對**出兵郡**的十格鄰郡：無主的跳過、同屬的跳過，其餘填 0
18a42: 選郡（0x1d4ec，提示 DS:0x6bd1「攻打那一郡」）
       回 0xFFFF → 顯示 DS:0x6bdd 之後取消
18a90: RND(5) + 80 與 es:[0x16f2] 比，不小於就跳走（還沒解）
```

**「發動戰役」要君主本人坐鎮該郡**——這一條在說明書裡沒有。
順序是**先選從哪裡出兵，再選打誰**；可打的目標只有出兵郡的鄰郡裡
「有主而且不是自己」的。

### 選郡的互動 `0x1d4ec`

```
1d606: lcall 33d8:115e(1, 42)
1d616: 0xFFFE → 重問
1d61b: 0xFFFF → 取消，原樣回傳
1d628: 清單[選中的郡] == 0xFFFF → 不在清單裡，重來
       否則回傳選中的郡
```

數字輸入 `33d8:115e`（線性 `0x34ede`）先由上限決定欄寬：
`< 10` 一位、`< 100` 兩位、`< 1000` 三位…… 所以「攻打那一郡(1-42)」
是**兩位數的欄位**。

### 戰鬥子系統的入口（**還沒解**）

碼段 dump 拉到 `0x050000` 之後找到幾個著手點，但整個戰術層還沒讀：

| 位址 | 是什麼 |
|---|---|
| `0x1938a` | 部隊移動（玩家與電腦共用；`0xb9f3` 與 `0x18fbc` 各呼叫一次）|
| `0x1b194` 一帶 | 一段顯示常式，`mov ax, 0x717f` 之後推位址去印 |
| `0x30f48` | 兵力損失的寫入點：`損失 ＝ 兵力 ÷ (10 − RND(n))`，先顯示訊息再扣 |

⚠ **`docs/re/04` 的位址是 `AA.EXE` 的檔案位移，不是執行期位址**
（那一份的開頭就寫著）。所以不能拿字串的位移直接去碼段裡找引用——
要先解出映像基底與各段的載入位置。`0x1b194` 那一列只確定它在推一個
`0x717f`，還不能斷定推的是哪一條字串。

找戰術層的下一步是**在戰鬥當中取快照**：主戰場的選單字串在開機後的
dump 裡找不到（`0x46c02` 那一帶是別的資料），所以那一層很可能是
overlay，要把原版驅動進一場戰役才讀得到。

驅動的工具已經備好（`internal/parity` 的 `TestZZBattleKeySweep`）：
**開機一次、存快照，每個候選按鍵序列還原之後再送**——開機要三分鐘，
一個候選十秒。盤面用 `stageABattle` 直接寫記憶體擺出來
（玩家守軍三千兵、錢糧管夠、一個鄰郡放上敵將，並把本郡第一位守將
設成君主，否則過不了 `0x1891f` 那道門）。

⚠ **卡在兩位數的輸入送不進去**：量到的是 `4`、`1`、Enter 之後
`0x34ede` 沒有回傳（還在等），而單獨一個 `1`、Enter 會回傳 1。
一段一鍵、加沉澱段、換 `int 21h` 與掃描碼兩條路徑都試過（十六輪），
現象不變。下一步是讀 `0x34f86` 之後那段按鍵迴圈，看它到底收哪些鍵碼
——**不要再猜鍵**。

## 1.4 電腦諸侯有六個等級，等級挑一整套行為（`L0`、`[base]`）

`0x00e8d2` 是**指令分派器**。它把參數夾在 0–5，存進 `es:[0x20f6]`，
然後連續用它索引 **18 張 far pointer 表**，中間沒有任何分支，
最後 `lret`：

```
e8de:  cmp word [bp+6],0 ; jge → mov word [bp+6],0     ; 下限
e8e9:  cmp word [bp+6],5 ; jle → mov word [bp+6],5     ; 上限
e8fb:  mov es:[0x20f6], ax
...
e91d:  mov bx, es:[0x20f6] ; shl bx ; shl bx           ; ×4（far pointer）
e926:  lcall far ptr [bx+0x54d4]
e937:  lcall far ptr [bx+0x5694]
e948:  lcall far ptr [bx+0x5674]
e959:  lcall far ptr [bx+0x5614]
e96a:  lcall far ptr [bx+0x5634]
e97b:  lcall far ptr [bx+0x5554]      ← 訓練兵士
e98c:  lcall far ptr [bx+0x5534]
e99d:  lcall far ptr [bx+0x56b4]
e9fc:  lcall far ptr [bx+0x5594]      ← 以下六張，呼叫前先算本回合預算
ea5b:  lcall far ptr [bx+0x5574]
eaba:  lcall far ptr [bx+0x5514]
eb19:  lcall far ptr [bx+0x55f4]
eb78:  lcall far ptr [bx+0x5654]
ebd7:  lcall far ptr [bx+0x56d4]
ebe8:  lcall far ptr [bx+0x56f4]
ebf9:  lcall far ptr [bx+0x55b4]
ec0a:  lcall far ptr [bx+0x55d4]
ec1b:  lcall far ptr [bx+0x54f4]
ec1f:  pop si ; mov sp,bp ; pop bp ; lret
```

**十八張全部無條件執行。** 分派點的完整清單是拿
`ff 9f`（`lcall far [bx+disp16]`）在碼段裡掃出來的，不是從某個位址
往下讀到覺得夠了為止——前八張與最後一張之間隔著預算計算的區塊，
順著讀很容易在 `0xe99d` 之後就停下來。

### 呼叫前先算本回合預算（`L0`）

中間那六張各自在 `lcall` 之前寫一次 `es:[0x3d16]`：

```
e9a5:  mov ax, es:[0x3f08] ; idiv 4 ; bx = 餘數        ; bx = T mod 4
e9b5:  mov ax, es:[0x20f6] ; shl ; shl                 ; ax = 4 × 等級
e9bd:  add bx, ax                                      ; k = 4×等級 + T mod 4
e9bf:  bx = 12 × k                                     ; 一筆 12 byte ＝ 6 個 word
e9c9:  fild  word ds:[bx+0x5714]                       ; 係數（六張各取一個 word）
e9e4:  fimul word es:[si+0x492]                        ; × 郡的金（州郡 offset 18）
e9ea:  fmul  qword ds:[0xa632]                         ; × 常數
e9ef:  lcall 05c4:4d60                                 ; → 整數
e9f8:  mov   es:[0x3d16], ax                           ; ← 本回合預算
```

六個位移剛好相差 2，對上六張表：

| 分派表 | 係數的位移 |
|---|---|
| `0x5594` | `ds:[bx+0x5714]` |
| `0x5574` | `ds:[bx+0x5716]` |
| `0x5514` | `ds:[bx+0x5718]` |
| `0x55f4` | `ds:[bx+0x571a]` |
| `0x5654` | `ds:[bx+0x571c]` |
| `0x56d4` | `ds:[bx+0x571e]` |

所以 `DS:0x5714` 是一張 **24 筆 × 6 word** 的係數表（6 個等級 × 4 個
`T mod 4` 的相位），**預算 ＝ 係數 × 郡的金 × 常數**。

常數 `ds:[0xa632]` 讀出來是 **`0.01`**，係數表也整張讀出來了
（`TestZZDispatch`），所以

```
本回合的預算 ＝ 郡的金 × 係數 ÷ 100
```

——**係數就是百分比**。24 筆（6 等級 × 4 相位）的內容：

| 等級 | 相位 | `0x5594` | `0x5574` | `0x5514` | `0x55f4` | `0x5654` | `0x56d4` |
|---|---|---|---|---|---|---|---|
| 0 | 0–3 | 2 | 30 | 20 | 20 | 20 | 0 |
| 1 | 0–3 | 2 | 30 | 15 | 20 | 20 | 0 |
| 2 | 0–3 | 2 | 40 | 20 | 10 | 20 | 0 |
| 3 | 0–2 | 2 | 50 | 20 | 10 | 15 | 0 |
| 3 | 3 | 2 | 50 | **0** | 10 | 15 | **20** |
| 4 | 0、2 | 2 | 50 | 20 | 20 | 15 | 0 |
| 4 | 1、3 | 2 | 50 | **0** | 20 | 15 | **20** |
| 5 | 0 | 2 | 50 | 20 | 20 | 15 | 0 |
| 5 | 1–3 | 2 | 50 | **0** | 20 | 15 | **20** |

等級 0–2 的四個相位完全相同，**等級 3 以上才開始分相位**：某些相位把
`0x5514` 的額度整份轉給 `0x56d4`。

觀測到的一輪（等級 5、`es:[0x3f08] ＝ 10`、相位 2）與這張表相符：
`0x5514` 的預算是 0（係數 0），`0x5594` 是 2、`0x5574` 是 56、
`0x55f4` 是 12、`0x5654` 是 9、`0x56d4` 是 12——後面幾個對應的是
前面幾張表花掉之後**剩下的**金。

⚠ `es:[0x3f08]` 只讀到一個值（10），所以「它是月份」還只是假說
（`L3`）。要多取幾個月的樣本才能定。

⚠ 那幾道 `lcall` **沒有 `26` 前綴，走 DS 不是 ES**。讀成 ES 會拿到
看起來像位址的垃圾。

表彼此相差 `0x20` ＝ 8 個 far pointer，所以表是八格的；但參數被夾在
0–5，**第 7、8 格到不了**——實測那兩格都是 `xor ax,ax; lcall 堆疊檢查;
lret` 的空操作，只為了把表補成 2 的冪。

### 等級從哪裡來

唯一的呼叫端在 `0x017504`：

```
1750f:  mov ax, 0xb0             ; 176 ＝ 州郡記錄大小
17512:  imul word [bp+6]         ; 郡編號 × 176
1751d:  imul byte es:[bx+0x49e]  ; 州郡 offset 30（所屬勢力）× 72（諸侯記錄大小）
17528:  mov ax, es:[bx+0x4]      ; ← 諸侯記錄的 offset 4
1752d:  push ax
1752e:  lcall 0e8d:0002          ; → 分派器
```

**`BASEMAS` 的 offset 4（16 位元）就是那個勢力的電腦諸侯等級。**
那張 72 位元組的表在此之前只解出 offset 2（君主的人物槽號）。

資料側對得上：劇本 001 的存檔裡槽 0–8 是 5、槽 9–14 是 4，而一個月裡
分派器收到 5 共 28 次、收到 4 共 4 次——正好是那兩群勢力所擁有、
且會行動的郡數。

### 訓練兵士那張表（`0x5554`）

| 等級 | thunk | 推的常數（除數）|
|---|---|---|
| 0 | `0xbe30` | 5 |
| 1 | `0xbe44` | 5 |
| 2 | `0xbe58` | 5 |
| 3 | `0xbe6c` | 4 |
| 4 | `0xbe80` | 4 |
| 5 | `0xbe94` | 3 |
| 6 | `0xbea8` | 空操作 |
| 7 | `0xbeb0` | 空操作 |

配上 §1.3 的公式：**訓練度 ＋= (智/3 + 武/2) / 除數[等級]**，上限 100。
等級越高練得越快。實作在 `game.TrainGain`／`game.AITrainDivisor`。

### 另外九張表的形狀（`L0`、`[base]`）

八格的內容從記憶體讀出來，再拿目標位址回到碼段看開頭的位元組。
空操作的形狀固定是 `33 c0 9a 1c 05 c4 05 cb`（八個位元組）。

| 表 | 等級 0–5 的形狀 | 讀得出來的 |
|---|---|---|
| `0x5514` | **八格全部是空操作** | **這張表什麼都不做**，儘管分派器仍為它算預算 |
| `0x54f4` | 0–2 空操作；3–5 各一份，開頭 `mov ax,176` | **等級 3 以上才做**，逐郡（176 ＝ 州郡筆長）|
| `0x56d4` | 0–2 空操作；3–5 各一份獨立函式 | 等級 3 以上才做 |
| `0x56f4` | 0–2 空操作；3–5 推 10／8／5 再 `lcall 1058:058c` | 等級 3 以上；**機率 `RND(10)`／`RND(8)`／`RND(5)`**，等級越高越常做 |
| `0x5574` | 0 自己一份（推 176）；1–5 都 thunk 到 `0xbeb8` | 等級 0 走另一條路 |
| `0x55b4` | 0–5 全部 thunk 到 `0xc2c4` | 行為不隨等級變 |
| `0x55d4` | 0–5 各一份，都推 176 | 逐郡，六份分開 |
| `0x55f4` | 0–5 各一份，都推 20 再 `lcall 1058:058c` | 一律 `RND(20)` |
| `0x5654` | 0–5 各一份獨立函式 | |

`lcall 1058:058c` 是亂數產生器（登用那一支也呼叫它）。

**低等級不做的有四張**（`0x54f4`／`0x56d4`／`0x56f4`，加上已解的
`0x56b4` 賞賜）——等級 0–2 的電腦諸侯行為明顯少一截。

⚠ 這九張**只讀了形狀，沒讀行為**。

### 前八張表的形狀（`L0`、`[base]`）

八個項目全部讀出來了（等級 6、7 到不了，一律是空操作）：

| 表 | 等級 0–5 的形狀 | 讀出來的 |
|---|---|---|
| `0x5554` | 六個 thunk，各推一個常數 | **訓練兵士**，除數 5 5 5 4 4 3 |
| `0x5534` | 六份各自的常式，`mov ax,K` 在同一個位移 | 常數 4 4 4 3 3 2 |
| `0x5614` | 六份常式 | 常數全部是 10 |
| `0x56b4` | **等級 0–2 是空操作**，3–5 推常數 2 | 低等級的電腦諸侯根本不做這件事 |
| `0x5674`／`0x5694`／`0x5594` | 六個 thunk 都 `push cs; call X; lret`，**不帶參數** | 目標 `0xd652`／`0xd7ae`／`0xc168`，行為不隨等級變 |
| `0x54d4` | 六份常式，等級 0–2 多兩行 | **選出這回合的行動者**（見下）|

三種形狀各有意思：**同一支常式配不同常數**（訓練）、
**同一支常式不分等級**（三張）、**低等級直接不做**（`0x56b4`）。

空操作的形狀固定是 `33 c0 9a 1c 05 c4 05 cb`（`xor ax,ax` ＋ MSC 的
堆疊檢查 ＋ `lret`），八個位元組，很好認。

### 表 `0x5594`：購置武器（`L0`）

常式 `0xc168` 走守軍清單（`es:[bx+0x58c]`，長度在 `es:[0xc]`），
每一位算一次「還缺多少武器」，付錢，然後重算武裝度。

**`objdump` 把中間幾段解成亂碼**，因為 MSC 6.0 的浮點程式不發 x87
指令，而是交給模擬器：`INT 34h`–`3Bh` 依序對應 ESC 位元組 `D8`–`DF`，
後面接原本的 modrm；`INT 3Ch` 是帶段前綴的形式，自己再帶一個原始的
ESC 位元組（這一支用它存取 `es:` 底下的欄位）。照這個對照換回去之後，
整支常式讀得完。

#### 買多少

```
c1cb: cd 3b 46 f6          fild  word [bp-0x0a]        ; 武裝度
c1cf: cd 3c de 8f 26 22    fimul word es:[bx+0x2226]   ; × 兵力
c1d5: cd 38 0e c8 a5       fmul  qword ds:[0xa5c8]     ; × 0.01
c1da: 9a 60 4d c4 05       lcall 05c4:4d60             ; → 整數（現有武器數）
c1df: 26 2b 87 26 22       sub   ax, es:[bx+0x2226]
c1e4: f7 d8                neg   ax                    ; 缺口 ＝ 兵力 − 武器數
c1e6: 89 46 fe             mov   [bp-2], ax
c1e9: b9 64 00             mov   cx, 100
c1ed: f7 f9                idiv  cx                    ; 金額 ＝ 缺口 ÷ 100
c1f3: 26 3b 06 16 3d       cmp   ax, es:[0x3d16]       ; 本回合預算
c1f8: 7e 0a                jle   c204
c1fa: 8b c1 26 f7 2e …     缺口 ＝ 預算 × 100          ; 買到錢用完為止
c204: 83 7e fe 00          cmpw  [bp-2], 0
c208: 7e 89                jle   下一位                 ; 缺口 ≤ 0 就跳過
c20a: …idiv cx; push ax
c211: 9a 54 03 8d 0e       lcall 0e8d:0354             ; ＝ 線性 0xec24，扣錢
```

**目標一律是滿編**：缺口 ＝ 兵力 − 現有武器數，也就是「人人有一件」。
這一支不擲骰、沒有門檻——武裝度已經 100 的人缺口是 0，直接跳過。

**價格是截斷除法**：`idiv 100` 之後 250 單位收 2 金，50 單位不用錢。
說明書的「每 100 單位武器耗費 1 金」是這條除法的敘述。

`es:[0x3d16]` 是勢力本回合的預算，以**金**計價（超支時反過來乘 100
換回武器數，兩邊的單位由此對上）。扣錢走 §2.12 那支共用常式，
所以**等級高的諸侯同樣的武器付得少**，但補的量不受折扣影響。

#### 重算武裝度

```
c225: 26 83 bf 26 22 00    cmpw es:[bx+0x2226], 0   ; 兵力是不是零
c22b: 7f 03                jg   c230
      → 武裝度 = 0
c239: cd 3b 46 f6          fild  word [bp-0x0a]     ; 武裝度
c23d: cd 3c df 87 26 22    fild  word es:[bx+0x2226]; 兵力
c243: cd 39 56 ee          fst   qword [bp-0x12]    ; 兵力存一份
c247: cd 3a c9             fmulp                    ; 武裝度 × 兵力
c24a: cd 38 0e c8 a5       fmul  qword ds:[0xa5c8]  ; × 常數 A
c24f: cd 3a 46 fe          fiadd word [bp-2]        ; ＋ 剛買的武器
c253: cd 38 76 ee          fdiv  qword [bp-0x12]    ; ÷ 兵力
c257: cd 38 0e a8 a5       fmul  qword ds:[0xa5a8]  ; × 常數 B
c25c: 9a 60 4d c4 05       lcall 05c4:4d60          ; → 整數
c261: 89 46 fc             mov   [bp-4], ax
c18e: 26 88 87 29 22       mov   es:[bx+0x2229], al ; 寫回武裝度
```

兩個常數從執行期記憶體讀出來（`TestZZDispatch`，`L0`）：

| 位址 | 值 |
|---|---|
| `DS:0xa5c8` | `0.01` |
| `DS:0xa5a8` | `100` |

代進去是

```
武器數 ＝ 武裝度 ÷ 100 × 兵力
武器數 ＋= 剛買的
武裝度 ＝ 武器數 ÷ 兵力 × 100
```

**武裝度是「有武器的兵佔多少百分比」**，不是武器的絕對數量。
買武器那一段的「缺口 ＝ 兵力 − 武器數」也只有在這個讀法下成立：
目標是每個兵一件武器。

`c225` 那個「兵力為零 → 武裝度為零」的分支**在這條路徑上到不了**：
缺口大於零已經蘊含兵力大於武器數 ≥ 0。它是防禦性的，
形狀與訓練度那一支相同。

⚠ **兵力與武器的絕對單位還沒量**（`L3`）：這一支只證明兩者同單位、
一金換 100 件。remake 的實作在 `internal/game/rules.go` 的
`Weapons`／`ArmsOf`／`ArmsAfterPurchase`，AI 那一面在
`internal/ai/ai.go` 的 `armsPurchase`。

⚠ 這一支沒有「玩家就跳過」的檢查（與 `0x5674` 相反）。**但那不表示它是
結算**：分派器一個月跑了 32 個相異的郡，**玩家的郡一次都沒有**
（`TestZZDispatchScope`）。所以這些表全部是 AI 決策，`0x5674` 開頭那個
檢查是多一層保險。

（AI 勢力共有 35 個郡而只跑了 32 個——差的三個還沒查，可能是沒有守將的郡。）

### 表 `0x5634`：登用人才（`L0`）

（等級 0–2 `(30, 0)`、3 `(20, 10)`、4 `(10, 20)`、5 `(0, 40)`）。

**牽絆閘門**蓋在能力值上面（`bx` ＝ 30 × 目標的 offset 14）：

### 每張表動到哪些欄位（`L1`、`[base]`）

時間軸歸屬：分派點與盤面寫入都帶著「執行到第幾道指令」，所以每一次
寫入都歸給它前面最近的那一次分派（`TestZZTableMeaning`）。一個月裡
**掛住的那九個分派點**觸發 288 次、盤面寫入 3,566 次。

⚠ 那一輪只掛了九個分派點，實際有十八個（見上）。所以下表的歸屬是
「掛住的九個之間」的，沒掛的九個造成的寫入會被算進它前面那個
掛住的分派點。

| 表 | 動到的欄位 | 看起來是 |
|---|---|---|
| `0x5534` | 州郡.地力×35、州郡.水利×1 | 內政（土地開發／洪水防治）|
| `0x5554` | 人物.訓練×81 | **訓練兵士**（§1.3 已獨立解出，兩條路對得上）|
| `0x5674` | 人物.身分×34 | 人事 |
| `0x5694` | 人物.身分×78 | 人事（另一種）|
| `0x56b4` | 人物.忠誠×64、魅×16、武×14、智×13、**諸侯 +15～+18** | 賞賜（金帛與物品）|
| `0x54d4`／`0x5614`／`0x5634` | 那一個月裡沒有寫入 | `0x5634` 只有登用成功才寫（見上）；另外兩張是判斷與統計 |
| `0x5594` | 人物.武裝×18（寫回點 `0xc193`）| **購置武器**（碼讀完了，見上）|

⚠ **`0x5594` 那一列不能只靠時間軸歸屬。** 它是**掛住的**九個分派點
裡的最後一個，所以「下一次分派之前的所有寫入」全部被歸給它——包含
後面九張表與整個回合結束之後的結算。這一列改用**位址**對上：`0xc193` 是常式 `0xc168` 裡
`mov es:[bx+0x2229], al` 的下一道指令，一個月 18 次，
與碼讀出來的「走守軍清單、每一位寫回一次武裝度」相符。

### 表 `0x5674` 開頭就擋掉玩家（`L0`）

```
d65d:  mov ax,0xb0; imul es:[0x30fc]      ; 目前的郡 × 176
d66f:  mov al,0x48; imul byte es:[bx+0x49e] ; 所屬勢力 × 72
d67c:  cmpw es:[bx+0x0], 1                 ; ← 諸侯 offset 0 == 1？
d682:  jne 繼續
       sub ax,ax; lret                      ; 是 1 → 什麼都不做
d69c:  mov ax, es:[bx+0x4a0]                ; 州郡 offset 32
d6a4:  inc ax; je 跳過                       ; == 0xFFFF → 沒有
```

**諸侯 offset 0 是控制者**（1 ＝ 玩家、2 ＝ 電腦、`0xFFFF` ＝ 沒在用），
**州郡 offset 32 是太守的人物槽號**。兩個都與資料側對得上
（`docs/formats/03`）。

擋掉玩家之後這一支做的是**指定太守**：

```
d6c2:  lcall 0f17:0490                  ; 把守軍清單排序（見下）
d6d9:  cmp byte es:[bx+0x2221], 2       ; 舊太守的身分是 2？
d6e1:  mov byte es:[bx+0x2221], 3       ; → 降回一般武將
d6eb:  mov ax, es:[0x58c]               ; 清單的第一位
d705:  mov es:[bx+0x4a0], ax            ; → 州郡 offset 32
d715:  cmp byte es:[bx+0x2221], 3       ; 新太守的身分是 3？
d71d:  mov byte es:[bx+0x2221], 2       ; → 升為太守
```

`0xf600` 是排序：比的是 `es:[di+0x221b]`，也就是人物 offset 11 ＝
**魅力**，由大到小。所以**魅力最高的那位當太守**。說明書只說「太守
魅力越高，登用與賑民的效果越好」——這裡是 AI 實際用的判準。

順帶確認了身分的編碼：**2 ＝ 太守、3 ＝ 一般武將**。

**`0x56b4` 那一列給了一條線索**：諸侯表未解的 offset 15–18 與賞賜同時
變動。賞賜物品會動君主的寶庫，所以那四個位元組很可能就是寶庫
（`L2`，還沒從碼裡確認）。

## 1.2 下一步：從實作位址回推決策

上面量到的是**命令的實作**，不是電腦諸侯選了哪一道。要拿到判斷式得
往上一層，而第一步是**把這一次執行的映像取出來**——現有的 `OVL.BIN`
不是這一層（見上）。取法是在同一個測試裡把 `0x00b000`–`0x01f000` 讀出來
寫成檔，位址就直接對得上，也不必處理 `DATA5.GRP` 有沒有打包過。

`docs/mechanics/70-ai` §2.3 量到的行為（每月花掉約一半的金、金為零時
賣米、徵兵 1:1 扣人口）是驗收那些判斷式的對照。

```
ea48:  push es:[si+0x2226]      ; 兵士數（word）
ea4d:  mov al, es:[si+0x2219]   ; 謀略
       push ds:0x5A27           ; "謀略 %3d    兵士數  %4d"

ea8d:  mov al, es:[si+0x2228]   ; 訓練度
ea94:  mov al, es:[si+0x221a]   ; 戰力
       push ds:0x5A3F           ; "戰力 %3d    訓練度   %3d"

ead4:  mov al, es:[si+0x2229]   ; 武裝度
eadb:  mov al, es:[si+0x221b]   ; 魅力
       push ds:0x5A58           ; "魅力 %3d    武裝度   %3d"
```

另有一組編號式的顯示在映像 `0x11E8F` 起：`1.年齡` `2.體能` `3.謀略`
`4.戰力` `5.魅力` `6.領地`，對應偏移 7／8／9／10／11／19。

州郡那一組在映像 `0x3206B`–`0x32444`：土地價值 27、洪水率 28、物價 29、
民眾忠誠 26、人口 14、金 18、米 20、在野武將 23、現役將 22、兵士 16。

## 3. 檔案系統

### `openGroup(n)`，執行期 `361E:027A`（映像 `0x3535A`）

開一組容器。`n` 是 0／1／2，對應 `DATA1`／`DATA2`／`DATA3`。做的事是：

```
fopen(檔名, "rb")  →  失敗回 −1
fclose
fopen(檔名, "r+b") →  失敗回 −1     ← 第二次要的是讀寫
```

檔名從資料段的一張表取（`ds:9E14` 起）：

```
DATA1.GRP  DATA2.GRP  DATA3.GRP
DATA1.GRP  DATA2.GRP  B:DATA3.GRP     ← 第二組帶 B: 前綴，雙磁碟機安裝
DATA1.IDX  DATA2.IDX  DATA3.IDX
DATA1.NAM  DATA2.NAM  DATA3.NAM
"rb"  "r+b"
```

索引的算法是 `(全域n × 3 + 組別) × 15 + 表基底`，全域 `n` 決定用哪一列
——那就是「硬碟安裝」與「雙磁碟機安裝」的切換。

### 失敗處理，執行期 `05C4:B52A`（映像 `0x1006A`）

```
fatal(名稱, 錯誤碼)
  → printf("ErrMsg: %s\n ErrNo: %d")
  → exit(1)
```

呼叫端十二處。開容器失敗那三處傳的名稱是 `File #0`／`File #1`／`File #2`，
錯誤碼 9。

## 4. 記憶體

### MCB 鏈走訪，映像 `0x778A`

```
mov bx,0FFFFh / mov ah,48h / int 21h   ; 用「配置最大值」的失敗當起點
cmp al,7                               ; AL=7 才是「MCB 鏈壞掉」
mov bx,ds:[13D0h] / dec bx             ; 自己的 PSP → 第一個 MCB
迴圈：ds=bx / ax=ds:[1]（擁有者）
      是我的 → 繼續；自由 → 記下第一塊；別人的 → 停
      bx += 1 + ds:[3]                 ; 下一個 MCB
      ds:[0]=='M' → 繼續；=='Z' → 收尾；其他 → 重來
sub bx,dx                              ; 總共構得到多少段
```

爬完的段數當參數傳給載入函式。**它沒有碰 `AH=52h`**——起點是自己 PSP 裡
的段值。同一條鏈也用來找自己的區塊釋放（`06DD:32C3`、`0583:3215`）。

執行器少了這條鏈的話，程式不會報錯，只會拿到一個與事實無關的數字
（`dosgolem/docs/spec/012`）。

## 5. 鍵盤

### IRQ1 處理常式，執行期 `0B01:0108`（映像 `0xA021`）

```
in   al,0x60                    ; 掃描碼
test al,0x80 / jne 結束         ; 放開鍵不理
mov  es:[0004],al               ; 存到 0000:0004（INT 1 的向量槽被拿來當暫存）
mov  es:[0005],1                ; 「有鍵」旗標
in   al,0x61 / or 80h / out / and 7Fh / out
mov  al,0x20 / out 0x20,al      ; EOI
iret
```

同一支程式也呼叫 `int 16h AH=01`（`_bios_keybrd(1)`）六十七萬次卻一次都
沒讀走。**「BIOS 鍵盤有被呼叫」不能拿來證明鍵是從 BIOS 進去的**
（`dosgolem/docs/spec/014`）。

## 6. 主迴圈

執行期 `1058:0651`。每一輪依序呼叫十六個函式指標（表在 `es:[bx+0x2176]`），
再帶著一個計數器呼叫 `05C4:2C9E`。

`05C4:051C` 是 MSC 的堆疊探測 thunk，不是遊戲邏輯——它在軌跡裡出現頻率
很高，容易被誤認成熱點。
