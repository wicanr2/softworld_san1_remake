# 06：四季事件與天災

`[base]`。四支常式由一個小分派器選（`0x15c1e`）：

```
0x15c29  ax = es:[0x3f08]        ; **月份** 1–12
0x15c48  cmp ax,10  je → 冬  0x16e70   人口成長 ＋ 進貢
         ja         → retf
         dec al     je → 春  0x15c5c   土地價值衰減 ＋ 人物異動 ＋ 地震
         sub al,3   je → 夏  0x164c8   水災 ＋ 瘟疫
         sub al,3   je → 秋  0x169d6   秋收 ＋ 蝗害
         retf                           ; 其餘八個月什麼都不跑
```

**`es:[0x3f08]` 是月份不是季節**，而且四季常式**一年各只跑一次**：
1 春、4 夏、7 秋、10 冬。其餘八個月沒有季節事件——天災因此一年各只有
一次機會（`docs/playtest/02`）。

月份的推進在 `0x159e9`（`L0`）：

```
es:[0x3f08]++
es:[0x3f08] > 12 → es:[0x3f08] = 1；es:[0x3140]++   ; 年
```

所以 `es:[0x3140]` 是年。⚠ 電腦諸侯的回合預算表（`70-ai` §2.14）拿的是
**`月 mod 4`**，四組各三個月，與這裡的 1／4／7／10 **不對齊**。

事件的字串集中在 `DS:0x6751`–`DS:0x680a`。字串與判定的對照：

| 事件 | 字串 | 印字的位址 | 判定 |
|---|---|---|---|
| 地震 | `DS:0x6751` ` 地 震 發 生 了 ` | `0x162fa` | 函式 `0x15c5c` |
| 水災 | `DS:0x6776` ` 洪 水 來 了 ` | `0x16603` | §1 |
| 瘟疫 | `DS:0x678e` ` 發 生 瘟 疫 ` | `0x1687e` | §2 |
| 蝗蟲 | `DS:0x67fc` ` 蝗 蟲 來 襲 ` | `0x16c68` | 函式 `0x169d6` |
| 人民反叛 | `DS:0x680a` ` 人 民 反 叛 了 ` | `0x16f9d` | 函式 `0x16e70` |
| 進貢 | `DS:0x6825` `%s主公, 各郡進貢…` | `0x172c9` | 同上 |

⚠ **有一張表夾在字串中間**：`DS:0x679c`–`DS:0x67f1` 是 43 個 word，
不是字串。逐字掃描字串的工具會直接跳過它（前一條字串以 NUL 結尾、
下一條從 `0x67f2` 開始），所以它一直沒被看見。

## 1. 水災（`0x164c8`–`0x167ae`，`L0`、`[both]`；加強版 `0x15423`–）

分兩段。**第一段逐郡 1..42，不看所屬**（無主郡也跑），每年四月都動到
洪水率：

```
新洪水率 = min(100, RND(洪水率 ÷ 4) + 洪水率 + 基礎[郡])   ; 0x16500–0x16543
州郡記錄 offset 28 ← 新洪水率                             ; 0x16552，寫回去
淹不淹：
  a = RND(新洪水率)                                      ; 0x16559
  b = RND(65)                                            ; 0x16567
  b + 5 >= a                    → 不淹                    ; 0x16574
  RND(100) <= 80                → 不淹                    ; 0x1657f–0x16585
  否則把郡編號記進候選清單 es:0x2102，計數 es:0x17c4
```

`mov %ax,%dx` 存的是除法之前的洪水率、`mov -0xa(%bp),%al` 讀回來的也
是它——加的是**整個舊值**，不是 `舊 % 4`。所以洪水率只會往上（每年至
少加基礎值），只有防洪（`FloodDrop` ＝ 謀略 ÷ 10）壓得下來，最後停在
100。`RND(n)` 在 `n <= 0` 時不抽亂數直接回 0（`0x10b0c`），所以洪水率
< 4 的郡第一擲不抽、新洪水率 0 的郡第二擲不抽——骰序對拍要照這個數。

`基礎[郡]` 就是 `DS:0x679c` 那張 43 格的表（AA.EXE 檔內位移 0x484d0、
ASV.EXE 0x3e8a5，兩版相同；0–12，總和 158），**索引就是郡編號**，
第 0 格是啞元郡：

```
郡  0– 7:  0  0  5  4  3  1  2  5
郡  8–15:  7  3  3  7  2  2  7  7
郡 16–23:  3  2  1  2  0  5  5  3
郡 24–31: 10  3 12  2  2  5  5 10
郡 32–39:  3  3  3  1  2  5  4  1
郡 40–42:  2  3  3
```

（`TestFloodBaseMatchesTheExe` 把 remake 的表對回兩支 EXE 的 43 個 word。）

**第二段**：清單不空才印字、放一次特效（`0x165f6` 叫 `0x32dfa`，
進去就擲 `RND(4)` 挑動畫，整個夏天一次），然後照清單的順序逐郡演
（`0x1663a`–`0x167ae`）：

```
人口（存的值）  ← 人口 × (RND(10) + 70) ÷ 100，< 50 補到 50   ; 0x1667c
土地價值       ← 土地價值 × (RND(20) + 60) ÷ 100             ; 0x166d0
洪水率         ← 洪水率 × (RND(20) + 120) ÷ 100，> 100 或 < 0 → 100 ; 0x1670e
掃全部 350 人：所在郡 == 郡 →                                ; 0x16748–0x167a5
    兵 ← 兵 × (RND(10) + 70) ÷ 100                           ; 0x16779
守將清單重整（0x1949e）                                       ; 0x167a9
```

人物那一段只看所在郡（offset 22），不看身分——在野的、別勢力的都掃到。

**水災完全不看民眾忠誠**，只看洪水率。說明書 p.36 的「天災多因人怨
引起」對水災不成立——那條講的是瘟疫（§2）。

對拍：`SAN1_MONTH=3 TestZZMonthParity` 把視窗推到四月（`SAN1_PLAGUE=1`
再把忠誠與土地價值歸零讓瘟疫必發）。淹了 3 個郡（含郡裡的人物）與
淹 1 個郡 ＋ 瘟疫 1 個郡兩趟，州郡表與季節動到的人物逐位元組相同
（`L1`、`[base]`）。

## 2. 瘟疫（`0x167df`–`0x169b4`，`L0`、`[both]`；加強版 `0x15799`–`0x1587f`）

**不逐郡掃，隨機挑一個郡，不看所屬**：

```
郡 = RND(42) + 1                                    ; 0x167e8
民眾忠誠（offset 26）>= RND(45) + 25 → 不發生        ; 0x167f8–0x16814，直接跳結尾
土地價值（offset 27）>= RND(40) + 20 → 不發生        ; 0x16824–0x1683a
否則 → 那個郡鬧瘟疫
```

兩道門是**一道一道擲的**：忠誠那一道沒過就不擲土地那一道。忠誠 70 以上
一定安全（門檻上限 69），忠誠 25 以下一定過第一關；土地價值同理，
59 以上安全、20 以下必過。**這才是說明書「天災多因人怨引起」的出處。**

發生了先印字、放一次特效（`0x16871` 叫 `0x32dfa`，`RND(4)`），再演
（`0x168c4`–`0x169b4`）：

```
人口（存的值）  ← 人口 × (RND(20) + 40) ÷ 100，< 50 補到 50   ; 0x168dd／0x16901
掃全部 350 人：所在郡 == 郡 →                                ; 0x1690d–0x169aa
    兵   ← 兵 × (RND(20) + 40) ÷ 100                         ; 0x1693e
    體能 ← 體能 × (RND(10) + 70) ÷ 100                       ; 0x1697c
守將清單重整（0x1949e）
```

說明書 p.36 的「將領體能下降」出處就是這一段。人物那一段同樣只看
所在郡。對拍見 §1 末段。

## 3. 人口成長（`0x16e70`–`0x16f16`，`L0`）

```
無主郡（offset 30 ＝ 0xFF）：RND(100) >= 30 → 跳過
有主郡或那 30%：
  倍率 = 土地價值 + 民眾忠誠 ÷ 2 + 1000
  人口 ← 人口 × 倍率 × 0.001        ; DS:0xa780 = 0.001
  > 10000 → 夾成 10000
```

倍率的上限是 `100 + 50 + 1000 = 1150`，也就是**最快 15%**，而且要
土地價值與忠誠都滿檔才到得了。

⚠ 這一條一度看起來與 `docs/mechanics/60` §1 的 `L1` 觀測衝突——那裡量到
十月的成長是「每個郡都剛好 15%」。**兩者其實一致**：對拍走的是「載入
舊進度」，而那份出貨存檔的土地價值是 100、忠誠 99–100（36 個有主的郡
裡 30 個倍率剛好到頂），所以每個郡都在上限，看起來像常數。劇本 001 的
倍率只有 1019–1059（2–6%），差得很遠。

分辨這件事的量測是 `TestZZSavedGameLandAndLoyalty`：它把「載入舊進度」
之後每個郡的土地價值與忠誠印出來。**兩份相衝的證據裡，先去看它們是不是
在同一個局面上量的**。

## 4. 土地價值的自然衰減（`0x15c8a`–`0x15cbc`，`L0`）

春季常式的**第一件事**，逐郡（1..42，無主的也跑）：

```
土地價值 ← 土地價值 − RND(土地價值 ÷ 10)
```

值越高掉越多，所以土地價值會停在「開發速度 ＝ 衰減速度」的地方，
不會一路到 100 就不動。**這是「土地開發要一直做」的原因**——
少了它，一次開發到頂就永遠不用再管，而畫面上看不出差別。

## 5. 地震（`0x162d2`，`L0`）

```
RND(3) != 0 → 不地震
郡 = RND(42) + 1
```

**沒有第二道門檻**：不看民眾忠誠、不看土地價值。說明書 p.36 的
「天災多因人怨引起」是瘟疫那一條（§2），不是地震。

## 6. 秋收與蝗害（`0x169d6`，`L0`）

秋季常式兩件事都做。**秋收逐郡跑**（`0x16a1b`–`0x16ac6`）：

```
收入 = (太守魅力 + 土地價值 × 4 + 民眾忠誠 × 2) × 人口 ÷ 300
金 ← 金 + 收入
收入加上原有的金不大於 0 → 改成 RND(土地價值 + 50)（取代，不是相加）
金 > 30000 → 夾成 30000
```

（人口用的是**存的值**，實際值 ÷ 100。常數在 `DS:0xa74e` ＝ 4.0、
`DS:0xa756` ＝ 1/300、`DS:0xa766` ＝ 30000.0。）

**三個因子都在裡面**：土地價值權重最大、忠誠其次、太守的魅力直接加。
太守是誰因此會影響收入。

**米那一半是另一組權重**（`0x16afa`–`0x16ba1`）：

```
收入 = (太守魅力 + 土地價值 × 3 + (100 − 洪水率) + 民眾忠誠 × 2)
       × 人口 × 0.005
米 ← min(30000, 米 + 收入)
收入加上原有的米不大於 0 → 改成 RND((土地價值 + 50) × 2)（取代）
```

（常數 `DS:0xa76e` ＝ 3.0、`DS:0xa776` ＝ 0.005、`DS:0xa766` ＝ 30000.0。）

**兩半不一樣的地方有兩處**：土地價值在米這一半是 ×3 不是 ×4，
而且**洪水率只進米的算式**（`100 − 洪水率`，`0x16b18`）——水利做得好
收成才多，那正是「防洪」這道指令的回報。金完全不看洪水率。

**秋收不動土地價值。** 說明書 p.21 說「收成後土地價值會略降」，
碼裡沒有這回事——掉的地方在春天（§4）。

**蝗害隨機挑一個郡**（`0x16bd5`）：

```
郡 = RND(42) + 1
民眾忠誠 >= RND(80) + 30  → 不發生
土地價值 <= RND(100) + 30 → 不發生
```

⚠ **土地價值越高越容易鬧蝗害**——田越肥蟲越多。這與瘟疫的方向相反
（瘟疫是土地價值**低**才發生）。照著「災害都因為窮」的直覺寫會寫反，
而寫反之後遊戲照樣跑得動。

### 秋季的第三件事：人望的年度調整（`0x16d4f`–`0x16e6a`，`L0`）

蝗害之後、不論有沒有鬧蝗（`0x16c00`／`0x16c24` 兩條「不發生」都直接跳到
`0x16d4f`）：

```
16d54  兩張 16 格的表歸零（es:0x24b2 領地數、es:0x2e36 和）
16d7b  for 郡 = 1..42：所屬（0x49e）== 0xFF → 跳過
16d9d    領地數[所屬]++
16da6    和[所屬] += 民眾忠誠(0x49a) ÷ 2 + 土地價值(0x49b) ÷ 2   ; idiv cl 各除一次
16dd5  for 勢力 = 0..15：領地數 <= 0 → 跳過
16dee    d = 君主魅力(人物 +11) + 和 ÷ 領地數 − 100
16e20    d ÷= 32（cwd / xor / sub / sar 5 / xor / sub ＝ 向零取整）
16e32    d += 人望(offset 8)；< 0 → 0；> 100 → 100
16e59    人望 ← d
```

兩張表與進貢（§9）是同一對緩衝區，係數不同（這裡 ÷2、÷2；進貢 ÷4、÷2）。
`TestZZPrestigeAutumnDrift` 對拍過（`docs/mechanics/50` §4.1）。
Issue #6 的諸侯表普查在 54 個月裡命中 `0x16e59` 47 次，才發現這一條
（`docs/re/11` §6）。

## 7. 四種天災的損失（`L0`）

每一項都是同一個形狀，**寫的是保留率不是損失率**：

```
新值 = 舊值 × (RND(幅度) + 底) ÷ 100
```

| 災害 | 欄位 | 位址 | 保留率 | 也就是損失 |
|---|---|---|---|---|
| 地震 | 人口 | `0x1638b` | RND(20)+60 ＝ 60–79% | 21–40% |
| 地震 | 金 | `0x163d5` | RND(20)+50 ＝ 50–69% | 31–50% |
| 地震 | 米 | `0x1640e` | RND(20)+40 ＝ 40–59% | 41–60% |
| 水災 | 人口 | `0x1666d` | RND(10)+70 ＝ 70–79% | 21–30% |
| 水災 | 土地價值 | `0x166c1` | RND(20)+60 ＝ 60–79% | 21–40% |
| 水災 | 洪水率 | `0x16701` | RND(20)+120 ＝ 120–139% | **往上** |
| 水災 | 郡裡每一位人物的兵 | `0x16779` | RND(10)+70 ＝ 70–79% | 21–30% |
| 瘟疫 | 人口 | `0x168ce` | RND(20)+40 ＝ 40–59% | 41–60% |
| 瘟疫 | 郡裡每一位人物的兵 | `0x1693e` | RND(20)+40 ＝ 40–59% | 41–60% |
| 瘟疫 | 郡裡每一位人物的體能 | `0x1697c` | RND(10)+70 ＝ 70–79% | 21–30% |
| 蝗害 | 米 | `0x16cba` | RND(10)+20 ＝ 20–29% | 71–80%（`L1`）|
| 蝗害 | 土地價值 | `0x16cfa` | RND(90)+80 ＝ 80–169% | **平均往上**（`L1`）|

倍率常數一律 `DS:0xa742` ＝ 0.01。人口讀寫的都是**存的值**（實際值 ÷ 100，
`filds` 那個字），乘完 `ftol` 截尾再存回去，零頭在那一刻就沒了。

四件要注意的：

- **地震對人口、金、米各擲一次**，不是同一個百分比套三次。
  人口另有下限 50（`0x163bb`，存的值，也就是五千人）；瘟疫同（`0x16901`）。
- **水災與瘟疫都動兵力，瘟疫還動體能**（§1、§2 的人物段）。掃的是全部
  350 人裡所在郡等於那個郡的，不看身分。蝗害不動人物。
- **每種災害發生時先放一次特效**：地震 `0x1633b`、水災 `0x165f6`、瘟疫
  `0x16871`、蝗害 `0x16c5b` 都叫 `0x32dfa`，進去就擲 `RND(4)` 挑動畫
  （`docs/re/05` §12.2）。骰序對拍要把這一擲算進去。
- **水災之後洪水率是乘上去的**（×1.20–1.39），算出來超過 100 或變成
  負的才寫 100（`0x16732`）。說明書 p.21 的「立刻升到 100」只對本來就
  高的郡成立。

⚠ **蝗害的土地價值保留率是 80–169%，平均會往上。** 這與「蝗蟲吃掉
收成」的直覺完全相反，而且是這一整組裡唯一一個往上的。位元組讀得很
清楚（`b8 5a 00` ＝ `RND(90)`、`05 50 00` ＝ `+80`、`dc 0e 42 a7` ＝
`× 0.01`），來源也確認是土地價值本身（`0x16cee` 的
`mov al, [si+0x49b]`）。**remake 照它，並夾在 100 以內**，
但這一條值得單獨對拍一次再定案。

## 8. 元月的人物年度處理（`0x15d40`–`0x16042`，`L0`）

**兩圈**，各走 350 個人物槽。第一圈（`0x15d40`–`0x15eb3`）是老死：

```
身分（offset 17）＝ 12（已故）→ 跳過                    ; 0x15d55，只跳這一種
RND(3) + 壽命（offset 28）< 年齡（offset 7）才往下      ; 0x15d63–0x15d81，有號比較
體能（offset 8）← max(0, 體能 + (壽命 − 年齡) × 25 − RND(50))
體能 ＝ 0 → 死（0x147c0，見下）
```

**年齡是有號的**：`0x15d71`／`0x15d79` 讀壽命與年齡都先 `cbw`，比較用 `jl`。
還沒出生的人年齡是負的（曹叡 189 年是 `0xF0` ＝ −16），自然過不了這一道；
當成無號讀就是 240 歲，第一年全部老死。**第一圈用的是加歲之前的年齡**——
加歲在第二圈。

第二圈（`0x15f64`–`0x16042`）：

```
年齡（offset 7）+1                                         ; 0x15f7a，350 筆全加，已故與未登場也加
勢力（offset 18）＝ 0xFF → 跳到出頭判定（§8.1）
身分（offset 17）∉ {1 軍師, 2 太守, 3 一般武將} → 跳到出頭判定   ; 君主不算
忠誠（offset 16）← 忠誠 + (諸侯記錄[8] − 60) ÷ 2            ; 向零
  < 0   → RND(5)
  > 100 → 100
武裝度（offset 25）−= RND(武裝度 ÷ 10)
訓練度（offset 24）−= RND(訓練度 ÷ 10)
出頭判定（§8.1）
```

**訓練度與武裝度每年自然衰減**，形狀與土地價值相同（§4）。
這是「訓練兵士」與「購置武器」要一直做的原因。**君主、在野、未登場的人
三項都不動**——這一段的兩道門把他們全部跳過。

老死的處置（`0x147c0`–`0x14893`，`L0`）：體能歸零的人

```
147f6 / 14881  身分（0x2221）← 12（已故）
147fe / 14889  勢力（0x2222）← 0xFF
14803 / 1488e  領地（0x2223）← 0xFF
14859          死者是軍師（身分 1）→ 諸侯記錄 offset 6 ← 0xFFFF
```

兩條路徑差在 `0x14809 call 0x14968`（死者是主事者時找人接手）。
君主另走 `0x14a40`（繼承，`docs/mechanics/80` §2.5）。

`諸侯記錄 offset 8` 是**人望**（`u16`，0–100）。判準是找出誰寫它：

| 位址 | 動作 |
|---|---|
| `0x204b4` | 戰役勝方 `+2`，夾在 100（`es:0x20dc` 是勝負值）|
| `0x204e0` | 戰役敗方 `−2`，夾在 0 |
| `0x1519a` | 春季隨機事件 `+RND(30) + 40`，夾在 100（前置條件未解）|

它**不對應君主的任何能力值**——年齡、體能、謀略、戰力、魅力逐格比過，
十五個勢力裡只各中一次（`TestZZMasterRecordFields`，巧合的量級）。
量到的 50–89 落在 0–100 裡面，與寫入端一致。

所以整條機制是：**打勝仗累積人望，人望高於 60 部下每年向心，
低於 60 每年離心。**

## 7.1 玉璽現世（`0x15cfd`／`0x15136`，`L0`）

春季常式在人物迴圈之前先做這一件（`0x15cf9`）：

```
es:0x2f6c != 0xFFFF → 跳過          ; 0xFFFF ＝ 玉璽還沒現世
RND(100) <= 50      → 跳過
從活著的勢力清單裡 RND 挑一個（清單在 0x15cc8 建，掃十六個諸侯記錄）
→ 0x15136(那個勢力)：
     諸侯記錄 offset 14（玉璽）← 1
     人望 += RND(30) + 40，夾在 100
     es:0x2f6c ← 0
```

**旗標只有兩個狀態**：`0xFFFF` 是還沒現世、`0` 是已經有人拿到。
進到 `0x15136` 時旗標已經是 0 的話會印 `DS:0x661b`
`"Double Seal event"`——**出貨版裡留著的除錯字串**，旁邊就是
`DS:0x6640` `"玉璽 !"`。

**玉璽的作用是人望，不是勝利條件**：統一判定（§9.5）沒有讀寶庫。
拿到的那一家人望 `+RND(30)+40`，而人望決定部下忠誠每年的漲跌。
劇本 001 開局就有人持有（孫堅），所以這個事件在那個劇本裡不會觸發。

諸侯記錄 offset 14 是玉璽，這與 AI 賞賜物品那一段的觀察一致
（「只有 offset 16／17／18 那三格會被送出去；14 是玉璽（不能送人）」，
`docs/mechanics/70-ai`）。

## 8.1 人物出頭（`0x16042`–`0x160a2`，`L0`）

第二圈每一筆的最後一段（加歲之後，所以比的是**加歲後**的年齡）：

```
身分（offset 17）≠ 11（未登場）→ 跳過
年齡（offset 7）<= 出頭年齡（offset 26）→ 跳過      ; 0x1605a，有號比較，比的是 >，不是 >=
牽絆對象（offset 14）＝ 自己          → 走退路
牽絆對象的勢力（offset 18）＝ 0xFF    → 走退路
牽絆對象所在郡的現役武將數 >= 50      → 走退路
否則 → 出現在牽絆對象的郡，加入他的勢力

退路（0x15ec4–0x15f5c）：
  位置（offset 19）← 出身郡（offset 13）
  身分 ← 9（在野，不列入郡的在野數）                 ; 0x15eda
  勢力 ← 0xFF
  才能 ← max(謀略 offset 9, 戰力 offset 10)          ; 0x15ee6–0x15efb
  年齡 >= RND(5) + 32        → 露面                  ; 0x15efe–0x15f23
  否則 RND(30) + 30 > 才能   → 露面                  ; 0x15f29–0x15f37
  否則                       → 留 9，要尋訪才出現
  露面 ＝ 身分 ← 8、出身郡的在野數（州郡 offset 23）+1   ; 0x15f45–0x15f5c
```

**年輕的名將是藏著的。** 謀略或戰力到 59 的年輕人一定留 9，30 以下的一定
露面，中間的機率是 `(才能 − 29) ÷ 30`；過了三十二到三十六歲不管才能都露面。
這是「尋訪人才」找得到人的來源之一（另一個是劇本開局就填 9 的人）。

**人物表 offset 26 是出頭年齡**，每個人自己一個——這一格原本在
`docs/spec/003` §2 的未解清單裡。

**牽絆對象有勢力就直接投奔他**：手冊 p.36 的「新將投效其親族朋友」
是字面意思，不是修辭。

## 9. 進貢（`0x170b2`–`0x17348`，`L0`）

發之前先掃一次州郡湊兩張 16 格的表（`0x170b2`–`0x17123`）：

```
for 郡 = 0..42：
    所屬 == 0xFF → 跳過
    領地數[所屬]++                                          ; es:0x24b2
    人才量[所屬] += 民眾忠誠(offset26)/4 + 土地價值(offset27)/2  ; es:0x2e36
```

**「人才量」名不副實**——它是民眾忠誠與土地價值的加權和，與武將數無關。
一個郡最多貢獻 25 ＋ 50 ＝ 75，所以單郡勢力的人才量就是 75 上下。

接著逐一走 16 個諸侯槽（`0x1712a`，回跳 `0x17346` 比 `0x10`）：

```
領地數 <= 0 → 跳過                     ; 0x17133，不抽亂數
基數 = 人才量 ÷ (RND(10) + 80)         ; 0x1713e–0x1715b
基數 <= 0 → 跳過                       ; 0x17160，亂數已經抽過了
四種寶物各一段（0x17167、0x1719a、0x171d0、0x17206，**展開寫的不是迴圈**）：
    v = RND(基數 + 1)
    c = RND(5) + 8
    c < v → v = RND(5) + 8             ; 再抽一次覆蓋
再 RND(4) 挑一種多給一件               ; 0x1723c，incw -0x8(%bp,%si)
逐種進庫（0x172f8）：庫存 = min(100, 庫存 + v)
```

**上限是 8–12**——手冊 p.37 只說「領地越多，貢品越多」，沒說有上限。
玉璽不在這四種裡。

**基數才是量的來源，領地數只是閘門。** 人才量 75 除以 80–89 是 0，
所以**只有一個郡的勢力一件都拿不到**，不是「拿得少」。

亂數的帳（`L1`，建安二年九月那一輪）：16 個槽 → 13 個過領地閘門
（各抽一次 `RND(10)`）→ 6 個過基數閘門，每個固定 **9 次**
（四種各 2 次 ＋ 挑一種的 `RND(4)`），重抽 2 次，合計 **69 次**。
挑一種那一抽**無條件**，四種都擲到 0 也照抽。

只有玩家控制的勢力（諸侯記錄 offset 0 ＝ 1）會看到訊息
（`DS:0x6825`）；電腦的照樣進貢，只是不印。

## 9.5 月底的收尾與兩個結束條件（`0x1581c`–`0x15977`，`L0`）

順序表走完（`es:0x20f4 >= 43`）之後，原版依序做六件事：

```
0x15828  if es:0x5b02 == 0 → call 0x1e1fc
0x1582d  call 0x1e394
0x15831  call 0x17364        ; 開新的一個月：順序表洗五輪、旗標全開
0x15835  call 0x159de
0x15839  call 0x15c1e        ; 四季分派器（§1）
0x1583d  call 0x15852        ; 統一判定
0x1584d  if es:0x5b02 != 0 → call 0x15924   ; 玩家是否全部絕嗣
```

**統一判定在四季常式之後**，所以天災、進貢、老死造成的滅國當月就算數。

### 統一判定 `0x15852`

```
基準 = 0
for i = 1..42:  if 所屬[i] != 0xFF: 基準 = 所屬[i]
for i = 1..42:
    if 所屬[i] == 0xFF: continue
    if 所屬[i] != 基準: return 0xFFFF        ; 還沒統一
es:0x0080 ← 0                                 ; 月內迴圈停
印 DS:0x66d4「%s 一統天下」（諸侯[基準] 的君主姓名）
es:0x3b92 ← 0
```

**除了郡的所屬與君主的姓名之外，它沒有讀任何東西**——沒有玉璽、
沒有寶庫、沒有年份。說明書 p.37 的「在遊戲結束前一定要拿到玉璽」
在碼裡沒有對應（`CONTEXT.md` §4 R19）。

**無主的郡跳過**，所以荒地不擋統一。

### 玩家全部絕嗣 `0x15924`

```
for i = 0..15:
    if 諸侯[i].操縱方 == 1 && 諸侯[i].君主 != 0xFFFF: return 0xFFFF  ; 繼續
es:0x0080 ← 0
印 DS:0x97d4「所有玩家皆無繼承人  遊戲結束」
```

判準是**君主欄**不是領地：領地被打光但君主還在的玩家，遊戲照樣繼續。

### `es:0x5b02` ＝ 有沒有人在玩

開局問「請問有幾人玩(0-16)」，答案 ≤ 0 時（`0x1216a`）印
`DS:0x5fcb`「電腦自動示範模式」，然後：

```
es:0x2f72 ← 2        ; 延遲時間壓到 2
DS:0x5b02 ← 0        ; 示範模式
es:0x2174 ← 0        ; 查看電腦戰役 ← 開啟
```

答案 > 0 時（`0x12196`）反過來：`es:0x2174 ← 1`（關閉）、
`DS:0x5b02 ← 0xFFFF`，接著逐一問每個玩家選哪一方。

所以三處判斷都讀得通：示範模式每個郡跑完會問 `0xb01:0x222` 要不要中斷
（`0x1577e`）、月底多跑一支 `0x1e1fc`（`0x15828`），而**絕嗣檢查只在
有人玩的時候做**（`0x1584c`）——全電腦的局面沒有「玩家」可以絕嗣。

`DS:0x5b00`（`BASEPRO` 位移 `0xAC`）就在它旁邊，但整個碼段 dump 裡
只有存檔（`0x1e6c6`）與讀檔（`0x142c2`）兩處引用，沒有第三處寫入或
使用。出貨的六個進度那一格都是 0。
