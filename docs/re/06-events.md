# 06：四季事件與天災

`[base]`。四支常式由一個小分派器選（`0x15c1e`）：

```
0x15c29  ax = es:[0x3f08]        ; 季節 0–3
0x15c2d  → 0x15c48 的跳躍表
   0 春  0x15c5c   土地價值衰減 ＋ 人物異動 ＋ 地震
   1 夏  0x164c8   水災 ＋ 瘟疫
   2 秋  0x169d6   秋收 ＋ 蝗害
   3 冬  0x16e70   人口成長 ＋ 進貢
```

**`es:[0x3f08]` 就是季節**，四季的分法與 remake 一致。

事件的字串集中在 `DS:0x6751`–`DS:0x680a`。字串與判定的對照：

| 事件 | 字串 | 印字的位址 | 判定 |
|---|---|---|---|
| 地震 | `DS:0x6751` ` 地 震 發 生 了 ` | `0x162fa` | 函式 `0x15c5c` |
| 水災 | `DS:0x6776` ` 洪 水 來 了 ` | `0x16603` | §1 |
| 瘟疫 | `DS:0x678e` ` 發 生 瘟 疫 ` | `0x1687e` | §2 |
| 蝗蟲 | `DS:0x67fc` ` 蝗 蟲 來 襲 ` | `0x16c68` | 函式 `0x169d6` |
| 人民反叛 | `DS:0x680a` ` 人 民 反 叛 了 ` | `0x16f9d` | 函式 `0x16e70` |
| 進貢 | `DS:0x6825` `%s主公, 各郡進貢…` | `0x172c9` | 同上 |

⚠ **有一張表夾在字串中間**：`DS:0x679c`–`DS:0x67f1` 是 43 個 word，
不是字串。逐字掃描字串的工具會直接跳過它（前一條字串以 NUL 結尾、
下一條從 `0x67f2` 開始），所以它一直沒被看見。

## 1. 水災（`0x164c8`–`0x165b3`，`L0`）

逐郡（1..42）跑，**每個月都會動到洪水率**：

```
新洪水率 = min(100, RND(洪水率 ÷ 4) + 洪水率 % 4 + 基礎[郡])
州郡記錄 offset 28 ← 新洪水率           ; 0x16552，寫回去
淹不淹：
  RND(65) + 5 >= RND(新洪水率)  → 不淹   ; 0x16574
  RND(100) <= 80                → 不淹   ; 0x16585
  否則把郡編號記進候選清單，最後一起演
```

`基礎[郡]` 就是 `DS:0x679c` 那張 43 格的表（0–12，總和 158）：

```
郡  1– 8:  0  0  5  4  3  1  2  5
郡  9–16:  7  3  3  7  2  2  7  7
郡 17–24:  3  2  1  2  0  5  5  3
郡 25–32: 10  3 12  2  2  5  5 10
郡 33–40:  3  3  3  1  2  5  4  1
郡 41–42:  2  3
```

（索引 0 是啞元郡，所以表的第 0、1 格都是 0。）

**水災完全不看民眾忠誠**，只看洪水率。說明書 p.36 的「天災多因人怨
引起」對水災不成立——那條講的是瘟疫（§2）。

洪水率會自己長：`RND(舊÷4) + 舊%4 + 基礎`，期望值約 `舊 × 0.625 + 基礎`，
所以低洪水率的郡會被基礎值推上去，高的郡會被 `÷4` 拉下來，最後停在
`基礎 ÷ 0.375` 附近。**防洪不是一勞永逸的**（`FloodDrop` ＝ 謀略 ÷ 10）。

## 2. 瘟疫（`0x167df`–`0x1683d`，`L0`）

**不逐郡掃，隨機挑一個郡**：

```
郡 = RND(42) + 1
民眾忠誠（offset 26）>= RND(45) + 25 → 不發生
土地價值（offset 27）>= RND(40) + 20 → 不發生
否則 → 那個郡鬧瘟疫
```

兩道門檻都要過。忠誠 70 以上一定安全（門檻上限 69），
忠誠 25 以下一定過第一關；土地價值同理，59 以上安全、20 以下必過。
**這才是說明書「天災多因人怨引起」的出處。**

## 3. 人口成長（`0x16e70`–`0x16f16`，`L0`）

```
無主郡（offset 30 ＝ 0xFF）：RND(100) >= 30 → 跳過
有主郡或那 30%：
  倍率 = 土地價值 + 民眾忠誠 ÷ 2 + 1000
  人口 ← 人口 × 倍率 × 0.001        ; DS:0xa780 = 0.001
  > 10000 → 夾成 10000
```

倍率的上限是 `100 + 50 + 1000 = 1150`，也就是**最快 15%**，而且要
土地價值與忠誠都滿檔才到得了。

⚠ 這一條一度看起來與 `docs/mechanics/60` §1 的 `L1` 觀測衝突——那裡量到
十月的成長是「每個郡都剛好 15%」。**兩者其實一致**：對拍走的是「載入
舊進度」，而那份出貨存檔的土地價值是 100、忠誠 99–100（36 個有主的郡
裡 30 個倍率剛好到頂），所以每個郡都在上限，看起來像常數。劇本 001 的
倍率只有 1019–1059（2–6%），差得很遠。

分辨這件事的量測是 `TestZZSavedGameLandAndLoyalty`：它把「載入舊進度」
之後每個郡的土地價值與忠誠印出來。**兩份相衝的證據裡，先去看它們是不是
在同一個局面上量的**。

## 4. 土地價值的自然衰減（`0x15c8a`–`0x15cbc`，`L0`）

春季常式的**第一件事**，逐郡（1..42，無主的也跑）：

```
土地價值 ← 土地價值 − RND(土地價值 ÷ 10)
```

值越高掉越多，所以土地價值會停在「開發速度 ＝ 衰減速度」的地方，
不會一路到 100 就不動。**這是「土地開發要一直做」的原因**——
少了它，一次開發到頂就永遠不用再管，而畫面上看不出差別。

## 5. 地震（`0x162d2`，`L0`）

```
RND(3) != 0 → 不地震
郡 = RND(42) + 1
```

**沒有第二道門檻**：不看民眾忠誠、不看土地價值。說明書 p.36 的
「天災多因人怨引起」是瘟疫那一條（§2），不是地震。

## 6. 秋收與蝗害（`0x169d6`，`L0`）

秋季常式兩件事都做。**秋收逐郡跑**（`0x16a1b`–`0x16ac6`）：

```
收入 = (太守魅力 + 土地價值 × 4 + 民眾忠誠 × 2) × 人口 ÷ 300
金 ← 金 + 收入
收入 ≤ 0 → 改成 RND(那個括號 + 50)
金 > 30000 → 夾成 30000
```

（人口用的是**存的值**，實際值 ÷ 100。常數在 `DS:0xa74e` ＝ 4.0、
`DS:0xa756` ＝ 1/300、`DS:0xa766` ＝ 30000.0。）

**三個因子都在裡面**：土地價值權重最大、忠誠其次、太守的魅力直接加。
太守是誰因此會影響收入。

**秋收不動土地價值。** 說明書 p.21 說「收成後土地價值會略降」，
碼裡沒有這回事——掉的地方在春天（§4）。

**蝗害隨機挑一個郡**（`0x16bd5`）：

```
郡 = RND(42) + 1
民眾忠誠 >= RND(80) + 30  → 不發生
土地價值 <= RND(100) + 30 → 不發生
```

⚠ **土地價值越高越容易鬧蝗害**——田越肥蟲越多。這與瘟疫的方向相反
（瘟疫是土地價值**低**才發生）。照著「災害都因為窮」的直覺寫會寫反，
而寫反之後遊戲照樣跑得動。

## 7. 四種天災的損失（`L0`）

每一項都是同一個形狀，**寫的是保留率不是損失率**：

```
新值 = 舊值 × (RND(幅度) + 底) ÷ 100
```

| 災害 | 欄位 | 位址 | 保留率 | 也就是損失 |
|---|---|---|---|---|
| 地震 | 人口 | `0x1638b` | RND(20)+60 ＝ 60–79% | 21–40% |
| 地震 | 金 | `0x163d5` | RND(20)+50 ＝ 50–69% | 31–50% |
| 地震 | 米 | `0x1640e` | RND(20)+40 ＝ 40–59% | 41–60% |
| 水災 | 人口 | `0x1666d` | RND(10)+70 ＝ 70–79% | 21–30% |
| 水災 | 土地價值 | `0x166c1` | RND(20)+60 ＝ 60–79% | 21–40% |
| 水災 | 洪水率 | `0x16701` | RND(20)+120 ＝ 120–139% | **往上** |
| 瘟疫 | 人口 | `0x168ce` | RND(20)+40 ＝ 40–59% | 41–60% |
| 蝗害 | 米 | `0x16cba` | RND(10)+20 ＝ 20–29% | 71–80% |
| 蝗害 | 土地價值 | `0x16cfa` | RND(90)+80 ＝ 80–169% | **平均往上** |

倍率常數一律 `DS:0xa742` ＝ 0.01。

三件要注意的：

- **地震對人口、金、米各擲一次**，不是同一個百分比套三次。
  人口另有下限 50（`0x163bb`，存的值，也就是五千人）。
- **水災、瘟疫、蝗害都不動兵力。** 掃過三段的欄位寫入，只有人口／金／
  米／土地價值／洪水率。remake 原本讓水災與瘟疫按同樣的比例減兵，
  那是加上去的。
- **水災之後洪水率是乘上去的**（×1.20–1.39），算出來超過 100 或變成
  負的才寫 100（`0x16732`）。說明書 p.21 的「立刻升到 100」只對本來就
  高的郡成立。

⚠ **蝗害的土地價值保留率是 80–169%，平均會往上。** 這與「蝗蟲吃掉
收成」的直覺完全相反，而且是這一整組裡唯一一個往上的。位元組讀得很
清楚（`b8 5a 00` ＝ `RND(90)`、`05 50 00` ＝ `+80`、`dc 0e 42 a7` ＝
`× 0.01`），來源也確認是土地價值本身（`0x16cee` 的
`mov al, [si+0x49b]`）。**remake 照它，並夾在 100 以內**，
但這一條值得單獨對拍一次再定案。

## 8. 元月的人物年度處理（`0x15f61`–`0x16042`，`L0`）

逐一走過 350 個人物槽：

```
年齡（offset 7）+1
勢力（offset 18）＝ 0xFF → 跳過
身分（offset 17）∉ {1 軍師, 2 太守, 3 一般武將} → 跳過   ; 君主不算
忠誠（offset 16）← 忠誠 + (諸侯記錄[8] − 60) ÷ 2
  < 0   → RND(5)
  > 100 → 100
武裝度（offset 25）−= RND(武裝度 ÷ 10)
訓練度（offset 24）−= RND(訓練度 ÷ 10)
```

**訓練度與武裝度每年自然衰減**，形狀與土地價值相同（§4）。
這是「訓練兵士」與「購置武器」要一直做的原因。

⚠ **`諸侯記錄 offset 8` 是個 word，語意未解。** 量到的值落在 50–89
（`TestZZMasterRecordFields`），而且**不對應君主的任何能力值**——
年齡、體能、謀略、戰力、魅力逐格比過，十五個勢力裡只各中一次
（那是巧合的量級）。所以忠誠的年度漂移**還沒實作**：輸入不知道是什麼，
硬填一個數會讓它看起來已經還原。

## 9. 進貢（`0x17164`–`0x1724c`，`L0`）

四種寶物（兵書、寶刀、美女、駿馬）**各算一次**：

```
n = RND(領地數 + 1)
若 RND(5) + 8 < n → n = RND(5) + 8
```

也就是 `min(RND(領地數 + 1), RND(5) + 8)`。四種都算完之後，
再 `RND(4)` 挑一種多給一件（`0x1723c`）。

**上限是 8–12 而且每一種各擲一次**——手冊 p.37 只說「領地越多，
貢品越多」，沒說有上限。玉璽不在這四種裡。

只有玩家控制的勢力（諸侯記錄 offset 0 ＝ 1）會看到訊息
（`DS:0x6825`）；電腦的照樣進貢，只是不印。

## 10. 還沒讀

- **`諸侯記錄 offset 8`**（年度忠誠漂移的輸入，§8）。
- 蝗害讓土地價值往上這件事要實跑對拍一次（§7）。
- 人物出頭的條件。
- `0x16294`–`0x162cf` 那一段：看得到 `忠誠 ← 忠誠 × 9 ÷ 10`、
  勢力與領地欄的搬移、州郡現役武將數 +1——像是**換主**的處理，
  但觸發條件還沒讀。
