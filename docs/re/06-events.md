# 06：四季事件與天災

`[base]`。四支常式由一個小分派器選（`0x15c1e`）：

```
0x15c29  ax = es:[0x3f08]        ; 季節 0–3
0x15c2d  → 0x15c48 的跳躍表
   0 春  0x15c5c   土地價值衰減 ＋ 人物異動 ＋ 地震
   1 夏  0x164c8   水災 ＋ 瘟疫
   2 秋  0x169d6   秋收 ＋ 蝗害
   3 冬  0x16e70   人口成長 ＋ 進貢
```

**`es:[0x3f08]` 就是季節**，四季的分法與 remake 一致。

事件的字串集中在 `DS:0x6751`–`DS:0x680a`。字串與判定的對照：

| 事件 | 字串 | 印字的位址 | 判定 |
|---|---|---|---|
| 地震 | `DS:0x6751` ` 地 震 發 生 了 ` | `0x162fa` | 函式 `0x15c5c` |
| 水災 | `DS:0x6776` ` 洪 水 來 了 ` | `0x16603` | §1 |
| 瘟疫 | `DS:0x678e` ` 發 生 瘟 疫 ` | `0x1687e` | §2 |
| 蝗蟲 | `DS:0x67fc` ` 蝗 蟲 來 襲 ` | `0x16c68` | 函式 `0x169d6` |
| 人民反叛 | `DS:0x680a` ` 人 民 反 叛 了 ` | `0x16f9d` | 函式 `0x16e70` |
| 進貢 | `DS:0x6825` `%s主公, 各郡進貢…` | `0x172c9` | 同上 |

⚠ **有一張表夾在字串中間**：`DS:0x679c`–`DS:0x67f1` 是 43 個 word，
不是字串。逐字掃描字串的工具會直接跳過它（前一條字串以 NUL 結尾、
下一條從 `0x67f2` 開始），所以它一直沒被看見。

## 1. 水災（`0x164c8`–`0x165b3`，`L0`）

逐郡（1..42）跑，**每個月都會動到洪水率**：

```
新洪水率 = min(100, RND(洪水率 ÷ 4) + 洪水率 % 4 + 基礎[郡])
州郡記錄 offset 28 ← 新洪水率           ; 0x16552，寫回去
淹不淹：
  RND(65) + 5 >= RND(新洪水率)  → 不淹   ; 0x16574
  RND(100) <= 80                → 不淹   ; 0x16585
  否則把郡編號記進候選清單，最後一起演
```

`基礎[郡]` 就是 `DS:0x679c` 那張 43 格的表（0–12，總和 158）：

```
郡  1– 8:  0  0  5  4  3  1  2  5
郡  9–16:  7  3  3  7  2  2  7  7
郡 17–24:  3  2  1  2  0  5  5  3
郡 25–32: 10  3 12  2  2  5  5 10
郡 33–40:  3  3  3  1  2  5  4  1
郡 41–42:  2  3
```

（索引 0 是啞元郡，所以表的第 0、1 格都是 0。）

**水災完全不看民眾忠誠**，只看洪水率。說明書 p.36 的「天災多因人怨
引起」對水災不成立——那條講的是瘟疫（§2）。

洪水率會自己長：`RND(舊÷4) + 舊%4 + 基礎`，期望值約 `舊 × 0.625 + 基礎`，
所以低洪水率的郡會被基礎值推上去，高的郡會被 `÷4` 拉下來，最後停在
`基礎 ÷ 0.375` 附近。**防洪不是一勞永逸的**（`FloodDrop` ＝ 謀略 ÷ 10）。

## 2. 瘟疫（`0x167df`–`0x1683d`，`L0`）

**不逐郡掃，隨機挑一個郡**：

```
郡 = RND(42) + 1
民眾忠誠（offset 26）>= RND(45) + 25 → 不發生
土地價值（offset 27）>= RND(40) + 20 → 不發生
否則 → 那個郡鬧瘟疫
```

兩道門檻都要過。忠誠 70 以上一定安全（門檻上限 69），
忠誠 25 以下一定過第一關；土地價值同理，59 以上安全、20 以下必過。
**這才是說明書「天災多因人怨引起」的出處。**

## 3. 人口成長（`0x16e70`–`0x16f16`，`L0`）

```
無主郡（offset 30 ＝ 0xFF）：RND(100) >= 30 → 跳過
有主郡或那 30%：
  倍率 = 土地價值 + 民眾忠誠 ÷ 2 + 1000
  人口 ← 人口 × 倍率 × 0.001        ; DS:0xa780 = 0.001
  > 10000 → 夾成 10000
```

倍率的上限是 `100 + 50 + 1000 = 1150`，也就是**最快 15%**，而且要
土地價值與忠誠都滿檔才到得了。

⚠ 這一條一度看起來與 `docs/mechanics/60` §1 的 `L1` 觀測衝突——那裡量到
十月的成長是「每個郡都剛好 15%」。**兩者其實一致**：對拍走的是「載入
舊進度」，而那份出貨存檔的土地價值是 100、忠誠 99–100（36 個有主的郡
裡 30 個倍率剛好到頂），所以每個郡都在上限，看起來像常數。劇本 001 的
倍率只有 1019–1059（2–6%），差得很遠。

分辨這件事的量測是 `TestZZSavedGameLandAndLoyalty`：它把「載入舊進度」
之後每個郡的土地價值與忠誠印出來。**兩份相衝的證據裡，先去看它們是不是
在同一個局面上量的**。

## 4. 土地價值的自然衰減（`0x15c8a`–`0x15cbc`，`L0`）

春季常式的**第一件事**，逐郡（1..42，無主的也跑）：

```
土地價值 ← 土地價值 − RND(土地價值 ÷ 10)
```

值越高掉越多，所以土地價值會停在「開發速度 ＝ 衰減速度」的地方，
不會一路到 100 就不動。**這是「土地開發要一直做」的原因**——
少了它，一次開發到頂就永遠不用再管，而畫面上看不出差別。

## 5. 地震（`0x162d2`，`L0`）

```
RND(3) != 0 → 不地震
郡 = RND(42) + 1
```

**沒有第二道門檻**：不看民眾忠誠、不看土地價值。說明書 p.36 的
「天災多因人怨引起」是瘟疫那一條（§2），不是地震。

## 6. 還沒讀

- 蝗蟲（`0x169d6`）的判定。`0x169d6` 前半在算
  `(魅力 + 土地價值 × 4 + 忠誠 × 2) × 人口 ÷ 300` 再加進州郡 offset 18
  （`0x16a6d` 的 `fiadd`），那看起來是**秋收**不是蝗害——同一支函式
  兩件事都做。
- 進貢（`0x172c9`）的件數怎麼算。
- 人物出頭的條件。
- 春季常式裡人物那一段（`0x16294`–`0x162cf`）：看得到
  `忠誠 ← 忠誠 × 9 ÷ 10`、勢力與領地欄的搬移、州郡現役武將數 +1，
  但整段的觸發條件還沒讀。
