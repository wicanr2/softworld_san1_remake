# 10：動畫

哪些地方原版會動、動的是什麼、remake 做了沒。**這一份是清單 ＋ 已解的
兩支**，不是全部；沒解的那幾項寫在 §4，不要當成「原版沒有」。

素材是 `org_game/三國演義/AA.EXE`，位址是**線性位址**
（`CLAUDE.md` §7 第 20 條）。

## 1. 動畫與音效是綁在一起的（`L0`）

兩支已解的動畫都是同一個形狀：

```
for 步進 {
    畫一格
    speak(0, 10)      ; lcall 0597:0210 ——槽 0 ＝ S000.SND
}
```

也就是**每畫一格就送一次 PC 喇叭的音效**（`docs/spec/008`）。
`speak()` 的 31 個遠呼叫端裡，這兩支就佔了 5 個。

所以「音效」在這一款不是事件音，是**動畫的節拍聲**。

## 2. 畫面轉場：四種拉幕（`0x32e40`，`L0`）

場景圖特效 `0x32dfa` 與尋訪共用的那一支；48 個呼叫端與各自的圖號、落點
在 `docs/spec/010` §1.1：

```
lcall 05C4:051C          ; 前置
RND(4) → 四選一
  0 → 0x32e6c    i = 3;  i < 0x60; i += 4     （24 步）
  1 → 0x32ec0    i = 3;  i < 0x60; i += 4     （24 步）
  2 → 0x32f14    i = 0;  i < 0xaf; i += 8     （22 步）
  3 → 0x32f6c    i = 0;  i < 0xaf; i += 8     （22 步）
每一步：lcall es:[0x3efc] 搬一塊 → speak(0, 10)
```

兩個參數 `[bp+6]`／`[bp+8]` 是那塊區域的原點（x、y），區域大小
**`0xaf+1 = 176` 寬、`0x5f+1 = 96` 高**——正好是一張場景圖 `SCG##.IMG` 的尺寸。
搬的來源是顯示記憶體的第二頁：`0x32dfa` 先 `es:[0x2e78](1)` 把場景圖畫在
第二頁再叫它。

分支 0 每一步搬的矩形是（依推入順序反推參數）：

```
(param0..5)
= ([bp+6], [bp+8]+0x5f−i, [bp+6]+0xaf, [bp+8]+0x5f, [bp+6], [bp+8])
= (432, 175−i, 607, 175, 432, 80)
```

**效果是「新畫面整塊滑進來」，不是「逐條露出」**（`L1`，
`TestZZTransitionFrames`）：第 n 步把新畫面靠對邊的那一塊（高 i+1）
貼到這一邊，i 每步變大，最後一步兩邊重合、新畫面歸位。

判準是**與前一步差異的範圍**：量到的是整個已蓋區（分支 0 第 5 步
`y80–99`），逐條露出的話那只會是新增的 `y96–99`。四個分支的逐步邊界、
以及「走完之後與最後一步差 0 個像素」記在 `docs/spec/010` §3。

⚠ **`es:[0x3efc]` 那支搬運常式沒有反組譯**：它的位址要執行期才知道
（`mov es, ds:[0xaa8e]` 之後的跳表），而上面的結論是從**畫面行為**
量出來的。足以重現效果，答不出「有沒有用遮罩」。

## 3. 防拷密碼的盤問畫面（`0x3eb0`，`L0`＋`L1`）

月內迴圈每一格都抽 `RND(12)`，小於月份就 `lcall 03EB:0000`
（`docs/re/08` §2）。那一支**就是防拷密碼的盤問**，不是配樂也不是雜訊：

| 階段 | 步數 | 畫面 |
|---|---|---|
| 1 | 160（`0x4055`–`0x40aa`）| 右側面板拉出一塊藍底 |
| 2 | 160（`0x4112` 那一圈）| 兩張頭像與一個地支沿著座標表滑進定位 |

座標表在 `DS:0x3e64`，每一步一組。兩圈各 `speak(0, 10)` 一次，
所以一次盤問正好 **320** 次音效——`docs/re/09` §8 量到的 320 次就是它。

結束後提示 `請輸入密碼(-%s-)`（`DS:0x5092`），`%s` 是地支。
畫面與按鍵路徑在 `docs/re/02` §3.3（「載入舊進度 → 內政 → 休息 → Y」
就會撞到）。

**remake 不實作防拷**（保存專案，而且密碼表在說明書掃描裡判讀不出來）。
但**那一次 `RND(12)` 要照抽**，否則整條亂數序列從第一個郡起就錯開
（`docs/re/08` §2 已經記著）。

## 4. 主選單右下角的小飾框（`L1`）

畫格來源已定案：`DATA1` 的 **`CURA0.IMG`～`CURA5.IMG`**，各配同名的
`CURA0M.IMG`～`CURA5M.IMG` 遮罩；不是 `MENU3` 的 y 切片、程式畫橢圓或
色盤循環。位置是 `(592,328)`、尺寸 8×16，合成契約是：

```text
目的像素 = (MENU3 背景像素 AND CURAnM 像素) OR CURAn 像素
```

六格與原版對應小飾框的 40×41 區域逐格 **0 像素差**。播放順序固定為
`CURA0 → CURA1 → CURA2 → CURA3 → CURA4 → CURA5 → CURA0`。

`TestZZMenuOrnamentFrames` 用 `bootToMenu` 的行為路標停在主選單掃描碼
迴圈，每 10,000 道指令取樣、共 1,000 次。每個完整畫格停留 25–26 個
樣本（約 25–26 萬道指令），相鄰 `CURA0` 起點固定相隔 155 個樣本，
所以一輪約 **155 萬道指令**。少量樣本落在遮罩與圖像兩次搬運的中間態，
不是第七格。

先前每 200 萬道指令的取樣把週期誤估成 1,400 萬；取樣間隔比真正一輪
還長，看到的是典型別名。這次改用小於單格 1/25 的間隔並直接驗播放相鄰
關係，不再從稀疏雜湊猜週期。

## 4.1 開機片頭（`L0`＋`L1`）

在 `DATA0` overlay 裡，不在主程式：船隊、逐列寫詞、調色盤淡出、頭像橫幅、
三英圖捲入。位址在 `docs/re/13`，逐拍的畫法在 `docs/spec/005`「片頭」。

## 4.2 大地圖上的戰役（`0x1ecfc`，`L0`＋`L1`）

電腦對電腦的戰役：攻方旗隊從攻方郡往守方郡走、守方旗隊原地，兩格交替，
每一格一聲 `speak`。版面與逐格畫法在 `docs/spec/005`「大地圖上的戰役」。
