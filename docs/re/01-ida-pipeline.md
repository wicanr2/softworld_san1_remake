# 反組譯管線：打包過的 overlay 怎麼看

日期：2026-09-06
工具：`tools/ida.sh`、`tools/ida/*.py`

## 1. 為什麼不能直接反組譯

`AA.EXE` 只是載入器（632 個函式），遊戲邏輯在它 chain-load 進來的
`DATA0.GRP` 裡。而 `DATA0.GRP` 是**打包過的執行檔**——檔頭只有 2 段、
1 筆重定位、內容高熵，靜態反組譯是亂碼。

解開後的碼**只存在於記憶體**。

## 2. 管線

```
dosgolem 跑原版
  → -dump-mem 0110:0000:77280   取解壓後的程式碼區
  → -coverage cov.json          取執行過的位址
IDA
  → idat -A -B -pmetapc -b0x110 OVL.BIN
  → tools/ida/seed_cov.py       拿覆蓋率當種子展開
```

### `[HARD]` 三個會安靜出錯的地方

1. **位址換算以 IDA 實際放的位置為準。** `-b0x110` 是把映像放在線性
   `0x1100`，換算是 `seg*16 + off`，不是 `(seg − 基底)*16 + off`。
   踩過：錯的算法讓一部分種子落在映像外（看得出來），
   另一部分落在**錯的位置卻種成功**（看不出來），在資料上造出假程式碼。
2. **段要設 16 位元。** IDA 對 raw binary 預設 32 位元，
   指令會整段解錯，**而且解得出來、不會報錯**。
3. **`exit code` 不能當證據**（`ida-pro-9.4.md`）。每支腳本都寫檔，
   輸出帶輸入檔 SHA-256 當 probe，否則分不出「沒找到」與「沒跑到」。
   實測 `AA.EXE` 的探針回報的 SHA-256 與檔案相符，才確定 IDAPython 真的跑了。

## 3. 成果與邊界

| | 值 |
|---|---|
| `AA.EXE`（有檔頭，正常載入）| 632 個函式、41 個段 |
| overlay dump，只種 6 個執行點 | 10 個函式 |
| overlay dump，種 9,082 個覆蓋率位址 | **220 個函式**，程式碼佔比 22.8% |

### ⚠ 覆蓋率只揭露執行過的碼

搜劇本三表的記錄步長（176／30／72，`docs/formats/03`）：
`mul`／`imul` **一次都沒有**，兩個看似命中的都是假陽性——
一個是 DGROUP 的欄位偏移（`shl bx,1` ＋ `les bx,[bx+1D90h]` 的陣列索引），
一個是 `int 21h AH=35h` 存中斷向量的緩衝區偏移（MSC 浮點模擬器的保存碼）。

**這不是「找不到」，是「那段碼還沒跑過」**：原版目前停在開場插圖／
`DATA5.GRP` 那一層，從未載入 `DATA2`，讀劇本表的程式碼因此不在
已反組譯的 22.8% 裡。

要拿到規則層的欄位版面，得先讓原版走到載入 `DATA2`。
**這一步是前置條件不是可繞過的**——照手冊猜欄位版面會得到自洽、
通過型別檢查、而且不會報錯的錯誤結構（`CLAUDE.md` §7 第 18 條）。
