# 09：PC 喇叭語音

`L0`（反組譯直接讀出）。素材是 `org_game/三國演義/AA.EXE`，

`474780e5be697b3b4899da5e0dbadd2f327e0bbe7e56306ac3b732a15fc124ca`；
執行期 dump `workplace/dump/code-000400.bin`（基底 `0x400`）。本文位址一律是

社群對這一款印象最深的是「用 PC 喇叭講話」

## 1. 它在哪裡

主程式的一個獨立模組，執行期在**段 `05C4`**（線性基底 `0x5C40`）：

| 位移 | 線性 | 是什麼 |
|---|---|---|
| `0x0001` | `0x5c41` | `xor byte es:[0x31aa], 1` ＋ `lret` ——**音效開關**（`docs/re/08` 的 `0xBA`）|
| `0x0039` | `0x5c79` | **公開入口**，四個參數的 far 函式 |
| `0x0085` | `0x5cc5` | 開始播放（設向量、設分頻值、放行 IRQ0）|
| `0x00D7` | `0x5d17` | IRQ0 的處理常式，每次送一個位元 |
| `0x015F` | `0x5d9f` | 停止（遮蔽 IRQ0、分頻值還原成 65536）|

模組自己的變數放在 `cs:` 底下：

| 位移 | 是什麼 |
|---|---|
| `0x1a` | 入口 B 的「播完了」旗標 |
| `0x1c` | 播放中旗標（`0xFFFF` ＝ 播放中）|
| `0x1e` | **分頻值**——說明書講的「語音速度 1–30000」|
| `0x20`／`0x22` | `int 08h` 的舊向量 |
| `0x24`–`0x2e` | **IRQ0 的暫存器保存區**：`AX`／`BX`／`CX`／`DX`／`ES`／`DS`（`0x5d17`–`0x5d39` 逐個存進去）|
| `0x30`／`0x32` | 資料指標（位移／段）|
| `0x34` | 結尾指標 |
| `0x36` | `CH` ＝ 目前這個位元組、`CL` ＝ 已經送掉幾個位元 |

⚠ `0x28` 是**保存區裡的 `CX` 那一格**，不是播放狀態。兩個公開入口都把
首位元組寫進 `0x28`，而播放迴圈讀的是 `0x36`——見 §5.1。

## 2. 公開入口的介面（`05C4:0039`）

```
push bp; mov bp,sp
…
test cs:[0x1c],0xFFFF    ; 已經在播就先停掉
je   +3
call 0x15F
mov  bx,[bp+6]           ; 參數 0：資料位移
mov  ax,[bp+8]           ; 參數 1：資料段
mov  cs:[0x30],bx
mov  cs:[0x32],ax
mov  ax,[bp+0x0a]        ; 參數 2：長度
add  ax,bx
mov  cs:[0x34],ax        ; 結尾 ＝ 起點 ＋ 長度
mov  ch,es:[bx]          ; 第一個位元組
mov  cl,0
mov  cs:[0x28],cx
mov  ax,[bp+0x0c]        ; 參數 3：分頻值（語音速度）
mov  cs:[0x1e],ax
call 0x85                ; 開始
```

所以是 `speak(far 指標, 長度, 語音速度)`。

## 3. 波形格式

**一位元 PCM，最高位先送，八個位元一個位元組。** 每一次 IRQ0 送一個位元：

```
mov  cx,cs:[0x36]
xor  ax,ax
rcl  ch                  ; CF ← CH 的 bit7
rcl  ah                  ; AH bit0 ← CF
rcl  ah                  ; AH bit1 ← 同一個位元
in   al,0x61
and  al,0xFC
or   al,ah
out  0x61,al             ; 喇叭的 bit0 與 bit1 一起等於那個取樣
inc  cl
cmp  cl,8
jne  存回
…取下一個位元組，到 cs:[0x34] 就 call 停止
```

**取樣率由哪一個入口決定**（§5 有兩個）：

| 入口 | 一個取樣的間隔 | 取樣率 |
|---|---|---|
| `05C4:0039`（走 IRQ0）| 8253 通道 0 的分頻值 | `1193182 ÷ 分頻值`，與機器無關 |
| `05C4:01AB`（軟體延遲）| `mov cx,分頻值; loop $` ＋ 送一個位元的碼 | **跟 CPU 速度成正比** |

**遊戲走的是後者**（§5），所以原版的音高**本來就因機器而異**——
說明書要玩家按機器設「語音速度」（`16 MHz 約 100`）就是這個緣故；
分頻值固定而音高不變的話，說明書不需要提 MHz。

粗估：`loop` 在 286 上一次約 8 個週期，送一個位元的路徑約 25 個週期，
所以 16 MHz、速度 100 時約 `16e6 ÷ (100×8+25) ≈ 19 kHz`。
**這是估的（`L3`）**，真值取決於機器與 BIOS 的等待狀態。

## 4. 開始與停止

開始（`0x85`）把 `int 08h` 的向量**直接寫進 `0000:0020`**，不走
`int 21h AH=25`；然後 `out 0x43,0x36`（通道 0、先低後高、模式 3），
把 `cs:[0x1e]` 送進 `out 0x40` 兩次，最後 `in 0x21; and al,0xFE; out 0x21`
放行 IRQ0。

停止（`0x15F`）清旗標、遮蔽 IRQ0、把分頻值寫回 `0`（＝65536，18.2 Hz）。

⚠ **埠 `0x21` 一定要讀得回自己寫進去的值**，執行器少了這一條會把
全部中斷關掉（dosgolem 的 `docs/spec/016` §3.3）。

## 5. 兩個入口，兩條時鐘

模組裡有**兩份**播放常式（IRQ0 的位元序列 `rcl ch; rcl ah; rcl ah;
in al,0x61` 在 `0x5d41` 與 `0x5e5d` 各出現一次）：

| 公開入口 | 時鐘 |
|---|---|
| `05C4:0039`（線性 `0x5c79`）| 重設 8253 通道 0，走 IRQ0，**播完就回**（非同步）|
| `05C4:01AB`（線性 `0x5deb`）| **不動 PIT，用軟體延遲迴圈**，**播完才回**（同步）|

入口 B 的主迴圈（線性 `0x5e2c`–`0x5e44`）：

```
mov  ax,0 ; mov cs:[0x1a],ax     ; 播完旗標清 0
迴圈：
mov  cx,cs:[0x1e]                ; 分頻值 ← 延遲圈數
loop $                           ; 空轉
call 0x5e4d                      ; 送一個位元（與 IRQ0 那一支同一段碼）
test cs:[0x1a],0xFFFF
je   迴圈
```

所以**一段語音播完之前遊戲整個停住**。這是 remake 的差異點：
remake 非同步播，畫面不等它（`docs/spec/008` R5）。

**遊戲走的是 `01AB` 那一個**（實測 320 次呼叫全部走它，通道 0 的分頻值
從頭到尾是 0）。所以只盯 PIT 或只盯 IRQ0 那一支的執行器會判成「沒出聲」
——擷取要掛在**埠 `0x61`** 上（dosgolem 的 `docs/spec/016`）。

### 5.1 第一個位元組播不出來

兩個公開入口的準備動作都是：

```
mov ch,es:[bx]        ; 首位元組
mov cl,0
mov cs:[0x28],cx      ; ← 寫進 IRQ0 的暫存器保存區
```

而兩份播放迴圈讀的都是 `cs:[0x36]`（`0x5d3a` 與 `0x5e56`）。
**首位元組因此從來沒被裝進播放狀態**：實際播出去的第一個位元組是
`cs:[0x36]` 裡上一段留下來的殘留值，八個位元送完之後才
`inc bx` 取到素材的第 1 個位元組，正常往下走到 `cs:[0x34]` 為止。

`L1`（`TestSpeechBitStreamMatchesTheClip`）：

| 候選 | 段數 | 與量到的 165 個間隔對得上 |
|---|---|---|
| 從素材第 0 個位元組起 | 170 | 60／165（36.4%）|
| **殘留位元組 ＋ 素材第 1 個位元組起** | 166 | **165／165（100.0%）** |

進入時的 `cs:[0x36]` 是 `FF00`（`CH` ＝ `0xFF`、`CL` ＝ 0），一個位元
約 34 道指令。

殘留的 `0xFF` 是上一段結束時 `mov ch,es:[bx]` 從緩衝區尾端**後面一個
位元組**讀到的值。所以它穩定，但它是越界讀來的，不是資料。

影響：音效少掉 128 分之 1、語音少掉數千分之一，聽不出來。
remake 怎麼處理寫在 `docs/spec/008` R7。

## 6. 遊戲怎麼叫它

### 6.1 `speak(索引, 速度)`（線性 `0x5b80`）

```
push bp; mov bp,sp
xor ax,ax; lcall 05C4:051C
mov es,[0xa562]
cmp word es:[0x31aa],0       ; ← 音效狀態；不是 0 就直接回 −1
jne 不播
cmp word [bp+6],0
jl  不播
cmp word [bp+6],3
jg  不播                      ; ← **索引只能 0–3**
filds  [0x17c6]              ; 速度校正值
fidivrs [bp+8]
fmull  ds:[0xa564]
lcall  05C4:4D60             ; 取整（MSC 的 ftol）
cmp    ax,0x0a
jge    +5
mov    word [bp+8],0x0a      ; **分頻值下限 10**
push   [bp+8]
push   es:[bx+0x3c8c]        ; 長度（[0xa560] 段，一項 2 bytes）
push   es:[bx+0x87a]         ; 資料段  ┐[0xa55e] 段
push   es:[bx+0x878]         ; 資料位移┘ 一項 4 bytes
lcall  05C4:01AB
```

四個索引 ＝ **四個已載入的緩衝槽**。門是**音效狀態**，不是語音狀態。

### 6.2 語音走訊息常式（線性 `0x3273e`，111 個呼叫端）

那支常式在顯示訊息之後：

```
cmp word es:[0x3148],0        ; ← 語音狀態
jne 跳過
push [bp-4]                   ; 速度
mov  ax,1 ; push ax           ; 槽 1
lcall 0597:0210               ; ＝ speak()
… 槽 2 …
… 槽 3 …
```

**一句話由三個槽接起來**（例如「人名」「動詞」「地名」）。同一支常式
另一處在語音開啟時組出檔名 `R%03d.OKR`（`DS:0x9b52`），索引先夾到
`≤ 0x1F3`（499）。

### 6.3 誰把資料載進槽

載入器 `loadClip(char far *name, int slot)`（線性 `0x5a76`）：

```
slot 不在 0–3        → "Invalid SND"  （DS:0x5402）
slot 0 且 長度 > 1000 → "Real#0>1000"  （DS:0x540e）
長度 > 0x1068(4200)  → "Real#1-3>4200"（DS:0x541a）
讀進 es:[0x878 + slot*4]（遠指標，段取自 DS:0xa55e）
長度寫 es:[0x3c8c + slot*2]（段取自 DS:0xa560）
```

四個呼叫端：

| 線性 | 槽 | 來源 |
|---|---|---|
| `0x117df` | 0 | `S000.SND`（開機一次）|
| `0x32b4b`／`0x32b77`／`0x32ba3` | 1／2／3 | `R%03d.OKR`（每則訊息現載）|

所以**槽 0 是音效、槽 1–3 是語音**——原版自己的訊息字串
（`Real#0>1000` vs `Real#1-3>4200`）就是這樣分的。

`L1`（`TestSpeechClipsAreTheAssetBytes`）：載入器一次，槽 0 ←
`S000.SND`；播放入口拿到的 128 個位元組與 `DATA1／S000.SND` **雜湊相同**。

### 6.4 語音資料在容器裡

`R000.OKR`–`R499.OKR`，**共 465 段**（兩版相同）：

| 容器 | 段數 | 範圍 |
|---|---|---|
| `DATA2` | 418 | `R000`–`R427` |
| `DATA3` | 47 | `R428`–`R499`（中間有洞）|

## 7. 兩個開關

| 開關 | 位置 | 值 |
|---|---|---|
| 音效狀態 | 工作段 `0x31aa` | 0 ＝ 開啟、1 ＝ 關閉 |
| 語音狀態 | 工作段 `0x3148` | 同上 |

**語音要兩個都開**：`speak` 自己的門是音效狀態，語音那三段的門才是語音
狀態。說明書 p.26 的「若關閉音效，語音將無法使用」就是這個結構。

## 8. 實測（`L1`）

`internal/parity/speech_oracle_test.go`，dosgolem。把兩個開關直接寫成
開啟、走「內政 → 休息 → Y」推一個月：

| 量到的 | 值 |
|---|---|
| `speak()` 進去 | 320 次 |
| 入口 B 進去 | 320 次 |
| IRQ0 那一支 | **0 次** |
| 8253 通道 0 分頻值 | 0（沒被動過）|
| 埠 `0x61` 切換 | **53,120 次**，跨 1,169 萬道指令（約 3.9 秒）|

波形的段長分佈是 1–8 個取樣為主、外加一叢 83–86，**不是等長的方波**
——那是真的取樣，不是嗶聲。

這一輪走到的是**音效**（訊息常式一次都沒進去）。320 次全部來自
**防拷密碼的盤問畫面**（`docs/re/10` §3：兩圈各 160 步，每步一次
`speak(0, 10)`）——那條按鍵路徑（載入舊進度 → 內政 → 休息 → Y）
撞到的就是它（`docs/re/02` §3.3）。

所以「音效」在這一款是**動畫的節拍聲**，不是事件音（`docs/re/10` §1）。
