# 09：PC 喇叭語音

`L0`（反組譯直接讀出）。素材是 `org_game/三國演義/AA.EXE`，
執行期 dump `workplace/dump/code-000400.bin`（基底 `0x400`）。

社群對這一款印象最深的是「用 PC 喇叭講話」
（`docs/reference/02-web-10-gameplay` §10）。整支播放器解出來了。

## 1. 它在哪裡

主程式的一個獨立模組，執行期在**段 `05C4`**（線性基底 `0x5C40`）：

| 位移 | 線性 | 是什麼 |
|---|---|---|
| `0x0001` | `0x5c41` | `xor byte es:[0x31aa], 1` ＋ `lret` ——**音效開關**（`docs/re/08` 的 `0xBA`）|
| `0x0039` | `0x5c79` | **公開入口**，四個參數的 far 函式 |
| `0x0085` | `0x5cc5` | 開始播放（設向量、設分頻值、放行 IRQ0）|
| `0x00D7` | `0x5d17` | IRQ0 的處理常式，每次送一個位元 |
| `0x015F` | `0x5d9f` | 停止（遮蔽 IRQ0、分頻值還原成 65536）|

模組自己的變數放在 `cs:` 底下：

| 位移 | 是什麼 |
|---|---|
| `0x1c` | 播放中旗標（`0xFFFF` ＝ 播放中）|
| `0x1e` | **分頻值**——說明書講的「語音速度 1–30000」|
| `0x20`／`0x22` | `int 08h` 的舊向量 |
| `0x30`／`0x32` | 資料指標（位移／段）|
| `0x34` | 結尾指標 |
| `0x36` | `CH` ＝ 目前這個位元組、`CL` ＝ 已經送掉幾個位元 |

## 2. 公開入口的介面（`05C4:0039`）

```
push bp; mov bp,sp
…
test cs:[0x1c],0xFFFF    ; 已經在播就先停掉
je   +3
call 0x15F
mov  bx,[bp+6]           ; 參數 0：資料位移
mov  ax,[bp+8]           ; 參數 1：資料段
mov  cs:[0x30],bx
mov  cs:[0x32],ax
mov  ax,[bp+0x0a]        ; 參數 2：長度
add  ax,bx
mov  cs:[0x34],ax        ; 結尾 ＝ 起點 ＋ 長度
mov  ch,es:[bx]          ; 第一個位元組
mov  cl,0
mov  cs:[0x28],cx
mov  ax,[bp+0x0c]        ; 參數 3：分頻值（語音速度）
mov  cs:[0x1e],ax
call 0x85                ; 開始
```

所以是 `speak(far 指標, 長度, 語音速度)`。

## 3. 波形格式

**一位元 PCM，最高位先送，八個位元一個位元組。** 每一次 IRQ0 送一個位元：

```
mov  cx,cs:[0x36]
xor  ax,ax
rcl  ch                  ; CF ← CH 的 bit7
rcl  ah                  ; AH bit0 ← CF
rcl  ah                  ; AH bit1 ← 同一個位元
in   al,0x61
and  al,0xFC
or   al,ah
out  0x61,al             ; 喇叭的 bit0 與 bit1 一起等於那個取樣
inc  cl
cmp  cl,8
jne  存回
…取下一個位元組，到 cs:[0x34] 就 call 停止
```

取樣率 ＝ `1193182 ÷ 分頻值`。說明書說「16 MHz 機種約 100」，
也就是約 11.9 kHz。

## 4. 開始與停止

開始（`0x85`）把 `int 08h` 的向量**直接寫進 `0000:0020`**，不走
`int 21h AH=25`；然後 `out 0x43,0x36`（通道 0、先低後高、模式 3），
把 `cs:[0x1e]` 送進 `out 0x40` 兩次，最後 `in 0x21; and al,0xFE; out 0x21`
放行 IRQ0。

停止（`0x15F`）清旗標、遮蔽 IRQ0、把分頻值寫回 `0`（＝65536，18.2 Hz）。

⚠ **埠 `0x21` 一定要讀得回自己寫進去的值**，執行器少了這一條會把
全部中斷關掉（dosgolem 的 `docs/spec/016` §3.3）。

## 5. 兩個入口

模組裡有**兩份**同樣的播放常式（IRQ0 的位元序列 `rcl ch; rcl ah; rcl ah;
in al,0x61` 在 `0x5d41` 與 `0x5e5d` 各出現一次）：

| 公開入口 | 差別 |
|---|---|
| `05C4:0039` | 四個參數：資料位移、資料段、長度、分頻值 |
| `05C4:01AB` | 同樣四個參數，另外把 `cs:[0x1a]` 清成 0 |

遊戲走的是 `01AB` 那一個。

## 6. 遊戲怎麼叫它：`speak(編號, 速度)`

唯一的呼叫端在線性 `0x5bf5`（另一個碼段，段基底在 `0x5C40` 以下）：

```
filds  [0x17c6]              ; 語音速度的校正值
fidivrs [bp+8]               ; ÷ 參數 1
fmull  ds:[0xa564]
lcall  05C4:4D60             ; 取整（MSC 的 ftol）
mov    [bp+8],ax
cmp    ax,0x0a
jge    +5
mov    word [bp+8],0x0a      ; **分頻值下限 10**
push   [bp+8]                ; 參數 3：分頻值
mov    es,[0xa560]
mov    bx,[bp+6]             ; 參數 0 ＝ 語音編號
shl    bx
push   es:[bx+0x3c8c]        ; 參數 2：長度（一項 2 bytes）
mov    es,[0xa55e]
mov    bx,[bp+6]
shl    bx ; shl bx
push   es:[bx+0x87a]         ; 參數 1：資料段
push   es:[bx+0x878]         ; 參數 0：資料位移（一項 4 bytes）
lcall  05C4:01AB
```

所以介面是 **`speak(編號, 速度)`**：

- 語音資料的遠指標表在 `[0xa55e]` 那個段的 `0x878` 起，一項 4 bytes。
- 長度表在 `[0xa560]` 那個段的 `0x3c8c` 起，一項 2 bytes。
- 分頻值是算出來的：`[0x17c6] ÷ 速度 × ds:[0xa564]`，取整，**不小於 10**。
  `0x17c6` 就在語音狀態 `0x17c2` 旁邊，是說明書講的「語音速度」那個
  可調參數（1–30000）。

## 7. 還沒解出來的

**誰呼叫 `speak`、以及編號對應哪一句。** `0x5bf5` 那一段所在的碼段
基底還沒定出來，所以它自己的呼叫端還沒掃。

實跑到目前為止一次都沒出聲：開場一千五百萬萬道指令
（`-steps 1500000000`）寫過的 I/O 埠只有 EGA 的六個
（`3C4 3C5 3CE 3CF 3D4 3D5`）；進到遊戲主畫面、把語音與音效兩個旗標
直接寫成開啟（`es:0x17c2`／`es:0x31aa` ← 0，`docs/re/08` §1）再跑
四億八千萬道指令也一樣。

加強版還沒掃：現有的 `plus-*` dump 都從 `0xb000` 起，而這個模組在
基本版落在 `0x5C40`——**掃不到不等於沒有**。

⚠ **「掃不到呼叫端」不等於「不會被呼叫」**：靜態掃描只涵蓋寫死的常數
（`CLAUDE.md` §7 第 1 條）。dosgolem 現在攔得到那兩個入口
（`internal/parity/speech_oracle_test.go` 掛在 `0x5cc5` 與 `0x5d17`），
缺的是把原版驅動到會講話的那一刻。
