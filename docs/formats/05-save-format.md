# remake 的存檔格式

原版有六個進度（說明書 p.25），存在 `DATA2.GRP` 容器裡：

| 項目 | 每槽 | 長度 | 內容 |
|---|---|---|---|
| `BASEMAS.SV1`–`.SV6` | 1 | 1,152 | 諸侯表 16 × 72 |
| `BASESTA.SV1`–`.SV6` | 1 | 7,568 | 州郡表 43 × 176 |
| `BASEGEN.SV1`–`.SV6` | 1 | 10,500 | 人物表 350 × 30 |
| `BASEPRO.SV1`–`.SV6` | 1 | 256 | 年月、難度、選項、月內進度 |
| `BASEPRE.SV1`–`.SV6` | 1 | 384 | 自創君主的十二個字模 |
| `SAVENAME.SVP` | 共用 | 126 | 六個存檔的名稱，六筆 21 byte |

三張主表的版面與六個劇本（`.001`–`.006`）完全相同，欄位見 `docs/spec/003`。

## remake 存到哪裡

一個進度是一個目錄，六個檔案，外加一個共用的名稱表：

```
saves/SV1/BASEMAS.SV1     諸侯表 16 × 72
saves/SV1/BASESTA.SV1     州郡表 43 × 176
saves/SV1/BASEGEN.SV1     人物表 350 × 30
saves/SV1/BASEPRO.SV1     年月、難度、選項、月內進度 256 B
saves/SV1/BASEPRE.SV1     自創君主的十二個字模 384 B
saves/SV1/REMAKE.JSON     前五個放不下的東西
saves/SAVENAME.SVP        六個進度共用的名稱 126 B
```

前五個與名稱表**都照原版的版面**。目錄位置由 `-saves` 指定，預設 `saves/`。

**不寫回原版的容器。** 原版的存檔是 `DATA2.GRP` 裡的項目，要存就得改寫
玩家自己的原版檔案；那是別人的東西，而且寫壞了沒有第二份。

## 為什麼照原版的版面寫

兩個理由。

一是**已知欄位可以直接與原版的存檔對拍**——同一個局面存兩邊，
逐位元組比對就看得出哪一欄還沒解對。用自訂格式就得先寫一層轉換，
而轉換本身也可能是錯的。

二是**沒解出來的位元組原封不動帶著走**。州郡表 176 個位元組已經逐格
盤點過（`docs/spec/003` §3.0），諸侯表 72 個還有六十幾個沒解。存檔時
只蓋已知欄位，其餘照抄載入時的值——**寫成零等於替將來解出它的人
銷毀證據**。

## 驗過的：什麼都沒做就存檔，與原版逐位元組相同

`TestUntouchedSaveMatchesTheOriginal` 把六個劇本各開一局、什麼都不做
就寫回三張表，與原版的 `.001`–`.006` 逐位元組比對——**六個劇本、
三張表、19,220 個位元組全部相同**。

這一條同時問到三件事：編碼與解碼對著同一張版面表；劇本起點的快照欄位
（郡的兵士、現役／在野武將數）與人物表一致；
未解的位元組真的原封不動。任何一項錯了都會在那裡變成一個位移。

## 已知欄位（存檔時會蓋掉的）

| 表 | 位移 | 欄位 |
|---|---|---|
| 州郡 | 14、16 | 人口、兵士（皆為實際值 ÷ 100）|
| 州郡 | 18、20 | 金、米 |
| 州郡 | 22、23 | 現役武將數快照、在野武將數 |
| 州郡 | 26–29 | 民眾忠誠、土地價值、洪水率、物價 |
| 州郡 | 30 | 所屬勢力 |
| 人物 | 7–13 | 年齡、體能、謀略、戰力、魅力、職位、出身郡 |
| 人物 | 16–19 | 忠誠、身分、勢力、所在郡 |
| 人物 | 21–25 | 兵種、兵力（uint16）、訓練度、武裝度 |
| 諸侯 | 2 | 君主的人物槽號（uint16）|

郡名與人名（各表的 offset 0）**不蓋**：那是靜態資料，不會在一局裡改變。
州郡表的第 0 筆是原版的啞元，整筆原樣帶過去。

## `REMAKE.JSON`

三張表裝得下原版存的東西，裝不下 remake 自己加的：

| 欄位 | 為什麼在這裡 |
|---|---|
| `player` | 原版靠諸侯表 offset 0（操縱方）認玩家，remake 另外記一份 |
| `edition` | 原版沒有「加強版」這回事 |
| `prefectures[].population` | **精確人口**。原版那一欄只放得下百位（格式字串是 `人口 %5d00`），而 remake 的四季事件用百分比縮放，算出來不是百的倍數；只靠原版那一欄，每存一次就掉最多 99 人 |

`year`、`month`、`difficulty`、六個選項與「這個月下過令沒」原本也在這裡，
現在走 `BASEPRO`。**同一個值不要有兩個真相**：`BASEPRO` 在就以它為準，
JSON 那幾格只為了讀得懂舊存檔而留著。
| `rewarded` | 這個月受過賞的人物槽號（每郡每月可賞每人一次，p.23）|
| `factions[].alive`／`chief`／`treasury` | 勢力存活、現任軍師、君主寶庫。寶庫在 `BASEMAS` 哪裡還沒解 |

`version` 是格式版本。**讀不懂要報錯，不要盡力而為**——
一份被半懂的程式讀進來的存檔，玩下去才會出事。

## 寫入是原子的

先寫到 `SV<n>.tmp` 再改名。存檔寫到一半當掉，玩家失去的是**上一次的
進度**，那比這一次沒存到嚴重得多。

## 讀原版存的進度

`save.ReadOriginal(c, slot, edition)` 把 `DATA2.GRP` 裡的一個進度讀成
一局。三張主表走既有的 `state.DecodeTables`，年月、難度、選項與
「這個月哪些郡還沒下令」來自 `BASEPRO`，玩家是諸侯表 offset 0 等於 1
的那個槽。

原版讀完後會從 `BASEPRO` 的月游標接回回合迴圈；游標若正停在玩家郡，
`0x17471` 先重整該郡的兵士與現役將快照，再顯示主命令。第 1 格因此把
郡 41 的兩欄由檔案的 `0／0` 刷成執行期的 `5／1`。remake 只在這個可證實
的玩家停點重現刷新，不把電腦郡尚未執行的整套分派器縮成兩個欄位更新。

出貨的六個進度裡有兩個特例，兩個都不是錯誤：

- **第 1 個進度的玩家一個郡都沒有。** 那是自創君主（諸侯槽 14、
  人物槽 346）輸掉的局面。
- **第 2 個進度的難度是 15**，超出原版輸入畫面給的 1–10。
  `ReadOriginal` **報錯不夾**——原版的難度係數表只有 11 格，
  夾成 10 會安靜地把整局的行為換掉（`docs/re/08` §5）。

## `BASEPRO`、`BASEPRE` 與 `SAVENAME`

版面與逐欄的出處在 `docs/re/08-save-load.md`；實作是
`internal/state/progress.go`，`internal/save/original.go` 負責與局面對接。

三支測試釘住它（`internal/state/progress_test.go`）：

- 出貨的六個進度逐欄核對，年份對得上名稱裡的 `Y201`／`Y208`／`Y215`／`Y220`；
  而且**未下令的郡數、順序表與游標三者相符**——那是三段獨立資料之間的
  關係，版面認錯一格就會破。
- 解完再編回去逐位元組相同，**包含沒解出用途的那 58 個位元組**。
- 十二個字模是四個名額 × 三個字，六個進度完全相同。

## 還沒做的

- `BASEPRO` 位移 `0xAC`（讀進 `DS:0x5b00`）沒有第三處引用，用途不明。
- 自創君主本身。範本（四個名額、姓名用造字 `A141`–`A14C`）已經讀出來，
  remake 還沒有畫字模的介面，所以 `BASEPRE` 目前一律寫空的。
- 讀檔選單還沒有「原版的進度」那一頁。命令列已經通了：

  ```
  go run ./cmd/san1 -root path/to/三國演義 -orig-load 3
  ```

  `save.ListOriginal` 列六格、`save.ReadOriginal` 讀一格，兩者都只讀
  容器，不寫回去。
