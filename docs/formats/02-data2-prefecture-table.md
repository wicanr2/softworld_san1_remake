# `DATA2.GRP` 的州郡表：42 個郡名

狀態：**郡名已驗**（`L0`）。整筆 176 byte 的欄位版面**未解**。
日期：2026-09-06。輸入 `org_game/三國演義/DATA2.GRP`（1,156,221 B）。

## 1. 怎麼找到的

`docs/reference/02-web-20-technical.md` 從社群資料整理出一張「磁區#位置」表，
並算出把磁區當 512 byte 之後，十二個區塊的州郡區長度都是 **7392 ＝ 42 × 176**。
那份資料的證據位階最低（`CLAUDE.md` §4 第 5 級），但它指出了一個
**一次讀取就能否證的位址**——這正是社群資料該有的用法。

驗證只花一次讀取：`DATA2.GRP` offset 818,235 起的 4 byte 解 `cp950` 是「遼東」，
第 5 個 byte 是 `00`。往後每 176 byte 讀一次，42 筆**全部**是合法 Big5 郡名，
順序由東北到南（遼東 → 涿郡 → … → 南海 → 鬱林）。

亂數不會排出這種順序，社群那張位址表因此成立。

## 2. 已驗的部分（`L0`）

- 州郡表起點 `818,235`（劇本一）
- 每筆 **176 byte**，共 **42** 筆
- 筆內 offset 0 是郡名：**4 byte Big5（兩個漢字）＋ 1 byte `00`**
- 原版與加強版的這個區段**逐位元組相同**

## 4. 沒解的部分

- **176 byte 裡除了郡名的其餘 171 byte**。第一筆郡名後面是
  `00 00 14 01 17 00 ff ff 00 00 46 00`——`ff ff` 很像哨兵值
  （`CLAUDE.md` §7 第 11 條：原版哨兵值 ≠ Go 零值），但欄位邊界還沒定。
  手冊 p.9–13 列了 15 項郡屬性（`docs/reference/01-manual-20`），
  那是**該去對的清單**，不是可以直接套上去的版面。
- 十二個區塊（六時期劇本 ＋ 六存檔槽）的其餘十一個起點還沒逐一驗。
- 同一份資料裡的諸侯表（每筆 72 byte）與人物表（每筆 30 byte）還沒驗。
  人物表 342 筆的話，應能對回手冊附錄三的 342 位（F16）——
  **那是下一個最便宜的交叉驗證**：兩份獨立來源的同一個數字對上，
  比任何單邊的推論都硬。

## 5. 這一條對專案的意義

手冊全書沒有郡名對照表，42 個郡一律只用編號（F15）。這張表因此**只能從資料取**，
而三國題材下憑印象補郡名，錯的東西會看起來非常合理——這正是
`CLAUDE.md` §7 第 5 條要防的。現在 42 個字沒有一個是猜的。
