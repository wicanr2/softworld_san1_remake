# 點陣圖

原版的圖有兩個副檔名：`.IMG`（畫面、圖塊、選單框）與 `.FAC`（人物肖像）。
三組容器裡共 **613 張**，全部同一個格式。

## 1. 版面

```
uint16  高（列）
uint16  寬（像素）
···     四個完整的位元平面
```

每個平面 `(寬+7)/8 × 高` 個位元組，每個位元組**由左而右**（最高位在左）。
平面依 **I、R、G、B** 的順序存：平面 0 是亮度、1 是紅、2 是綠、3 是藍，
對到色號的 bit 3、2、1、0。

⚠ **表頭是「高、寬」不是「寬、高」。** `F000.FAC` 的前四個位元組是
`50 00 40 00`＝80、64，而肖像是 64 寬 80 高。反過來讀不會報錯——
`(寬+7)/8 × 高 × 4` 這個等式對兩種讀法都成立（兩邊都是 8 的倍數時），
只會得到一張寬高互換的雜訊。

## 2. 怎麼確定的

版面的部分（四個完整平面、最高位在左）**肉眼分得出來**：換一種讀法
就不是圖。但**平面與顏色的對應只換顏色不換結構**，二十四種排列
在結構上完全一樣——選錯的那一張仍然是一張圖，只是顏色不對。

所以拿原版自己算出來的色號比對：

1. 用 dosgolem 把原版跑到君主選擇畫面，把 EGA framebuffer 存成 PNG
2. 把 PNG 的 RGB 換回 EGA 色號
3. 把候選解讀拿去畫面裡找完全相符的位置

結果：`F000.FAC` 在 (488,56)、`F005.FAC` 在 (420,56)，
**逐像素 100% 相符**（各 5,120 個像素全中），而且只有
`平面→位元 = [3 2 1 0]` 這一組對得上。

工具是 `cmd/san1imgcheck`，隨時可以重跑：

```sh
# 先產畫面（在 dosgolem-san）
DOSGOLEM_ORIG=.../org_game tools/go.sh run ./cmd/probe \
  -exe "/orig/三國演義/AA.EXE" -root "/orig/三國演義" \
  -steps 3000000000 -keys '122' \
  -keys-at '250000000:\r,900000000:1,1500000000:1' \
  -ega-every '100000000:640x350=/src/workplace/shots/s'

# 再比對
tools/go.sh run ./cmd/san1imgcheck -shot workplace/lords.png \
  -root /path/to/三國演義 -container DATA1 -items F000.FAC,F005.FAC
```

> 一開始是用「同色像素比例」在二十四種排列裡挑，挑出來的那張膚色自然、
> 頭冠是金褐色，看起來完全合理——但它是 `[2 1 0 3]`，與畫面比對出來的
> `[3 2 1 0]` 不同。**看起來合理的解讀不等於對的解讀**，這種只換顏色的
> 錯誤沒有任何辦法從資料本身分辨。

## 3. 尺寸

| 項目 | 尺寸 | 張數 |
|---|---|---|
| `F###.FAC` 肖像 | 64 × 80 | 306（`DATA1` 50、`DATA3` 256）|
| `TITL0`–`TITL3.IMG` | 160 × 400 | 4 |
| `ENDO0`–`ENDO3.IMG` | 160 × 336 | 4 |
| `SCG##.IMG` 事件圖 | 176 × 96 | 31 |
| `MAINMAP1`–`7`、`B`、`C` | 640 × 36 | 9 |
| `CP###.IMG` | 24 × 24 | 44 |
| `8x8PAT0`–`3`、`8x8AND0`–`3` | 8 × 8 圖塊與遮罩 | 8 |
| `WEATHER0`–`2.IMG` | 32 × 32（對應戰場的晴／風／雨）| 3 |

肖像固定 2,564 個位元組：4 個表頭 ＋ 8 × 80 × 4 個平面 ＝ 2,560。

**主畫面的地圖是九條 640×36 的橫帶**（`MAINMAP1`–`7`、`B`、`C`）。
九條疊起來是 324 列，主畫面地圖區的高度就在這個量級——原版顯然是
逐帶貼上去的。

## 4. 色盤

用的是 **EGA 的預設十六色**。

`EGAFILL.PAL` 與 `HERCFILL.PAL` 各 1,024 個位元組，**不是色盤**：
內容全是 0x0C（EGA 亮紅）或 0x00／0x0F 這種色號，看起來是**填色圖樣表**
——每種邏輯顏色一小塊 EGA 色號的圖樣，Hercules 那一份只有黑與白。
用途未解。

原版跑 mode 10h，有沒有重寫色盤暫存器還沒查；上面的 100% 比對是在
dosgolem 的預設色盤下成立的，所以至少那一個畫面沒有改過色盤。

## 5. 匯出

`cmd/san1assets` 把每一張存成 PNG：

```sh
tools/go.sh run ./cmd/san1assets -root /path/to/三國演義 -out workplace/assets
```

⚠ 匯出的是玩家自己那一份原版的內容，**不隨本專案散布**。
輸出目錄預設在 `workplace/`（已被 gitignore 擋掉）。

## 6. 還沒解的

- `TITL0`–`3` 四張 160×400 的圖怎麼組成 640×350 的標題畫面。
  拿它們去標題畫面裡找**找不到完全相符的位置**，所以不是單純的貼上——
  可能經過遮罩、轉置或動畫。
- `.MSK` 與 `8x8AND*`（遮罩）怎麼與圖搭配。
- `EGAFILL.PAL`／`HERCFILL.PAL` 的填色圖樣怎麼用。
