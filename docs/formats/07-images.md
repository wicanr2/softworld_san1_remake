# 點陣圖

原版的圖有兩個副檔名：`.IMG`（畫面、圖塊、選單框）與 `.FAC`（人物肖像）。
三組容器裡共 **613 張**，全部同一個格式。

## 1. 版面

```
uint16  高（列）
uint16  寬（像素）
···     四個完整的位元平面
```

每個平面 `(寬+7)/8 × 高` 個位元組，每個位元組**由左而右**（最高位在左）。
平面依 **I、R、G、B** 的順序存：平面 0 是亮度、1 是紅、2 是綠、3 是藍，
對到色號的 bit 3、2、1、0。

⚠ **表頭是「高、寬」不是「寬、高」。** `F000.FAC` 的前四個位元組是
`50 00 40 00`＝80、64，而肖像是 64 寬 80 高。反過來讀不會報錯——
`(寬+7)/8 × 高 × 4` 這個等式對兩種讀法都成立（兩邊都是 8 的倍數時），
只會得到一張寬高互換的雜訊。

## 2. 怎麼確定的

版面的部分（四個完整平面、最高位在左）**肉眼分得出來**：換一種讀法
就不是圖。但**平面與顏色的對應只換顏色不換結構**，二十四種排列
在結構上完全一樣——選錯的那一張仍然是一張圖，只是顏色不對。

所以拿原版自己算出來的色號比對：

1. 用 dosgolem 把原版跑到君主選擇畫面，把 EGA framebuffer 存成 PNG
2. 把 PNG 的 RGB 換回 EGA 色號
3. 把候選解讀拿去畫面裡找完全相符的位置

結果：`F000.FAC` 在 (488,56)、`F005.FAC` 在 (420,56)，
**逐像素 100% 相符**（各 5,120 個像素全中），而且只有
`平面→位元 = [3 2 1 0]` 這一組對得上。

工具是 `cmd/san1imgcheck`，隨時可以重跑：

```sh
# 先產畫面（在 dosgolem-san）
DOSGOLEM_ORIG=.../org_game tools/go.sh run ./cmd/probe \
  -exe "/orig/三國演義/AA.EXE" -root "/orig/三國演義" \
  -steps 3000000000 -keys '122' \
  -keys-at '250000000:\r,900000000:1,1500000000:1' \
  -ega-every '100000000:640x408=/src/workplace/shots/s'

# 再比對
tools/go.sh run ./cmd/san1imgcheck -shot workplace/lords.png \
  -root /path/to/三國演義 -container DATA1 -items F000.FAC,F005.FAC
```

> 一開始是用「同色像素比例」在二十四種排列裡挑，挑出來的那張膚色自然、
> 頭冠是金褐色，看起來完全合理——但它是 `[2 1 0 3]`，與畫面比對出來的
> `[3 2 1 0]` 不同。**看起來合理的解讀不等於對的解讀**，這種只換顏色的
> 錯誤沒有任何辦法從資料本身分辨。

## 3. 尺寸

| 項目 | 尺寸 | 張數 |
|---|---|---|
| `F###.FAC` 肖像 | 64 × 80 | 306（`DATA1` 50、`DATA3` 256）|
| `TITL0`–`TITL3.IMG` | 160 × 400 | 4 |
| `ENDO0`–`ENDO3.IMG` | 160 × 336 | 4 |
| `SCG##.IMG` 事件圖 | 176 × 96 | 31 |
| `MAINMAP1`–`7`、`B`、`C` | 640 × 36 | 9 |
| `CP###.IMG` | 24 × 24 | 44 |
| `8x8PAT0`–`3`、`8x8AND0`–`3` | 8 × 8 圖塊與遮罩 | 8 |
| `WEATHER0`–`2.IMG` | 32 × 32（依序是晴、雨、風）| 3 |

肖像固定 2,564 個位元組：4 個表頭 ＋ 8 × 80 × 4 個平面 ＝ 2,560。

**主畫面的地圖是九條 640×36 的橫帶**（`MAINMAP1`–`7`、`B`、`C`）。
九條疊起來是 324 列，主畫面地圖區的高度就在這個量級——原版顯然是
逐帶貼上去的。

## 4. 色盤

用的是 **EGA 的預設十六色**。

`EGAFILL.PAL` 與 `HERCFILL.PAL` 各 1,024 個位元組，**不是色盤**：
內容全是 0x0C（EGA 亮紅）或 0x00／0x0F 這種色號，看起來是**填色圖樣表**
——每種邏輯顏色一小塊 EGA 色號的圖樣，Hercules 那一份只有黑與白。
用途未解。

原版跑 mode 10h，有沒有重寫色盤暫存器還沒查；上面的 100% 比對是在
dosgolem 的預設色盤下成立的，所以至少那一個畫面沒有改過色盤。

## 5. 匯出

`cmd/san1assets` 把每一張存成 PNG：

```sh
tools/go.sh run ./cmd/san1assets -root /path/to/三國演義 -out workplace/assets
```

⚠ 匯出的是玩家自己那一份原版的內容，**不隨本專案散布**。
輸出目錄預設在 `workplace/`（已被 gitignore 擋掉）。

## 6. 還沒解的

- `TITL0`–`3` 四張 160×400 的圖怎麼組成標題畫面（並排成 640×400，畫面 408 列）。
  拿它們去標題畫面裡找**找不到完全相符的位置**，所以不是單純的貼上——
  可能經過遮罩、轉置或動畫。
- `.MSK` **怎麼與圖搭配**（格式解出來了，見下一節；用途沒解）。
- `8x8AND*` 怎麼與圖搭配。
- `EGAFILL.PAL`／`HERCFILL.PAL` 的填色圖樣怎麼用。

## `.MSK`：單平面的一位元遮罩

表頭與 `.IMG` **完全相同**（高、寬各一個 `uint16`，先高後寬），
但**只有一個平面**——一個位元一個像素，最高位先送，每一列補齊到位元組。

判準是長度：`stride × h` 而不是 `stride × h × 4`。所以拿 `DecodeImage`
去解 `.MSK` 會在長度那一關被擋下來，**不會安靜地解出半張圖**
（`assets.DecodeMask`）。

整套素材裡**只有一張**：`DATA2` 的 `ENDO4.MSK`，**640×151**，
內容是一條山巒的輪廓（下方全 0、上方全 1）。它與 `ENDO0`–`ENDO3`
（四張 160×336 並排成 640×336 的朝堂圖）放在一起，但那張圖裡沒有山
——**它蓋在哪一張圖上還沒解**。

用它們的是 `DATA0.GRP`／`DATA4.GRP` 那兩支 overlay：主程式的映像裡
一次都沒出現 `ENDO`／`UPR`／`REC1` 這些字串。

## `EGAFILL.PAL`：州郡的填色圖樣

`DATA1` 的 `EGAFILL.PAL` 是 1024 個位元組 ＝ **16 × 64**：十六個勢力各一塊
8×8 的圖樣，一格一個位元組、值就是 EGA 的顏色索引。同一份還有
`HERCFILL.PAL`（Hercules 單色卡用的）。

前四塊是純色（12、9、10、14），其餘十二塊是兩色的 2×2 網點：

| # | 內容 | | # | 內容 |
|---|---|---|---|---|
| 0 | 純 12 | | 8 | 13／9 |
| 1 | 純 9 | | 9 | 12／14 |
| 2 | 純 10 | | 10 | 13／11 |
| 3 | 純 14 | | 11 | 10／6 |
| 4 | 13／14 | | 12 | 12／1 |
| 5 | 純 7 | | 13 | 11／2 |
| 6 | 2／15 | | 14 | 15／13 |
| 7 | 2／6 | | 15 | 1／11 |

**網點對齊的是畫面座標不是區塊**：填色時取 `pat[(y mod 8)×8 + x mod 8]`，
所以相鄰的兩塊接得起來。拿單一顏色去畫，十六個勢力裡有十二個會錯。

驗證：原版剛載完第一個進度的主畫面（`orig-loaded.png`），把 remake
從同一個進度算出來的填色**逐格**比——35 個有主的郡裡 34 個全中
（`internal/ui` 的 `TestPrefectureFillsMatchTheOriginal`）。

**還沒解的一個**：長沙（勢力 2 的本據）原版畫的是圖樣 0（純淺紅），
而它的所屬寫的是 2（圖樣 2 是純淺綠），803 格逐格都不同。
排除過玩家顏色、本據顏色、「只有一個郡的勢力」、太守與君主所屬不一致
四種解釋。

## `8x8PAT*`／`8x8AND*`：底紋與遮罩

八張 8×8，`DATA1`。`PAT` 是**底紋**，四張都是 2×2 的兩色棋盤
（`PAT0` 黃／青、`PAT1` 淺青／灰、`PAT2` 淺紅／藍、`PAT3` 白／藍）；
主戰場整個畫面鋪的是 `PAT0`（`0x223e4`）。

`AND` 是**遮罩**，用法是 `畫面 &= 遮罩`——15 的地方留著、0 的地方變黑：

| | 留下來的比例 | 樣子 |
|---|---|---|
| `AND0` | 1/4 | 偶數列的偶數欄 |
| `AND1` | 1/2 | 棋盤 |
| `AND2` | 1/8 | 斜線，每四格留一格 |
| `AND3` | 1/2 | 偶數列整列 |

**紮寨那一步用的是 `AND0`**：可以下寨的格子照常畫，其餘蓋遮罩。
判準是原版走到紮寨的那一格畫面——78 格裡 73 格與「圖塊 AND `AND0`」
逐像素相同，照常畫的正好 4 格（`TestCampMaskMatchesTheOriginal`）。

遮罩與底紋一樣**對齊畫面座標**，所以跨格子接得起來。
