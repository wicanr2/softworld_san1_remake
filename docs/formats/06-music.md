# 配樂與音色

原版開機主選單的第五項是「音樂欣賞」，底下列五首：

```
 5.     末 路
 4.     戰 鼓
 3.     風 雲
 2.     小 徑
 1.     思 古
```

（`AA.EXE` `0x47bb9`–`0x47c0d`，`docs/re/04` §10）

## 1. 資料在哪

`DATA1` 容器裡的四個項目，本身又是一組 `.IDX`／`.GRP`——**巢狀容器**，
版面與外層相同（`docs/formats/01`）：

| 項目 | 大小 | 內容 |
|---|---|---|
| `MUS.IDX` | 40 | 10 個結束位移 |
| `MUS.GRP` | 29,081 | 五首曲子 ＋ 五份音色庫 |
| `MUSV.IDX` | 8 | 2 個結束位移 |
| `MUSV.GRP` | 27,551 | 一首長曲 ＋ 一份音色庫 |

項目**成對出現**：偶數項是曲子，奇數項是那首曲子用的音色庫。

解出來的五首與主選單的曲名一一對上，而且**內容自己就是佐證**：

| # | 曲名 | 事件 | 速度 | 長度 | 音色 |
|---|---|---|---|---|---|
| 1 | 思古 | 555 | 100 | 76.8 秒 | oboe1 piano1 flute2 |
| 2 | 小徑 | 973 | 120 | 96.0 秒 | syn9 organ1 flute2 clarinet piano1 |
| 3 | 風雲 | 2,250 | 120 | 96.0 秒 | sea3 piano1 oboe1 piano2 ＋ 五件打擊 |
| 4 | 戰鼓 | 2,548 | 120 | 64.0 秒 | organ1 piano1 tromb1 ＋ 五件打擊 |
| 5 | 末路 | 437 | 75 | 51.2 秒 | flute-a piano1 flute ＋ 五件打擊 |

「戰鼓」的打擊樂器最多，「思古」只有三件管樂與鋼琴，「末路」是最慢的
75 BPM——曲名與內容相符，所以順序與配對不是猜的。

## 2. 曲子的版面

前 0x46 個位元組是表頭，其後是事件流。把六首曲子的表頭排在一起比對，
只有這幾個位移非零：

| 位移 | 型別 | 內容 |
|---|---|---|
| `0x00` | uint16 | 版本，全部是 1 |
| `0x24` | uint16 | 固定值 `0x04F0` |
| `0x26` | uint32 | 全曲長度（tick）|
| `0x2A` | uint32 | 事件流的位元組數 |
| `0x2E` | uint32 | 事件數 |
| `0x3A` | uint8 | 1 ＝ 節奏模式 |
| `0x3B` | uint8 | 1 |
| `0x3C` | uint8 | 速度（BPM）|
| `0x46` | — | 事件流的起點 |

`0x2A` 對每一首都精準等於「項目長度 − 0x46」，所以表頭長度是確定的。

**每拍 120 個 tick**（`TicksPerBeat`）是推的：事件流裡最常見的時間差是
`0x78` ＝ 120，而 120 是 MIDI 常用的每四分音符 tick 數；用它換算出來的
曲長（51 秒到 96 秒）也合理。要確認得聽原版。

## 3. 事件流是 MIDI，但有兩處不同

事件的形狀是標準 MIDI：可變長度的時間差、狀態位元組、參數，
而且**支援 running status**。看得到的種類有 `0x90` note on、
`0xC0` program change、`0xE0` pitch bend、`0xA0`、以及 `0xF8`／`0xFC`。

沒有 `0x80` note off——音符靠**力度為 0 的 note on** 關掉，這是 MIDI 的
常規做法。

兩處與標準不同：

- **`0xA0` 只帶一個參數**，標準 MIDI 的 polyphonic key pressure 帶兩個。
  資料裡的樣子是 `00 A3 58 | 00 A4 58 | 00 A5 58`。
  ⚠ 照標準讀會把下一個事件的狀態位元組吃掉，整串從那裡開始歪掉，
  **而且不會報錯**——走出來的音符看起來仍然像音樂。
- **`0xF8`／`0xFC` 這類即時訊息也算進表頭的事件數**。它們沒有參數，
  而且不影響 running status。

驗收方式是**事件數要與表頭吻合**：五首曲子全部精準相等
（555／973／2,250／2,548／437）。一個讀錯版面的解析器照樣會吐出一串
看似合理的音符，所以這個檢查不能省。

## 4. 頻道對應 OPL2 的兩種模式

OPL2（YM3812）有兩種模式：旋律模式九個聲部，節奏模式六個旋律聲部
加五件打擊樂器。表頭 `0x3A` 選哪一種，而曲子用到的聲部與它吻合：

| 曲 | `0x3A` | 用到的頻道 | 音色庫 |
|---|---|---|---|
| 思古 | 0 | 0–8 | 3 件，全部旋律 |
| 小徑 | 0 | 0–6 | 5 件，全部旋律 |
| 風雲 | 1 | 0–5、7、8 | 4 旋律 ＋ 5 打擊 |
| 戰鼓 | 1 | 0–5、7、8、10 | 3 旋律 ＋ 5 打擊 |
| 末路 | 1 | 0–4 | 3 旋律 ＋ 5 打擊 |

`0x3A` 是 0 的兩首用到第七至九個聲部，是 1 的三首旋律聲部都不超過六個
——正好是兩種模式各自的上限。用到 6 以上的曲子**一律跳過 6**，
而多出來的那些聲部掛的音色是 `snare1`、`tom1`、`hihat3` 這一類。
節奏模式的聲部順序是低音鼓、小鼓、通鼓、鈸、腳踏鈸：

| 聲部 | 6 | 7 | 8 | 9 | 10 |
|---|---|---|---|---|---|
| 樂器 | 低音鼓 | 小鼓 | 通鼓 | 鈸 | 腳踏鈸 |
| 風雲用的音色 | — | `snare1` | `tom1` | — | — |
| 戰鼓用的音色 | — | `mltrdrum` | `tom1` | — | `hihat3` |

原版擷取到的埠寫入也對得上：節奏模式的曲子播放期間 `0xBD` 的位元 5
是 1，換到 `思古` 之後整段是 0。

program change 的編號也全部落在該曲音色庫的範圍內，這把「偶數是曲子、
奇數是它的音色庫」這個配對釘死了。

## 5. 音色庫的版面

| 位移 | 型別 | 內容 |
|---|---|---|
| `0x00` | uint16 | 版本，1 |
| `0x02` | uint16 | 音色數 n |
| `0x04` | uint16 | 參數區的起點，等於 `6 + 9n` |
| `0x06` | — | n 個名稱，每個 9 個位元組（NUL 補齊）|
| `6+9n` | — | n 份參數，每份 **56 個位元組** |

六個音色庫全部整除，零餘數。名稱是 AdLib Visual Composer 的標準音色名
（`piano1`、`oboe1`、`organ1`、`bdrum1`、`snare1`、`tom1`、`cymbal1`、
`hihat1`…）。

56 個位元組是 **28 個小端 16 位元欄位**，排成兩個運算子加兩個波形：

| 欄位 | 內容 |
|---|---|
| 0–12 | 調變運算子：KSL MULT FB AR SL EG DR RR TL AM VIB KSR CON |
| 13–25 | 載波運算子：同樣的十三項 |
| 26–27 | 兩個運算子的波形 |

十三項的順序與 AdLib Visual Composer 音色庫（`.BNK`）的運算子記錄相同，
只是每一項從一個位元組加寬成一個字。

兩個欄位不能照抄：

- **載波的 FB 是垃圾。** OPL2 的回授寫在 `0xC0`，一份是整個頻道共用的，
  音色庫在載波那一格留的是未初始化的值（`piano1` 是 `0x40F6`、
  `bdrum1` 是 `0x102F`）。
- **CON 與暫存器的位元相反。** 音色庫寫 1 代表調頻，而 `0xC0` 的位元 0
  是 1 代表相加。

節奏模式的小鼓、鈸、鈴鼓、通鼓在 OPL2 裡是單運算子，音色庫裡另一半
沒有意義——`hihat1` 的載波整段是別的資料，四位元的欄位會出現上千的值。
要用哪一半由聲部決定，不由音色決定。

## 6. 原版怎麼寫 OPL2

用 dosgolem 的 `-dump-ports` 把埠 `0x388`／`0x389` 的寫入序列錄下來
（選 AdLib 開機），看得到完整的初始化：

```
04=60 04=80        重置計時器與 IRQ 旗標
02=FF 04=21        計時器 1 設 255 並啟動   ← 標準的 AdLib 偵測
04=60 04=80        重置
BD=00 08=00        關節奏模式、關 CSM
40=4F C0=06 60=F1 80=53 20=01 E0=00     ← 一個運算子一份，六個暫存器
…（九個頻道、十八個運算子各一遍）
A0..A8=00 B0..B8=00                     全部 key-off
E0..F5=00                               波形歸零
01=20                                   開啟波形選擇
```

**每個運算子六個暫存器，順序固定是 `40, C0, 60, 80, 20, E0`。**
`0x40` 是 KSL＋總音量、`0x60` 是 attack／decay、`0x80` 是 sustain／release、
`0x20` 是 AM／VIB／EG／KSR／MULT、`0xE0` 是波形、`0xC0` 是 feedback／連接
（每個頻道一份）。

dosgolem 預設 OPL2 不存在，`In8(0x388)` 一律回 0，偵測過不了，原版會吐
`ErrMsg: AdLib / ErrNo: -1` 離開。`cmd/probe` 的 `-adlib` 讓它過關。

## 7. 音色版面怎麼驗的

把放歌時的寫入序列切成「一次把一份音色填進某個頻道」，再拿它與音色庫的
28 個欄位逐項比（`cmd/san1opl`）：

```sh
tools/go.sh run ./cmd/probe -exe "/orig/三國演義/AA.EXE" -root "/orig/三國演義" \
  -adlib -steps 3000000000 -keys '222' \
  -keys-at '250000000:\r,900000000:5,1500000000:1' \
  -dump-ports '388,389=/src/workplace/opl.tsv'

tools/go.sh run ./cmd/san1opl -ports workplace/opl.tsv -root /orig -after 20000000
```

58 段音色載入裡，**25 段的二十三個參數與音色庫逐項相同**，涵蓋
`bdrum1`、`clarinet`、`flute2`、`oboe1`、`piano1`、`tromb1` 六件不同的音色；
連接位元的反相關係 58 段全部成立。

其餘 32 段不是版面錯：它們是驅動程式重設時對九個頻道**各填一次**的內建
預設音色（四輪，每輪九段，步數連號），那一份的調變部分與 `piano1` 相同
而載波的起音不同，音色庫裡沒有它。

## 8. 音高怎麼驗的

原版播 `思古` 時送出的 `0xA0`／`0xB0`，拆成 block 與 F-number 之後，
與 remake 走同一首曲子產生的寫入**逐次相同**：沒有滑音的五個聲部完全
一樣，有滑音的四個最多差一個 F-number（約三音分）。

```
        原版                                         remake
ch0     4/222 4/266 4/222 4/1E6 4/222 4/198 …        4/222 4/266 4/222 4/1E6 4/222 4/198 …
ch4     3/28A 3/28A 3/266 3/28A 3/28A 3/266 …        3/28A 3/28A 3/266 3/28A 3/28A 3/266 …
ch1     4/21F 4/262 4/21F 4/1E3 4/21F 4/196 …        4/21F 4/262 4/21F 4/1E3 4/21F 4/196 …
```

這一項同時釘住曲子的解析、聲部對頻道的對應、音符表的值與滑音的算法
（`TestNotesMatchTheOriginal`）。

音符表是量出來的，不是等律算出來的：block 取 `音高 / 12 − 1`，
半音查十二格的 F-number 表。沒有滑音的聲部一共蓋到七個半音，剩下五格
用等比補。量到的七個都比等律略高，而且高得不平均（最多約七音分），
所以**不能拿公式代替**。

## 9. 還沒解的

**滑音的算法。** `.ROL` 用一個 0..2 的倍率表示滑音，`思古` 裡有四個聲部
的值是 0.85，原版把它們彈得比不滑音的低約 11 音分。倒推出來的幅度
（一整格 69.5 音分）七組量測裡符合六組。差的地方是原版的差值不是嚴格
等比——`0x198` 差 2 而更低的 `0x16C` 差 3——中間有整數運算。
差的一個 F-number 是三音分，聽不出來，但要對到位元組就得再挖驅動程式。

**`MUSV` 那一首長曲。** 26,700 個位元組、13 件音色、66,240 tick，
走出來 6,926 個事件，表頭說 6,932 個——**少六個**。少的是什麼還不知道。
`TestLongSongIsStillOpen` 把這個差距釘住了：解出來的那一天它會變紅。

## 10. 現在能做什麼

`internal/music` 解得出曲子與音色庫，也合得出聲音。`cmd/san1music`
列出來：

```sh
tools/go.sh run ./cmd/san1music -root /path/to/三國演義
```

`tools/assets.sh` 把整份素材轉成通用格式，配樂出來的是 **OGG**：

```sh
tools/assets.sh /path/to/三國演義
```

合成走 `internal/music` 自己的 OPL2：事件流照 §4 的聲部分配送進晶片，
音色參數照 §5 的版面填進暫存器，取樣率 49,716 Hz（OPL2 的原生速率），
再交給容器裡的 ffmpeg 編成 Vorbis。

同一個工具也匯出**標準 MIDI 檔**，那是給編輯用的——一般 MIDI 音源不是
AdLib，音高與節奏對得上，音色不會是 OPL2 的聲音。

⚠ 匯出的內容是玩家自己那一份原版的東西，**不隨本專案散布**。
