# 事件：四季、天災、進貢

## 1. 季節與月份

**四季事件一年各只跑一次**（`L0`、`[both]`；原版 `0x15c48`、加強版
`0x14c0e`）。分派器讀的是**月份**（原版工作區 `es:[0x3f08]`、加強版
`es:[0x3f14]`），跳躍表比的是 1、4、7、10，其餘八個月直接 `retf`：

| 月 | 原版 | 加強版 | 內容 |
|---|---|---|---|
| 1 | `0x15c5c` | `0x14c4c` | 土地價值衰減、玉璽、老死、年齡增長、忠誠漂移、人物出頭、地震 |
| 4 | `0x164c8` | `0x153fe` | 水災、瘟疫 |
| 7 | `0x169d6` | `0x158a6` | 秋收、蝗害、**人望的年度調整** |
| 10 | `0x16e70` | `0x15cd0` | 人口成長、進貢、人民反叛 |

四支常式兩版逐段對照相同，只有元月的忠誠漂移加強版多一道門（§1.1）。
對拍：`SAN1_MONTH=12`／`3`／`6`／`9`（視窗各跨進元月、四月、七月、十月）
與 `SAN1_MONTH=3 SAN1_PLAGUE=1`，`TestZZMonthParity` 與 `TestZZMonthParityPlus`
各五個視窗三張表整月 0 個位元組（`L1`、`[both]`，Issue #44）。

畫面上的季節分界仍是農曆的三個月一季（元月春、四月夏、七月秋、十月冬），
但**事件只在每季的第一個月發生**。

⚠ 這一格原本被讀成「季節 0–3」，remake 因此每個月都跑季節常式——
天災的機率是原版的十二倍（`CONTEXT.md` §4 的 R16）。

年度事件的月份因此全部是量到的：

| 事件 | 月 | 等級 | 依據 |
|---|---|---|---|
| **年齡增長** | 元月 | `L1` | 人物表全部 350 筆的年齡欄只在建安三年元月與建安四年元月變動 |
| **人口成長** | 十月 | `L1` | 二三十個郡的人口只在十月一起變動，十二個月後再來一次 |
| **秋收** | 七月 | `L0` | 在秋季常式裡，而秋季常式只在七月跑 |
| **各州郡進貢** | 十月 | `L0` | 在冬季常式裡，與人口成長同一支 |

事件在**推進到新的月份之後**跑——事件屬於新的那個月；季節常式排在
開月洗牌之後，所以骰序上四季的擲落在新月份的第一個郡之前。

### 1.1 元月的順序（`L0`／`L1`、`[both]`）

元月常式（原版 `0x15c5c`、加強版 `0x14c4c`）的順序決定骰序，逐段是：

1. **土地價值衰減**（`0x15c96`）：逐郡 1..42、不看所屬，`−RND(土地價值 ÷ 10)`；
   `÷ 10` 之前先 `cbw`，蝗害推到 128 以上的值是負的，`RND(負)` 不抽、不掉。
   說明書「秋收後土地值會稍微下降」講的就是這一條——掉的時間在元月，不在秋天。
2. **玉璽現世**（§5.1）。
3. **老死那一圈**（`0x15d40`–`0x15eb3`）：只跳過已故（身分 12），未登場也掃也擲；
   `RND(3) + 壽命 < 年齡`（帶號）才走到 `RND(50)` 的體能衰減；體能歸零的人，
   身分 1–3 先播一次特效（`RND(4)`），處置常式 `0x14792` 不分身分印一則對白
   （`RND(8)`；君主走繼承 `0x14968`，那一則在 `0x14a38`），槽 96 再多一則
   （`0x148eb`）。除名只寫身分 12、勢力 `0xFF`、所在 `0xFF`，忠誠不動。
4. **加歲那一圈**（`0x15f64`–`0x16042`）：全部 350 筆加歲；有勢力且身分 1–3 的
   才做忠誠漂移（`(人望 − 60) ÷ 2`，負的換 `RND(5)`）、武裝 `−RND(武裝 ÷ 10)`、
   訓練 `−RND(訓練 ÷ 10)`；最後每一筆都過一次出頭判定（§6）。
   **加強版**在漂移寫回之前多一道門（`0x14f8d`–`0x14fb9`）：忠誠原本就
   `>= (難度 − 1) mod 10 + 90` 的人不寫回（難度 5 是 94 以上不動）；
   `RND(5)` 在門之前，照抽。原版沒有這道門（`90-version-diff` §6.6）。
5. **地震**（§2、§3）。

## 2. 天災與民眾忠誠

**兩種災害的判定讀出來了，而且形狀完全不同**（`L0`、`docs/re/06`）。

### 水災（`0x164c8`）——只看洪水率，不看忠誠、不看所屬

逐郡 1..42 跑（無主的也跑），每年四月都會動到洪水率：

```
新洪水率 = min(100, RND(洪水率 ÷ 4) + 洪水率 + 基礎[郡])
淹不淹：RND(65) + 5 < RND(新洪水率)  而且  RND(100) > 80
```

`基礎[郡]` 是 `DS:0x679c` 那張 43 格的表（0–12，索引就是郡編號，
郡 42 是 3），各郡不同——**有些郡天生就容易淹**。洪水率只會往上
（每年至少加基礎值），只有防洪（`FloodDrop` ＝ 謀略 ÷ 10）壓得下來，
所以防洪不是一勞永逸的。淹了的郡集中在掃完之後一起演（§3）。

### 地震（`0x162d2`）——純機率，什麼都不看

```
RND(3) != 0 → 不地震
郡 = RND(42) + 1                  ; 不看所屬，無主郡也震
```

每個春月三分之一的機率，落在隨機一個郡。**沒有第二道門檻。**
發生時先播一次特效（`0x1633b` → `0x32dfa`，`RND(4)`），再擲各項保留率（§3）。

### 蝗害（`0x16bd5`）——隨機挑一個郡，**田越肥蟲越多**

```
郡 = RND(42) + 1                  ; 不看所屬（`0x16bf6` 直接讀忠誠，沒有 0x49e 的比較）
民眾忠誠 >= RND(80) + 30  → 不發生
土地價值 <= RND(100) + 30 → 不發生 ; 第一道沒過就不擲這一道（`0x16c00`）
```

⚠ **方向與瘟疫相反**：蝗害要土地價值**高**，瘟疫要土地價值**低**。
發生時先播一次特效（`0x16c5b`，`RND(4)`），再擲米與土地價值的保留率。

### 瘟疫（`0x167df`）——隨機挑一個郡，看忠誠與土地價值

```
郡 = RND(42) + 1                  ; 不看所屬
民眾忠誠 >= RND(45) + 25 → 不發生
土地價值 >= RND(40) + 20 → 不發生 ; 第一道沒過就不擲這一道
```

兩道都要過。忠誠 70 以上一定安全，25 以下一定過第一關。

**說明書 p.36 的「天災多因人怨引起」講的是這一條，不是水災。**
remake 原本對所有災害套同一條
`災害機率 = 基礎 × (200 − 忠誠) ÷ 200`（`TuneDisasterBase`），
把兩種形狀不同的判定混成一種。

**「意外產生水災後，洪水率會立刻升到 100」**（說明書 p.21，`L2`）——
這一條有出處，不是 remake 加的。

## 3. 各種災害的損失

全部 `L0`／`[both]`（`docs/re/06` §7）。碼裡寫的是**保留率**：
`新值 = 舊值 × (RND(幅度) + 底) ÷ 100`。

| 災害 | 人口 | 金 | 米 | 土地價值 | 洪水率 | 郡裡每一位人物 |
|---|---|---|---|---|---|---|
| 地震 | 剩 60–79% | 剩 50–69% | 剩 40–59% | — | — | **兵剩 40–59%**（`0x16444`–`0x1649c`）|
| 水災 | 剩 70–79% | — | — | 剩 60–79% | **×1.20–1.39** | 兵剩 70–79% |
| 瘟疫 | 剩 40–59% | — | — | — | — | 兵剩 40–59%、體能剩 70–79% |
| 蝗害 | — | — | 剩 20–29% | **×0.80–1.69** | — | — |

- **每一格各擲一次**，不是同一個百分比套到底；人口另有下限五千人
  （地震、瘟疫），而且算的是存的百位值，零頭直接沒了。
- **地震、水災與瘟疫都動兵力，瘟疫還動體能**——手冊 p.36「將領體能下降」
  的出處。掃的是所在郡等於那個郡的每一位人物，不分在職在野、不分勢力；
  動完重整守將清單，郡的兵士跟著變成 Σ兵 ÷ 100。
- **蝗害的土地價值不夾**：`0x16d26` 把 `ftol` 的低位元組直接寫回，
  100 × 1.69 ＝ 169 裝得下，之後元月的衰減把它當負數（`cbw`）而不抽。
- **水災之後洪水率是乘上去的**，越界才變 100——說明書 p.21 的
  「立刻升到 100」只對本來就高的郡成立。
- 每種災害發生時先放一次特效動畫（`RND(4)` 挑哪一種），骰序對拍時
  算一擲。

驗證：`SAN1_MONTH=3 TestZZMonthParity`（視窗推到四月）淹 3 郡、以及
`SAN1_PLAGUE=1` 淹 1 郡 ＋ 瘟疫 1 郡，州郡表與人物表逐位元組相同
（`L1`、`[base]`）；加強版同兩個視窗（`TestZZMonthParityPlus`）也是
0 個位元組（`L1`、`[both]`，常式 `0x153fe`–`0x1587f` 逐段對照相同）。

⚠ **蝗害的土地價值平均會往上**（80–169%）。這與直覺相反，位元組讀得
很清楚，remake 照它、**也不夾**（`L0`）；七月視窗的對拍沒有剛好鬧蝗，
這一格還沒有 `L1`。

## 4. 秋收

`L1`／`[both]`（原版 `0x16a1b`–`0x16ba1`、加強版 `0x158cd`–`0x15a5c`，
`docs/re/06` §6）：金與米各一條算式（`game.HarvestGold`／`HarvestRice`），
洪水率只進米那一半；秋收**不動**土地價值（掉的地方在元月，§1.1）。
兩版的六個常數相同（4.0、1/300、0、30000、3.0、0.005；加強版在
`DS:0xa922`–`0xa94a`）。七月視窗（`SAN1_MONTH=6`）兩版各 0 個位元組。

### 4.1 人望的年度調整（`L1`、`[both]`）

秋季常式的第三件事（`0x16d4f`–`0x16e6a`，蝗害之後、不論有沒有鬧蝗都跑）：

```
兩張 16 格的表歸零
for 郡 = 1..42：所屬 == 0xFF → 跳過
    領地數[所屬]++
    和[所屬] += 民眾忠誠 ÷ 2 + 土地價值 ÷ 2        ; 各自先除再加
for 勢力 = 0..15：領地數 <= 0 → 跳過
    d = 君主魅力 + 和 ÷ 領地數 − 100
    d = d ÷ 32（向零取整）                          ; sar 5，MSC 的帶號除法
    人望 = clamp(人望 + d, 0, 100)
```

差距最大 ±100，所以一年最多 ±3；人望會朝「君主魅力 ＋ 領地平均狀態」
對 100 的差距慢慢漂。這是人望除了戰役 ±2、春季玉璽、繼承折損之外
**唯一的變動來源**——漏掉它，人望就永遠卡在開局值，而部下忠誠每年照
`(人望 − 60) ÷ 2` 離心（`20-personnel`）。

對拍：`TestZZPrestigeAutumnDrift`，把君主魅力交錯改成 100／10 之後走過
一個秋季，十三個勢力逐一相同，含一個負向樣本（10 ＋ 19 − 100 → −2，
向零；向下會是 −3）。remake 是 `game.PrestigeDrift`／`adjustPrestige`。
兩張表與冬季進貢用的是同一對緩衝區，係數不同（進貢是 ÷4、÷2，§5）。

## 5. 冬季進貢

`L1`／`[both]`（原版 `0x170b2`–`0x17348`，逐條見 `docs/re/06` §9；十月視窗
`SAN1_MONTH=9` 兩版各 0 個位元組，寶庫在諸侯表裡一起比）。
發之前先按郡湊出每個勢力的**領地數**與**人才量**
（人才量 ＝ Σ 民眾忠誠÷4 ＋ 土地價值÷2，一個郡最多 75）：

```
領地數 = 0 → 這個勢力沒有                 ; 閘門一
基數 = 人才量 ÷ (RND(10) + 80)
基數 = 0 → 這個勢力沒有                   ; 閘門二
四種寶物（兵書、寶刀、美女、駿馬）各算一次：
    min(RND(基數 + 1), RND(5) + 8)
四種都算完，再 RND(4) 挑一種多給一件
逐種進庫：庫存 = min(100, 庫存 + 件數)
```

**只有一個郡的勢力一件都拿不到**：人才量 75 除以 80–89 等於 0，
卡在閘門二。領地數只是閘門，決定量的是基數。

**上限 8–12，每一種各擲一次。** 手冊 p.37 只說「領地越多，貢品越多」，
沒說有上限——照字面寫成正比的話，一統天下的勢力一年會拿到四十件，
而寶物是賞賜用的，那等於忠誠無限。玉璽不在這四種裡。

寶物進的是**君主的寶庫**，不是郡的庫房（`Faction.Treasury`）。
只有玩家控制的勢力會看到訊息，電腦的照樣進貢。

## 5.1 玉璽現世（`L0`、`[base]`）

順序在元月常式的第二段（土地價值衰減之後、老死之前，§1.1）：先列活著的
勢力，`RND(100) > 50` 才 `RND(活著的數)` 挑一家，人望 `+= RND(30) + 40`。

```
玉璽還沒現世（全域旗標）而且 RND(100) > 50
  → 隨機挑一個活著的勢力：玉璽 ← 1，人望 += RND(30) + 40
```

每個春月判一次。**玉璽的作用是人望**——拿到的那一家人望大漲，而人望
決定部下忠誠每年的漲跌（`20-personnel`）。它不是統一的條件
（`80-victory` §1）。

⚠ **劇本 001 開局就有人持玉璽**（孫堅），所以這個事件在那個劇本裡
不會觸發。remake 原本完全不會發玉璽，而正是因為劇本 001 開局就有，
那個缺口看不出來。

## 6. 人物出頭

`L1`／`[both]`（`0x16042`–`0x160a2`；元月視窗兩版各 0 個位元組）。
元月加歲那一圈的每一筆最後過一次（§1.1 第 4 段，加歲之後）：

```
身分（offset 17）≠ 11（未登場）→ 跳過
年齡（offset 7，帶號）<= 出頭年齡（offset 26）→ 跳過
牽絆對象（offset 14）不是自己、有勢力、
  而且他所在的郡**存的**現役武將數（州郡 offset 22）< 50
    → 特效 RND(4)；牽絆對象不是君主再一則對白 RND(8)；再一則 RND(8)
    → 直接投奔他：位置 ＝ 他的郡、勢力 ＝ 他的勢力、身分 ＝ 一般武將、
      忠誠 ＝ 他的忠誠 × 9 ÷ 10；那一郡存的現役將 +1（`0x162ca`）
否則
    → 出現在**出身郡**（offset 13），身分 9、無勢力，再看露不露面：
      年齡 >= RND(5) + 32 直接露面（身分 8）；年輕的才擲第二道
      RND(30) + 30 > max(謀略, 戰力) 才露面，否則藏著等尋訪
```

**兩件與 remake 原本不同的事**：

- **出頭年齡是每個人自己的**（人物表 offset 26），不是一個全域常數。
  原本是 `TuneComingOfAge = 20`，已退役。
- **牽絆對象有勢力的話，人直接投奔他**，不是回出身郡當在野。
  手冊 p.36 說的「新將投效其親族朋友」原來是字面意思。少了這一條，
  名將的子姪與舊部都會變成散落各地的在野人士，而「牽絆」在登用之外
  就沒有別的作用。
