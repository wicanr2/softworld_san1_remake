# 事件：四季、天災、進貢

## 1. 季節與月份

季節分界 `L1`／`[base]`：原版主畫面左側直排寫年月與季節，三張畫面
對出元月春、四月夏、八月秋——**分界照農曆，正月就是春天**。

| 季節 | 月 |
|---|---|
| 春 | 1–3 |
| 夏 | 4–6 |
| 秋 | 7–9 |
| 冬 | 10–12 |

年度事件落在哪一個月，兩個是量出來的、兩個是 remake 挑的：

| 事件 | 月 | 等級 | 依據 |
|---|---|---|---|
| **年齡增長** | 元月 | `L1` | 人物表全部 350 筆的年齡欄只在建安三年元月與建安四年元月變動 |
| **人口成長** | 十月 | `L1` | 二三十個郡的人口只在十月一起變動，十二個月後再來一次；其他月份只動零星幾個郡 |
| 秋收 | 九月 | remake 挑的 | 說明書只說在秋天。原版那一邊看不出來——米糧每個月都被電腦諸侯買賣，年度收成的尖峰埋在裡面 |
| 各州郡進貢 | 十二月 | remake 挑的 | 說明書只說每年一次 |

其餘按季節發生的事件（`L2`／`[base]`，`internal/game/events.go`）：

| 季節 | 事件 |
|---|---|
| 春 | 體能衰退、老死、地震 |
| 夏 | 水災、瘟疫 |
| 秋 | 蝗害 |
| 冬 | — |

事件在**推進到新的月份之後**跑——事件屬於新的那個月。

### 還沒對上的

原版在**元月**還會調二三十個郡的**地力**（`L1`，兩次，相隔十二個月）。
說明書說「秋收後土地值會稍微下降」，但那個下降如果在秋天，就不該出現在
元月的年度變動裡。兩者的關係還沒解（`L3`）。

## 2. 天災與民眾忠誠

`L2`／`[base]`。「天災多因人怨引起，民眾忠誠最好不要太低」
（說明書 p.36）。remake 的做法：

```
災害機率 = 基礎 × (200 − 民眾忠誠) ÷ 200
```

忠誠 100 時降到基礎值的一半，忠誠 0 時是基礎值的兩倍。**基礎值是
remake 選的**（`TuneDisasterBase`）。

水患另外吃洪水率：洪水率越高機率越高。**「意外產生水災後，洪水率會立刻
升到 100」**（說明書 p.21，`L2`）——這一條有出處，不是 remake 加的。

## 3. 各種災害的損失

全部 `L2`／`[base]`，方向來自說明書，**幅度是 remake 選的**：

| 災害 | 損失 |
|---|---|
| 地震 | 人口／金／米／兵 各減一定百分比 |
| 水災 | 人口與土地價值下降，洪水率升到 100 |
| 瘟疫 | 人口與兵力下降，將領體能下降 |
| 蝗害 | 米與土地價值下降 |

## 4. 秋收

`L2`／`[base]`。說明書只寫「土地價值會略降，稅金入庫、米糧進倉」，
沒給係數。remake 的做法是產出與土地價值成正比、收完土地價值略降。

## 5. 冬季進貢

`L2`／`[base]`。「冬季各州郡會進貢，領地越多貢品越多」——
每幾個郡一年進貢一件寶物（比例是 remake 選的）。
寶物進的是**君主的寶庫**，不是郡的庫房（`internal/game/state.go` 的
`Faction.Treasury`）。

## 6. 人物出頭

`L2`／`[base]`。未登場的人物到某個年齡才出現在他的出身郡，成為在野將領。
年齡門檻是 **remake 選的**（`TuneComingOfAge`）。

## 7. 未解

- **人物出頭的實際條件**：是年齡、是年份、還是劇本寫死的時程，還沒查。
- 說明書提到的其他事件（如果有）還沒逐頁對過。
