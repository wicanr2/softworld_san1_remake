# 事件：四季、天災、進貢

## 1. 季節與月份

**四季事件一年各只跑一次**（`L0`、`0x15c48`）。分派器讀的是**月份**，
跳躍表比的是 1、4、7、10，其餘八個月直接 `retf`：

| 月 | 常式 | 內容 |
|---|---|---|
| 1 | `0x15c5c` | 土地價值衰減、年齡增長、老死、人物異動、地震、玉璽 |
| 4 | `0x164c8` | 水災、瘟疫 |
| 7 | `0x169d6` | 秋收、蝗害 |
| 10 | `0x16e70` | 人口成長、進貢、人民反叛 |

畫面上的季節分界仍是農曆的三個月一季（元月春、四月夏、七月秋、十月冬），
但**事件只在每季的第一個月發生**。

⚠ 這一格原本被讀成「季節 0–3」，remake 因此每個月都跑季節常式——
天災的機率是原版的十二倍（`CONTEXT.md` §4 的 R16）。

年度事件的月份因此全部是量到的：

| 事件 | 月 | 等級 | 依據 |
|---|---|---|---|
| **年齡增長** | 元月 | `L1` | 人物表全部 350 筆的年齡欄只在建安三年元月與建安四年元月變動 |
| **人口成長** | 十月 | `L1` | 二三十個郡的人口只在十月一起變動，十二個月後再來一次 |
| **秋收** | 七月 | `L0` | 在秋季常式裡，而秋季常式只在七月跑 |
| **各州郡進貢** | 十月 | `L0` | 在冬季常式裡，與人口成長同一支 |

其餘按季節發生的事件（`L2`／`[base]`，`internal/game/events.go`）：

| 季節 | 事件 |
|---|---|
| 春 | 體能衰退、老死、地震 |
| 夏 | 水災、瘟疫 |
| 秋 | 蝗害 |
| 冬 | — |

事件在**推進到新的月份之後**跑——事件屬於新的那個月。

### 還沒對上的

原版在**元月**還會調二三十個郡的**地力**（`L1`，兩次，相隔十二個月）。
說明書說「秋收後土地值會稍微下降」，但那個下降如果在秋天，就不該出現在
元月的年度變動裡。兩者的關係還沒解（`L3`）。

## 2. 天災與民眾忠誠

**兩種災害的判定讀出來了，而且形狀完全不同**（`L0`、`docs/re/06`）。

### 水災（`0x164c8`）——只看洪水率，不看忠誠

逐郡跑，每個月都會動到洪水率：

```
新洪水率 = min(100, RND(洪水率 ÷ 4) + 洪水率 % 4 + 基礎[郡])
淹不淹：RND(65) + 5 < RND(新洪水率)  而且  RND(100) > 80
```

`基礎[郡]` 是 `DS:0x679c` 那張 43 格的表（0–12），各郡不同——
**有些郡天生就容易淹**。洪水率會自己往那個基礎值收斂，所以
防洪（`FloodDrop` ＝ 謀略 ÷ 10）不是一勞永逸的。

### 地震（`0x162d2`）——純機率，什麼都不看

```
RND(3) != 0 → 不地震
郡 = RND(42) + 1
```

每個春月三分之一的機率，落在隨機一個郡。**沒有第二道門檻。**

### 蝗害（`0x16bd5`）——隨機挑一個郡，**田越肥蟲越多**

```
郡 = RND(42) + 1
民眾忠誠 >= RND(80) + 30  → 不發生
土地價值 <= RND(100) + 30 → 不發生
```

⚠ **方向與瘟疫相反**：蝗害要土地價值**高**，瘟疫要土地價值**低**。

### 瘟疫（`0x167df`）——隨機挑一個郡，看忠誠與土地價值

```
郡 = RND(42) + 1
民眾忠誠 >= RND(45) + 25 → 不發生
土地價值 >= RND(40) + 20 → 不發生
```

兩道都要過。忠誠 70 以上一定安全，25 以下一定過第一關。

**說明書 p.36 的「天災多因人怨引起」講的是這一條，不是水災。**
remake 原本對所有災害套同一條
`災害機率 = 基礎 × (200 − 忠誠) ÷ 200`（`TuneDisasterBase`），
把兩種形狀不同的判定混成一種。

**「意外產生水災後，洪水率會立刻升到 100」**（說明書 p.21，`L2`）——
這一條有出處，不是 remake 加的。

## 3. 各種災害的損失

全部 `L0`／`[base]`（`docs/re/06` §7）。碼裡寫的是**保留率**：
`新值 = 舊值 × (RND(幅度) + 底) ÷ 100`。

| 災害 | 人口 | 金 | 米 | 土地價值 | 洪水率 |
|---|---|---|---|---|---|
| 地震 | 剩 60–79% | 剩 50–69% | 剩 40–59% | — | — |
| 水災 | 剩 70–79% | — | — | 剩 60–79% | **×1.20–1.39** |
| 瘟疫 | 剩 40–59% | — | — | — | — |
| 蝗害 | — | — | 剩 20–29% | **×0.80–1.69** | — |

- **地震對三個欄位各擲一次**，不是同一個百分比套三次；人口另有下限
  五千人。
- **沒有一種災害動兵力。** remake 原本讓水災與瘟疫按同樣的比例減兵，
  那是加上去的。將領體能下降（手冊 p.36）在碼裡也找不到，
  remake 保留它（`TunePlagueStamina`），否則瘟疫與「人口減少」同義。
- **水災之後洪水率是乘上去的**，越界才變 100——說明書 p.21 的
  「立刻升到 100」只對本來就高的郡成立。

⚠ **蝗害的土地價值平均會往上**（80–169%）。這與直覺相反，位元組讀得
很清楚，remake 照它並夾在 100 以內，但值得單獨對拍一次再定案。

## 4. 秋收

`L2`／`[base]`。說明書只寫「土地價值會略降，稅金入庫、米糧進倉」，
沒給係數。remake 的做法是產出與土地價值成正比、收完土地價值略降。

## 5. 冬季進貢

`L0`／`[base]`（`0x170b2`–`0x17348`，逐條見 `docs/re/06` §9）。
發之前先按郡湊出每個勢力的**領地數**與**人才量**
（人才量 ＝ Σ 民眾忠誠÷4 ＋ 土地價值÷2，一個郡最多 75）：

```
領地數 = 0 → 這個勢力沒有                 ; 閘門一
基數 = 人才量 ÷ (RND(10) + 80)
基數 = 0 → 這個勢力沒有                   ; 閘門二
四種寶物（兵書、寶刀、美女、駿馬）各算一次：
    min(RND(基數 + 1), RND(5) + 8)
四種都算完，再 RND(4) 挑一種多給一件
逐種進庫：庫存 = min(100, 庫存 + 件數)
```

**只有一個郡的勢力一件都拿不到**：人才量 75 除以 80–89 等於 0，
卡在閘門二。領地數只是閘門，決定量的是基數。

**上限 8–12，每一種各擲一次。** 手冊 p.37 只說「領地越多，貢品越多」，
沒說有上限——照字面寫成正比的話，一統天下的勢力一年會拿到四十件，
而寶物是賞賜用的，那等於忠誠無限。玉璽不在這四種裡。

寶物進的是**君主的寶庫**，不是郡的庫房（`Faction.Treasury`）。
只有玩家控制的勢力會看到訊息，電腦的照樣進貢。

## 5.1 玉璽現世（`L0`、`[base]`）

```
玉璽還沒現世（全域旗標）而且 RND(100) > 50
  → 隨機挑一個活著的勢力：玉璽 ← 1，人望 += RND(30) + 40
```

每個春月判一次。**玉璽的作用是人望**——拿到的那一家人望大漲，而人望
決定部下忠誠每年的漲跌（`20-personnel`）。它不是統一的條件
（`80-victory` §1）。

⚠ **劇本 001 開局就有人持玉璽**（孫堅），所以這個事件在那個劇本裡
不會觸發。remake 原本完全不會發玉璽，而正是因為劇本 001 開局就有，
那個缺口看不出來。

## 6. 人物出頭

`L0`／`[base]`（`0x16042`–`0x160a2`）。元月逐槽掃：

```
身分（offset 17）≠ 11（未登場）→ 跳過
年齡（offset 7）<= 出頭年齡（offset 26）→ 跳過
牽絆對象（offset 14）不是自己、有勢力、
  而且他所在的郡現役武將數 < 50
    → 直接投奔他：位置 ＝ 他的郡、勢力 ＝ 他的勢力、身分 ＝ 一般武將
否則
    → 出現在**出身郡**（offset 13），身分 9（在野露面）、無勢力
```

**兩件與 remake 原本不同的事**：

- **出頭年齡是每個人自己的**（人物表 offset 26），不是一個全域常數。
  原本是 `TuneComingOfAge = 20`，已退役。
- **牽絆對象有勢力的話，人直接投奔他**，不是回出身郡當在野。
  手冊 p.36 說的「新將投效其親族朋友」原來是字面意思。少了這一條，
  名將的子姪與舊部都會變成散落各地的在野人士，而「牽絆」在登用之外
  就沒有別的作用。
