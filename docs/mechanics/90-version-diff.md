# 原版 vs 加強版

## 0. 加強版跑得起來了（2026-09-07）

`internal/parity` 的 `TestZZBootPlus` 把 `ASV.EXE` 載進 dosgolem，
答完裝置選單（與原版同樣的 `"122"`）之後開了 253 個檔並畫出標題畫面。
**兩版的程式碼從此可以逐段對讀**——那是唯一剩下的差異來源（§5）。

⚠ 一度以為是加強版載不進來：它在一個檔案都沒開的情況下就
`run-time error R6005 - not enough memory on exec`。真正的原因是
加強版的 `DATA0.GRP` 檔頭有一格垃圾——`e_cblp = 0xAA90`，而那一格
只有低九位有意義（一頁 512 個位元組）。遮成九位得到 144，
`(172−1)×512 + 144` 正好是檔案長度 87,696。兩版 15 個 MZ 檔裡
**只有這一個越界**。修在 `dosgolem/internal/machine/loader.go`。

## 1. 狀態：只知道檔案層的差異，不知道規則層的差異

兩版共用一套規則層是**目標**，不是現況。目前**沒有任何一條機制斷言
是在 `[plus]` 上驗過的**。

⚠ `CLAUDE.md` §3.4：**在解出差異之前不要預先造版本旗標**。
造出來的旗標會固定住一個還沒驗證的假設。

## 2. 檔案層的差異（`L0`／已量過）

| 相同 | 不同 | 只在原版 | 只在加強版 |
|---|---|---|---|
| **全部 6 個 `.IDX`**、**全部 6 個 `.NAM`**、`DATA1/3/4.GRP`、`COPYRIG.EXE`、`README.*` | `DATA0.GRP`（42,488 → 87,696）、`DATA2.GRP`（**同長度、內容不同**）、`DATA5.GRP`（145,378 → 287,590）| `10.GRP`／`20.GRP`／`D5.GRP`、`10.BAT`／`20.BAT`／`PLAY.BAT`、`PARTNSAV.FIL` | `NAME001`–`NAME006.SHA`、`SV.COM`、`CHKLIST.CPS`、`ASV.PIF`／`SV.PIF`、`弧.TXT`（0 bytes）|

進入點：原版 `AA.EXE`（354,960 B）、加強版 `ASV.EXE`（300,494 B）。

## 3. 這些差異能推出什麼

| 觀察 | 推論 | 等級 |
|---|---|---|
| 6 個 `.IDX` 與 6 個 `.NAM` **完全相同** | 容器的**項目清單與邊界沒變**——加強版沒有新增或刪除項目 | `L2` |
| `DATA2.GRP` 同長度不同容 | 劇本資料被改過但**版面沒變**（三張表的尺寸是固定的）| `L2` |
| `DATA5.GRP` 幾乎變兩倍 | 主程式碼大幅增加。`DATA5` 是主迴圈所在（`docs/re/03`）| `L2` |
| `DATA1/3/4.GRP` 完全相同 | **配樂、人物頭像、地圖圖形沒動** | `L0` |
| 加強版多了 `NAME001`–`NAME006.SHA` | **不是遊戲檔**，是 bundle 裡混進來的第三方資料（§4.1）| `L0` |

`DATA2.GRP` 兩版等長不同容，**是逐位元組 diff 最划算的一份**：
版面已知（三張表），所以 diff 出來的每一格都對得回欄位。

## 4. `DATA2.GRP` 逐項比過了：兩版的劇本資料**完全相同**

`cmd/san1diff` 把兩版的 506 個項目按名字一對一比（`.NAM` 與 `.IDX`
兩版相同，所以項目清單與邊界一樣）。結果（`L0`）：

| 類別 | 項數 | 結果 |
|---|---|---|
| 完全相同 | 473 | — |
| 存檔槽（`*.SV1`–`SV6`、`SAVENAME.SVP`）| 30 | 各自 bundle 附的進度，**不是版本差異** |
| 真的不同 | 3 | `R233.OKR`、`R234.OKR`、`ENDO2.IMG`（1/26,884 個位元組）|

**六個劇本的三張表逐位元組相同**：`BASEMAS`／`BASESTA`／`BASEGEN`
六個槽全部零差異。加強版的開局盤面與原版一模一樣——人物能力、州郡數值、
勢力歸屬都沒動。

### 那三項不是內容差異

`.OKR` 是 1 位元的點陣資料（長串的 `00` 與 `FF`，418 項、R000–R427、
共 367 KB）。**`R234.OKR` 在原版裡含著一段 DOS 開機磁區的字串**：

```
IBMBIO  COMIBMDOS  COMIO      SYSMSDOS   SYS
Disk Boot Failure
Non-System disk or disk error
Replace and press any key when ready
```

那不是遊戲內容，是打包時沒清乾淨的緩衝區留下的東西。加強版的同一項是
另一段高熵的垃圾。`ENDO2.IMG` 只差一個位元組，同一個形狀。

所以 **`DATA2.GRP` 兩版沒有實質差異**（`L2`）——長度相同、內容相同，
差的三項是未初始化的殘留。

## 4.1 `NAME00n.SHA` 不是這個遊戲的檔案（`L0`）

六個檔的標頭是

```
11 "WSHA V1B NewType" 1a 10 「一般命名列印格式」
```

內容是**八字命名軟體的存檔**：十神（正印、比肩、食神、偏財）、
十二長生（帝旺、墓、病）、神煞（將星、羊刃）、「元神」「取用神」，
加上六筆個人的姓名與出生時辰。時辰寫成國曆民國 **87 年與 91 年**
（1998、2002）——**1991 年的遊戲不可能含 2002 年的資料**。
`NAME001.SHA` 那份還內嵌一張 32×32 的 16bpp Windows BMP。

決定性的一條：**`ASV.EXE` 與 `SV.COM` 裡連 `NAME00` 或 `SHA`
這兩個字串都沒有**（各出現 0 次）——遊戲從來不開這些檔。

所以它們是打包 js-dos bundle 時混進來的第三方檔案，
**不是加強版的資料，也不構成版本差異**。內容含真實個人資料，
不轉錄、不散布。

## 5. 下一步

`DATA0.GRP`（42,488 → 87,696）與 `DATA5.GRP`（145,378 → 287,590）
都是 MZ 執行檔，差異要反組譯才看得出來。`NAME00n.SHA` 排除掉之後
（§4.1），**這是唯一剩下的線索**。

`DATA2` 既然沒有實質差異，**版本旗標的粒度就不會落在劇本資料上**。
差異只能在程式碼（`DATA0`／`DATA5`）或加強版獨有的 `NAME00n.SHA` 裡。

## 6. 未解

- **規則層的差異**：一條都還沒有。`DATA2` 與 `NAME00n.SHA` 都排除掉之後，
  剩下的全在程式碼裡（`DATA0`／`DATA5`）——**而加強版現在跑得起來了**
  （§0），所以下一步是把兩版的執行期碼段對讀。
- `SV.COM` 是第三方的除防拷貝補丁（檔案裡寫著
  `this is for THE RISING DYNASTY no protect` 與
  `written by --You--.funny..1997`），不是智冠的檔案，
  **不列入版本差異**。
- `.OKR` 的用途（418 項 1bpp 點陣資料，索引怎麼算見 `CONTEXT.md` F62）。
