## 戰後收降（`L0`、`[base]`）

電腦對電腦的戰役打完之後，敗方留在戰場那一郡的人由勝方逐一決定收不收
（原版 `0x1ff7c`／`0x1feba`，`docs/re/05` §7.1）：

```
君主不被收編
戰場郡的現役將滿 50 → 一個都不收
抵抗 ＝ max(謀略, 戰力) ＋（牽絆的對象與自己同勢力 ? 60 − RND(30) : 0）
勝方的人望 >= 抵抗 ÷ 2 → 收編
```

收編改四個欄位：

| 欄位 | 變成 |
|---|---|
| 忠誠 | `min(100, 勝方的人望)` |
| 勢力 | 勝方 |
| 身分 | **3（一般武將）** |
| 所在郡 | 戰場那一郡 |

原本是軍師的人被收編時，**舊主的軍師位子跟著空出來**（諸侯記錄 offset 6
清成 `0xFFFF`）。

**收編一律降成一般武將**，忠誠直接等於新主的人望——人望高的諸侯收來的
降將一開始就死心塌地，人望低的收來就搖搖欲墜。牽絆那一項與登用、挖角
同一個路子：舊主那邊還有牽掛的人就不容易收編。

remake 這一邊是 `game.WarRecruitResistance`／`WarRecruited`／
`WarRecruitLoyalty`；接進安置流程還沒做（`CONTEXT.md` worklist）。

## 身分的編碼：還有一個 10（`L0`、`[base]`）

原版的「登用人才」常式（`0xd0ae`）收兩種身分：

```
cmpb es:[bx+0x2221], 0x0a   ; 身分 10
je  收
cmpb es:[bx+0x2221], 8      ; 身分 8（在野露面）
jne 跳過
```

**身分 10 是 remake 沒有的編碼**（`internal/state` 只列了 0、1、2、3、
8、9、11）。它與 8 一樣可以被登用，但是什麼還沒解。

其餘的編碼都由碼確認過：**0 君主、2 太守、3 一般武將、8 在野露面、
9 在野未露面**（`docs/re/03` §1.4）。

## 訓練兵士：`(智/3 + 武/2) / 3`（`L0`、`[base]`）

從原版的碼直接讀出來的（`docs/re/03` §1.3）：

```
對該郡守軍的每一位：
    兵士數 == 0 → 訓練度 = 0
    否則        → 訓練度 = min(100, 訓練度 + (智/3 + 武/2) / 除數)
```

**逐項截斷**——智與武各自先整數除，再相加，再除。

兩件說明書沒寫的事：**訓練是對整個守軍跑一遍，不挑人**；
**沒有兵的人訓練度會被歸零**。

那個參數由兩個 thunk 決定（3 或 4），一個月裡 28 次走 3、4 次走 4，
兩者的呼叫端是同一個分派點，**分岔的條件還沒解**。`internal/game`
取 3（`game.TrainGain`）。

說明書只說「各將的能力影響其麾下的訓練度提升」——方向對，係數是碼裡
才有的。

## 徵兵：人口 1:1 變成兵（`L1`、`[base]`）

受控實驗（`internal/parity` 的 `TestZZAIProbe`）：同一個盤面只改金額，
讓原版的電腦諸侯自己決定要不要徵兵。

| 給的金 | 兵士 | 人口（沒徵兵時會是 164）|
|---|---|---|
| 5,000 | ＋33 | 131 ＝ 164 − 33 |
| 20,000 | ＋133 | 31 ＝ 164 − 133 |

**兵士增加多少，人口就少多少，一個不差。** 兩個量級各驗一次。
（兩欄存的都是實際值 ÷ 100。）

（`docs/spec/003` §2.1）：

| 職位 | 帶兵上限 |
|---|---|
| 諸侯 | 5,000 |
| 軍師・大將 | 3,000 |

| 主簿・裨將 | 2,000 |
| 謀士・牙將 | 1,500 |

## 3. 身分

`L0`／`[base]`（`BASEGEN` 位移 17，`docs/spec/003` §2.2）：
諸侯／軍師／太守／現役／在野／未登場。

「在野」有兩種：列入該郡在野數的，與**尋訪之後才會出現的**。
後者在資料裡是另一個身分值——所以「尋訪人才」找得到的人是本來就在那個郡的
（`internal/game/personnel.go` 的 `Search`）。

## 4. 人事四項

| 指令 | 規則 | 等級 |
|---|---|---|
| 尋訪人才 | 每次 5 金，謀略越高機會越大 | `L2`（說明書 p.22）|
| 登用人才 | 每人 30 金，判定見 §4.1 | `L0`（`0xce8c`）|
| 賞賜金帛 | 上限 100 金，**每郡每月每人一次** | `L2`（p.23）|
| 撤職 | 遣散費 10 金，**主事者不能撤** | `L2`（p.23）|

尋訪、賞賜、撤職的成功率係數是 **remake 選的**（`TuneSearchIntel` 等）；
登用不是（§4.1）。

⚠ **成功率型的指令在 remake 裡是決定性的**：用局面本身當種子
（年、月、郡、人物），同一個局面同一個決定永遠得到同一個結果。
理由與 AI 相同——帶系統亂數的話「這一次為什麼失敗」無法回答，對拍也無從
下手。**這不是原版的亂數**；原版的亂數產生器還沒反組譯到
（`internal/game/personnel.go` 的 `roll`）。

### 4.1 登用人才的判定（`L0`、`[base]`）

原版把它拆成說服力與難度兩個數，**說服力大於難度才成功**：

```
說服力 ＝ (人望 × 3 ＋ 太守魅力) ÷ 3 ＋ 加成
難度   ＝ 謀略 ÷ (RND(4)+3) ＋ 戰力 ÷ (RND(4)+3)
```

難度前面有一道**牽絆閘門**，蓋過能力值（人物表 offset 14，
`docs/spec/003` §2.6）：

| 牽絆對象現在效力於 | 難度 |
|---|---|
| 招募方 | 0（一定成功）|
| 在野 | 照上面算 |
| 第三方 | 160 ＋ `RND(10)`（幾乎不可能）|

成功之後：

```
忠誠 ＝ 人望 ÷ 2 ＋ RND(人望 ÷ 2) ＋ 加成      ; 夾到 1..100，不到 1 當沒成功
身分 ← 3（一般武將）；效力的勢力 ← 本郡的勢力
州郡的現役將數 ＋1、在野武將數 −1、兵士 ＋= 他的兵力 ÷ 100
```

說明書「太守的魅力越高，成功的機會越大」對上了公式裡的 `太守魅力 ÷ 3`；
**人望是更重的一項**（係數 1 對 1/3），而說明書沒提。

**費用與加成成對，由電腦諸侯的等級決定**：

| 等級 | 0–2 | 3 | 4 | 5 |
|---|---|---|---|---|
| 費用 | 30 | 20 | 10 | 0 |
| 加成 | 0 | 10 | 20 | 40 |

等級 0–2 那一組的 30 金正是說明書給玩家的價目，所以玩家照 `(30, 0)`
算（`L2`：玩家那支常式沒有單獨讀過）。

⚠ 開頭還有兩道守門：本郡現役將已達 50 位、或電腦諸侯本回合的預算
用完，都直接回 −1 不做。

實作在 `game.Recruit`／`game.RecruitPersuasion`／`game.RecruitDifficulty`，
三條閘門路徑由 `TestRecruitBondGate` 各驗一次。

|---|---|---|
| 指定軍師 | **謀略不得低於 80**、君主不得兼任、同時只能有一位 | `L2`（說明書 p.23）|
| 指定太守 | 指定**自身所在之外**的領地部將；不耗命令 | `L2`（p.23）|

| 登用他國人才 | 每次 100 金；諸侯挖不動；**太守被挖角則全郡易主** | `L1`（見 §5.1）|

### 5.2 賞賜物品（`L1`、`[base]`，分派表 `0x56b4` 底下四支）

等級 0–2 是空操作；等級 3–5 各自把四支跑一遍，一支管一種寶物：

| 寶物 | 諸侯 offset | 能力 | 增幅 | 忠誠增幅 |
|---|---|---|---|---|
| 兵書 | 15 | 謀略 | `RND(2) + 2` | `RND(30) + 新謀略 ÷ 2` |
| 寶刀 | 16 | 戰力 | `RND(2) + 3` | `RND(30) + 新戰力 ÷ 2` |
| 美女 | 17 | 魅力 | `RND(2) + 5` | **`RND(50) + 50`** |
| 駿馬 | 18 | 戰力＋魅力 | `RND(2)+2`／`RND(2)+3` | `RND(30) + 新戰力 ÷ 2` |

**說明書 p.24 的數字是下界不是定值**——手冊沒寫錯，只是沒提那一擲
（`0xda44`／`0xdba2`／`0xdd09`／`0xde7f`／`0xde96` 的 `add $底,%al`）。
能力上限 90、忠誠上限 100 都在碼裡。

每一支的前置：

```
RND(100) > 40 → 不做
庫存 <= RND(2) + 2 → 不做              ; 囤到 3–4 件以上才發
```

收禮的是名單裡**第一個**「該能力 > `RND(20) + 60`，**或者是君主**」
而且該能力 < 90 的人——君主一律跳過能力門檻。

三個月 **186 次**對拍，四種都走到（53／52／38／43），逐次相同
（`docs/playtest/02`）。

「上限 90」是**賞賜的上限不是能力的上限**——原本就 95 的人不會因為收到
禮物而掉到 90（`internal/game/personnel.go` 的 `raiseTo`）。

### 5.1 挖角的成敗（`L0`、`[base]`，常式 `0x1dc0a`）

候選過濾（忠誠 < `RND(15) + 80`、牽絆對象不在他自己陣營）挑出人之後，
`0x1de46` 先扣 100 金，再呼叫 `0x1dc0a` 判成敗。
**它回的不是布林，是「成功之後的忠誠」**——算出來 <= 0 就當失敗。

```
前置：目標是君主（身分 0）→ 挖不動
      目標的牽絆對象與他同一勢力 → 挖不動        ; 在野的人略過這兩道

門檻 ＝ (我方君主的魅力 × 3 ＋ 我方人望 × 4) ÷ 6 ＋ 加成
抵抗 ＝ 目標忠誠 ＋ 戰力 ÷ 10 ＋ 謀略 ÷ 10
       ＋ (對方人望 − 50) ÷ 3          ; 對方人望 >= 50 才加
       ＋ RND(對方人望 ÷ 2)            ; RND(5) + 90 <= 對方人望
       ＋ RND(30)                      ; RND(7) + 87 <= 目標忠誠
       ＋ 1000                         ; **對方諸侯持有玉璽**
抵抗 < 門檻 → 成功
新忠誠 ＝ clamp((100 − 舊忠誠) ÷ 2 ＋ 我方人望 ÷ 2, 0, 100)
```

**玉璽那一條等於免疫**：抵抗加一千，而門檻最高不過兩百出頭。
諸侯記錄 offset 14 就是玉璽那一格。說明書 p.24 只說「諸侯挖不動」，
玉璽這一條是碼裡才有的。

**對拍過**（`L1`，`docs/playtest/02`）：四個月 **25 次判定**，
三個條件式加項各走到 25／2／23 次，而**觸發與否在全部 25 次上都與條件
相符**（沒觸發的那些也算數）。「君主要在本郡」加上候選過濾讓這一支
本來就罕見，成功只有 1 次。

⚠ **忠誠有兩道相反的門**：候選過濾要 `忠誠 < RND(15) + 80`（最高 94），
「目標忠誠」那個加項要 `忠誠 >= RND(7) + 87`（最低 87）——只有 87–93
同時滿足。把忠誠設到 95 想逼出那個加項，反而會被候選過濾先擋掉，
看起來像「這個加項不存在」。

實作是 `game.HeadhuntOffer`／`HeadhuntResistance`／`HeadhuntNewLoyalty`，
`TuneHeadhuntBase` 退場。

## 6. 年齡與死亡

年齡在**每年的第一個春月**增長一次，不是每個春月都加（`L1`）。

**老死看壽命**（人物表 offset 28，`L1`、`0x15d5d`）：

```
RND(3) + 壽命 >= 年齡 → 這一年完全不動體能
否則  體能 ← max(0, 體能 + (壽命 − 年齡) × 25 − RND(50))
      體能 ＝ 0 才是死
```

**壽命是「幾歲開始走下坡」不是「幾歲一定死」**，而**體能是壽命的緩衝**：
體能 80 的人過壽一年只掉到 5–55，過壽四年（`−100`）才必死。
沒過壽命的人體能一點都不掉——所以「體能低」不代表快死了，
那是打仗打出來的傷，養得回來。

壽命的值域是 46–75，與史實年齡接近（劉備 62、關羽 57、曹操 65、
孫堅 46）。填充槽是 `0xFF` 哨兵。

**對拍過了**（`docs/playtest/02`）：把六十個槽的年齡擺成壽命 + 1、
讓原版自己跑一年，二十一次老死判定寫回去的體能與這條算式逐次相同。

未登場的人物到**自己的出頭年齡**（offset 26）才出頭。

## 7. 未解

- **兵種的地形適性方向**還是 `L2`（說明書 p.18）。編號對應本身是 `L0`
  ——原版的字串表在 `DS:0x5962`，七項每項 5 bytes，用 offset 21 直接
  索引（`docs/spec/003` §2.1）。
- **忠心度怎麼隨時間變**。現在只有賞賜與挖角會動它。
- 位移 6 與 20 還沒解（20 全部是 `0xFF`、沒有任何讀寫）。
  位移 26（出頭年齡）、27（肖像編號）、28（壽命）已解；
  15、23 是相鄰 `u16` 欄位的高位，29 全部是 0 且沒有讀寫
  （`docs/spec/003` §2.9）。位移 14 的**用途**解出來了
  （登用的牽絆閘門，§4.1），代表什麼關係還沒定。

## 訓練度與武裝度每年自然衰減（`L0`、`[base]`）

元月逐一走過 350 個人物槽（`0x16006`／`0x16025`）：

```
武裝度 −= RND(武裝度 ÷ 10)
訓練度 −= RND(訓練度 ÷ 10)
```

值越高掉越多，形狀與土地價值相同（`60-economy` §1.1b）。
**這是「訓練兵士」與「購置武器」要一直做的原因**——少了它，
一次練到頂就永遠是精兵，而數值欄停在 100 看起來完全正常。

## 忠誠的年度漂移（`L0`、`[base]`）

同一個迴圈還做忠誠：

```
忠誠 ← 忠誠 + (人望 − 60) ÷ 2      ; 只對軍師／太守／一般武將，君主不算
  < 0   → RND(5)
  > 100 → 100
```

**人望是諸侯記錄 offset 8**（`u16`，0–100）：戰役勝方 +2、敗方 −2
（`0x204b4`／`0x204e0`），另有一個春季隨機事件 `+RND(30) + 40`。

**60 是分水嶺。** 人望不到 60 的諸侯，部下每年都在離心——這把
「打勝仗」與「留得住人」接在一起。少了這一條，一個從不打仗也從不
賞賜的諸侯，部下的忠誠會永遠停在開局值。
