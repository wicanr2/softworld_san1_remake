## 戰後收降（`L0`、`[base]`）

電腦對電腦的戰役打完之後，敗方留在戰場那一郡的人由勝方逐一決定收不收
（原版 `0x1ff7c`／`0x1feba`，`docs/re/05` §7.1）：

```
君主不被收編
戰場郡的現役將滿 50 → 一個都不收
抵抗 ＝ max(謀略, 戰力) ＋（牽絆的對象與自己同勢力 ? 60 − RND(30) : 0）
勝方的人望 >= 抵抗 ÷ 2 → 收編
```

收編改四個欄位：

| 欄位 | 變成 |
|---|---|
| 忠誠 | `min(100, 勝方的人望)` |
| 勢力 | 勝方 |
| 身分 | **3（一般武將）** |
| 所在郡 | 戰場那一郡 |

原本是軍師的人被收編時，**舊主的軍師位子跟著空出來**（諸侯記錄 offset 6
清成 `0xFFFF`）。

**收編一律降成一般武將**，忠誠直接等於新主的人望——人望高的諸侯收來的
降將一開始就死心塌地，人望低的收來就搖搖欲墜。牽絆那一項與登用、挖角
同一個路子：舊主那邊還有牽掛的人就不容易收編。

收不下來的人**離開敗方**：不是君主而戰場郡的在野將沒滿 50 → 變成戰場郡
的在野（身分 10、勢力 `0xFF`、郡的在野將 ＋1，`0x200f4`）；君主、在野將已滿
50、或有牽絆的人第二次判定沒過 → 下野（身分 12、勢力與所在郡都 `0xFF`，
`0x20050`）。逃得掉的人（`RND(200)` 高過謀略 ＋ 戰力 ÷ 2，而且退路鄰郡
有位子）根本不進名單，直接退到那個郡。整條流程與位址在 `docs/re/05` §7.1
（`L0`＋`L1`、`[both]`）。

remake 這一邊是 `game.WarRecruitResistance`／`WarRecruited`／
`WarRecruitLoyalty`，安置是 `game.placeAfterAIBattle`。加強版月度對拍的
兩場戰役安置逐人相同（`docs/playtest/02` §7）。

## 身分的編碼：還有一個 10（`L0`、`[base]`）

原版的「登用人才」常式（`0xd0ae`）收兩種身分：

```
cmpb es:[bx+0x2221], 0x0a   ; 身分 10
je  收
cmpb es:[bx+0x2221], 8      ; 身分 8（在野露面）
jne 跳過
```

**身分 10 是「剛失去勢力、留在原地」**（`L0`）。全表只有一種寫法，
兩份同形的碼各一次（`0x20183`／`0x201c7` 與 `0x261f5`／`0x26239`）：

```
身分 == 0（君主）→ 先把他的勢力存進全域 0x20f0
身分 == 1（軍師）→ 先把諸侯[勢力] offset 6 清成 0xFFFF
全域 0x24d6 ← 人物槽，全域 0x31b8 ← 全域 0x1bf8（郡），全域 0xc4 ← 2
身分   ← 10
勢力   ← 0xFF
所在郡 ← 全域 0x1bf8
```

**讀的地方一律與 8 成對**：九處比對 10 的碼，每一處旁邊都有一處比 8
（`0x0d0e0`／`0x0d0e8` 那六份是登用的六個等級，`0x0fc4f`／`0x0fd39`
是 `buildRoster` 的模式 1 與 4）；`0x0ff80` 更直接寫成
`8 <= 身分 <= 12` 的範圍。**原版沒有任何一處把 10 與 8 分開。**
唯一的不對稱在行動者排序的加權表：身分 10 是 400，8 與 9 是 0
（`docs/mechanics/70-ai` §2.11）。

其餘的編碼都由碼確認過：**0 君主、1 軍師、2 太守、3 一般武將、
8 在野露面、9 在野未露面、11 未登場、12 已故**（`docs/re/03` §1.4）。
12 不是填充專用——月度對拍那個盤面上有 14 個人是 12，而填充只有 4 筆。

## 訓練兵士：`(智/3 + 武/2) / 3`（`L0`、`[base]`）

從原版的碼直接讀出來的（`docs/re/03` §1.3）：

```
對該郡守軍的每一位：
    兵士數 == 0 → 訓練度 = 0
    否則        → 訓練度 = min(100, 訓練度 + (智/3 + 武/2) / 除數)
```

**逐項截斷**——智與武各自先整數除，再相加，再除。

兩件說明書沒寫的事：**訓練是對整個守軍跑一遍，不挑人**；
**沒有兵的人訓練度會被歸零**。

那個參數由兩個 thunk 決定（3 或 4），一個月裡 28 次走 3、4 次走 4，
兩者的呼叫端是同一個分派點，**分岔的條件還沒解**。`internal/game`
取 3（`game.TrainGain`）。

說明書只說「各將的能力影響其麾下的訓練度提升」——方向對，係數是碼裡
才有的。

## 徵兵：人口 1:1 變成兵（`L1`、`[base]`）

受控實驗（`internal/parity` 的 `TestZZAIProbe`）：同一個盤面只改金額，
讓原版的電腦諸侯自己決定要不要徵兵。

| 給的金 | 兵士 | 人口（沒徵兵時會是 164）|
|---|---|---|
| 5,000 | ＋33 | 131 ＝ 164 − 33 |
| 20,000 | ＋133 | 31 ＝ 164 − 133 |

**兵士增加多少，人口就少多少，一個不差。** 兩個量級各驗一次。
（兩欄存的都是實際值 ÷ 100。）

## 3. 身分

`L0`／`[base]`（`BASEGEN` 位移 17，`docs/spec/003` §2.2）：
諸侯／軍師／太守／現役／在野／未登場。

「在野」有兩種：列入該郡在野數的，與**尋訪之後才會出現的**。
後者在資料裡是另一個身分值——所以「尋訪人才」找得到的人是本來就在那個郡的
（`internal/game/personnel.go` 的 `Search`）。

| 指令 | 規則 | 等級 |
|---|---|---|
| 尋訪人才 | 每次 5 金，謀略越高機會越大 | `L2`（說明書 p.22）|

登用與賞賜不是（§4.1、§4.3）。

### 4.3 賞賜金帛

**兩條路完全分開。**

**玩家那條不擲骰、沒有加成**（`L1`）：

```
增幅 ＝ 太守魅力 × k × 金 ÷ 100       k ∈ [0.6405, 0.6429)
```

魅力與賞金兩個維度各掃十來個點，二十四點沒有任何散布
（`docs/playtest/04` §3.3）。**乘完才截斷**：先把效果截成整數再乘金，
金 30／60／90 會少一格。花費就是打進去的數字，忠誠已滿、增幅是 0 時
照樣扣。

⚠ 係數只夾出區間，還沒解出確切值——魅力 89 賞 100 金給 57、魅力 14 給 8。
`internal/game` 目前用 641/1000，量到的點全部重現。

**電腦那條**（`0xd374`／`0xd3ed`，`L0`，六個等級 605 次逐次相同）：

```
效果 ＝ RND(加成 ÷ 2) ＋ 太守魅力 ÷ 3 ＋ 加成
增幅 ＝ 效果 × 金 ÷ 100（夾到忠誠 100）
花費 ＝ min(實際增幅 × 100 ÷ 效果, 100)
```

加成隨 AI 等級變（3→10、4→30、5→40，其餘 0）。**照實際增幅反算花費是
電腦專有的**：忠誠接近 100 時它付的錢跟著變少，玩家不會。

⚠ **成功率型的指令在 remake 裡是決定性的**：用局面本身當種子
（年、月、郡、人物），同一個局面同一個決定永遠得到同一個結果。
理由與 AI 相同——帶系統亂數的話「這一次為什麼失敗」無法回答，對拍也無從
下手。**這不是原版的亂數**；原版的亂數產生器還沒反組譯到
（`internal/game/personnel.go` 的 `roll`）。

### 4.1 登用人才的判定（`L0`、`[base]`）

原版把它拆成說服力與難度兩個數，**說服力大於難度才成功**：

```
說服力 ＝ (人望 × 3 ＋ 太守魅力) ÷ 3 ＋ 加成
難度   ＝ 謀略 ÷ (RND(4)+3) ＋ 戰力 ÷ (RND(4)+3)
```

難度前面有一道**牽絆閘門**，蓋過能力值（人物表 offset 14，
`docs/spec/003` §2.6）：

| 牽絆對象現在效力於 | 難度 |
|---|---|
| 招募方 | 0（一定成功）|
| 在野 | 照上面算 |
| 第三方 | 160 ＋ `RND(10)`（幾乎不可能）|

成功之後：

```
忠誠 ＝ 人望 ÷ 2 ＋ RND(人望 ÷ 2) ＋ 加成      ; 夾到 1..100，不到 1 當沒成功
身分 ← 3（一般武將）；效力的勢力 ← 本郡的勢力   ; 0xd058–0xd07e
州郡的現役將數 ＋1、在野武將數 −1、兵士 ＋= 他的兵力 ÷ 100
```

**職位（offset 12）不動**（`L0`＋`L1`、`[both]`）：成功那一段只寫忠誠、
身分、勢力三格，帶兵上限沿用他在野時的職位——加強版月度對拍量到剛
登用的人在調整兵力裡照舊職位分兵。

說明書「太守的魅力越高，成功的機會越大」對上了公式裡的 `太守魅力 ÷ 3`；
**人望是更重的一項**（係數 1 對 1/3），而說明書沒提。

**費用與加成成對，由電腦諸侯的等級決定**：

| 等級 | 0–2 | 3 | 4 | 5 |
|---|---|---|---|---|
| 費用 | 30 | 20 | 10 | 0 |
| 加成 | 0 | 10 | 20 | 40 |

等級 0–2 那一組的 30 金正是說明書給玩家的價目，所以玩家照 `(30, 0)`
算（`L2`：玩家那支常式沒有單獨讀過）。

⚠ 開頭還有兩道守門：本郡現役將已達 50 位、或電腦諸侯本回合的預算
用完，都直接回 −1 不做。

實作在 `game.Recruit`／`game.RecruitPersuasion`／`game.RecruitDifficulty`，
三條閘門路徑由 `TestRecruitBondGate` 各驗一次。

### 5.2 電腦諸侯的賞賜物品（`L1`、`[base]`，分派表 `0x56b4` 底下四支）

等級 0–2 是空操作；等級 3–5 各自把四支跑一遍，一支管一種寶物：

| 寶物 | 諸侯 offset | 能力 | 增幅 | 忠誠增幅 |
|---|---|---|---|---|
| 兵書 | 15 | 謀略 | `RND(2) + 2` | `RND(30) + 新謀略 ÷ 2` |
| 寶刀 | 16 | 戰力 | `RND(2) + 3` | `RND(30) + 新戰力 ÷ 2` |
| 美女 | 17 | 魅力 | `RND(2) + 5` | **`RND(50) + 50`** |
| 駿馬 | 18 | 戰力＋魅力 | `RND(2)+2`／`RND(2)+3` | `RND(30) + 新戰力 ÷ 2` |

**說明書 p.24 的數字是下界不是定值**——手冊沒寫錯，只是沒提那一擲
（`0xda44`／`0xdba2`／`0xdd09`／`0xde7f`／`0xde96` 的 `add $底,%al`）。
能力上限 90、忠誠上限 100 都在碼裡。

每一支的前置：

```
RND(100) > 40 → 不做
庫存 <= RND(2) + 2 → 不做              ; 囤到 3–4 件以上才發
```

收禮的是名單裡**第一個**「該能力 > `RND(20) + 60`，**或者是君主**」
而且該能力 < 90 的人——君主一律跳過能力門檻。

三個月 **186 次**對拍，四種都走到（53／52／38／43），逐次相同
（`docs/playtest/02`）。

「上限 90」是**賞賜的上限不是能力的上限**——原本就 95 的人不會因為收到
禮物而掉到 90（`internal/game/personnel.go` 的 `raiseTo`）。

### 5.3 玩家的賞賜物品（`L0`＋`L1`、`[base]`，`0x1cfd6`／`0x1d118`）

玩家那一道和電腦的四支**不是同一段碼，算法也不同**。

**流程**（`0x1cfd6`）是兩層迴圈：

```
進命令：已賞名單 es:0x31c2[0..349] 全設 0xFFFF；回傳值 ＝ 0xFFFF
外層：可挑的郡 ＝ 主人等於下令那一郡主人的每一郡（不看君主在哪）
      「賞賜那一郡的將軍」(1-42)；不在清單重問；空 Enter → 回傳
內層：「賞賜那一位」＝ 那一郡的名單（buildRoster 模式 2：身分 0–3，不分勢力）
      挑到 → 0x1d118(人, 勢力)；回 0 → 回傳值改成 0
      回 −1 或空 Enter → 「取消」、延遲；空 Enter 回外層，否則再問那一位
```

主命令迴圈看回傳值：`0xFFFF`（一件都沒送）回主選單再問（`0x17791`），
否則這個郡的回合結束。**已賞名單每道命令重設**，所以「%s已賞賜過了」只擋
同一道命令裡的同一位——跨命令、跨月都不擋；但送出過一件，這個郡這個月
就不能再下令了。

**效果**（`0x1d118`）：

| 物品（輸入） | 能力 | 忠誠 |
|---|---|---|
| 兵書（2） | 謀略 ＋2 | `RND(30)` ＋ 謀略 ÷ 2 |
| 寶刀（3） | 戰力 ＋3 | `RND(30)` ＋ 戰力 ÷ 2 |
| 美女（4） | 魅力 ＋5 | `RND(50)` ＋ 50 |
| 駿馬（5） | 魅力 ＋3、戰力 ＋2 | `RND(30)` ＋ 戰力 ÷ 2 |

- **能力的增幅是定值**，沒有電腦那四支的 `RND(2)`。
- 忠誠看的是**加完、還沒截斷**的能力：謀略 91 收兵書先變 93，忠誠加 `RND(30)＋46`，
  謀略之後才截回 91（看截斷後的算法會是 45；對拍量到忠誠 20→77，擲出 11）。
- 截斷全是位元組運算：忠誠以有號位元組看，大於 100 或小於 0 都寫 100；
  三項能力各自大於 90 寫 90，又比賞賜前小就寫回賞賜前的值。
- 沒有那一件就重問「那一樣(2-5)」；1 是玉璽，不在範圍裡。

驗證：`TestZZGiftLoopMatchesTheOriginal`（出貨進度擺成兩位、兵書寶刀各一件，
送兵書、同一位再送被擋、送寶刀、兩次空 Enter；逐問提示與三張表逐位元組相同），
規則層 `game.GiftRound`／`TestGiftRoundFollowsTheOriginal`。

### 5.1 挖角的成敗（`L0`、`[base]`，常式 `0x1dc0a`）

候選過濾（忠誠 < `RND(15) + 80`、牽絆對象不在他自己陣營）挑出人之後，
`0x1de46` 先扣 100 金，再呼叫 `0x1dc0a` 判成敗。
**它回的不是布林，是「成功之後的忠誠」**——算出來 <= 0 就當失敗。

```
前置：目標是君主（身分 0）→ 挖不動
      目標的牽絆對象與他同一勢力 → 挖不動        ; 在野的人略過這兩道

門檻 ＝ (我方君主的魅力 × 3 ＋ 我方人望 × 4) ÷ 6 ＋ 加成
抵抗 ＝ 目標忠誠 ＋ 戰力 ÷ 10 ＋ 謀略 ÷ 10
       ＋ (對方人望 − 50) ÷ 3          ; 對方人望 >= 50 才加
       ＋ RND(對方人望 ÷ 2)            ; RND(5) + 90 <= 對方人望
       ＋ RND(30)                      ; RND(7) + 87 <= 目標忠誠
       ＋ 1000                         ; **對方諸侯持有玉璽**
抵抗 < 門檻 → 成功
新忠誠 ＝ clamp((100 − 舊忠誠) ÷ 2 ＋ 我方人望 ÷ 2, 0, 100)
```

**玉璽那一條等於免疫**：抵抗加一千，而門檻最高不過兩百出頭。
諸侯記錄 offset 14 就是玉璽那一格。說明書 p.24 只說「諸侯挖不動」，
玉璽這一條是碼裡才有的。

**對拍過**（`L1`，`docs/playtest/02`）：四個月 **25 次判定**，
三個條件式加項各走到 25／2／23 次，而**觸發與否在全部 25 次上都與條件
相符**（沒觸發的那些也算數）。「君主要在本郡」加上候選過濾讓這一支
本來就罕見，成功只有 1 次。

⚠ **忠誠有兩道相反的門**：候選過濾要 `忠誠 < RND(15) + 80`（最高 94），
「目標忠誠」那個加項要 `忠誠 >= RND(7) + 87`（最低 87）——只有 87–93
同時滿足。把忠誠設到 95 想逼出那個加項，反而會被候選過濾先擋掉，
看起來像「這個加項不存在」。

實作是 `game.HeadhuntOffer`／`HeadhuntResistance`／`HeadhuntNewLoyalty`，
`TuneHeadhuntBase` 退場。

## 6. 年齡與死亡

年齡在**每年的第一個春月**增長一次，不是每個春月都加（`L1`）。
**年齡是有號的**（`L0`、`[base]`：`0x15d79`／`0x1605a` 都先 `cbw`）：
還沒出生的人年齡是負的（曹叡 189 年是 −16），要等到真的長到出頭年齡才出現。
當成無號讀，那些人是二百多歲——開局第二年全部出頭、隔年全部老死
（`docs/playtest/05` §6 的第一個差就是它）。

元月的人物處理是**兩圈**（`docs/re/06` §8）：第一圈老死，第二圈加歲、
忠誠漂移、訓練與武裝衰減、出頭。**老死比的是加歲之前的年齡**，
先加再比的話每個人都早一年走下坡。

**老死看壽命**（人物表 offset 28，`L1`、`0x15d5d`）：

```
RND(3) + 壽命 >= 年齡 → 這一年完全不動體能
否則  體能 ← max(0, 體能 + (壽命 − 年齡) × 25 − RND(50))
      體能 ＝ 0 才是死
```

**壽命是「幾歲開始走下坡」不是「幾歲一定死」**，而**體能是壽命的緩衝**：
體能 80 的人過壽一年只掉到 5–55，過壽四年（`−100`）才必死。
沒過壽命的人體能一點都不掉——所以「體能低」不代表快死了，
那是打仗打出來的傷，養得回來。

壽命的值域是 46–75，與史實年齡接近（劉備 62、關羽 57、曹操 65、
孫堅 46）。填充槽是 `0xFF` 哨兵。

**對拍過了**（`docs/playtest/02`）：把六十個槽的年齡擺成壽命 + 1、
讓原版自己跑一年，二十一次老死判定寫回去的體能與這條算式逐次相同。

**死掉的人身分一律寫 12（已故）**，君主與部下都一樣（`L0`：`0x147f6`／
`0x14881`／`0x14a5d`，同時勢力 ← `0xFF`、領地 ← `0xFF`；死者是軍師時
諸侯記錄的軍師欄 ← `0xFFFF`，`0x1486e`）。已故的人尋訪不到、登用不了；
原版一局跑到 279 年時已故累積 342 人，remake 同一顆種子也是 342
（`docs/playtest/05` §6）。remake 的 `retire` 照做。

**主事者之外的人死掉，原版不動郡的歸屬**——郡是下一次重算歸屬
（`0x1e394`）時才落掉的。remake 在 `retireBy` 提前做：死者是郡裡最後一位
現役（軍師在代理主事）就當場把郡寫成無主，形狀與主事者陣亡相同
（`TestLastChiefDeathReleasesThePrefecture`）。

未登場的人物到**自己的出頭年齡**（offset 26）才出頭（`L0`、`[base]`，
`docs/re/06` §8.1）。牽絆對象有勢力、他的郡還收得下（現役 < 50）就直接
投奔他；否則回**出身郡**當在野，而且**年輕的名將是藏著的**：

```
年齡 >= RND(5) + 32                 → 露面（身分 8，郡的在野數 +1）
否則 RND(30) + 30 > max(謀略, 戰力) → 露面
否則                                → 藏著（身分 9），要尋訪才出現
```

謀略或戰力到 59 的年輕人一定藏著，30 以下的一定露面，中間的機率是
`(才能 − 29) ÷ 30`。remake `game.DebutShowsUp`（`TestDebutShowsUp`）。

## 訓練度與武裝度每年自然衰減（`L0`、`[base]`）

元月逐一走過 350 個人物槽（`0x16006`／`0x16025`），**只有在職的部下
（身分 1–3）會掉**——君主、在野、未登場的人凍在原值（`0x15f7f`–`0x15fa2`
的兩道門，`docs/re/06` §8）：

```
武裝度 −= RND(武裝度 ÷ 10)
訓練度 −= RND(訓練度 ÷ 10)
```

值越高掉越多，形狀與土地價值相同（`60-economy` §1.1b）。
**這是「訓練兵士」與「購置武器」要一直做的原因**——少了它，
一次練到頂就永遠是精兵，而數值欄停在 100 看起來完全正常。

## 忠誠的年度漂移（`L0`、`[base]`）

同一個迴圈還做忠誠：

```
忠誠 ← 忠誠 + (人望 − 60) ÷ 2      ; 只對軍師／太守／一般武將，君主不算
  < 0   → RND(5)
  > 100 → 100
```

**人望是諸侯記錄 offset 8**（`u16`，0–100）：戰役勝方 +2、敗方 −2
（`0x204b4`／`0x204e0`），春季玉璽事件 `+RND(30) + 40`，繼承時折損，
以及**每年秋季 `+= (君主魅力 + 平均(民忠÷2 + 土地÷2) − 100) ÷ 32`**
（`0x16e59`，`50-events` §4.1，`L1`）——最後這一條是人望平常唯一會動的地方。

**60 是分水嶺。** 人望不到 60 的諸侯，部下每年都在離心——這把
「打勝仗」與「留得住人」接在一起。少了這一條，一個從不打仗也從不
賞賜的諸侯，部下的忠誠會永遠停在開局值。
