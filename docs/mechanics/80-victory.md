# 勝負：統一判定與玉璽

## 1. 統一的條件（`L0`、`[base]`、`0x15852`）

只有一條：**所有有主的郡屬於同一個勢力**。

原版逐郡掃兩遍——先取一個有主的郡的所屬當基準，再確認其他有主的郡
都是同一方——然後印「%s 一統天下」（`DS:0x66d4`，君主的姓名），
把月內迴圈的旗標 `es:0x0080` 清成 0，遊戲結束。

**無主的郡不算。** 掃描碰到所屬 `0xFF` 就跳過，所以地圖上還留著荒地
也照樣算統一。

**玉璽不是條件。** 那支常式除了郡的所屬與君主的姓名以外沒有讀任何東西
（`docs/re/06` §9）。說明書 p.37 的「在遊戲結束前一定要拿到玉璽」
在碼裡沒有對應（`CONTEXT.md` §4 R19）。

判定的時機是**每個月的最後一件事**，緊接在四季常式之後（`0x1583d`）。

**兩版相同、六個劇本相同**（`[both]`）。加強版的同一支在 `0x148c7`
（編譯目標是 186，用 `imul r,rm,imm` 而不是 `mov ax,imm; imul`），
兩層迴圈、跳過 `0xFF`、清 `es:0x0080` 再印字串的結構逐條對得上。
**這支常式沒有讀年份、劇本編號或任何劇本專屬的資料**，所以
「劇本之間的勝利條件差異」這個問題的答案是：沒有差異。

## 1.1 另一個結束條件：玩家全部絕嗣（`L0` ＋ `L1`、`0x15924`）

掃十六個諸侯槽，只要有一個是**玩家操縱**（offset 0 ＝ 1）**而且君主欄
不是 `0xFFFF`**，遊戲就繼續。一個都沒有時印「所有玩家皆無繼承人
遊戲結束」（`DS:0x97d4`）並結束。

也就是說**輸的定義是「沒有繼承人」不是「沒有領地」**：君主還活著、
領地被打光的玩家，遊戲照樣讓他繼續。

remake 照這條寫：`Session.PlayerAlive` 問的是「這個勢力還有沒有君主」
（`State.Lord`），不是「還有沒有領地」。配套是**沒有繼承人時把君主欄
清成哨兵**（`events.go` 的陣亡處理寫 `f.Lord = -1`，寫回諸侯表時是
`0xFFFF`）——不清的話那一格會一直指著已故的那一位，判定永遠成立。

**「君主活著卻沒有領地」是兩種判準會分岔的狀態**：以領地判會把他判出局，
原版讓他繼續——他還能靠麾下的武將翻身。所以判定要問君主欄，不要問領地。

**兩個出口都實跑走過**（`L1`，`TestNoHeirEndsTheGame`）：同一個盤面推一個月，
君主欄不動時走 `0x1595b`（遊戲繼續），把玩家勢力的君主欄清成 `0xFFFF`
之後走 `0x15962`（清畫面、印 `DS:0x97d4`）。remake 這一邊同一個狀態下
`State.Lord` 也讀不到君主。

## 2. 玉璽

`L0`／`L2`／`[base]`：

- 玉璽是五件寶物之一（玉璽／兵書／寶刀／美女／駿馬），
  在**君主的寶庫**裡（`BASEMAS` offset 14，`Faction.Treasury`）。
- **玉璽現世**是春季事件：未現世且 `RND(100) > 50` 時隨機給一個活著的
  勢力，並且**人望 += RND(30) + 40**（`0x15cfd`／`0x15136`，`L0`）。
  那個人望才是它的作用。
- 原版的已現世旗標在 `es:0x2f6c`（`BASEPRO` offset `0xC4`），
  **不從當前寶庫推導**：絕嗣會清掉玉璽，但旗標仍為已現世，
  後續春季不會再發一次（`L0`、`[base]`，`docs/re/06` §7.1）。
- 冬季進貢**不會**產生玉璽（`50-events` §5）。
- **玉璽不能賞賜給部將**（說明書 p.24）——其他四件可以。
- 戰役決勝時退場君主的**四類一般寶物**按 `0x26c08` 分配：四類之一
  先加 2，再各取半數加 `RND(半數)`；**玉璽不在分贓常式**（`L0`、
  `[base]`，`docs/re/05` §14；加強版相同四類算法見
  `docs/mechanics/90` §6）。舊結論「玉璽會隨滅國轉手」只根據
  說明書 p.35，已被原版讀寫端推翻；繼承或絕嗣的玉璽處置須獨立看
  `0x14968`，不能歸因於分贓。

## 2.5 君主繼承（`L1`、`[base]`、`0x14a40`–`0x14ce6`）

君主死掉時原版做的事，照順序：

```
死者：身分 ← 12（已故）、勢力 ← 0xFF、領地 ← 0xFF
候選 ＝ 掃全人物表（350 筆），勢力欄等於這一方的人
候選依**魅力**由高到低排序（選擇排序，0x14ad2）
候選是空的 → 「無人繼承」（DS:0x657a），勢力 offset 0 ← 0xFFFF
             手上有玉璽的話一併釋出（offset 14 ← 0）
否則：
    電腦操縱（諸侯 offset 0 ＝ 2，0x14c24）→ 取排頭（魅力最高）
    其餘 → 開清單自己挑（0x14f7c，不能取消）
    勢力人望 ← 四捨五入(繼承者魅力 × 原人望 ÷ 100)
    繼承者原本是軍師 → 軍師欄 ← 0xFFFF
    諸侯記錄的君主欄 ← 繼承者
    繼承者：職位 ← 0、兵種 ← 6、身分 ← 君主
```

**候選不限於死者所在的郡**——掃的是整張人物表。君主戰死在外地時，
只從同一個郡找會找不到人，而勢力就這樣無聲地滅了。

**魅力就是繼承的代價。** 人望決定部下忠誠每年的漲跌，魅力 100 的世子
保住全部人望，魅力 50 的一上任就折半，整個勢力跟著慢慢離心。
那條乘法在原版是浮點的 `× 0.01` 再 `+ 0.5` 取整（`DS:0xa6f8`／`DS:0xa700`）。

「只有在繼承君主時才會改變等級」（說明書 p.18）講的是這一刻。

**「依魅力排序」是交換排序，不是穩定排序**（`0x14ad5`–`0x14b41`：外圈 i、
內圈 j＞i，`魅力[j] > 魅力[i]` 才互換）。魅力相同的兩位誰排前面由被換走的
那一位決定，所以 remake 照抄那兩層迴圈（`State.HeirCandidates`），
不用 `sort.SliceStable`。

remake 這一邊是 `State.SucceedLord`／`HeirCandidates`／`SuccessionPrestige`；
**玩家操縱的勢力照原版停下來問**（`NeedsHeir`／`AssignHeir`，`cmd/san1` 的
`askHeir`，清單版面見 `docs/spec/014` §4.4 末段）。規則層不能停著等鍵，
所以先把排頭扶上去、再把這一次排進佇列，玩家答了才復原改套——人望用
**繼承之前**的值重算，不是拿上一位折過的值再折一次。
`TestZZHeirMatchesTheOriginal`：玩家的君主老死，清單與原版相同，
挑第三位之後三張表逐位元組相同。

**無人繼承之後**（`L0`＋`L1`，`[base]`，`TestZZNoHeirReleasesTerritory`）：
原版只寫兩件事——操縱方 ← `0xFFFF`（`0x14ba3`）、手上有玉璽就釋出
（`0x14bcf`）。**郡不必另外釋出**：絕嗣代表這個勢力一個武將都不剩
（候選清單掃的就是勢力欄），而郡的歸屬是從人物表重算的（`0x1e394`），
下一次郡回合入口就全部變成無主。對拍：挑一個一郡多將的電腦勢力，
把部下清成在野、君主擺成過壽，走到三月——兩邊都是操縱方 `0xFFFF`、
君主身分 12、勢力 `0xFF`、持郡 0。remake 的 `Faction.Alive` 跟著在這一刻
變假（`retire`）。

**人望那條對拍過了**（`docs/playtest/02`）：擺三個電腦君主過壽，
原版寫回去的人望與 remake 的整數算式逐次相同，而且三個樣本
跨在四捨五入的兩側（51.87 進位、71.44 與 80.08 捨去）。

## 3. 勢力消滅

`L0`／`[base]`：**「活著的勢力」是君主槽 != `0xFFFF`，不是有沒有領地。**
春季玉璽的候選清單（`0x15cd4`）與玩家出局的判定（`0x15924`）看的都是
君主槽；統一判定（`0x15852`）看的才是郡。所以一個勢力只在**絕嗣**時消滅
（§2.5）；領土歸零而君主還在的勢力照樣活著，能靠麾下的武將翻身（§1.1）。
remake 的 `Faction.Alive` 就是這一格（`Lord` ＝ −1 時為假），
先前「領土歸零就不再存活」那條是 `L2` 的推測，已推翻（`CONTEXT.md` R58）。
要問「還持有郡嗎」用 `Territory`。

**開新局時就有一批槽被清掉**（`L0` ＋ `L1`、`[both]`；原版 `0x1241b`–
`0x1248b`、加強版 `0x11a35`–）：君主槽指向自創君主範本（人物 346 起，
`docs/re/08` §6）而沒被玩家選成自創君主的諸侯槽，操縱方／君主／軍師
一律寫 `0xFFFF`，那筆範本寫成已故（身分 12、勢力 `0xFF`、領地 `0xFF`）。
劇本一、二的填充槽在 14／15，劇本三到六的夾在中間（槽 4、5、10、11…）
而且操縱方是 2——**不看領地、不看操縱方，只看君主槽 ≥ 346**（有號比較，
`0xFFFF` 不碰）。remake `game.New` 的 `clearFillerSlots` 照做，並把那些
槽從 `factions` 拿掉；逐位元組驗收 `docs/spec/015` §8.3。

## 4. 一局跑得完，但兩邊的形狀不同

`L1`／`[base]`（`docs/playtest/05`）：

- **原版**（劇本一、難度 5、電腦自動示範模式）跑完的兩局都在 **284／285 年元月**
  由曹爽（曹操一脈的繼承者）統一，14 個勢力在九十幾年裡打到剩一個；
  另外兩局逾時時走到 65 年剩 9 個、90 年剩 3 個，趨勢相同。
- **remake**（`ai.ModeBase`，接原版亂數）八局裡五局在 266／267 年元月「統一」——
  那是君主相繼老死的結果，三局的「統一者」君主欄是空的；另外三局到 339 年
  還剩 2–3 個勢力對峙不動。
  差異來自兩條 remake 缺口：絕嗣勢力的郡沒有釋出（§2.5 末段），以及人望每年
  秋季的調整沒有實作（`docs/re/11` §6）。修掉再比年份。

經濟數字在二十年後仍然合理（總人口 2,223,448）。
