# 戰役

原版的戰役分三階段（說明書 p.26–35）：

```
召集 → 對陣 → 決勝
```

remake 把它切成兩層：`internal/game` 是戰略層（誰打誰、贏了誰接手、
被擒的將領怎麼處置），`internal/battle` 是戰術層（主戰場上的三十天）。
兩層的接縫在 `internal/game/tactical.go`。

## 1. 戰略層

`internal/game/battle.go`。照手冊的規則：

- 「由該州郡獨力進犯**鄰郡**」——只能打相鄰的郡
- 「主守軍必須派出所有兵力」——守方自動是全部駐軍
- 「若進攻順利，軍隊將駐進被攻下的州郡」
- 「因任何事故所形成的空白郡均不屬任何諸侯」——傾巢而出會被擋下
- 「除了主守軍之外的軍隊都必須從己郡攜帶金、米」——攻方帶走原郡一半的錢糧
- 「獲勝軍若於戰後捉到敵軍君主，其寶物將全歸獲勝軍所有」
- 被擒敵將的四種處置；**諸侯被擒只能斬首或釋放**

`Power`／`DefencePower` 是**估算**用的，只給 AI 判斷出不出兵；
真正的勝負由主戰場打出來。

## 2. 戰術層

`internal/battle`。一場戰役是最多三十天的主戰場，每一回合耗去一天。

| 項目 | 手冊 | 實作 |
|---|---|---|
| 主戰場的格子與六方向 | p.5、p.29 | `field.go`：軸座標，方向編號與手冊按鍵相同（1 左下 … 6 右上）|
| 九種地形與攻防效應 | p.31–33 | `field.go`：平原／沙漠／山丘／樹林／淺水／深水／城池／關寨／大山 |
| 移動力 | p.29–30 | `army.go` `MovePoints`：訓練度為主、全副武裝稍減；地形消耗看兵種適性 |
| 七種兵種的地形適性 | p.18 | `field.go` `TroopKind.Suits`；強力軍是萬能兵種 |
| 四種軍力、五種戰鬥隊伍、編隊與紮營順序 | p.26–28 | `army.go`、`battle.go` `formUp`；每組最多十名將領 |
| 休息 | p.29–30 | `Rest`：移動力 +2，並恢復體力 |
| 快戰／死戰 | p.32 | `QuickBattle`／`DeathBattle` |
| 弓箭 | p.32 | `Archery`：次數 ＝ 各單武裝度算術平均 ÷ 20；目標須同一直線相間一格，不得隔著大山、城池、關寨 |
| 單挑 | p.30 | `Duel`：依戰力分高下、與兵力無關，體能降到 0 落敗；拒絕挑戰麾下部份逃跑 |
| 六種計謀 | p.32–34 | `tactics.go`：智力門檻 80/75/60/60/70/65，費用 600/500/400/100/300/200，含天氣與地形限制 |
| 誘敵與圍攻的結算 | — | `battle.go` `exchange` ＋ `strikeMultiplier`：倍率表 `DS:0x81a2`，誘敵落第 1 格、圍攻第 0 格 |
| 天氣 | p.32–33 | `Weather`：火攻要刮風、水淹要下雨、燒糧下雨天不能用 |
| 退兵 | p.34 | `Retreat`：被地形與敵軍完全包圍則逃不掉；退成功錢糧盡失 |
| 缺糧逃亡 | p.28 | `EndDay`：米不夠就有士兵陸續逃亡 |
| 三十天判定 | p.35 | `checkOver`：守方堅持滿卅天且城池未被奪去即衛郡成功 |
| 統帥條件 | — | `checkOver`：一方的（主＋助）統帥不在陣中，對方勝（原版 `0x24f8c`）|
| 版本規則 | — | `rules.go`：加強版難度 11–20 不判守方統帥全滅（`docs/spec/004` §5）|

**勝負先看統帥、再看兵**。原版三十天之前分勝負的那一條比的是
「軍力記錄的統帥」與「該方第一支部隊的第一位將領」——統帥死了、被俘了、
所屬部隊撤退或全滅了都對不上。remake 等價地問「他本人還在某一支還在
場上的部隊裡」（`Battle.CommanderAlive`），統帥取該方名單的排頭。
兩邊統帥都不在時判攻方勝，那是原版兩段寫入的先後決定的。

加強版難度 11–20 把守方那一半關掉（`battle.RulesFor`），戰役繼續打到
卅天期滿由城池歸屬決定；但守方的**兵**打光還是判敗——加強版另有一條
不看難度的「總兵數為 0 者敗」。

自動作戰（`auto.go`）是決定性的：同一場戰役重跑得到同一份戰報。
玩家不看的戰役也要打得完——原版的「其他 → 戰役」就是那個開關。

它的優先序是：中陷阱不動 → 敗到剩三成而且整體居劣勢就退兵 →
貼身的敵人（戰力壓過對方但正面打不贏就單挑，佔上風打死戰，其餘打快戰）
→ 用計 → 射箭 → 往目標移動 → 剩餘移動力拿去休息。

用計是把付得起的**一個一個試過去**，不是只試最貴的那一個：
六種計謀各有天氣與地形限制，只試火攻的話，不刮風的日子就一招都不會用。
效果還掛著的計（對已中誘敵的部隊再誘敵、對已中陷阱的再設陷阱）也會跳過，
否則貴的計會把錢用完，便宜的一次都輪不到。

`TestAutoUsesTheWholeRepertoire` 掃過一批戰役，數戰報裡有沒有出現
單挑、退兵、射箭、六種計謀與全滅——**一個只會「走過去砍」的 AI
會讓整層看起來完全正常**，每一招各自可用不代表有人用得到。

## 3. 地形版面是原版的資料

每個郡的主戰場圖（郡地理誌，說明書 p.19；查看選單的第 5 項）就存在
**州郡記錄 offset 55–174**：120 個位元組、12 欄 × 10 列，一格一個位元組，
低四位是地形、高四位是標記（`docs/spec/003` §3.3）。戰鬥一開始整份複製
到工作區（`docs/re/05` §1），所以查看到的與打起來用的是同一張。

42 個郡 42 張圖，沒有兩張相同；劇本 001 只有兩種形狀：
12 欄 × 7 列（21 個郡）與 8 欄 × 10 列（21 個）。載入是 `battle.Load`，
寫回是 `Field.Bytes`，`TestEveryPrefectureHasTheOriginalField` 拿真的資料
逐位元組 round-trip——**判準是寫回去一模一樣**，不是「看起來像地圖」。

地圖只帶地形碼與標記，圖塊本身是美術素材，仍然不重製也不散布；
remake 用自己的圖畫同一張版面。`.OKR`（`DATA2`／`DATA3`，465 項，
壓縮過、格式未解，`docs/formats/04` §3）不是這張圖，它是別的東西。

`generate.go` 留著當**沒有劇本資料時的退路**（自組的測試局面），
輸入是郡編號、土地價值、洪水率、鄰郡清單與城寨數，`xorshift32`
決定性推演：同一個郡永遠得到同一張圖，所以那條路徑也仍然可重現。

`TestGenerateCityReachableFromEveryGate` 釘住每個入口都走得到城池——
隨機山脈有機會把城池封死，而那在畫面上只看得出「電腦的軍隊在原地繞圈」。

## 4. 數值的出處

有出處的直接寫在用到的地方並標頁碼：六種計謀的門檻與費用、弓箭次數公式、
地形效應的**方向**、三十天判定、休息 +2 移動力、陷阱困住九日、
每組上限十名將領。

沒出處的一律走 `Tune*`（`docs/design/02`）：傷害係數、單挑的體能消耗、
被擒機率、弓箭的單次殺傷。誘敵與圍攻原本的兩個 `Tune*`
（`TuneEnragedPenalty`／`TuneLureDays`／`TuneSiegeBonus`）已經退役——
那兩招的倍率是量到的。
`grep -rn Tune internal/battle` 就是全部的清單。

## 5. 玩家親自指揮

原版的主戰場有**兩層指令**（`docs/re/04` §4，`AA.EXE` 的字串表）：

```
部隊層（0-8）  1.移動 2.對戰 3.快戰
               4.死戰 5.弓箭 6.策略
               7.查看 8.退兵 0.休息

單位層（0-4）  1.行軍 2.單挑 3.攻擊
               7.查看 0.休息

方向            4 5 6
                1 2 3
```

remake 照這個編號。`battle.Runner` 依手冊 p.28 的順序輪流讓每一支部隊
行動，遇到玩家的部隊就停下來等輸入，其餘交給 `AutoTurn`。

戰略層那一側分成兩步：`BeginAttack` 收條件、擺陣、扣掉隨軍帶走的錢糧，
但**不打**；打完之後 `FinishAttack` 把傷亡、被擒、城池歸屬搬回局面。
電腦諸侯走的還是 `Attack`（＝ 擺陣 ＋ `Auto` ＋ 收尾），兩條路共用
同一組出兵條件（`musterAttack`）——兩份檢查會慢慢分家，而分家的那一天
只有一邊擋得住。

出兵前先問攜帶的錢糧（原版 `攜帶多少金`／`攜帶多少米`），
畫面同時把三十天要多少米算出來——`battle.RiceForCampaign` 與 `EndDay`
的每日耗用**出自同一條算式**，不然畫面上說夠、打起來卻餓死，
而那要打完三十天才發現。

接著逐隊紮營（原版 `(%2d%s)%s之%s請%s將軍紮寨`）：方向鍵移游標、
`0` 定位、`9` 剩下的照預設排好。`Camp` 不扣移動力也不看距離，
那是佈陣不是行軍；落點仍然要走得進去而且沒有人。

⚠ **出兵不能反悔。** `BeginAttack` 一叫就已經動到局面：攻方帶走的錢糧
當場從原郡扣掉，主事者親征也已經交接。原版也是這樣。

「查看」敵軍要花 **10 金**（原版的訊息是 `查看敵軍須10金!`，`0x46ccf`）；
看自己的部隊不用錢。

畫面在 `internal/ui/battlescreen.go`：12×10 的格子畫在文字畫布上，
奇數列右移半格，地形用單一漢字（漢字剛好填滿兩個半形格，不會有縫），
部隊用隊伍的第一個字，攻守兩色。無頭產得出來：

```sh
tools/go.sh run ./cmd/san1dump -root /path/to/三國演義 \
    -what none -screen battle -sel 22 -months 6 -png battle.png
```

## 6. 還沒做的

### 對戰的子地圖那一層（**刻意不做**）

原版選「2.對戰」之後會進到另一個畫面：雙方的將領各自站在一張
12 × 10 的子地圖上，一個一個下「行軍／單挑／攻擊／查看／休息」
（`docs/re/05` §10）。remake 把它收斂成**一次部隊對部隊的交手**。

**底下的公式全部照原版**：將領戰力值、移動力、一次交手的傷亡、
單挑的接受判定與勝負、拒絕的損失。差的只有「一位一位在子地圖上走」
這個互動層——那一層的規則（行軍的餘步、攻擊的方向）與主戰場同構，
再做一次會讓同一條規則有兩份實作（`CLAUDE.md` §7 第 6 條）。

這是**登記在案的 remake 差異**，不是還沒讀。

- **原版的移動力與戰力公式。** 現在的係數是 remake 選的；要換成原版的
  得先在 dosgolem 裡把對應的函式追出來。
- **助攻軍與助守軍的來源。** 資料結構已經有四種軍力，但「助攻軍必須運用
  謀略才能得到」（p.26）還沒和 `plot.go` 的出兵型計謀接起來。
- **助攻軍與助守軍的自動判斷。** 現在只有主攻與主守會真的上場。
