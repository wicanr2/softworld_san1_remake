# 戰役

原版的戰役分三階段（說明書 p.26–35）：

```
召集 → 對陣 → 決勝
```

remake 把它切成兩層：`internal/game` 是戰略層（誰打誰、贏了誰接手、
被擒的將領怎麼處置），`internal/battle` 是戰術層（主戰場上的三十天）。
兩層的接縫在 `internal/game/tactical.go`。

## 1. 戰略層

`internal/game/battle.go`。照手冊的規則：

- 「由該州郡獨力進犯**鄰郡**」——只能打相鄰的郡
- 「主守軍必須派出所有兵力」——守方自動是全部駐軍
- 「若進攻順利，軍隊將駐進被攻下的州郡」
- 「因任何事故所形成的空白郡均不屬任何諸侯」——傾巢而出會被擋下
- 「除了主守軍之外的軍隊都必須從己郡攜帶金、米」——攻方帶走原郡一半的錢糧
- 「獲勝軍若於戰後捉到敵軍君主，其寶物將全歸獲勝軍所有」
- 被擒敵將的四種處置；**諸侯被擒只能斬首或釋放**

`Power`／`DefencePower` 是**估算**用的，只給 AI 判斷出不出兵；
真正的勝負由主戰場打出來。

## 2. 戰術層

`internal/battle`。一場戰役是最多三十天的主戰場，每一回合耗去一天。

| 項目 | 手冊 | 實作 |
|---|---|---|
| 主戰場的格子與六方向 | p.5、p.29 | `field.go`：軸座標，方向編號與手冊按鍵相同（1 左下 … 6 右上）|
| 九種地形與攻防效應 | p.31–33 | `field.go`：平原／沙漠／山丘／樹林／淺水／深水／城池／關寨／大山 |
| 移動力 | p.29–30 | `army.go` `MovePoints`：訓練度為主、全副武裝稍減；地形消耗看兵種適性 |
| 七種兵種的地形適性 | p.18 | `field.go` `TroopKind.Suits`；強力軍是萬能兵種 |
| 四種軍力、五種戰鬥隊伍、編隊與紮營順序 | p.26–28 | `army.go`、`battle.go` `formUp`；每組最多十名將領 |
| 休息 | p.29–30 | `Rest`：移動力 +2，並恢復體力 |
| 快戰／死戰 | p.32 | `QuickBattle`／`DeathBattle` |
| 弓箭 | p.32 | `Archery`：次數 ＝ 各單武裝度算術平均 ÷ 20；目標須同一直線相間一格，不得隔著大山、城池、關寨 |
| 單挑 | p.30 | `Duel`：依戰力分高下、與兵力無關，體能降到 0 落敗；拒絕挑戰麾下部份逃跑 |
| 六種計謀 | p.32–34 | `tactics.go`：智力門檻 80/75/60/60/70/65，費用 600/500/400/100/300/200，含天氣與地形限制 |
| 天氣 | p.32–33 | `Weather`：火攻要刮風、水淹要下雨、燒糧下雨天不能用 |
| 退兵 | p.34 | `Retreat`：被地形與敵軍完全包圍則逃不掉；退成功錢糧盡失 |
| 缺糧逃亡 | p.28 | `EndDay`：米不夠就有士兵陸續逃亡 |
| 三十天判定 | p.35 | `checkOver`：守方堅持滿卅天且城池未被奪去即衛郡成功 |

自動作戰（`auto.go`）是決定性的：同一場戰役重跑得到同一份戰報。
玩家不看的戰役也要打得完——原版的「其他 → 戰役」就是那個開關。

它的優先序是：中陷阱不動 → 敗到剩三成而且整體居劣勢就退兵 →
貼身的敵人（戰力壓過對方但正面打不贏就單挑，佔上風打死戰，其餘打快戰）
→ 用計 → 射箭 → 往目標移動 → 剩餘移動力拿去休息。

用計是把付得起的**一個一個試過去**，不是只試最貴的那一個：
六種計謀各有天氣與地形限制，只試火攻的話，不刮風的日子就一招都不會用。
效果還掛著的計（對已中誘敵的部隊再誘敵、對已中陷阱的再設陷阱）也會跳過，
否則貴的計會把錢用完，便宜的一次都輪不到。

`TestAutoUsesTheWholeRepertoire` 掃過一批戰役，數戰報裡有沒有出現
單挑、退兵、射箭、六種計謀與全滅——**一個只會「走過去砍」的 AI
會讓整層看起來完全正常**，每一招各自可用不代表有人用得到。

## 3. 地形版面是 remake 自己畫的

原版每個郡有一張主戰場圖（郡地理誌，說明書 p.19；查看選單的第 5 項）。
最接近的候選資料是 `DATA2`／`DATA3` 的 `.OKR`：465 項，長度多半是
50 的倍數加一，自相關約 0.55，判定為壓縮過，格式尚未解出
（`docs/formats/04` §3）。主程式用 `R%03d.OKR` 組檔名，那個格式字串
落在戰役程式碼的區域（`docs/re/04` §13）；但 465 不是 42 的倍數，
所以不是一郡一張。索引怎麼算的還沒解。

即使解出來，那也是美術素材，與主畫面地圖同理不重製也不散布。

所以 `generate.go` 自己生成版面，輸入是郡編號、土地價值、洪水率、
鄰郡清單與城寨數，`xorshift32` 決定性推演：**同一個郡永遠得到同一張圖**，
所以整場戰役可重現，對拍也成立。生成規則本身仍取自手冊：

- 每個鄰郡在邊界上有一個通道，「也是鄰郡攻入時的發兵地點」（p.19）
- 城池在場上，守方守的就是它（p.35）
- 關寨每郡最多五座（p.21）

土地價值高的郡平原多、洪水率高的郡水域多，這一條手冊沒說，是 remake 的詮釋。

`TestGenerateCityReachableFromEveryGate` 釘住每個入口都走得到城池——
隨機山脈有機會把城池封死，而那在畫面上只看得出「電腦的軍隊在原地繞圈」。

## 4. 數值的出處

有出處的直接寫在用到的地方並標頁碼：六種計謀的門檻與費用、弓箭次數公式、
地形效應的**方向**、三十天判定、休息 +2 移動力、陷阱困住九日、
每組上限十名將領。

沒出處的一律走 `Tune*`（`docs/design/02`）：傷害係數、移動力係數、
計謀殺傷的**幅度**、單挑的體能消耗、被擒機率。
`grep -rn Tune internal/battle` 就是全部的清單。

## 5. 還沒做的

- **原版的移動力與戰力公式。** 現在的係數是 remake 選的；要換成原版的
  得先在 dosgolem 裡把對應的函式追出來。
- **助攻軍與助守軍的來源。** 資料結構已經有四種軍力，但「助攻軍必須運用
  謀略才能得到」（p.26）還沒和 `plot.go` 的出兵型計謀接起來。
- **玩家親自指揮。** 現在戰役一律由 `Auto` 打完；手動下令的介面
  （選隊伍 → 選動作 → 選方向）還沒做。逐日戰報已經留在
  `BattleResult.Log` 裡，畫面接得上去。
